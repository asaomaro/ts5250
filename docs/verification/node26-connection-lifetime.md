# Node.js 26 と接続保持設定の検証

2026-11-13。変更前の基準は main `4d5756f7`。

## 設定の意味

- 5250 の `connectionHold`（分）はブラウザとの通信断・心拍消失の共通の保持時間。個別値、`--connection-hold`、明示した旧 CLI の順で適用する
- 通常の起動は無期限。0 は保持しない。明示的な切断や正常に届いたタブ終了通知は従来どおり即時終了
- プリンターの常駐寿命と 3270 / VT の再接続方式は変更しない
- TCP の `keepAlive` は独立した設定で、既定 false を維持する。`keepAliveOptions` は開始待ち・再試行間隔・回数。既定 60000 ms / 1000 ms / 10 回
- Node.js 26.4 の [net API](https://nodejs.org/api/net.html#socketsetkeepalive) が再試行間隔・回数を扱う。古い内蔵 Node が余分な引数を無視する事態を避けるため、サーバーは 26.4 以降を起動時に要求する
- VSCode と Electron の UI は内蔵ランタイムのまま。サーバーだけ外部 Node で起動し、実行ファイルは `ts5250.nodePath` / `TS5250_NODE_PATH` で指定できる

## OS への反映を確認

Linux / Node v26.13.1。ループバックの接続を作り、scratch の N-API モジュールから `getsockopt` で実際の `TCP_KEEPIDLE` / `TCP_KEEPINTVL` / `TCP_KEEPCNT` を取得した。測っている値は応答時間ではなくカーネルに設定された整数であり、並行ビルド負荷の影響は受けない。

| 経路 | 開始待ち（秒） | 再試行間隔（秒） | 回数 |
|---|---:|---:|---:|
| Node net.Socket の直接呼び出し | 120 | 15 | 8 |
| 別の net.Socket の直接呼び出し | 60 | 30 | 4 |
| ビルド済み tn5250 TcpTransport の TLS 接続（別経路） | 90 | 5 | 7 |

各値が入力と一致した。scratch のネイティブモジュールと自己署名証明書は配布物へ追加していない。
切断までの時間は間隔×回数が目安だが、送信済みデータの再送や OS の実装も関わるため、厳密な期限は保証しない。

## 自動検証

- Node 26.13.1 で全ワークスペースの既存・追加テストを実行
- 実 TCP 接続で 5250 / 3270 / VT の詳細値、5250 とプリンターの接続オプション転記を確認
- 実サーバーによる VSCode 設定の保存・更新・復元、通常版の認証なし/admin/user の設定保存・表示を確認
- 通信断・心拍消失の双方で期限直前の保持と期限での切断、無期限、0、復帰時の解除を確認
- Electron の配布パス相当の一時フォルダーから、外部 Node の実子プロセス起動・health 応答・終了時の後始末を確認（GUI は起動しない）
- Node 26 で IP を SNI に入れる既存 TLS テストが失敗したため、全 TLS トランスポートで IP の SNI を省略。証明書の既定拒否と明示許可の双方を再確認
- Node の Web Storage と jsdom の衝突で画面テストが失敗したため、jsdom 用テストプロセスでは `--no-experimental-webstorage` を指定。実ブラウザの Storage 処理は変更しない
- 回帰注入：TCP の再試行間隔を 1000 ms 固定に戻すと TCP テストが失敗。統一保持時間の適用を外すと期限のテストが失敗。両方とも復元して成功を再確認

IBM i 実機への接続、実ネットワークのパケット破棄を伴う切断時間、Windows/macOS の OS 設定値、VSCode/Electron の実 GUI は未確認。OS 設定値の測定とループバック試験を実機の無通信耐性測定の代わりには扱わない。
