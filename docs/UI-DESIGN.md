# UI デザインガイド（web-ui）

このセッションの UI 調整で確立した、**再利用すべき見た目・振る舞いの規約**をまとめる。
新規の画面・コンポーネントを足すときはこの規約に合わせる（`packages/web-ui`）。

---

## テーマ / 配色

- **配色は CSS 変数で一元化**し、コンポーネントは変数を使う（生の色コードを避ける）。定義は
  `packages/web-ui/src/styles.css`（light / dark を両方定義）。
- 主要変数:
  - 面・枠: `--crt`（CRT 面）/ `--crt-bezel` / `--crt-line`、`--card`、`--line`、`--bg`
  - 文字: `--ink`（本文）/ `--muted`
  - アクション・状態: `--accent`（**緑・主アクション/プリンター**）/ `--accent-soft`、
    `--t-green` / `--t-blue`（**5250端末**）/ `--t-yellow` / `--t-red`
- **テーマは `useTheme`**（`composables/useTheme.ts`）: ライト → ダーク → **システム（OS 追従）** の 3 モード。
  `data-theme` 属性で適用し、system は `prefers-color-scheme` 変更に追従する。
- **新規スタイルは light / dark 両テーマで確認**する（変数経由なら基本追従する）。

## ボタン意匠（面の系統に合わせる）

用途・設置面で意匠を統一する。混在させない。

- **トップバーのトグル** `.theme-btn`: `--card` 背景・`--line` 枠・角丸。**固定高さ 28px＋`inline-flex` 中央寄せ**
  （絵文字の有無で高さがブレないように）。
- **CRT ペイン内ツールバー**（プリンターペイン等の暗色面）: `StatusBar` の `.fk` に合わせる
  = `--crt` 背景・`--crt-line` 枠・`--muted` 文字・hover で `--t-green`。
- **テキストリンク** `.link`: 枠/背景なし・`--accent` 色。

## トグルボタンの安定化（レイアウトシフト防止）

> **鉄則: トグルボタンは ON/OFF（状態切替）でボタンの幅も高さも変わらないこと。**
> 自分が動くだけでなく、**隣接するボタンの位置がずれる**のが実害。新しいトグルを足すときは必ず満たす。

- **幅**: 切替でラベル幅が変わる部分（`ON`/`OFF`、`カナ`/`英`、`{ }`/`␣`、`☀ ライト`/`🖥 システム` 等）は、
  **固定幅の `inline-block` span で幅を確保**して、ボタン幅を一定に保つ。幅は**長い方の状態に合わせる**。
  ```html
  <!-- 良い例: 変化する部分だけを固定幅 span で包む -->
  自動出力: <span class="onoff">{{ enabled ? "ON" : "OFF" }}</span>
  <!-- .onoff { display: inline-block; width: 2.2em; text-align: left; } -->
  ```
  ラベル全体が入れ替わる場合（`☀ ライト` ⇄ `🖥 システム`）は**ラベル全体を固定幅 span で包む**。
- **高さ**: 絵文字の有無で行高が変わるため、`height` を固定し `inline-flex` + `align-items:center` で中央寄せする
  （トップバーは 28px）。`line-height: 1` を併用する。
- 複数トグルは**1 グループ（`.toggles`）にまとめ、`margin-left:auto` はグループに 1 つだけ**付ける。
  個々のボタンに `margin-left:auto` を付けると flex で均等分散して**バラつく**（アンチパターン）。
- アイコングリフは**同サイズの対**を使う（例 `«`/`»`、`◧`/`◨`）。`◧`/`▤` のように別ブロックの
  異サイズ文字を対にしない（開/閉でサイズが変わる）。

## 情報ポップオーバー

- 構造: **バックドロップ**（`position: fixed; inset: 0;` 透明）＋**本体**（`position: absolute; top: 100%;`。
  アンカーとなる親に `position: relative`）。共通実装は `InfoPopover.vue`（`rows` を渡す）。
- **閉じ方**: バックドロップ（外側）クリック＋トリガ再クリック。本体は `@click.stop` / `@mousedown.stop` で
  伝播を止める。
- **行のラベル/値**: ラベル列は全角ラベルが折り返さない幅＋`white-space: nowrap`。長い値（FQDN 等）は
  `word-break` 許可、ジョブ番号のような一体データは `nowrap`（`SessionInfo.vue` 参照）。

## セッション種別の表記・チップ

- 種別ラベルは **「5250端末」（表示セッション）/「プリンター」** を使う。**「表示」「エミュレーター」は使わない**
  （アプリ全体がエミュレーターのため紛らわしい。「5250端末」がプリンターと対になり明確）。
- チップ（`.kind`）配色で種別を一目化: **5250端末＝青（`--t-blue`）/ プリンター＝緑（`--accent`）/ サーバー設定＝破線**。

## リスト / カード表示

- 表示モードは**専用の修飾クラス**（`view-card` / `view-list`）で分岐する。
  **`.list.list` のような同一クラス重複セレクタは使わない**——CSS では「クラスを 1 つ持つ要素」と同義になり、
  意図せず両モードに当たる（実際にカード表示が一覧レイアウトで崩れた原因）。
- 一覧モードは 1 行の高さを抑える（アクションアイコンは横並び＝`flex-direction: row`、`flex: none`）。

## ローディング表示

- 接続待ち等の待機は**全面オーバーレイ＋スピナー**を出す（`.spinner` + `@keyframes spin`）。
  `@media (prefers-reduced-motion: reduce)` でアニメーションを緩める。`role="status"` を付ける。

## アクティブ状態に応じた表示切り替え

- ヘッダー等の**機能ボタンは、アクティブ（フォーカス中）ペインの内容に連動**させる。ペイン分割があるため、
  `workspaceStore.focusedGroup().activeTab` のセッション種別で判定する。
  - 例: 5250 専用トグル（SO/SI・カナ・リンク・キー）は**表示セッションがアクティブなときだけ**出す。
    接続画面・`admin:*` タブ・プリンター・空ペインでは隠す。テーマ切替は常時表示。

## ペインの最大化

- **分割しているときだけ**タブ帯の右端に最大化ボタンを出す（`PaneTabs` の `.maximize`）。
  単一ペインは既に全面なので、押しても何も変わらないボタンは置かない。最大化中は同じ位置が「元に戻す」になる。
- 最大化は `workspaceStore.maximizedGroupId` の**表示上の切り替えだけ**で、分割ツリー（`root`）は書き換えない。
  比率も配置もそのまま残るので、元に戻すのは ID を消すだけで済む。描画は `displayRoot()` が担う。
- **最大化中はさらに分割できない**（入れ子になり、戻したときの形が予測できなくなる）。端ドロップは
  `zoneFrom` が無効化し、`split()` は合流（`moveTab`）へフォールバックする。**タブ移動だけ許可**する。
- グループが消える／分割が解けたら `syncMaximized()` が最大化を自動解除する。

## 一覧表の列見出し

- 表を持つペイン（一覧・管理・SQL）は**ペイン自体をスクロールさせない**。ペイン根を `flex-direction: column` にし、
  スクロールは内側の 1 枚（`.scroll` / `.section` / `.rows-scroll`）に閉じ込める。
  こうすると絞り込みの帯や見出しが流れず、`thead th { position: sticky; top: 0 }` が**ペインの上端**に効く。
- **スクロールの枠は「中身を出す箱」に置く。** 実行計画は図と詳細を**別々に**縦スクロールさせる
  （`PlanViewer` の `.pv-main` / `.pv-side`）。外側（`SqlPane` の `.plan-view` /
  `PlanListPane` の `.pl-viewer`）は `overflow: hidden` にする——外でもスクロールさせると
  縦棒が 3 本並び、どれを動かせばよいか分からなくなる（利用者の指摘）。
  枠には**親から高さを貰い切らせる**（`height: 100%` ＋ `min-height: 0`）。中身なりの高さだと
  横スクロールバーが画面の途中に浮き、その下が死んだ余白になる。
- sticky な `th` には**背景色（`--card`）が必須**——行に背景が無いので、無いと本文が透けて重なる。
- `border-collapse: collapse` では sticky にした `th` の罫線が一緒にスクロールして消える。
  罫線は `border-bottom` ではなく `box-shadow: inset 0 -1px 0 var(--line)` で描く。

## SQL 欄のキー操作

- **入力欄は `textarea` のまま**。CodeMirror / Monaco は入れない（バンドル規律）。
  行単位の文字列操作は純関数に切る（`sqlEdit.ts`）ので、選択範囲の維持まで含めてテストできる。
- Ctrl+Enter＝実行 / **Ctrl+/＝コメントの切り替え** / **Tab・Shift+Tab＝字下げ**。
  コメントの判断は**行ごと**（コメントの行は外し、素の行は付ける）。「1 行でも素のものが
  あれば全部付ける」（エディタ一般）だと `-- A` が `-- -- A` になって二重に積み上がる。
  付ける位置は**これから付ける行の中で一番浅い字下げ**に揃える（行ごとに付けると段差が記号でばらける）。
- ⚠ **Tab を奪うとキーボードだけで欄から出られなくなる。** `Esc` の直後の Tab は素通しして
  逃げ道を残す。この操作はヒント行に必ず書く。
- **`.` で候補を出す。** 表名・別名なら**列**（`QSYS2.SYSCOLUMNS`）、ライブラリー名なら
  **表**（`QSYS2.SYSTABLES`）。候補は入力欄に重ねた箱で、**フォーカスは渡さない**——
  渡すと日本語入力の変換が確定してしまう。↑↓ で選び、Enter / Tab で確定、Esc で閉じる。
  ⚠ **`FROM ライブラリー.` は書く位置で先に判別する**（`isTablePosition`）。
  `tableRefsOf` から見ると `FROM TESTLIB` は「表 1 つ」に見えるので、
  素直に解くと「`TESTLIB` という表の列」を引きに行って空振りする。
- 候補が引けない・表が解けないときは**黙って閉じる**。補完のためにエラーを出して書く手を止めない。

## SQL フッターの接続表示

- SQL ペインのフッターには、**いま繋がっているホスト側のジョブ**（`job=…`）と接続先（`host:port`）を出す。
  5250 の OIA と同じで「どこに繋がっているか」は常に見えるところに置く（従来は実行ログを開かないと分からなかった）。
- 実行ログの `connect` 行は**張り直したときだけ**出すが、フッターは**使い回し（`reused`）でも更新する**——
  ログは「いつ張り直したか」、フッターは「いまどれか」を答えるものなので、条件が違う。

## 信頼設定の UI ゲート

- サーバー上の**パス書き込み・コマンド実行・秘密**につながる設定（PDF 出力先 `autoPdfDir`・自動印刷
  `autoPrint`・パスワード等）は、**認証オフ（ローカル単一利用）または admin のときだけ** UI に露出・編集させる。
  サーバー側でも同じゲート（`canEditProfiles`）で受理し、一般ユーザー・未認証からは受理も露出もしない（信頼境界）。

## デザインスキン（`data-skin`）

- **端末（5250）＋ Web アプリ風スキン**を `documentElement` の `data-skin` で切り替える
  （`composables/useSkin.ts`・選択 UI は `DesignMenu.vue`）。DOM・グリッド配置は一切変えず、
  `styles.css` の `:root[data-skin="..."]` が**クロームと端末のトークンを両方**差し替える。
- スキンを足すときは**クロームと端末の明暗を揃える**こと。OIA / F キーは
  背景＝端末（`--crt` / `--crt-bezel`）・文字＝クローム（`--muted`）の混在で、揃えないと読めなくなる。

## 画面表示設定（⚙ 画面）とトークン上書き

- 表示設定（SO/SI・半角カナ・リンク化・コントロール表現・配色・画面の質感・フォント）は
  `stores/viewSettings.ts` の**単一の設定**として保持し、変更は即 localStorage へ保存して全画面に効く。
  **項目定義（表示順・選択肢）は `VIEW_ITEMS` に集約**し、⚙ 画面メニューとキー設定が同じ定義を参照する。
- **見た目の切り替えは `.pane` への属性／カスタムプロパティ上書きで行う**（`EmulatorPane.vue`）。
  カスタムプロパティは scope をまたいで DOM を継承するので、子の `ScreenGrid`（別 scope）の
  セル色・グロー・反転（`--cell`）まで一括で追従する。ルールを複製しないこと。
  - 配色 `data-color-mode="semantic"`: 5250 の 7 色を役割ベースへ再マップ（`--t-*` を再定義）。
    **赤＝エラー・黄＝注意・青＝情報は意味を残して据え置く**。
  - 質感 `data-surface`: `flat` はグロー無し＋やわらかい影のカード、`crt` は
    `--t-glow` と `.grid-span` の `text-shadow` でフォスファのにじみを出す。
  - コントロール表現 `data-controls`: `plain` / `underline` / `filled` / `rich`。
    **色替えは `box-shadow` と限定的な背景のみ**（桁とホスト色を崩さない）。保護欄には出さない。
    定義は `.grid-input` と同じ scope（`ScreenGrid.vue`）に置き、base の `:focus` に確実に勝たせる。

## 等幅フォント（`--mono` と `--screen-mono` の使い分け）

- **`--screen-mono`（画面グリッド・帳票）の既定スタックは和欧 1:2 の一体フォントだけ**を並べる。
  桁位置は `ch` 単位で DBCS を 2ch と仮定するため、**欧文専用フォントを混ぜると比が崩れて桁がずれる**。
- **フォントの選択肢は「標準（自動）」＋インストール済みフォント＋名前の直接入力**
  （`composables/screenFonts.ts`）。**「推奨」の固定一覧は廃止した。**
  一覧に無いフォントを選べない・導入判定に外れると選べない、が実際の使用で問題になったため。
  - 設定値は**ファミリー名そのもの**。既定スタックの前に足すだけなので、当たらなければ
    既定へ落ちる＝1:2 のフォールバックは常に残る。
  - 一覧は Local Font Access（Chromium 系）で列挙し、ファミリー単位に畳む。**非対応・権限拒否では
    一覧を出さず、名前の直接入力へ倒す**（列挙できないことを理由に指定を諦めさせない）。
  - 桁揃え（半角どうし同幅・全角が 2 倍）は `measureFontFit` で実測し、**揃うもの／ずれるものを
    グループで分ける**。ずれるものも選べる（利用者の判断）が、選ぶと注意書きを出す。
  - 旧「推奨」一覧の id（`hackgen` 等）は `LEGACY_FONTS` に残す。**過去の保存値を解決するためだけ**で、
    選択肢としては出さない。選択中なら「指定中」にラベルで出す（id を生で見せない）。
  - **ファミリー名はインライン style（`--screen-mono`）へ流し込むので `sanitizeFamily` を必ず通す。**
    設定値は localStorage 由来＝書き換えられうるため、引用符・`;`・`()` を落とさないと
    別プロパティを注入できてしまう。
- **`--mono`（クローム: OIA・F キー・タブ・表）は桁揃えの制約が無い**ので、モダンな等幅を先頭に置いてよい
  （現在は自ホストの IBM Plex Mono。日本語は字ごとに後続の CJK 等幅へフォールバック）。

## 画面テキストの「操作できるもの」化（リンク・機能キー凡例）

- 画面テキストの一部を装飾・操作可能にするときは、**同一の `.grid-span` 内でインラインに分割**し、
  差し込む要素に `padding` / `margin` / `border` を持たせない（`font` は継ぐ）。
  これで**桁が動かない**。`linkify`（URL）と機能キー凡例のボタン（`.fkey-btn`）が同じ流儀。
  色は指定せず**ホストが送った色を継ぐ**（属性色を奪わない）。
- **位置は必ず「桁」で数える。文字列インデックスで数えてはいけない。**
  DBCS があると両者はずれる（実測: 同じ行で `F12` が文字列 37・桁 43）。
  `cells`（1 セル = 1 桁、DBCS は lead + tail の 2 セル）を基準に、
  「表示文字列」と「文字列 index → 桁」の対応を同時に作る（`composables/fkeyLegend.ts`）。
- **検出対象はフィールド外の定数（`kind:"text"` セグメント）に限る**。`rows()` がフィールドを
  `input` セグメントへ分けるので、入力値を誤って操作要素にしない。
- **窓（ヘルプ等）が出ているときは窓の内側だけ**を対象にする。窓の外＝下の画面のテキストは
  ラベルが切れていたり（`F13= この画`）、押すと前面の窓の文脈で解釈されて表示と食い違う
  （`F3= 終了` が実際には「ヘルプ終了」）。窓の矩形は `gui.windows` があればそれを使い、
  **無ければ罫線文字から検出する**——通常のヘルプ窓は `gui.windows` に出ない（文字で描かれる）。
- 画面内に差し込むボタンは `tabindex="-1"`（Tab はフィールド間移動に使う）、
  `mousedown` を `preventDefault`（フォーカス＝カーソル位置を奪わない）。

## ウィンドウの装飾（重ねるだけ）

- ウィンドウ（ヘルプ窓・アプリの WINDOW DSPF）の見せ方は **`.pane[data-window]`** で出し分け、
  **重ねる要素だけ**で表現する（文字・桁・ホスト色には触れない）。
- 矩形は `composables/fkeyLegend.ts` の `detectWindowRect()` を**再利用**する。
  拡張5250 の窓（`gui.windows`）と文字で描かれた窓（罫線検出）の両方を 1 つの関数が返すので、
  装飾側は窓の種類を意識しない。
- 重ねる要素には必ず **`pointer-events: none`** を付ける。付けないと窓の中の入力・クリック・
  矩形選択を奪う。重なり順は**文字より上・カーソル/矩形選択より下**（選択を隠さない）。
- 背景を暗くする（スモーク）ときは、全面を覆って窓を切り抜くのではなく、
  **窓の上・下・左・右の 4 枚**で覆う。窓の中を一切覆わないので読みやすさが落ちない。

## ウォーターマーク（画面に重ねる透かし）

- ウィンドウ装飾と**同じ「重ねるだけ」の流儀**（`WatermarkOverlay.vue`）。文字・桁・ホスト色に触れない。
  `pointer-events: none` に加えて **`user-select: none` が要る**——透かしは画面領域の中に置く DOM 文字なので、
  付けないと**画面のコピーに透かしの語が混ざる**。重なり順は文字より上・矩形選択(3)/カーソル(4) より下。
- **敷き詰めは「対角線を一辺とする正方形」を回して作る**。どの角度でも元の矩形を覆えるので、
  角度ごとの場合分けが要らない。実測するのは 1 単位（文字＋区切り）の幅だけで、行数・繰り返し数は
  そこから割り出す（レイアウトの無い環境では 1 単位に畳んで壊れないようにする）。
- 色を指定しなければ**端末の前景色（`--t-white`）に追従**させる。テーマ・スキンを切り替えても浮かない。
  指定を受け付けるときは **`#rrggbb` に限る**——値は CSS の色としてそのまま使われるため、
  自由文字列を通すと style へ別の宣言を混ぜられる（検証はサーバーのスキーマ側で行う）。
- 設定の置き場は**セッション設定**（`ConfigCard` の編集フォーム）。表示だけの設定なので接続時に
  持ち回らず、`EmulatorPane` がセッション設定を直に引く＝**保存した瞬間に開いている画面へ反映**される。
  信頼設定ではないので、`.trusted`（アクセントの縦帯＝サーバー側に効く設定の合図）の意匠は使わない。

## 「押せるもの」の意匠（ボタン意匠）

- 入力欄の見せ方（**コントロール表現**）と、押せるものの見せ方（**ボタン意匠**）は**別の軸**にする。
  ボタン意匠は `.pane[data-buttons]` で、**機能キー凡例のボタンと拡張5250 の選択肢の両方**に効かせる
  （利用者から見た「押せるもの」の見た目を 1 つに統一する）。
- `none` は凡例をボタン化しないが、**拡張5250 の選択肢は現状の意匠で描き続ける**
  （ホストが宣言した操作部品なので、見えなくすると機能が損なわれる）。
- どの意匠でも `selected` / `unavailable` の区別を残す。色替えは `box-shadow` と限定的な背景のみ。

## ヘッダーのポップオーバー

- ヘッダーのメニューは**同時に 1 つだけ**開く。開いているメニュー id を `composables/headerMenu.ts` で
  共有し、別を開くと前が閉じる。各ボタンは `@click.stop` するため、**相手の外側クリック検出には頼れない**。

## キー割り当て

- キーバインドは AID キーのほか `view:<項目>` で**表示設定の順送り**を割り当てられる
  （`stores/keybindings.ts`・`composables/useKeymap.ts`）。`view:*` はホストへ送らずローカル処理のみ。
- 切り替わったら **OIA の操作員メッセージ**（`notice`）で「項目: 新しい値」を通知する。
  ホスト由来の `systemMessage` とは別枠で、次のキー操作で消える。

## アクセシビリティ / 動作

- キーボード focus の可視化、`prefers-reduced-motion` の尊重、`role` / `aria-*`（`role="status"`・
  `aria-pressed`・`aria-label` 等）を適切に付ける。
