# 5250 データストリームの未実装コマンド

`wtd-applier.ts` の `default` 節は**未知のコマンドでレコードの残りごと捨てる**。
パラメータ長が分からない以上それは妥当だが、**捨てた後ろに READ があると入力待ちに入り、
利用者には「待機中・ホストから応答がない」としか見えない**。

この形で 3 回踏んでいる:

- `SAVE SCREEN`（0x02）に応答せず、SEU の F1 ヘルプが 30 秒返らなかった
- `WRITE ERROR CODE TO WINDOW`（0x22）未処理で、同じレコードの READ ごと捨てた
- **`SAVE PARTIAL SCREEN`（0x03）未処理で QSH が固まった**（2026-07-30・
  `20260730-qsh-save-partial-screen`。実測は `scripts/diag-qsh.mjs`）

## 未実測（実装は入っているが実機で確かめていない）

- [ ] **RESTORE PARTIAL SCREEN（0x13）**
  - `0x03` で預けた保管物をホストが返してくる側。局所の退避スタックから復元する実装を入れた
  - **QSH の経路では 1 度も届かなかった**ので、実機での動作は未確認
  - 確かめるなら「0x03 を送ってくる画面で、戻る操作をしたときに 0x13 が来るか」を追う
- [ ] **ROLL（0x23）**
  - `方向＋行数(1) 上端(1) 下端(1)`（上位ビットで方向・下位 5 ビットで行数）で実装した。
    形式は SC30-3533 / tn5250 の定義に従う
  - **QSH は行送りに使わず、`CLEAR UNIT` ＋ `WTD` で画面を描き直していた**（research F4）
  - どの画面が実際に ROLL を送ってくるのかが分かっていない。
    （5250 の Roll Up/Down キー＝当方の PageUp/PageDown はホストへ AID を送る側で、これとは別）
- [ ] **SAVE PARTIAL SCREEN のパラメータ 5 バイトの意味**
  - 実機はすべて `00` だった。範囲（上端・左端・深さ・幅）と見られるが**未解明**
  - 現状は**解釈せず写して返す**（ホストにとって不透明な保管物なので実害は無い）

## 未実装（届いたら捨てる）

- [ ] `READ IMMEDIATE`（0x72）/ `READ IMMEDIATE ALT`（0x83）
- [ ] `READ SCREEN TO PRINT` 系（0x66 / 0x68 / 0x6A / 0x6C）
- [ ] `SAVE / RESTORE SCREEN` の**部分指定**以外の変種

いずれも**実機で届いたのを見てから**実装する（形式を推測で書かない）。
