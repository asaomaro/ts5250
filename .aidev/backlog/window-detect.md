# ウィンドウ判定（罫線推測をやめて受信データで決める）

ウィンドウ装飾（`windowFrame` / `windowBackdrop`）を出す範囲を、**画面に描かれた罫線から
推測**している。この推測に誤検出があるという報告を受け、2026-07-28 に現状を実測した。
**判定材料そのものを変えないと直らない**と分かったので、調査結果と方針をここへ積む。

## 現状の仕組み

`packages/web-ui/src/composables/fkeyLegend.ts:205` の `detectWindowRect` が 2 段構え。

1. `snap.gui.windows` があればそれを使う（`CREATE_WINDOW(51)` 構造化フィールド由来＝**ホストの宣言**）
2. 無ければ**罫線から推測**する。同ファイルの `detectReverseFrame`（反転で描く ATNPGM の窓）も併用

呼び出し側は `packages/web-ui/src/components/ScreenGrid.vue` の `decoWindow`。
ホストが枠を送っている場合は推測を止める作りになっており、**そこは正しい**。

問題は 2 の側で、コメントにあるとおり**通常のヘルプ窓は `gui.windows` に出ない**
（文字で描かれる）ため、**実際はこの推測経路がほとんどを占める**。

推測の条件が緩い（`fkeyLegend.ts:35-47`）:

- `BORDER_H`（`. - ─ ━ ═ _ ＿`）が **8 桁以上連続**する行が 2 本、80% 以上重なる
- 間の行の**左右どちらか**に `BORDER_V`（`: ： | ｜ │ ┃ ║`）が**半数以上**ある

「どちらか」「半数以上」なので、罫線で囲っていない画面でも成立してしまう。

## 実測（2026-07-28）: 誤検出を再現した

| 画面 | 判定 | 枠の外側の非空白セル数 |
|---|---|---|
| ① 本物の窓（F1 ヘルプ相当。上下 `.`・左右 `:`） | 検出（正） | **130** |
| ② 一覧画面（PDM 風。`---` 区切り 2 本） | null（正） | — |
| ③ 表（左右に `:` が並ぶ帳票） | **誤検出** | 176 |
| ④ 反転バナー（見出し行＋末尾行が反転） | **誤検出** | **0** |

③ は罫線経路、④ は反転経路で誤る。**両方の経路に誤検出がある**。

## 却下: 「枠の外に何も無ければ窓」は逆効果（再検討しないこと）

「背景なしの全画面ウィンドウなら枠の外に何も無いはず」という条件を検討したが、
**上の実測で否定された**。

- **本物の窓ほど外側に内容がある**（① は 130 セル）。窓は背景の上に開くので当然で、
  背景が残るのが窓の一般形
- 誤検出の ④ はむしろ外側が **0**

つまりこの条件で絞ると**本物を弾いて誤検出を通す**。「背景なしの全画面ウィンドウに限る」と
限定しても、④ のような偽物が同じ条件を満たすため判別材料にならない。

## 本命: 受信データの書き込み範囲で決める

**窓かどうかは描画結果ではなく受信データに出ている。**

- 本物の窓: 背景を消さずに**窓の領域だけ**書く → 書き込み範囲＝窓
- ③④ のような通常画面: 画面全体を書く → 書き込み範囲＝全画面 → 窓ではないと判定できる

**この情報は現在捨てられている。** `packages/core/src/protocol/wtd-applier.ts:10-33` の
`ApplyResult` には書き込み範囲も「CLEAR したか」も無く、`ScreenBuffer` も dirty 領域を持たない。
判定が見た目しか見られないのは、そもそも材料が渡っていないからで、
**推測条件をいくら調整しても限界がある**。

- [ ] **core: レコード適用ごとの書き込み範囲を記録して snapshot に載せる**
  - セルへの書き込みは `packages/core/src/screen/buffer.ts:407-443` の
    `setChar` / `setDbcs` / `setAttr` / 範囲クリア の **4〜5 箇所に集約されている**ので、
    そこで外接矩形を更新すれば済む。レコードの頭でリセットする
  - `CLEAR_UNIT` / `CLEAR_UNIT_ALTERNATE` を通ったかも併せて持つ
- [ ] **web-ui: 判定の第一級条件を「直近の書き込みが画面の一部に閉じた矩形か」にする**
  - 罫線検出・反転検出は**「窓かどうか」から「枠がどこか」を詰める補助**へ降格する
  - 通常画面は 1 行目や F キー凡例まで書くので外接矩形が全画面になり、自然に外れる
  - 注意: 「メッセージ行だけ書き換えた」ような小さな更新も矩形が小さくなる。
    高さ・幅の下限を置くか、前回画面との差分を見るかは実装時に決める
- [ ] **補助条件（core 改修を待たずに足せる）**
  - **入力欄が全て矩形内に収まっているか**（`snap.fields`）。③ のような表は枠外にも
    入力欄があるので弾ける。安価なわりに効く

## 着手の順番

core 改修が入るので、いきなり判定を切り替えない。

1. 書き込み範囲を snapshot に載せるところまでやり、**既存テストが通ることだけ**確かめる
   （`window-view` / `stacked-window` / `reverse-frame-window` / `pane-cursor-window`）
2. 上の実測 4 画面を回帰テストに起こす（③④ が窓と判定されないことを固定）
3. そのうえで判定を切り替える
