# 画面の欄の指し方（id と検索）

**→ 2026-08-04、`20260804-field-addressing` で着地。**

**スクリプト・MCP・HLLAPI・Playwright が同じ語彙で入力欄を指せるようにする。**

いまは指す手段が経路ごとにばらばらで、しかもどれも脆い:

| 経路 | 指し方 | 弱さ |
|---|---|---|
| スクリプト / MCP | `{index}` か `{row,col}` | `index` は**手前の欄が増減すると全部ずれる** |
| web-ui の DOM | `data-field-index` | 同上（連番） |
| Playwright | **指す手段が無い** | 座標で当てるしかない（E2E を書いて実際に困った） |

## 前提: 5250 には安定した識別子が無い（調査済み・2026-08-04）

**電文が欄の名前を運ばない。** DDS の項目名は端末に届かない。
GUI 構造体の `id` すら電文由来ではなく、ts5250 が `++this.guiIdSeq` で振っているだけ
（`packages/tn5250/src/screen/buffer.ts:265`）。

**つまり導出した id はどれもレイアウト変更に耐えない。** 設計の巧拙ではなくプロトコルの性質。
ここを認めたうえで、**壊れ方を選ぶ**のがこの作業の本質。

| 規則 | 壊れる条件 |
|---|---|
| `(row, col)` 由来 | **その欄が動いたとき**（局所的） |
| 画面項目順の連番 | **手前の欄が 1 つ増減しただけで全部ずれる**（広範） |

**連番にしない。** 既存の `Field.index` が連番で、その脆さがこの作業の動機。

## やること

- [x] ~~`Field` に~~ **共有関数 `fieldId(field)`** を置く（`@ts5250/tn5250`。
      **型に必須で足す案は取り下げた**——テストの器が 123 箇所壊れ churn に見合わない。
      規則を 1 か所に置く目的は共有関数が唯一の実装であることで達せられ、
      外へ出す口（DOM 属性・MCP の structuredContent）で derive する。
      **ブラウザ連携より手前**に置くこと——スクリプトと MCP も同じ id を使うため）。
      **意味的な安定は主張しない名前にする**（位置由来だと読んで分かる形）。
      `Field` は WsScreen で web-ui まで流れているので、追加の配線は要らない。
      MCP の出力スキーマは `.passthrough()` 済みなので壊れない（`20260803-hllapi-bridge`）
- [x] **一意性を検査で担保する。** 「構造上ぶつからないはず」で済ませない。
      実測は欄のある画面 4 枚・6 欄しか通せておらず、根拠として弱い
- [x] web-ui の `<input>` に id を出す（`data-field-index` の隣。
      **1 つの欄が複数の input になる**ことに注意——行をまたぐ欄は `data-slice` で分割される）
- [x] **ラベル錨の検索を共有層へ**。`packages/server/src/hllapi-ps.ts` の
      `psSearch` / `fieldAt` / `nextInputField` が既にこの作法を実装しているが、
      HLLAPI 層に閉じていてスクリプトからも MCP からも使えない
- [x] 検索は**厳格モード**。複数当たったら**黙って先頭を取らず、例外＋候補一覧**

## 検索が厳格でなければならない理由（実機で確認・2026-08-04）

実機の `WRKSPLF`:

```
10|                     OPT   出力        状況          ← 見出しは 1 つ
11|                          PRT01                     ← 装置名（入力なし）
12| [入力 col=2 len=2]        QPDZDTALOG  印刷装置が停止した
13| [入力 col=2 len=2]        QPDZDTALOG  ← 同じ名前
14| [入力 col=2 len=2]        EMPSFR
15| [入力 col=2 len=2]        EMPDSPF
16| [入力 col=2 len=2]        EMPDSPF     ← これも
```

- **1 つの見出しが 9 個の欄を支配する**（1 対 N）。「ラベルの直後の欄」では決まらない
- **行の内容も重複する。** スプール名は正当に重複する（ジョブや番号が違うだけ）ので、
  「その行を含む行の欄」でも決まらない

**導出できる一意な鍵は存在しない。** よって曖昧さは**利用者に返す**しかない。
Playwright の strict mode と同じ判断で、このリポジトリでも HLLAPI の `Connect` が
同名セッション 2 つに対して `rc=11` で断っている（同じ原則）。

### 絞り込みの手段（重ねられる形にする）

- 行の内容（**複数列を併せて**）
- 列で絞る
- 領域（行範囲・窓の中）で絞る

**`nth`（一覧の N 番目）は作らない。** 順序依存で事故の元
（2026-08-04 に方針決定）。絞り込めない画面が出たら、そのとき改めて考える。

## 触ってはいけないもの

`fieldSignon` は「最初の非 hidden 欄をユーザー、最初の hidden 欄をパスワード」と
**黙って先頭を取る**。サインオン画面という既知の形に特化した便宜なので**据え置く**。
**汎用検索の手本にしない**——これを一般化すると、上の一覧画面で静かに間違った欄へ書く。

## 見返り

- **Playwright から欄を直接指せる**（`[data-field="…"]`）。
  E2E を書いたとき座標でしか当てられず、実際に困った
- スクリプト・MCP・HLLAPI・ブラウザが**同じ言葉で欄を指す**
