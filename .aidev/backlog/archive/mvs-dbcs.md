## 背景

3270 の DBCS は、**手元に実ホストが無い**まま来ている。
ローカルに立てられる唯一の 3270 ホストは **TK4-（MVS 3.8j, 1981 年）**で、
**英語 SBCS 専用**——日本語が入るのは z/OS の Japanese feature（ライセンス製品）から。

そのため `packages/tn3270` の DBCS は、**自前コーデックで符号化した合成データを
`mini3270` から流し、`s3270 -codepage cp930/cp939` と突き合わせる**方法だけで裏付けている
（`20260815-tn3270e-basic/review.md` の 5〜7 回目）。

## 分かっていること

- **OS の改修は「DBCS を表示させる」ためには不要**。DBCS は 3270 データストリーム上の
  取り決めで、`TPUT FULLSCR` / `NOEDIT` は生のバイトを素通しする。
  **バイトを吐くプログラム 1 本**あれば画面には出る
- TK4- は **VTAM と TCAM の 2 経路**を持つ（**VTAM は TK4- にも載っている**。
  telnet 側を担うのは Hercules 内蔵の 3270 サーバーで、こちらは TN3270E を提示しない）。
  ~~VTAM＝ポート 3270 / TCAM＝ポート 83xx~~ ← **実測で誤りと判明**。
  3270 のポートは `CNSLPORT` の **1 本だけ**で、経路の切り替えは**装置番号**で行う:
  VTAM=00C0-00C6 / TCAM=03C0-03C7（`GROUP=TCAM`）。8038 は HTTP コンソール。
  マニュアルは「TCAM では `TPUT NOEDIT` が `FULLSCR` として処理され、
  **3270 データストリームが歪むことがある**」と明記——**検証には VTAM 経路を使う**
  （実測では TCAM でも歪みは WCC 1 バイトに留まった。下の「## 結果」）
- 導入プログラムの一覧は `SYS2.HELP(UTILS)`、変更は `SYS2.ASM` に置く作法

## 「本当に OS を DBCS 対応にする」なら要るもの

- TSO の行編集が `0x0E`/`0x0F` を制御文字として壊さないようにする
- 装置定義（TCAM/VTAM）に DBCS の文字集合を足す
- コードページ変換、パネル処理、入力側の桁勘定

MVS 3.8j はソースが手に入るので**理論上は可能**だが、IBM が製品リリース 1 本かけた範囲。

## 段取りの案

1. **まず `TPUT FULLSCR` で `SO`/`SI` ＋ DBCS バイトを吐くアセンブラを 1 本**——
   経路がバイトを素通しするかだけを確かめる（ここまでは OS 改修不要）
2. 素通ししないなら、どこで壊れるかを突き止める（TSO / TCAM / VTAM のどれか）
3. その先で初めて OS 側に手を入れる話になる

## 注意

**この作業で `packages/tn3270` の検証が良くなるわけではない**。
正しさの判定役は s3270 のままで、バイトの出どころが変わるだけ。
**面白さと、実ホスト経路の素通し確認**が目的。

## 結果（2026-08-16 / `mvs-dbcs` プロジェクト `20260816-165748`）

**素通しする。** `TPUT FULLSCR` に渡した `SO`(0x0E) / `SI`(0x0F) と DBCS 2 バイトは、
**VTAM 経路でも TCAM 経路でも 1 バイトも変わらずに**クライアントへ届いた。
段取り1 の問い「経路がバイトを素通しするか」は **YES** で確定。

| 経路 | 送出（バッファ） | 線上に出たレコード |
|---|---|---|
| VTAM | `C2 1140401D60 6E6E6E 0E4562456648E70F 4C4C4C` | `F1` ＋ 同じ ＋ `13` |
| TCAM | 同上 | `F1` ＋ **WCC だけ `C2`→`C0`** ＋ 同じ |

分かった副産物:

- **`TPUT FULLSCR` はコマンドコード（`F1`＝WRITE）を自分で前置する**。
  バッファの先頭は**コマンドではなく WCC**。VTAM は末尾に `13`（IC）も足す
- **TCAM は WCC を書き換える**（`C2`→`C0`、キーボード復帰ビット）。**データ部には及ばない**。
  マニュアルの言う「TCAM で 3270 データストリームが歪む」の実体は、少なくとも
  `FULLSCR` 明示の今回については WCC 1 バイトに留まった
- TK4- のカードリーダーは**ソケット（:3505）**なので、アセンブル・リンクは画面操作ゼロで回せる
