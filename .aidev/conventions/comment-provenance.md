## 規約

**コメントに書く出所は、後から検証できる形で書く。**
AGENTS.md「コメントの残し方（意図中心）」は「判断の出所を明記する」と定めているが、
**明記されていても間違っている**ことが繰り返し起きた。足すのは「明記せよ」ではなく「検証できる形にせよ」。

1. **引いた出所は、書く前に現物で確かめる。** D 番号・節名・`file:line`・数値は grep して実在と内容を見る。
   ——「存在しない D 番号」「別 work の D 番号」「出所と食い違う数」がこの work で 10 件出た。
2. **同じ変更で動く行を、恒久コメントから行番号で指さない。** 消える／動く行を指すなら、
   **コミット ID を添える**（`HEAD 90f5636f の :482-483`）か、名前で指す（「畳み込み前の `retryReconnect`」）。
3. **work をまたぐ参照は work を明示する。** `前 work の D10` / `20260908-... の review ラウンド3` のように。
   素の `D10` / `review ラウンド2` は、同じファイルに 2 つの work の参照が並んだ瞬間に読めなくなる。
4. **「読むのは X だけ」と書くなら、読み手を数え切ってから書く。** 網羅の主張は grep で裏を取る。
   数え漏らした主張は、次の人が「じゃあ消してよい」と判断する根拠になる。
5. **数を書いたら、その数の出所も書く。** 「12 箇所」「5 系統」は、どこを数えたのかが無いと突き合わせられない。

**なぜ条項にするか**: この観点は**型検査でも lint でも変異注入でも検出できない**。
この work では独立点検だけが見つけており、しかも 32 件出た。機械で下げられる層が無いので規約に置く。
