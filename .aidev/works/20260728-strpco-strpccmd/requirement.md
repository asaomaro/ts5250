# 要件: STRPCO / STRPCCMD（PC Organizer）対応

## 背景 / 課題

IBM i には、5250 セッションを張っている**クライアント側の PC でコマンドを実行させる**仕組みがある。

- `STRPCO`（Start PC Organizer） — PC Organizer を開始／終了する
- `STRPCCMD PCCMD('...') PAUSE(*NO|*YES)` — PC 側でコマンド（アプリ起動等）を実行する

業務 CL の中から「帳票を PDF ビューアで開く」「PC 上のツールを起動する」といった用途で
実際に使われており、ACS / PCOMM / tn5250j などの既存エミュレーターは対応している。
**本エミュレーターは未対応**で、この命令を含む CL を流すとホスト側は PC の応答を待ち続ける
（画面が進まない／`PC Organizer が開始されていません` になる）ため、既存資産がそのまま動かない。

本エミュレーターは ACS の代替を狙っており（AGENTS.md「規格どおりより既存クライアントと同じ挙動」）、
ここが欠けていると移行の障害になる。

## 目的 / ゴール

ホストが送ってくる PC Organizer のデータストリームを検出し、
**指定されたコマンドをエミュレーター稼働ホスト上で実行して、ホストへ応答を返す**。

実行される場所は「5250 セッションを持っているプロセスが動いている機械」＝サーバープロセスのホスト。

- **localhost 運用（自 PC でサーバーを起動 / Electron 版）** → 利用者のローカル PC で実行される
- **サーバーモード運用（別ホストのサーバーへブラウザで接続）** → **サーバー機**で実行される
  （ブラウザが動いている PC では実行されない）

この「どこで実行されるか」を利用者に明示し、誤解のないようにすることまでを含む。

## スコープ

### 対象

- 5250 データストリーム中の **PC Organizer マーカーの検出**（STRPCCMD 開始 / PCO 終了）
- 検出したコマンド文字列と待ち合わせ指定（`PAUSE`）の取り出し
- サーバープロセスでのコマンド実行（同期／非同期）と、ホストへの自動 Enter 応答
- **既定は無効**。信頼設定として明示的に有効化したときだけ実行する（後述）
- 実行の可視化（Web UI での通知・履歴、ログ）
- Electron 版（ローカル PC 実行）での動作
- 実機での E2E 検証（検証用 CL を作成する）

### 対象外

- PC Organizer のその他の機能（共有フォルダー／ファイル転送 `CPYTOPCD`・`CPYFRMPCD`、
  PC5250 のキーボード割当変更など）。既存エミュレーターも STRPCCMD 以外は概ね非対応
- ブラウザが動いている**クライアント PC 側**での実行（ブラウザからローカルコマンドは起動できない）
- MCP ツールとしての公開（必要になったら別途）

## 機能要件

1. WTD データストリーム中の PC Organizer マーカーを検出し、コマンド文字列・待ち合わせ指定を取り出す
2. マーカーを検出したら、ホストが待っている応答（Enter/AID）を返す。
   `PAUSE(*YES)` 相当ならコマンド終了を待ってから、`PAUSE(*NO)` 相当なら待たずに返す
3. コマンドは**エミュレーターサーバーのホスト OS** で実行する（Windows / Linux 双方）
4. 機能の有効・無効を設定で切り替えられる。**既定は無効**
5. 実行したコマンド・実行場所（ローカル PC かサーバーか）・終了コードを利用者が確認できる
6. PCO 終了マーカーを受けたときも、ホストへ応答を返してセッションを進める

## 非機能要件 / 制約

- **これはホスト起点の任意コード実行**である。AGENTS.md「アカウント・権限設計」の
  **信頼境界（trusted config）**に該当する ＝ 受理してよいのは
  **canEditProfiles（認証オフ or admin ＋ ファイル由来のサーバー設定）**のルートだけ。
  一般ユーザーの個人設定（`connections.json`）からは**スキーマごと持たせない**
- 既定 OFF（オプトイン）。有効時もサーバーログに実行内容を残す
- プロトコルの実装は**推測で書かない**。実機の生データストリームを捕捉して確定する
  （AGENTS.md「既存プロトコル実装の移植」／過去の Query Reply・Read Screen の教訓）
- 参照実装（tn5250j / xtn5250）は**事実（バイト配置・定数）としてのみ**参照し、逐語移植しない
- 既存の 5250 画面描画を壊さない（マーカーはノンディスプレイ属性配下にあり、
  画面には出さないのが既存クライアントの挙動）

## 完了条件 (受け入れ基準)

- [ ] 実機で `STRPCO` → `STRPCCMD` を実行する CL を作り、生データストリームを捕捉して
      マーカー形式・コマンド位置・待ち合わせ指定を**実測値として**記録した
- [ ] 検出ロジックのユニットテストがある（実測バイト列を fixture にする）
- [ ] 実機で `STRPCCMD` が実際にサーバー側コマンドを起動し、CL が次の行へ進むことを確認した
      （`PAUSE(*NO)` / `PAUSE(*YES)` 双方）
- [ ] 機能 OFF（既定）のときは実行されず、ホストは固まらない（応答は返す or 従来どおり）
- [ ] 一般ユーザーの設定経路からは有効化できない（403 / スキーマ拒否）
- [ ] Web UI で「何を・どこで実行したか」が分かる
- [ ] README / docs に、実行場所とセキュリティ上の注意を明記した

## 未確定事項 / 確認したいこと

- **`STRPCO` 単体でホストが何を送ってくるか**（開始のハンドシェイクがあるか、
  こちらが何か応答しないと `STRPCCMD` が失敗するか）→ research（実機捕捉）で確定する
- コマンド長の上限（V7R1 まで 123 文字、V7R2 以降 1023 文字という情報がある）→ 実機で確認
- 待ち合わせ指定（`PAUSE`）がデータストリーム上どのバイトに載るか → 実機で確認
- **機能 OFF のときにホストへ何を返すのが安全か**（無反応だとホストが固まる恐れ）→ research / spec
