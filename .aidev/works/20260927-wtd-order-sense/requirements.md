# 要件: WTD の中のオーダーの誤りに ACS と同じ否定応答を返す（読み手の例外でレコードを捨てない）

## 背景 / 課題
`.aidev/backlog/acs-parity.md` の「【まとめ】DS5250 のうち否定応答の残り」。当 PJ は WTD の中の短いオーダー・画面の外の番地・RA/EA の後戻りで例外になり、
`handleRecord` がレコードの結果ごと黙って捨て、応答もしない。ACS はセンスを送り、WTD の中の誤りならレコードの終わり（CC2）も走らせる。
あわせて同じ台帳の「SOH の長さが 0 か 8 以上のとき」（ACS は 0x1005012B、当 PJ は無条件にフォーマットテーブルを消す）。

## 目的 / ゴール
WTD の中のオーダーの誤りで、画面・CC2・否定応答（センス）が ACS と同じになっている状態（実機で確かめてある）。

## ユーザーストーリー
- US1: 5250 端末の利用者として、ホストが誤ったオーダーを送っても、誤りの前までの画面と表示灯が ACS と同じで、ホストに否定応答が返ってほしい。なぜなら応答が無いとホストの次の処理が ACS と変わるから。（受け入れ: AC1, AC2）

## スコープ
### 対象
- SBA・IC・MC・RA・EA・SOH・TD・SF・WEA の長さ不足（0x10050121）、SBA・IC・MC・RA・EA の行・桁が画面の外（0x10050122）、RA・EA の後戻り（0x10050123）、SOH の長さ 0 か 8 以上（0x1005012B）、EA の長さ 2〜5 以外（0x1005012D）
### 対象外
- SBA の行 1・桁 0（ACS は番地 -1 として受ける。当 PJ は受けられないので例外のまま——backlog）
- SF の中身の誤り（FFW・属性・欄の長さ 0 など）・WEA の属性の値・TD の長さが画面を超える・WDSF の中（backlog に残す）

## 機能要件
- 上の誤りで否定応答を立ててこの WTD を打ち切り、レコードの残りは読まない。誤りの前の書き込み・カーソルの確定・CC2 はそのまま。

## 非機能要件 / 制約
- 実機で作った試験プログラムは消す。ワイヤの記録（パスワードを含む）は読み終えたら消す。

## 完了条件 (受け入れ基準)
- [ ] AC1: 実機（DSM）で WTD（CC2）＋誤ったオーダーの 1 レコードを 5 通り（SBA の外・RA の後戻り・SOH の長さ 0・EA の長さ 7・SBA の短い）出させ、ACS のコアと当 PJ の画面・メッセージ待ち・否定応答のセンスが同じ
- [ ] AC2: 対象の誤りすべてを単体テストで固定する（正しい境界の対照も）
- [ ] AC3: 実機の試験プログラムと記録を片付ける
