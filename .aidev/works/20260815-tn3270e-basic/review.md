### 指摘と対応

- [must] **ハーネスが `BIND-IMAGE` を合意してしまい、s3270 が画面を描かなかった。**
  RFC 準拠に直した結果「要求されたリストをそのまま `IS` で返す」ようにしたが、
  s3270 は既定で `BIND-IMAGE` を要求するため、合意すると **BIND を送るまで
  `connected-unbound` のまま**になる。「s3270 が 3270 モードに入らない」という
  紛らわしい失敗として出た。
  / 対応: **修正済**。§7.2.1 に従い **`REQUEST` で対案**を返して `BIND-IMAGE` を外す。
  対案の往復経路も同時に踏めるようになった。

- [must] **後退経路でも 5 バイトヘッダを付けていた**（ハーネス）。`tn3270e:false` の
  クライアントが `WONT` を返した後も `useE` を見てヘッダを前置していたため、画面が空になった。
  / 対応: **修正済**。`fellBack` を持ち、後退後は基本 TN3270 として振る舞う。

- [must] **`S3270.waitReady()` が `connected-3270` しか見ていなかった。**
  TN3270E の状態名は `connected-tn3270e` なので、正常に繋がっているのに
  「モードに入らない」と誤判定していた。
  / 対応: **修正済**。両方を受理する。コメントに理由を残した。

- [should] テストの EBCDIC 変換を手書き表で書き、**`S` を書き落として** `"TEST"` が
  `"TE T"` になった。
  / 対応: **修正済**。実コーデック（`codecForCcsid(37)`）を使う。
  **手書きの変換表を持たない**のが正しい——取りこぼしが静かに通る。

- [nit] 未使用変数 2 件（ハーネスの `delayMs` 残骸、テストの `E`）を lint が検出。/ 対応: 除去。

## ラウンド 2（2026-08-15T16:35:09Z）— 代替画面サイズ（EWA）の検証を足す

### なぜ足したか

fixture を解析したところ、**実ホストが送ってきたのは `EraseWrite`(F5) と `WSF`(0x11) だけ**で、
**`EraseWriteAlternate`(7E / SNA 0D) は 1 件も無かった**。つまり EW/EWA の切り替えは
**RFC の読解だけが根拠**で、実バイトで動かした実績がゼロだった。

```
実ホストが送ったコマンド:  EraseWrite ×4 / WSF(SNA) ×2
出現したオーダー:          SBA・SF・SFE・RA・IC・PT
一度も無し:                EWA / ReadBuffer / ReadModifiedAll / EraseAllUnprot
```

ISPF はモデル 3/4/5 の代替サイズを多用するので、**z/OS を相手にする前に踏んでおく**。
バッファのサイズ管理という根幹に関わる箇所を未検証のまま残すのは、
この作業で 4 回踏んだ「推測で書いた箇所が実測で覆る」と同じ形になる。

### 追加した検証（`test/e2e-altsize.test.ts`）

**単体（docker 不要）**
- モデル 3/4/5 で **EWA → 代替サイズ、EW → 標準 24x80 に戻る**（内部状態）
- **代替サイズでしか届かないアドレス**に書ける（model 5 の最終行は 24x80 に存在しない）
- **SNA 系のコード（0x0D）でも代替サイズになる**
- モデル 2 は代替も 24x80（RFC 1576）

**照合（`TN3270_E2E=1`）**
- モデル 3（32x80）／4（43x80）／5（27x132）で、**画面全体が s3270 と一致**
- 空振り防止として、代替領域の右下に置いた印が実際に描かれていることを先に確認

> **s3270 の性質に注意**——あちらは EW/EWA のどちらを受けても**モデルの代替サイズで報告する**
> （decisions D5）。よって「EWA で代替サイズになる」は突き合わせられるが、
> 「**EW で標準サイズに戻る**」は自実装の内部状態でしか確かめられない。テストもそう分けてある。
