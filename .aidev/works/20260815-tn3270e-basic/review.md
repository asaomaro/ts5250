## ラウンド 2（2026-08-15T16:35:09Z）— 代替画面サイズ（EWA）の検証を足す

### なぜ足したか

fixture を解析したところ、**実ホストが送ってきたのは `EraseWrite`(F5) と `WSF`(0x11) だけ**で、
**`EraseWriteAlternate`(7E / SNA 0D) は 1 件も無かった**。つまり EW/EWA の切り替えは
**RFC の読解だけが根拠**で、実バイトで動かした実績がゼロだった。

```
実ホストが送ったコマンド:  EraseWrite ×4 / WSF(SNA) ×2
出現したオーダー:          SBA・SF・SFE・RA・IC・PT
一度も無し:                EWA / ReadBuffer / ReadModifiedAll / EraseAllUnprot
```

ISPF はモデル 3/4/5 の代替サイズを多用するので、**z/OS を相手にする前に踏んでおく**。
バッファのサイズ管理という根幹に関わる箇所を未検証のまま残すのは、
この作業で 4 回踏んだ「推測で書いた箇所が実測で覆る」と同じ形になる。

### 追加した検証（`test/e2e-altsize.test.ts`）

**単体（docker 不要）**
- モデル 3/4/5 で **EWA → 代替サイズ、EW → 標準 24x80 に戻る**（内部状態）
- **代替サイズでしか届かないアドレス**に書ける（model 5 の最終行は 24x80 に存在しない）
- **SNA 系のコード（0x0D）でも代替サイズになる**
- モデル 2 は代替も 24x80（RFC 1576）

**照合（`TN3270_E2E=1`）**
- モデル 3（32x80）／4（43x80）／5（27x132）で、**画面全体が s3270 と一致**
- 空振り防止として、代替領域の右下に置いた印が実際に描かれていることを先に確認

> **s3270 の性質に注意**——あちらは EW/EWA のどちらを受けても**モデルの代替サイズで報告する**
> （decisions D5）。よって「EWA で代替サイズになる」は突き合わせられるが、
> 「**EW で標準サイズに戻る**」は自実装の内部状態でしか確かめられない。テストもそう分けてある。

## レビュー（追加 3 回目）: `Read Buffer` と `SA` / `MF` / `EUA` / `GE`

**前回「残る未検証」に挙げた 2 行**——`Read Buffer` の応答と `SA`/`MF`/`EUA`/`GE`——を
s3270 との照合で埋めた。**うち 2 つが誤っていた。**

### 誤り 1: `GE` を無視していた（`⁼` を `A` と描いていた）

`GE`（0x08）を「次の 1 バイトは普通の文字」として素通りさせていた。正しくは
**次の 1 バイトだけ代替文字集合（APL 記号と罫線素片）で引く**。

`GE` に 0x40〜0xfe を総当たりで続けた画面を s3270 に流し、**113 文字**の対応を採って
`src/screen/graphic-escape.ts` にした。バッファ側は生バイトを保ったまま
**`geMark` という並行配列**で印を立て、描画（snapshot）で引き直す
——`Read Buffer` は生バイトを返す必要があるので、置き換えてしまうと戻せない。

### 誤り 2: `Read Buffer` の属性桁が二重に間違っていた

1. **`SF` オーダーが抜けていた**——属性バイトを裸で置いていた。
   s3270 は `…6040 40 1d60 d9c2…`、こちらは `…6040 40 60 d9c2…`。
2. **属性バイトをそのまま返していた**——正しくは
   **意味を持つ 6 ビットだけ残し、アドレスと同じ CODE 表で引き直す**。

2 番目は 0x00〜0xff の **256 通り全部**を SF で書き込んで測った
（`artifacts/s3270-readbuffer-attr-256.hex`）。`00`→`40`、`02`→`40`、`f2`→`f0`、`ff`→`7d`。
**256 通りすべてが `CODE[attr & 0x3d]` に一致**したので、規則として実装した
（`encodeAttribute()`）。1 例だけ見て「0x40 を立てる」と読んでいたら外していた
——`f2`→`f0` は 0x80 が残るので、その読みでは説明できない。

### 誤りではなかったもの

`SA` / `MF` / `EUA` は**画面全体が s3270 と一致**した。
`EUA` はこちらのテストの期待値が属性桁 1 桁分ずれていただけで、実装は合っていた。

### 追加した検証（`test/e2e-orders.test.ts` ほか）

- `SA`/`MF`/`EUA`/`GE` を全部使う画面で、**24 行すべてが s3270 と一致**
- `Read Buffer` の**応答バイトが s3270 と完全一致**（同じ mini3270 に両者を繋いで撃つ）

**単体（docker 不要）**

- 代替文字集合の代表値（`c1`→`⁼`、`85`→`│`）と、対応の無いバイト

## レビュー（追加 4 回目）: `Read Modified All` と `Erase All Unprotected`

**残る未検証の最後の 2 命令**を s3270 との照合で埋めた。**4 か所が誤っていた。**
いずれも「命令 1 つの動き」ではなく、**端末が持つ状態を 1 つ見落としていた**ことに起因する。

### 見落としていた状態: 端末は**直前の AID を覚えている**

ホスト起因の読み（`Read Modified` / `Read Modified All` / `Read Buffer`）の先頭バイトを
**0x60 固定**にしていた。実際は**直前に操作者が押したキーの AID** が乗る。

実測（`PA1` を押した後にホストから各命令を撃つ）:

| ホストが撃つ命令 | s3270 の応答 | 旧実装 |
|---|---|---|
| `F6` Read Modified | `6c`（短形式のまま） | `60` ＋カーソル＋欄 |
| `6E` Read Modified All | `6c` ＋カーソル＋欄 | `60` ＋カーソル＋欄 |
| `F2` Read Buffer | `6c` ＋バッファ | `60` ＋バッファ |

**この記憶が消えるのはキーボードが復旧したとき**。`WCC` の復旧ビット付きの書き込みで消え、
**復旧ビットの無い書き込みでは消えない**（`F1 00` と `F5 00` の両方で確かめた）。
`EAU` もキーボードを復旧させるので、同時に忘れる。

### 誤り 1: `Read Modified` と `Read Modified All` を**同じ扱い**にしていた

両方とも `AID_NONE ＋ カーソル ＋ 変更欄` を返していた。
**違いは短形式の扱いだけ**——`PA1`〜`PA3`・`Clear` の後、
`Read Modified` は AID 1 バイトで答え、`Read Modified All` は**短形式を無視して欄まで返す**。
「PA キーの後でも入力内容が欲しい」ためにホストが使う命令なので、
ここを同じにしていると**命令の存在理由そのものが消えていた**。

### 誤り 2: `Read Buffer` が AID を返していなかった（誤り 1 と同根）

### 誤り 3: `EAU` がカーソルを動かしていなかった

`EAU` は**カーソルを最初の非保護桁へ**移す。非保護欄が 1 つも無ければ 0 桁目
（`ALLPROT` だけの画面と、書式なし画面の両方で確認）。
カーソル位置は読みの応答に乗るので、**放置すると以後の応答が全部ずれる**。

### 誤り 4: `EAU` の後も AID を覚えたままだった（誤り 1 と同根）

### 誤りではなかったもの

- **MDT を落とすのは非保護欄だけ**——保護欄に MDT が立っていても残る
  （属性 0x61 の欄を置いて確認。`1d61` のまま返ってくる）。実装は元から合っていた
- **`EAU` は応答を返さない**（`WCC` もオーダーも持たない命令）
- **書式なし画面の `EAU` はバッファ全体を消す**

### 追加した検証

**照合（`TN3270_E2E=1`・`test/e2e-rma-eau.test.ts`）**
- 同じ画面に同じ入力をして `PA1` を押し、
  `F6` → `6E` → `F2` → `6F` → `F2` → `F6` と撃つ **7 応答が 1 バイト残らず一致**
- `EAU` に**応答が返らない**ことも「無いこと」として突き合わせ
- `EAU` 後の `Read Buffer` が語る中身（AID・カーソル・保護欄の残存・MDT）を**明示のテスト**にした
  ——回帰したとき何が壊れたか読めるようにするため

> **`Read Buffer` の応答を比較の軸に選んだ**理由——画面の中身・カーソル位置・MDT ビット・
> 覚えている AID が**全部この 1 本に乗る**。`EAU` が何をしたかを 1 回の比較で丸ごと確かめられる。

**単体（docker 不要・`test/session.test.ts`）**
- 短形式の記憶、`Read Modified All` による覆し、`Read Buffer` の AID
- 復旧ビットの有無で記憶が消えるかどうかが変わること

## レビュー（追加 5 回目）: OSS 3270 エミュレータの DBCS 実装を調べて取り込む

### 調査——DBCS を実装している OSS は **x3270 だけ**だった

主要な OSS 3270 実装を実際にクローンして数えた。

| 実装 | 言語 | DBCS |
|---|---|---|
| **x3270 / s3270 / c3270 / b3270**（pmattes） | C | **あり**（`ctlr.c` だけで DBCS 参照 147 箇所） |
| tnz（IBM 公式の Python ライブラリ） | Python | **無し**（Query Reply のビット説明に語が出るだけ。SO/SI 処理が無い） |
| dm3270 | Java | **無し**（"double-byte" はテレネットコマンドの話） |
| Open3270（.NET） | C# | **無し** |
| tn3270lib | Python | **無し** |

**「実装していないことも事実」**（AGENTS.md）——IBM 自身の Python ライブラリですら
DBCS を持たない。3270 の DBCS は x3270 が事実上の唯一の参照実装だった。

### 参照して分かったこと 1: **DBCS の入口は 3 本ある**

x3270 は `enum dbcs_why { DBCS_FIELD, DBCS_SUBFIELD, DBCS_ATTRIBUTE }` の 3 通りを区別していた。

| 入口 | 形 | 自実装 |
|---|---|---|
| SO/SI 小区間 | `SO` … `SI` | **実装済み** |
| **DBCS 欄** | `SFE` の文字セット属性（`0x43` = `0xf8`）で欄まるごと。**SO/SI を使わない** | **無かった** |
| **SA 指定** | `SA 43 f8` で文字の並びだけ | **無かった** |

`0xf8` が DBCS、`0xf1` は APL、それ以外は基本文字集合——**値の振り分けも実測で確認**した
（`0xf1` の欄は日本語にならない）。

### 参照して分かったこと 2: **対の左右は「行」では決まらない**

自実装は**行ごとに**「SO を見たか」を持って左右を決めていた。
正しくは**区間の先頭からの通し番号の偶奇**で、その結果
**DBCS 1 文字が行末で割れる**（左半分が 80 桁目、右半分が次行 1 桁目）。
s3270 は割れても正しく描く。`DBCS_LEFT_WRAP` / `DBCS_RIGHT_WRAP` という状態まで持っている。

あわせて 2 つの後始末も入れた。

- **相方の来ない左半分**（dead position）は文字にしない
- **DBCS として成立しないバイト対**（どちらかが 0x40〜0xfe の外）は**空白 2 桁**として描く
  ——これが無いと、SI の来ない区間が NUL の海に出たところで化け続ける

### x3270 と**わざと違えた** 1 点

x3270 の後処理は「アドレス 0 を支配する属性桁の**次**から一周」で回る。
そのため**その属性桁自身が処理されず**、アドレス 0 を含む欄が DBCS でも対にならない。

実測 3 通りで裏を取った——画面の先頭に DBCS 欄を置くと化け（`･a･eｨX`）、
手前に別の欄を 1 つ置くだけで正しく `日本語` になる。欄が 1 つだけの画面でも化ける
（その欄がアドレス 0 を含むため）。

**こちらは化けない実装にした。**規格から外れているのではなく回り込みの取りこぼしで、
