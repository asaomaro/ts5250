# 決定記録

## D1: 測定と実装を work の起票より先に始めた（記録の順序の注記）

- 背景: 台帳の「DS5250 の残り」を読みながら ACS の原典（`DS5250.sendAll`）を確かめ、そのまま DSM の TRANSP・プローブ・実装・実機の確認まで進めてから `aidev new` した
- 決定: 工程の start の時刻は起票後のもの。所要時間（requirements〜coding）は実態より短く出る——メトリクスとしては無効に扱う
- 影響: 成果物（research の事実・実測値）は作業の順序に依らず同じ

## D2: READ INPUT 系は原典どおりに入れる（実機では測れなかった）

- 背景: DSM の 2 回目の読み（`QsnReadInp`）が CPFA306 で待たずに終わり、ACS の READ INPUT 系のワイヤを採れなかった
- 決定: 原典（`DS5250.sendAll` の 6・66・114）どおりに、透過の欄はヌルを空白に換えず欄長ぶん送る。未確認として test-result に残す

## D3: ~~DBCS の原本を持つ透過の欄は桁ごとの原本（`dbcsRawCells`）で組む。変異 2 つは等価として残す~~ → レビュー（ラウンド 1）でセルごとに元のバイトで組む形に置き換えた

- 背景: `fieldValue` は DBCS の構造を持つ欄で原本を 1 本の文字列にし、全角の後半桁が生バイトを持たないとき空文字になって桁がずれる
- 決定: 桁ごとの配列（`dbcsRawCells`）を先に使う。「原本を使わない」「後半桁を飛ばさない」の変異は、後半桁が生バイトを持つ実際の形（ホストが書いた全角）では結果が同じで生き残る——等価として記録する

## D4: 透過の欄はセルごとに元のバイト（`hostByte ?? rawByte`）で組む

- 背景: 独立レビューの指摘。字を符号化し直すと 0x1C・0x1E のセルが `*`・`;` になり、ACS（HostPlane のまま）と違う。1 桁が 1 バイトにならない字で平たい形の位置がずれる
- 決定: セルごとに 1 バイト（空 0x00・属性・元のバイト・SO/SI・全角は 2 桁に割る）。どのセルも 1 バイトなので長さは欄の桁数と一致し、区間ごとの切り詰めは要らない（入れた切り詰めは変異が生き残る防御だったので外した）
