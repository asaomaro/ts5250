# 要件: 930（日本語カタカナ）の Katakana / Katakana Extended を利用者に選ばせる

## 背景 / 課題

台帳 `.aidev/backlog/acs-parity.md`「930 の申告の選択」項。CCSID 930 の入力規則は ACS 自身が
**利用者に選ばせる**設定（ホスト・コード・ページの選択とは別の、キーボード種別の選択。ACS の
「Katakana」＝`KEY_JAPAN_KATAKANA`・290 扱い・CHARSET 332、「Katakana Extended」＝
`KEY_JAPAN_KATAKANA_EX`・CHARSET 1172）である。利用者から実際の ACS の画面
（ホスト・コード・ページ＝「930 日本語（カタカナ）」の選択画面）を確認してもらったところ、
これは ACS の仕様として利用者ごとに選べる項目であることが確定した——「どちらが正しいか」を
当 PJ が決め打ちする問題ではない。

当 PJ は現状、**どちらとも一致しない折衷**になっている: 入力は全欄で大文字化する（Katakana ＝290
と同じ向き）が、`[ ] ^ ` { } ~ ¢` の 8 記号は拒否しない（Katakana Extended と同じ向き）。
CHARSET は 1172（Extended）を申告している（`packages/base/src/device-env.ts`）。

## 目的 / ゴール

利用者が自分の ACS の設定（Katakana か Katakana Extended か）に合わせて選べる状態。
選んだ側に応じて、CHARSET の申告と入力の可否（大文字化・8 記号の可否）が ACS と一致する。

## ユーザーストーリー

- US1: 930 でホストへ繋ぐ利用者として、自分の ACS が使っているのと同じキーボード種別を選びたい。
  なぜなら、選択が合わないと、ACS では通る入力（小文字のコマンド・8 記号）が拒否されたり、
  逆に ACS では拒否される入力が通って送信時にエラーになったりするため。（受け入れ: AC1, AC2, AC3）
- US2: 設定を変えない利用者として、今までどおり動いてほしい。なぜなら、既定値を変えることで
  無指定の利用者の挙動が変わるのは避けたいため。（受け入れ: AC4）

## スコープ

### 対象

- CCSID 930・5026（Katakana 系）に対する「キーボード種別」設定の追加
  （`system` / `session` 設定の階層。既存の `ccsid` と同じ並びに置く）
- 選択に応じた CHARSET の申告切り替え（332 / 1172）
- 選択に応じた入力規則の切り替え（大文字化の要否・8 記号の可否）
- 設定 UI（システム設定・セッション設定のフォーム）への項目追加

### 対象外

- 939/5035/931/1399 など他の DBCS CCSID（Katakana の選択肢を持たない。ACS でも 930/5026 系だけの設定）
- 5026 に別の選択肢があるかどうかの検証（930 と同じ扱いとして進める。930 とは別の実機確認は行わない）
- 290 という CCSID そのものの独立申告（930 の中の1バリアントとして扱う。ACS も 290 という別の
  CCSID を名乗るのではなく、930 のまま CHARSET だけを変える）
- 5026 に Katakana / Katakana Extended の選択が実在するかの検証（930 と同じ扱いとして進める。
  未確認のまま踏み込む理由は「非機能要件 / 制約」参照）

## 機能要件

- system 設定・session 設定のスキーマに、930/5026 のときだけ意味を持つ新しい項目を追加する
  （既定は下記のとおり現状維持）
- 新しい項目の値に応じて `deviceEnvFor` 相当の CHARSET 申告を切り替える
- 新しい項目の値に応じて、web-ui の入力規則（大文字化・8 記号の拒否）を切り替える
- 設定 UI（システム / セッション設定のフォーム）に選択肢を出す。930/5026 以外の CCSID では出さない
  （AGENTS.md UI ガイド「環境の検出結果で選択肢を塞がない」と同じ思想——930 以外では**意味を持たない**
  ので隠すのは検出ではなく妥当性の問題）

## 非機能要件 / 制約

- 既定値は**現状の CHARSET（1172＝Extended 寄り）を維持**する。既定の入力規則（大文字化する）も
  当面は維持し、明示的に選んだ利用者だけ挙動が変わる（無指定の利用者への影響を避ける。AC4）
- 5026 は 930 と同じ規則に従わせる（別軸を増やさない）

## 完了条件 (受け入れ基準)

- [ ] AC1: 930/5026 のシステム・セッション設定で「Katakana」を選ぶと、CHARSET 332 を申告し、
      入力は大文字化・8 記号（`[ ] ^ ` { } ~ ¢`）を拒否する
- [ ] AC2: 「Katakana Extended」を選ぶと、CHARSET 1172 を申告し、入力は小文字のまま許可・
      8 記号も入力できる
- [ ] AC3: 930/5026 以外の CCSID では、この設定は UI に出ず、値を持っていても無視される
- [ ] AC4: 設定を明示しない場合は、現状の申告（CHARSET 1172）・現状の入力規則（大文字化する・
      8 記号は許可）のまま変わらない

## 未確定事項 / 確認したいこと

- なし（5026 の扱いは「対象外」に一本化した）
