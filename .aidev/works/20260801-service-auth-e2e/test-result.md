## 検証が見つけたもの（2 件とも直した）

### 1. 一般ユーザーがサービス一覧に辿り着けなかった

ランチャーの「アプリ」段は**システムを選んだ後**にしか出ず、サーバー設定のシステムは
admin にしか見えない。つまり一般ユーザーは**選べるシステムが 0 件**で、
「システムがまだありません」から先へ進めなかった。

「見るだけは許す」と決めても、**入口が閉じていれば意味が無い**。

### 2. `printer-stop` の拒否が返らず、プロセスが落ちた

```
As400Error: forbidden: not the owner of this session
    at assertOwner ... at SessionManager.stopPrinter ... at ws-handler.js:228
Node.js v24.15.0        ← プロセスごと終了
```

`void withAudit(...)` で promise を捨てていた。捨てると**拒否が利用者に返らず**
（`handle()` の catch が `error` を送る経路を迂回する）、**未処理の rejection で落ちる**。

**認証オフでは絶対に踏まない**——`assertOwner` が全通過するため。
「認可が効いているかを測っていない」ことの実害がそのまま出た形。

## 未検証（穴）

- **トークン認証（Bearer）経路**は見ていない（Cookie セッションのみ）。
- **一般ユーザーが自分の個人設定で作った監視**を操作できるか、は見ていない
  （`assertOwner` は所有者を通すので効くはずだが、測っていない）。
- 実機 E2E は `npm test` に乗らないので、**走らせないと腐る**（この検証自体がその実例を生んだ）。
