# 要件: その場で戻る否定応答のとき、同じレコードの CC2（警報・メッセージ待ち）を ACS と同じく効かせない

## 背景 / 課題
`.aidev/backlog/acs-parity.md` の「否定応答で早く戻るときの CC2 と SAVE PARTIAL の応答」。ACS `DS5250.processCommand` はいくつかの否定応答で直ちに戻り、
レコードの終わりの `processWCC2`（警報・メッセージ待ち）と SAVE PARTIAL の応答を飛ばす。当 PJ は同じレコードで先に来た WTD の CC2 を効かせる。
backlog は「DSM で WTD＋不正な ROLL を ACS のコアと当 PJ に出させて測ってから直す」としている。

## 目的 / ゴール
その場で戻る否定応答を含むレコードで、メッセージ待ち表示・警報が ACS と同じになっている状態（実機で確かめてある）。

## ユーザーストーリー
- US1: 5250 端末の利用者として、ホストが誤ったレコードを送ってきたときも ACS と同じ表示灯・警報であってほしい。なぜなら ACS と表示が違うと、メッセージの有無を読み違えるから。（受け入れ: AC1, AC2）

## スコープ
### 対象
- ESC が無い・CLEAR UNIT ALTERNATE の引数・ROLL の指定・WSF が短い（当 PJ が否定応答にしている、ACS がその場で戻るもの）での CC2（警報・メッセージ待ち）
- 実機での測定（ACS のコアと当 PJ）

### 対象外
- SAVE PARTIAL の応答（ACS は戻ったレコードでは送らず、次のレコードの終わりに持ち越す——原典の読み。実機では測っていない。backlog に残す）
- READ による解錠（当 PJ は READ で解錠する。ACS の戻り方との差は測っていない。backlog に残す）
- ACS がその場で戻るが当 PJ が否定応答にしていない短いレコード（WTD・READ・WRITE ERROR CODE の本体が無い）——backlog に残す

## 機能要件
- 上の 4 つの否定応答では、そのレコードの CC2 の警報・メッセージ待ちを効かせない。WSF D9/72 のフラグ 0x80 では効かせる（ACS も終わりまで走る）。

## 非機能要件 / 制約
- 実機で作った試験プログラムは消す。

## 完了条件 (受け入れ基準)
- [ ] AC1: 実機（DSM）で WTD（CC2＝メッセージ待ちを点ける）＋不正な ROLL の 1 レコードを出させ、ACS のコアと当 PJ のメッセージ待ちが同じ（点かない）
- [ ] AC2: 4 つの否定応答で警報・メッセージ待ちを効かせず、D9/72 では効かせることを単体テストで固定する
- [ ] AC3: 実機の試験プログラム（DSCMD・IFS の /tmp/dscmd.*）を消す
