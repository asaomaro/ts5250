# 要件: サーバー設定を画面から作り始められるようにする

## 背景 / 課題

利用者の報告:

> start.sh で起動し単独ユーザーで利用していますが、システム新規作成でサーバー設定の
> 選択肢が出てきません

原因は**鶏と卵**だった。

- 画面の「保管場所: サーバー設定」は `canEditServer` が true のときだけ出る
- `canEditServer` は「**保存できるとき**」を要求する（`persistable`）
- `persistable` は**ファイル由来のときだけ** true
- `--profiles` を渡さないと `ServerConfigStore` は path を持たない空のストアになる
- `start.sh` は**ファイルが既にあるときだけ** `--profiles` を渡す

→ **ファイルを作らないとサーバー設定を作れず、画面から作らないとファイルができない。**

利用者の指摘:

> profiles.json がなくても管理者ユーザーであることは分かっているなら、画面から新規システム
> 追加して、結果を profiles.json に保存するようにするだけなのでは？

その通りで、**個人設定（`connections.json`）は元からそう作られている**——既定パスがあり、
ファイルが無ければ**空で始めて path は持つ**。サーバー設定だけが取り残されていた。

## 目的 / ゴール

**ファイルを手で用意しなくても、画面からサーバー設定を作り始められる。**

## スコープ

### 対象

- サーバー設定の既定パスと、ファイルが無いときの振る舞い（個人設定に合わせる）
- `start.sh` の保存先の決め方
- `.gitignore`（既定の保存先に資格情報が入るため）
- README

### 対象外

- `canEditServer` の条件そのもの（「保存できないボタンを出さない」は正しい）
- 認可の設計

## 機能要件

- `--profiles` 未指定なら**既定パス**（`profiles.json`）を保存先にする。無ければ空で始める
- `--profiles` を**明示指定**したときは、無ければ**起動しない**（打ち間違い保護）
- `start.sh` は無ければ空のファイルを作る（master key の自動生成と同じ扱い）
- 壊れたファイルは**黙って空にしない**

## 完了条件 (受け入れ基準)

- [ ] ファイルが無い状態で起動して `editable: true` になる
- [ ] 保存すると実際にファイルができる
- [ ] `--profiles` の打ち間違いは起動時エラー
- [ ] 既定の保存先が `.gitignore` に入っている
- [ ] ビルド・lint・全テストが通る
