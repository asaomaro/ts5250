# 仕様: サーバー設定を画面から作り始められるようにする

## 設計方針

### 個人設定と同じ形にするだけ

`PersonalConfigStore.fromFile` は**元からこう振る舞う**——ENOENT なら空のストアを作り、
**`setPath` は行う**（＝ `persistable: true`）。サーバー設定に同じものを足す。

**新しい概念を作らない。** 非対称だっただけなので、揃える。

```ts
// ファイルが無ければ空で始める（既定パス用）
static fromFileOrEmpty(path, crypto?, warn?): ServerConfigStore
```

### 明示指定と既定パスを分ける

| 呼ばれ方 | ファイルが無いとき |
|---|---|
| `--profiles <path>`（明示） | **エラーで起動しない** |
| 未指定（既定 `profiles.json`） | **空で始める** |

**打ち間違えたパスで空の設定が立ち上がると、既存の設定が消えたように見える。**
明示指定は「そこにあるはず」という意思表示なので、無ければ黙らない。

`fromFile` は従来どおり投げ、`fromFileOrEmpty` だけが許す——**呼び分けで意味を表す**。

### `start.sh` は無ければ作る

`start.sh` は単一利用者向けのローカル起動で、**既に master key（`.env`）を自動生成している**。
設定ファイルも同じ扱いにする。

明示的に作るのは、`--profiles` に渡す以上「無ければエラー」の側に入るため
（作らずに渡すと起動しない）。

### `.gitignore`

既定の保存先には**接続先・ユーザー名・暗号化パスワード**が入る。`connections.json` が
既に無視されているので、`profiles.json` も同じ扱いにする（雛形 `.example` は追跡のまま）。

## 対象範囲

| ファイル | 変更 |
|---|---|
| `config-store.ts` | `ServerConfigStore.fromFileOrEmpty` |
| `main.ts` | 既定パス `profiles.json` を使う |
| `start.sh` | 無ければ空で作ってから渡す |
| `.gitignore` | `profiles.json` / `.tmp` |
| `README.md` | 手で用意しなくてよいこと・明示指定の注意 |

## 振る舞いの詳細

| 状況 | 結果 |
|---|---|
| 既定パス・ファイル無し | 空で起動、`editable: true`、保存で作られる |
| 既定パス・ファイルあり | 読む |
| 既定パス・壊れている | **エラー**（黙って空にしない） |
| `--profiles` 明示・無し | **エラー** |

## セキュリティ上の変化

`canEditServer` が true になる場面が**広がる**（今まではファイルが無いと常に false）。

- **認証あり**: admin だけが得る。admin は元よりサーバー設定を管理する役なので変化なし
- **認証なし**: 単一利用者・ローカル前提の運用。ポートに到達できる相手は既に
  保存済み資格情報でセッションを張れるので、**新しい種類の力ではない**

信頼設定（パス書き込み・コマンド実行・Webhook）を書ける相手の**条件は変えていない**
——変えたのは「保存先が決まっているか」だけ。
