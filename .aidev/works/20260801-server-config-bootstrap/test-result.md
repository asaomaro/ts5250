## 実物で確かめたこと

**この変更は「起動の仕方」なので、単体テストだけでは足りない**——`main.ts` の分岐と
実際の応答まで見る。

```
### 1. 既定パス・ファイル無し → 保存できる状態で起動
{"systems":[],"editable":true}                    ← ここが false だったのが今回の不具合

### 2. --profiles で存在しないパス → エラーで止まる
"failed to read profiles ./nope.json: ENOENT..."  ← 打ち間違い保護は残っている
"server failed to start"

### 3. 既定パスに既存ファイルがあれば読む
{"systems":[{"ref":"srv:s1","name":"すでにある",...}],"editable":true}
```

## 新規の単体テスト（6 件）

| 内容 |
|---|
| 空で始まり `persistable` になる |
| **保存すると実際にファイルができる**（画面から作り始められる） |
| **個人設定と同じ `persistable`**（非対称を直したのが今回） |
| 既存ファイルの中身を読む |
| **壊れたファイルは黙って空にしない**（設定が消えたように見せない） |
| **明示指定は無ければ投げる**（打ち間違いで空の設定を立ち上げない） |

  今回触っていない。
