# 要件: 1 本のレコードの中の応答をコマンドの順に送る・SAVE SCREEN のオペコードのレコードは退避だけ

## 背景 / 課題
台帳「節目の懸念の残り」の「応答をコマンドの順に送らない」。当 PJ はレコードを最後まで適用してから、応答を固定の順（退避 → WSF → READ SCREEN 系）で送る。
2026-09-28 に DSM の RESPORDER / RESPORDER2 で 1 本のレコードに応答の要る命令を 2 つ並べ、実機の ACS のコアのワイヤを採った（research F1）。

## 目的 / ゴール
同じレコードに応答の要る命令が複数あるとき、当 PJ がホストへ返す応答の並び（と有無）が ACS と同じ状態。

## ユーザーストーリー
- US1: ホストのプログラム（DSM を使う業務・IBM の画面）として、端末の応答を命令の順に受け取りたい。なぜなら、順が違うと 1 本目の読みで違う応答を受け取り、処理が狂うから。（受け入れ: AC1, AC2）

## スコープ
### 対象
- `[WSF Query][SAVE SCREEN]`（オペコード 03）の応答の順
- オペコード 04（SAVE SCREEN）でデータが `04 02` で始まるレコードは退避だけ（ACS `DS5250.tokenizeData` の case 4）
- ほかの応答（READ SCREEN 系・READ IMMEDIATE 系）もコマンドの順にする（同じ仕組み）
### 対象外
- 応答の中身を「その命令の時点の画面」で組むこと（今はレコードを最後まで適用した後の画面。別の差として台帳に残す）
- カーソル送りの番号の範囲（同じ台帳項目の残り）

## 完了条件 (受け入れ基準)
- [ ] AC1: オペコード 03 の `[WSF Query][SAVE SCREEN]` で、Query の応答 → 退避の応答の順に送る（単体。ACS のワイヤ）
- [ ] AC2: オペコード 04 の `[SAVE SCREEN][WSF Query]` で、退避の応答だけを送り、Query には答えない（単体。ACS のワイヤ）
- [ ] AC3: 実機のブラウザ（当 PJ）で RESPORDER / RESPORDER2 のワイヤが ACS と同じ並び
- [ ] AC4: 既存のテストが緑（応答の中身は変えない）
