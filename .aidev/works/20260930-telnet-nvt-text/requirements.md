# 要件: 交渉の前に届いたテキスト（NVT）を画面に出す（ACS と同じ）

紐づく charter ゴール: charter.md なし（`.aidev/backlog/acs-parity.md`「telnet の交渉前のテキスト・バックアップホスト」。利用者の指示で対応不要から再開）

## 背景 / 課題
ACS は BINARY・EOR を交渉するまでに届いた通常データを、NVT のテキストとして 5250 の画面へ書く（`NVT.NVT_process_outbound`）。当 PJ は溜めるだけで捨て、
ゲートウェイ・プロキシのバナーやエラーの文言、5250 でないサービスの応答が画面に出ず、「時間切れ」としか分からない。

## 目的 / ゴール
交渉の前のテキストが、ACS と同じ規則で画面に出て、接続の待ちも解ける状態。

## ユーザーストーリー
- US1: ゲートウェイ越しに 5250 へ繋ぐ運用者として、ゲートウェイが返した文言（拒否の理由など）を画面で読みたい。なぜなら「時間切れ」では原因が分からないため。（受け入れ: AC1, AC2, AC3）
- US2: ゲートウェイの後ろの本物の IBM i に繋ぐ運用者として、バナーの後も 5250 の起動・画面が壊れずに続いてほしい。（受け入れ: AC3）

## スコープ
### 対象
- tn5250 の telnet 層（テキストの見分けと渡し）・NVT の書き出し（純関数）・`Session5250`（接続の待ちを解き、画面へ出す）

### 対象外
- 3270・VT（VT は元から端末。3270 の NVT は別）、NVT の入力（キー入力を交渉前の相手へ送る。ACS は送れるが、当 PJ は施錠のまま）
- バックアップホスト（ACS の利用者向けの設定画面に無い機能。decisions D1）

## 完了条件 (受け入れ基準)
- [ ] AC1: 書き出しの規則（表示できる ASCII・CR・LF/VT/FF・BS・ENQ・無視するバイト・折り返し・回り込み・SBA 1,0 の拒否）が、ACS のコアに同じ受信を当てた画面・カーソルと一致する
- [ ] AC2: telnet 層は BINARY・EOR のどちらにも応じていない間の通常データを、IAC のコマンドの手前と受信の終わりでテキストとして渡す。IAC EOR で終わる塊は従来どおりレコード
- [ ] AC3: セッションはテキストを画面へ出して接続の待ちを解き、施錠のまま。後から 5250 の起動応答が来ても最初のレコードとして読まれる

## 未確認 / 確かめたいこと
- 画面の終わりを越えた後の ACS は入力禁止のまま動かなくなる（Reset でも戻らない）。当 PJ は続く受信も書く（decisions D2）
