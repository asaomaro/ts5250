# 要件: 5250端末画面のマクロ機能（記録・再生）

## 背景 / 課題

IBM i の運用では、同じ画面操作を毎日・毎回くり返す場面が多い（サインオン、メニュー階層をたどる、
定型の照会条件を打ち込む、締め処理の一連手順など）。これらは手順が固定されているにもかかわらず、
現状の本エミュレーターでは毎回すべて手で打ち直すしかない。

IBM i Access Client Solutions（ACS）の 5250 エミュレーターには**マクロ機能**があり、
一連の操作を記録して再生できる。ACS からの移行を考えるユーザーにとって、マクロが無いことは
「ACS で出来ていたことが出来なくなる」という具体的な後退であり、乗り換えの障壁になる。

ACS が提供していたマクロ操作は次の4つ:

1. マクロの**記録**
2. マクロの**再生**
3. マクロの再生・記録の**休止**
4. マクロの再生・記録の**停止**

## 目的 / ゴール

5250端末セッションでの一連の操作を**記録して名前を付けて保存し、あとから再生できる**状態にする。
ユーザーが定型操作を「一度覚えさせて、次からは呼び出すだけ」にできることをもって達成とする。

## スコープ

### 対象

- **記録**: 5250端末セッションでのユーザー操作を記録し、名前を付けて保存する
- **再生**: 保存済みマクロを選んで、記録した操作をセッションに対して再現する
- **休止**: 記録中・再生中を一時停止し、同じ地点から再開できる
- **停止**: 記録中・再生中を終了する（記録は保存の可否を確定し、再生は途中で打ち切る）
- **マクロの管理**: 保存済みマクロの一覧・命名・削除
- 上記を操作するための UI（既存の web-ui の意匠・配置規約に沿ったもの）
- 記録・再生・休止・停止の**現在状態がユーザーに見えること**（今どの状態なのかが分かる）

### 対象外

- ACS のマクロファイル形式との**バイナリ／XML 互換**（ACS で作ったマクロをそのまま読み込むこと）
- スクリプト言語によるマクロ記述（ACS の Java／JavaScript／VBScript 系マクロ）
- 条件分岐・ループ・変数・計算などの**プログラミング構文**
- プリンターセッションのマクロ（対象は5250端末セッションのみ）
- マクロのスケジュール実行・自動起動（無人バッチ的な使い方）
- 複数セッションをまたぐマクロ

> 上記のうち「ACS 互換」「スクリプト構文」は、まず**記録・再生という中核**を成立させることを
> 優先するための除外であり、将来的な追加を否定するものではない。

## 機能要件

- **F1 記録開始**: ユーザーが記録を開始でき、開始以降のセッション操作が記録対象になる
- **F2 記録内容**: 打鍵した文字入力と、送信操作（Enter・F1〜F24・その他の AID キー相当）が記録される
- **F3 記録停止と保存**: 記録を停止し、名前を付けて保存できる。保存せず破棄もできる
- **F4 再生**: 保存済みマクロを選んで再生でき、記録時と同じ操作がセッションに送られる
- **F5 再生の同期**: 再生はホストの応答を待ち合わせて進む（画面が返る前に次の操作を送って取りこぼさない）
- **F6 休止／再開**: 記録中・再生中を休止でき、休止地点から再開できる
- **F7 停止**: 記録中・再生中を任意の時点で停止できる
- **F8 状態表示**: 「記録中」「再生中」「休止中」「停止（待機）」が UI 上で判別できる
- **F9 マクロ管理**: 保存済みマクロを一覧・改名・削除できる
- **F10 永続化**: 保存したマクロはブラウザ／セッションを閉じても残る

## 非機能要件 / 制約

- **既存の UI 規約に従う**: `docs/UI-DESIGN.md` の配色・ボタン意匠・ポップオーバー・
  「アクティブペイン連動」の規約に従う。新たな見た目の系統を作らない
- **既存の入力経路を壊さない**: マクロ機能が無効・未使用のときの打鍵・カーソル移動・
  フィールド挙動は現状から変化しない（回帰させない）
- **セキュリティ**: マクロにパスワードなどの秘密が記録されうる点を要件として認識する。
  実資格情報を平文で成果物・ログに残さない（AGENTS.md のセキュリティ規約に従う）
- **信頼設定の扱い**: 認証オン時の露出範囲は、既存の信頼設定（PDF 出力先・自動印刷・秘密）の
  ゲート方針と矛盾しないこと
- **テスト**: 変更にはユニット／コンポーネントテストを伴う。web-ui のテストは
  パッケージ dir から実行する（AGENTS.md）
- **型チェック**: `npm run build -w @as400web/web-ui`（`vue-tsc -b && vite build`）を通す
