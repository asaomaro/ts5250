# 要件: SCS の空白は下の字を消さない（ACS の JPS と同じ）

## 背景 / 課題
- 台帳「SCS の解釈の差」の「重ね打ち（CR だけで行頭へ戻る）」。R11 の調査で、ACS の JPS（Windows の既定の経路）を headless で動かす道具を作り、当 PJ の `ScsDecoder` と桁単位で突き合わせた。
  JPS は 1 字ずつ `drawString` するだけで**何も消さず**、空白（0x40）も「空白を描く」だけ。CR で行頭へ戻って同じ行に重ね書きすると、2 度目の空白は下の字の上を通り過ぎるだけで、
  `ABCDEF` CR `␠␠␠XY` は A B C が残り D・E に X・Y が重なる。当 PJ は空白も書き込むので `␠␠␠XYF`（A B C が消える）だった。
- 実採取 3 件（DSPLIBL）は重ね打ちを含まないので、突合せの結果は新旧で不変。

## 目的 / ゴール
- 空白（半角・全角）が下の字を消さず、位置だけ進む状態。

## ユーザーストーリー
- US1: 帳票を読む利用者として、同じ行を 2 度に分けて重ね書きした帳票で、1 度目の字が黙って消えないでほしい。なぜなら、情報が欠けると気づけないから。（受け入れ: AC1〜AC4）

## スコープ
### 対象
- `ScsDecoder` の `put`・`putWide`（空白の書き込み）。
### 対象外
- 非空白の重ね打ち（下線・二度打ち・合成文字。ACS は両方描く）。構造の側（重ね層）を直す設計案は台帳に残す。実帳票の採取が先。

## 完了条件 (受け入れ基準)
- [ ] AC1: 半角の空白が、すでに字のある桁を消さない（`ABCDEF` CR `␠␠␠XY` → `ABCXYF`）。空白だけを重ねても下の字が残る。
- [ ] AC2: 全角空白も同じ（全角の字・半角 2 字・2 桁にかかる半角 1 字の上）。継続桁に半角の空白が来ても全角の字を壊さない。
- [ ] AC3: 何も無い桁への空白・行末の空白の桁（`cols`）・非空白の重ね書き（後の字が残る）は従来どおり。生バイトは下の字のまま。
- [ ] AC4: 各分岐を外すとテストが落ちる（`verify-by-mutation`）。実採取 3 件の結果は変わらない。
