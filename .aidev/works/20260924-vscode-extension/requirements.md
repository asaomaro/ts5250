# 要件: VSCode拡張機能によるts5250画面のWebView表示

## 背景 / 課題

現状、VSCode上でts5250（5250/3270エミュレータ・スプール表示・SQL実行等）を使うには、
`start.sh`等でサーバーを別途起動し、ブラウザないしVSCodeのSimple Browserで
`http://localhost:<port>`を手動で開く必要がある（画面表示自体がSimple Browserだけで
実用レベルに動くことは`20260827`の実測で確認済み——キー・DBCS・ペースト・セッション維持
いずれも問題なし）。

しかし、この運用は接続先ごとに手動でURLを開き直す・サーバーのライフサイクルを自分で管理する・
複数接続先の切り替えをブラウザのタブ管理に頼る、という煩雑さがあり、VSCodeのワークスペースに
「接続設定」をファイルとして持ち込めない。IBM iを相手に日常的にVSCodeで作業する利用者にとって、
接続先ごとの設定ファイルを開くだけで該当画面が表示される体験が望ましい。

## 目的 / ゴール

- 利用者が独自拡張子（`.ts5250`）の設定ファイルをVSCodeで開くだけで、そのファイルに書かれた
  接続情報・アプリ種別に応じた画面がWebViewタブとして表示されている状態
- 複数の`.ts5250`ファイルを同時に開いても、バックグラウンドサービス（既存`packages/server`）が
  VSCode全体で1インスタンスだけ起動している状態（画面ごとに別サービスが乱立しない）
- 開いていた`.ts5250`のWebViewをすべて閉じると、サービスが自動的に停止している状態
- WebView画面上の設定ボタンから接続情報を入力・変更すると、元の`.ts5250`ファイルに反映されている状態
- パスワードを保存する場合、既存の`profiles.json`/`connections.json`と同じ規約
  （平文禁止・暗号化必須）がこの新設ファイルにも適用されている状態

## ユーザーストーリー

- US1: IBM i開発者として、VSCodeで`.ts5250`ファイルを開くだけで5250/3270エミュレータ・スプール
  表示・SQL実行・IFSブラウザの画面を使いたい。なぜなら、外部ブラウザやElectronアプリを別途
  起動する手間なく、コードエディタと同じウィンドウ内で作業を完結できるから。（AC1, AC2, AC3）
- US2: IBM i開発者として、複数の接続先（`.ts5250`ファイル）を同時に開いても裏側のサービスは
  1つだけ動いてほしい。なぜなら、画面ごとに別プロセスが立つとポート枯渇・リソース浪費・
  多重起動時の不整合が起きるから。（AC4, AC5）
- US3: IBM i開発者として、WebView画面上の設定ボタンから接続先情報を直接編集したい。なぜなら、
  最初は最低限の情報だけ書いた設定ファイルを、画面を見ながらその場で補完・修正できると
  効率的だから。（AC6, AC7）
- US4: プロジェクトの利用者として、設定ファイルのパスワードを誤ってGitに平文でコミットして
  しまう事故を避けたい。なぜなら、既存の`profiles.json`/`connections.json`と同じ規約
  （暗号化必須）がこの新設ファイルだけ守られないと、新機能がそのままセキュリティホールに
  なるから。（AC8）

## スコープ

### 対象

- VSCode拡張機能本体（リポジトリ直下`vscode-extension/`。`electron/`と同じ立て付けで新設し、
  ロジックは可能な限り`packages/*`側へ逃がす）
- `.ts5250`拡張子のCustom Editor登録・WebViewでの表示
- 対応アプリ種別（第一弾）: 5250/3270エミュレータ（表示端末）・プリンター/スプール表示・
  SQL実行・IFSブラウザ
- バックグラウンドサービス（既存`packages/server`を流用）のVSCode全体での単一起動・
  全WebViewクローズ時の自動停止
- WebView内の設定ボタンによる接続情報の入力・`.ts5250`ファイルへの書き戻し
- パスワードの暗号化保存（既存`signon.passwordEnc`相当の方式。master keyの置き場所は
  design/research で詰める）
- 単一アプリに特化した最小WebView UI（新規。既存web-uiのワークスペースUI——タブ帯・
  システム切替等——とは別）

### 対象外

- VSCode Marketplaceへの公開（`.vsix`のローカルインストールのみを対象とする）
- Remote-SSH / Codespaces / devcontainer上での動作保証（ローカルVSCodeのみ想定）
- エミュレータ・スプール・SQL・IFS以外のアプリ種別（ジョブ一覧・コマンド実行・DTAQ・
  プログラム呼び出し等。web-uiには存在するが今回は対象外。将来拡張）
- 既存web-uiのワークスペースUI（タブ帯・システム切替・ランチャー等）をWebView内にそのまま
  持ち込むこと

## 機能要件

- FR1: `.ts5250`ファイルを開くと、対応するCustom EditorがWebViewパネルとしてタブに表示される
- FR2: `.ts5250`ファイルの内容から接続先（host/port/tls/ccsid等）とアプリ種別
  （emulator|printer|sql|ifs）を読み取り、該当する単一アプリの画面を表示する
- FR3: 最初の`.ts5250`WebViewが開かれたときにバックグラウンドサービスを起動し、空いている
  ポートで待ち受ける
- FR4: 2つ目以降の`.ts5250`WebViewは、起動済みのサービスをそのまま再利用する（多重起動しない）
- FR5: 開いているすべての`.ts5250`WebViewが閉じられたら、バックグラウンドサービスを停止する
- FR6: 各WebView画面に設定ボタンを配置し、押すと接続情報（パスワード以外を含む）を
  入力・編集できる
- FR7: 設定ボタンでの入力内容は、対応する`.ts5250`ファイルへ書き戻される
  （VSCode標準の保存・Undo・Diffがそのまま効く）
- FR8: パスワードは平文で`.ts5250`ファイルに書き込まれない。暗号化フィールドとして保存する
- FR9: 同一`.ts5250`ファイルを複数回開いても、WebViewタブは1つに寄る（多重表示しない）

## 非機能要件 / 制約

- 既存の`packages/server`をそのまま起動対象にする（新規サーバー実装は作らない。
  `electron/main.cjs`の起動パターン——空きポート探索・healthz待機・profiles/connections引数——
  を踏襲する）
- 新規コードは`vscode-extension/`に置き、ロジックは可能な限り`packages/*`側の既存資産に
  委ねる（`packages/server`本体は変更範囲を最小にする）
- 秘密情報の扱いは既存規約（AGENTS.md「アカウント・権限設計」「セキュリティ」節）に準拠する。
  新設する`.ts5250`もこの規約の対象とする（平文パスワード禁止・秘密を持つファイルは
  `.gitignore`対象に追加）
- 対応OS: 既存electron版と同じ範囲（Windows/macOS/Linux）を想定

- [ ] AC4: 2つ目以降の`.ts5250`ファイルを開いても、バックグラウンドサービスのプロセスは

- [ ] AC6: WebView画面の設定ボタンから接続情報（パスワード以外）を入力・保存すると、

- [ ] AC7: パスワードを設定ボタンから入力すると、`.ts5250`ファイルには暗号化された値として

## 相互作用の受け入れ基準（UI を伴う work のみ）

- [ ] AC-I1 開く/閉じる: `.ts5250`ファイルをエディタで開く操作でWebViewが開き、タブを
  閉じる操作でWebViewが閉じる。閉じても`.ts5250`ファイル自体の内容（保存済みの接続情報）は
  そのまま保持される
- [ ] AC-I2 確定/取り消し: 設定ボタンのフォームで「保存」を押すとファイルへ反映され、
  「キャンセル」を押すと元の内容のまま変更を破棄する
- [ ] AC-I3 キーボードだけで完結するか: `.ts5250`ファイルを開く→設定ボタンにフォーカス→
  フォーム入力→保存、を一通りキーボードのみで操作できる
- [ ] AC-I4 フォーカスの行き先: 設定フォームを開いたらフォームの最初の入力欄へフォーカスが
  移り、保存/キャンセルで元の画面（エミュレータ等）へフォーカスが戻る
- [ ] AC-I5 既存の操作を妨げないか: 設定フォームを開いていないときは、既存の5250エミュレータの
  キー操作（Tab/Enter/Fキー等）が従来通りWebView側に届く

## 未確定事項 / 確認したいこと

- master key（パスワード暗号化の鍵）の保存場所（VSCodeの`SecretStorage` / `globalStorage`内の
  ファイル / ワークスペースの`.env`等）——design以降で決定
- サービスの起動方式（extension host内でserverモジュールを`import()`するか
  ［`electron/main.cjs`と同じ方式］、子プロセスとして`spawn`するか）——design/researchで検討
- 単一アプリ専用の最小WebView UIを、既存web-uiのVueコンポーネント（`EmulatorPane.vue`・
  `SpoolPane.vue`・`SqlPane.vue`・`IfsPane.vue`等）から部分再利用するか、新規実装するか
  ——design/researchで検討
- `.ts5250`ファイルの正確なJSONスキーマ（既存の`systems`/`sessions`設定との対応関係。
  1ファイルに両方の情報を自己完結させる形になる見込み）——designで確定
- 同一ファイルを複数回開いたときのVSCode標準のCustom Editorの挙動（自動的に単一タブへ
  寄るか、拡張側での制御が要るか）は要検証——research推奨
