# 要件: Attn の窓を出すと背面の入力欄の下線が伸びる

## 背景 / 課題

利用者からの報告:

> Attn でコマンドを表示すると、画面上部の入力欄の罫線が延びてしまいます。F1 ヘルプの場合は問題ありません。

WRKOBJPDM の画面で Attn を押すと、背面の「ライブラリー」「位置指定」「タイプの位置指定」の入力欄の
**下線が右へ伸び、次の行へ回り込む**。F1 ヘルプでは起きない。

### 原因（実機で採取）

Attn の窓を描く WTD が **SOH でフォーマットテーブルを消している**。

```
Attn 前のフィールド数: 44   ← PDM 画面の入力欄を含む
Attn 後のフィールド数:  2   ← 窓の 2 欄だけ
受信: opcode=0x03 306B commands=[WTD, READ_MDT] SOH あり
```

当実装は下線・色の**終端をフィールド長で境界付けて**いる（`docs/PROTOCOL.md` 4.3。閉じ属性を送らない
アプリで下線が非編集エリアへ漏れるのを防ぐ ACS 準拠の処置）。境界の出所が
`ScreenBuffer.fields`（＝フォーマットテーブル）**だけ**なので、ホストがテーブルを消すと
**画面の中身は変わっていないのに境界が消え**、下線が次の属性桁まで伸びる。

F1 ヘルプで起きないのは、ホストが `CLEAR UNIT ＋ 全画面 WTD` で背面ごと描き直し、
フィールド定義も作り直されるため。

### なぜこれは誤りか

**Attn を押しても背面の表示内容は 1 桁も変わっていない。** 変わったのは入力の受け皿
（フォーマットテーブル）だけで、5250 の表示属性は本来「属性桁から次の属性桁まで」であって
入力欄の登録状況とは別物。**入力の話が表示を変えてしまっている**のが不具合。

## 目的 / ゴール

ホストがフォーマットテーブルを消しても、**背面の見え方が変わらない**ようにする。

## スコープ

### 対象

- 表示属性の終端境界を、フォーマットテーブルとは**別に保持**する。
  フィールド定義時に境界を覚え、**フォーマットテーブルのクリアでは失わない**。
- 画面そのものが消える操作（CLEAR UNIT / 画面サイズ変更）では境界も消す。
- SAVE / RESTORE SCREEN の退避・復元に境界を含める（復元後も見え方が変わらない）。

### 対象外

- 下線の境界付けという方式そのものの見直し（`docs/PROTOCOL.md` 4.3 の ACS 準拠処置は維持する）。
- ホストが SOH を送ること自体への介入（ホスト側の正しい動作）。
- 入力の可否・カーソル移動・送信対象（MDT）の扱い。**表示だけ**を直す。

## 機能要件

- フィールドが定義されたら、その終端（`startAddr + length`）を表示境界として記録する。
- `clearFormatTable()`（SOH / CLEAR FORMAT TABLE）は入力の受け皿だけを消し、**表示境界は残す**。
- `clearUnit()` / 画面サイズ変更は表示境界も消す（画面の中身が消えるため）。
- `saveScreen()` / `restoreScreen()` は表示境界も退避・復元する。
- 同じ開始アドレスにフィールドが再定義されたら、境界も新しい長さに追従する。

## 非機能要件 / 制約

- 変更は `packages/core` の画面バッファに閉じる。web-ui は触らない。
- 既存の下線・色の見え方（フィールドがある通常の画面）を変えない。
- `docs/PROTOCOL.md` に、境界がフォーマットテーブルと独立であることを追記する。

## 完了条件 (受け入れ基準)

- [ ] フィールド定義 → `clearFormatTable()` の後も、下線が元の終端で止まることをユニットテストで確認できる。
- [ ] `clearUnit()` 後は境界が消える（次の画面に古い境界が漏れない）ことを確認できる。
- [ ] `saveScreen()` → 画面変更 → `restoreScreen()` で境界が戻ることを確認できる。
- [ ] 同一開始アドレスの再定義で境界が新しい長さに追従することを確認できる。
- [ ] 既存の全テストが通る（下線・属性・READ SCREEN 応答の回帰を含む）。
- [ ] **実機の WRKOBJPDM で Attn を押しても、背面の下線が伸びない**（スクリーンショット）。

## 未確定事項 / 確認したいこと

- **古い境界が残ることの副作用**。ホストが同じ場所を別レイアウトで描き直したとき、消えた欄の境界が
  残って下線が早く切れる可能性がある。実際に起きうるか（描き直しは属性桁も書き直すので実害が無いか）を
  spec で確認する。
- **READ SCREEN 応答（`fieldEndAttrAddrs`）が同じ境界を使うべきか**。あちらは
  `buf.orderedFields()` から閉じ属性の位置を決めている。表示境界と出所を揃えるべきかを spec で判断する。
