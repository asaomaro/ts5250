## 自分で見つけて直したこと

1. **空文字を「未指定」として扱っていた** — `char` にとって空文字は全空白という正当な入力。
   単体テストが落ちて気づいた。`undefined` だけを「無い」とみなすようにした
2. **`count` が `init` を見ていなかった** — 記述が既定件数を持つのに拒否していた
3. **10 進の変換の失敗に項目名が付かなかった** — `数値として読めません: ""` だけでは、
   構造体の中でどの欄か探せない。**実ブラウザの検証で踏んだ**（19 件中 1 件が落ちた）
4. **並びを変える属性を黙って無視していた** — `minvrm` / `maxvrm` / `offset` / `offsetfrom` /
   `outputsize`。無視すると**読めたつもりで位置がずれる**。読めないと言う方が安全なので断るようにした。
   これはレビュー中に自分で気づいたもので、実機では踏んでいない

## 残した弱いところ

### 1. 画面がサーバーと同じ規則を持っている

`PcmlPane.vue` の `rowsOf` は、サーバーの `planField` と**同じ順序・同じ名前**を組み立てる。
ずれると「見えている名前」と「送られる名前」が食い違う。

**そうした理由**: 欄を並べるには件数と入れ子を先に知る必要があり、サーバーに聞くと
1 文字打つたびに往復することになる。**正しさの判断はサーバーに一本化**してある
（画面は組まない。送るのは名前と値だけ）ので、食い違えば**サーバーが断る**——
黙って違う値が入ることはない。

### 2. 実機 API の PCML はまだ通らない

`QGYOLOBJ` のような一覧 API の PCML は `offset` / `outputsize` を使う。
上の 4 で**断る**ようにしたので誤った呼び出しにはならないが、**呼べない**。
実務では効くところなので、次の作業で扱う。

### 3. サービスプログラムは呼べない

`entrypoint` を持つ記述は明示的に断る。呼び方が別物（`QZRUCLSP` 経由）で、
`buildServiceProgramParams` は既にあるので配線だけだが、**この作業では試験片を作っていない**。

### 4. `date` / `time` / `timestamp` / `varchar`

名指しで断る。`dateformat` などの書式属性が別の沼なので、別途測ってから。

### 5. `trim` / `chartype` / `bidistringtype` を見ていない

値の見た目にだけ効く（並びは変わらない）。`char` は空白を残したまま返す。
画面では末尾の空白がそのまま見えるので、**取り違えは起きない**が、jt400 と文字列が一致しない場合がある。

## 範囲の外で直したこと

`npm test` が **exit 1** で終わっていた（`main` でも同じ）。
`host-connection-stream.test.ts` の偽サーバーがソケットの `error` を拾わず、
未処理例外になっていた。**全件緑なのに 1 で終わる**ため、
この作業の検証結果を「通っている」と言えない状態だった。
`main` の作業ツリーを別に立てて**この作業が原因ではない**ことを確かめてから、1 行足した。
