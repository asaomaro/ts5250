## 途中で分かって足したこと

**`length` も名前でありうる。** `qcdrcmdd.pcml` の `length="bytesReturned"` で気づいた。
原典（`PcmlData.setLength`）を読むと `count` / `outputsize` と同じ「整数か要素名か」の作り。
**要件を書いた時点では見落としていた**——16 本を並べて属性を数えたときに `length` を数えていなかった。

指す先が**出力**なら呼ぶ前には決まらない。そこで:

> `qcdrcmdd.xml の長さは qcdrcmdd.bytesReturned で決まりますが、
>  bytesReturned は出力なので呼ぶ前には決まりません（この経路では扱えません）`

**「入れてください」と言わない**のがここでの肝で、入れようがないものを求められると
利用者は自分の入力を疑って時間を溶かす。

## 残した弱いところ

### 1. `offset` / `offsetfrom` はまだ通らない（16 本中 5 本）

`RUser` / `RJobLog` / `RMessageQueue` / `NetServer` / `RJavaProgram` / `quhrhlpt`。
出力の読み取りを「**先頭から順に解く**」へ作り替えれば通る。
出力を指す `count` / `length` も**同じ作り替え**で解けるので、まとめて次の作業にする。

いまは**断る**ので誤った呼び出しにはならない。

### 2. `outputsize` は入れ子で使われても top-level と同じに扱う

原典は入れ子の `outputsize` で「その要素以下を数えない」挙動をする。
IBM 同梱の 16 本では**すべて top-level の受取域**に付いており、入れ子の例が無い。
**実例が無いまま合わせにいかない**——踏んだら測って直す。

### 3. 版の判定はホストの版だけを見る

原典と同じ。PTF 単位の差は見ない（`minvrm` / `maxvrm` の粒度がそもそも版）。

### 4. 画面は予約域を「（予約）」と一括で呼ぶ

記述に名前が無いので、それ以上の呼び名を作れない。連続する予約域は複数行になる。
**隠さない**方を選んだ——隠すと「なぜ長さが合わないのか」が画面から分からなくなる。
