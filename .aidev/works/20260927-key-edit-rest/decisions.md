# 決定記録

## D1: 文字の割当 `char:` を新しい割当先にし、欄で修飾の無い打鍵として投げ直す
- ACS の既定は Alt と記号のキーに文字を割り当てる（`A512 = ¢` など）。当 PJ の割当先は AID・表示・マクロ・ローカル編集だけだった。打鍵の経路を通すので、型・挿入・DBCS・エラー中の拒否・欄外の 0005 は普通の文字と同じ。
- キー設定の画面で `char:` の割当を新しく作る口は無い（外す・初期化で戻すだけ）。作る口は必要になったら足す（nit・未対応）。

## D2: J 欄がホーム位置のとき、Home は SO の次へ移り Record Backspace を送らない
- 実測は空の J 欄だけ。全角の状態の E 欄・先頭が SO の O 欄は原典の読み（未確認）。IC で J 欄の SO の桁に置かれた直後の Home（ACS は `cursorSBA == homePos` で Record Backspace を送りうる）は当 PJ の列ビューに SO の桁が無いので区別できない（未確認）。
- Erase Input の着地（ACS も SO なら 1 つ進める）は、当 PJ の列ビューが SO の桁にキャレットを止めないので同じになる（変更なし）。

## D3: Test Request は施錠中は送らず、送ったら施錠して応答を待つ
- 独立点検の must: ACS の `keyDown` が施錠中に通すのは Attn・SysReq ほかだけで、Test（63694 → 61）は捨てる。`sendAid` は Test でも施錠する。~~施錠中も通す（Attn・SysReq と同じ非常口）~~ を破棄。
- AID の前の検査（ME・MF）からは外す（ACS `processAIDCode` の 61 の除外）。溜めた AID（`pending_aid`）にもしない。3270 には写す先が無いので、画面の側で送らない。

## D4: C17（Ctrl 単独で改行）は入れない
- プローブ（ECL）は Java のキー処理を通さないので測れない。Ctrl を押すたびに改行すると Ctrl の組み合わせのキーと衝突する（未確認のまま）。
