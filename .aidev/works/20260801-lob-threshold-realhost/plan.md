# 計画: LOB フィールドしきい値を使えるようにする

## subtask 分割の判定

**分割しない**。実装 3 ファイル・テスト 4 ファイル・スクリプト 1 本。

## 実装方針

**実機で測りながら進めた**。しきい値以下の LOB がどう届くかは仕様書に無く、
「作ってから測る」しかない。順序は

1. しきい値を**指定できるようにする**（実験の乗り物）
2. 実機で**何が起きるか測る**（型コード・並び・往復・バイト数）
3. 測った形に**復号を合わせる**
4. 全角で測り直す（**SBCS だけだと通ってしまう**）
5. 単体テストに**実機で採った形を固定**する

実際に 4 で `日本語` → `日` を踏んだ。3 の時点では緑に見えていた。

## 作業順序と依存関係

1. **T1** `lobFieldThreshold` オプション＋丸め（`clampLobThreshold`）
2. **T2** 再現スクリプトを書き、実機で型コードと並びを測る（依存: T1）
3. **T3** `SUPPORTED` に非ロケーター LOB を足す（依存: T2）
4. **T4** インライン LOB の復号（依存: T3）
5. **T5** 全角（DBCLOB）で測り直し、長さの単位を直す（依存: T4）
6. **T6** 単体テスト 2 本（並び・丸め）（依存: T5）
7. **T7** 既存テストの「LOB は対象外」を実態に合わせる（依存: T3）
8. **T8** `npm run build` / `npm run lint` / `npm test`（依存: 全部）

## リスク / 留意点

- **既定を動かさない**。上げると過去の実測（DBCLOB(2M) 2 行で 8.4MB）が再現する。
  `clampLobThreshold` は迷ったら 0 へ倒す
- **SBCS だけで確かめない**。文字数とバイト数が一致するので取り違えが見えない。
  DBCLOB は必ず全角で測る
- **既存テストが 2 件落ちる**のは想定内（「LOB 型は対象外」を固定していた）。
  これは**挙動を意図的に変えた**ので、テストを実態へ寄せるのが正しい。
  ただし**ロケーター型（960/964/968）は対象外のまま**であることは残す
- 実機の表（`TESTLIB.LOBTHR`）は作り直しが効く形にする（冪等）

## テスト方針

- **単体**: 実機で採った並びをバイト列で固定する（4 バイト接頭辞・DBCLOB は文字数・
  長さ 0 と NULL の区別・宣言幅超過は撥ねる）。丸めは境界値（0 / 負 / 非有限 / 上限 / 超過）
- **実機**: `scripts/research-lob-threshold.mjs` で、
  しきい値 0 と 65,536 の両方・CLOB / BLOB / DBCLOB・往復数とバイト数を採る
- **回帰**: 既定を変えていないので、**既存の LOB テストは無変更で通る**こと
  （落ちた 2 件は「対象外」の宣言なので実態へ更新）
