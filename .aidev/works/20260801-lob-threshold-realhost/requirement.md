# 要件: LOB フィールドしきい値を実機で確かめ、往復を消せるか決める

## 背景 / 課題

`20260801-lob-batch-retrieval-research`（PR #243）で、**LOB をまとめて取る要求形式は原典に
無い**ことが確定した。原典が往復を減らすのは別の手段——**LOB フィールドしきい値**（`0x3822`）で、
超えた LOB だけがロケーターになり、以下は**行データに載って返る**（追加の往復 0）。
JTOpen の既定は 32,768 バイト、上限は 15,728,640。

こちらは同じつまみを **0（＝常にロケーター）** にしている（`db-connection.ts:42`）。
実測で DBCLOB(2M) の表を 2 行取っただけで応答が 8.4MB（0 なら 10KB）になったため。

PR #243 は「実装は実機でしか確かめられない」として次の work に送り、backlog に
**実機で確かめること 3 点**を残した。実機が使えるようになったので確かめる。

## 目的 / ゴール

**しきい値を上げたときに何が起きるかを実測し、採るか採らないかを数値で決める。**

最大の未知は「**行データの復号が壊れないか**」。`db-decode.ts:110-120` は LOB 列を
**型コードで判定して 4 バイトのロケーターとして読む**。しきい値以下の LOB が
インラインで来たとき、
- 列の型コードは `CLOB_LOCATOR` のままなのか、別の型で来るのか
- 行バッファ内の並びはどうなるのか

が分からない。**ここを外すと以降の列が全部ずれる**（静かに壊れる種類の欠陥）。

## スコープ

### 対象

- 実機（IBM i 7.3）に LOB のフィックスチャ表を作る
  （`TESTLIB` に CLOB / BLOB / DBCLOB。既存の `build-*.mjs` と同じ流儀）
- しきい値を変えられるようにする（実験の乗り物。採用するなら本番の入口にもなる）
- しきい値 **0 と >0** で次を実測する:
  - 列メタデータ（型コード・長さ）が変わるか
  - 行バッファ内の並びと、`decodeValue` が読む 4 バイトが何になるか
  - **往復数**と**応答バイト数**（0 との比較）
- 結果に基づいて**採否を決め**、決定を記録する
- 再現できる調査スクリプトを `scripts/` に残す

### 対象外

- **画面 / MCP の既定の変更**（採ると決めた場合でも、既定を動かすかは別の判断）
- LOB の書き込み（`0x1817`）
- ロケーターの明示的な解放（`0x1819`。**別 work**）
- PUB400（7.5）での確認（資格情報が無い）

## 機能要件

- しきい値の設定は**接続時の属性**として渡す（原典と同じ位置。`setServerAttributes`）
- **既定は 0 のまま変えない**——上げるのは明示的に指定したときだけ。
  「既定を上げて静かにメモリを食う」ことが起きない形にする
- 上限は原典に合わせて **15,728,640** で頭打ちにする
  （公表の 16,777,216 は通らない。`AS400JDBCConnectionImpl` のコメント）
- 実測は**数値で**残す（往復数・バイト数・所要時間）。次に測る人が基準線を持てる

## 非機能要件 / 制約

- **実機に副作用を残しすぎない**。フィックスチャ表は `TESTLIB` に作り、
  作り直しが効く（冪等）ようにする
- 実資格情報を成果物・コミット・PR に書かない（`.env` のみ）
- 既定の挙動を変えないので、既存テストは**無変更で通る**こと

## 完了条件 (受け入れ基準)

- [ ] しきい値を接続時に指定できる（既定 0・上限 15,728,640 で頭打ち）
- [ ] しきい値 >0 のとき、**列の型コードと行バッファの中身が実測で記録されている**
- [ ] `decodeValue` の 4 バイト読みが成立するか**しないか**が、実測に基づいて判定されている
- [ ] しきい値 0 と >0 の**往復数・応答バイト数**が数値で比較されている
- [ ] 採否の判断と理由が `decisions.md` に残っている
- [ ] 再現用スクリプトが `scripts/` にあり、`scripts/README.md` に載っている
- [ ] `npm run build` / `npm run lint` / `npm test` が通り、**既存テストは無変更**
- [ ] backlog の該当項目が実態に合わせて更新されている

## 未確定事項 / 確認したいこと
