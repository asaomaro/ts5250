# 計画

| # | 段 | 中身 | 確かめ方 |
|---|---|---|---|
| 1 | 解析 | `offset` / `offsetfrom` を受け入れ、`ccsid` も名前で解く | IBM 同梱 **16 本すべて**が解析できること |
| 2 | 読み取り | `pcml-read.ts` を書く（逐次解析） | 単体（飛び先・件数・長さ・CCSID・境界） |
| 3 | 差し替え | `readPcmlOutputs` を委譲。入力の `offset` を断る | **既存の試験が 1 件も変わらずに通る** |
| 4 | 実機 | `RUser.pcml` の `USRI0300` | **SR-OSAKA。ホームディレクトリを SQL と突き合わせ** |
| 5 | 画面 | 出力で決まる件数の行の見せ方 | 単体 ＋ 実ブラウザ |

## 3 が肝

**`offset` を含まない記述の結果は 1 バイトも変わってはならない。**
既存の `pcml-layout.test.ts` / `pcml-ibm.test.ts` / `host-pcml.test.ts` /
`pcml-pane.test.ts` が**無変更で通る**ことをもって確かめる。
（通らなければ、逐次解析が静的な当てはめと食い違っているということ）

## 危ないところ

| 危険 | どうするか |
|---|---|
| 飛び先が外を指す | 例外。**黙って空を返さない** |
| 長さが外を指す | 同上 |
| 出力の CCSID が扱えない | **どの項目のどの CCSID か**を言って断る |
| 無限に進まない（`length="0"` の連続） | 飛ばない場合は 0 バイト消費で次へ。件数は記述由来なので有限 |
| 既存の結果が変わる | 3 の通り、既存試験を無変更で通す |
