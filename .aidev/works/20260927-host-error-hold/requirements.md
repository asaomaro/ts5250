# 要件: ホストのエラーのメッセージを出している間、ホストの WTD を保留する（ACS `checkContention`）

## 背景 / 課題
`.aidev/backlog/acs-parity.md` の「エラー（と SysReq）のメッセージを出している間、ホストの WTD を保留する」（`20260927-error-msgline-wtd` から割った）。
ACS はエラーのメッセージの間 WTD を止めて待ち、抜けてから処理する。当 PJ は受けた時点で処理し、メッセージ行への書き込みでエラーのメッセージとエラー状態を Reset を待たずに終える。

## 目的 / ゴール
エラーのメッセージの間は画面がホストの WTD で変わらず、エラー状態を抜けた（Reset・カーソルキー・AID・クリック・CLEAR UNIT・SAVE）ところで止めた出力が流れる——ACS と同じ見え方の状態。

## ユーザーストーリー
- US1: 5250 端末の利用者として、エラーのメッセージを読んでいる間に画面が勝手に変わらず、Reset してから次の画面になってほしい。なぜなら ACS と同じ操作の流れで使えるから。（受け入れ: AC1, AC2, AC3）

## スコープ
### 対象
- core: WTD の保留と、抜けたときの処理（`dismissHostError`）。AID を送るときは抜けてから
- server: 画面の側が抜けたことを受ける（`dismiss-host-error`）
- web-ui: エラー状態を抜けたら知らせる
### 対象外
- SysReq の行を出している間の保留（ACS は同じ仕組みで止める。当 PJ の SysReq の行は画面の側だけ——backlog に残す）
- 0x22 の WTD の部分（当 PJ の 0x22 は WTD を通らない）

## 機能要件
- エラーのメッセージ（`systemMessage`）がある間、WTD コマンドから後ろを処理せず溜め、後ろのレコードも溜める。
- 抜けたら（画面の側の通知・AID の送信）メッセージを外し、溜めたものを順に処理する。番号の違うエラーでは抜けない。
- CLEAR UNIT・SAVE はエラー状態を解くので、その後の WTD は止めない（今の core の規則のまま）。

## 非機能要件 / 制約
- 画面の無い呼び出し（MCP）でも止まったままにしない（AID で抜ける）。

## 完了条件 (受け入れ基準)
- [ ] AC1: core の単体テストで、エラーの間の WTD・後ろのレコードが溜まり、抜けると順に流れることを固定する（同じレコードの WEC の後ろの WTD・番号違い・AID・CLEAR UNIT も）
- [ ] AC2: web-ui の単体テストで、ホストのエラーを抜けると `dismiss-host-error`（番号つき）を送ることを固定する
- [ ] AC3: 実機（DSM の ERRMSGWTD / ERRMSGRST）で、エラーの間は画面が変わらず、抜けた後の 24 行目が ACS の Reset の後と同じ
