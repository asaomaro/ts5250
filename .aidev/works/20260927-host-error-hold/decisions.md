# 決定記録

## D1: エラー状態は画面の側に置いたまま、core に「止める・流す」を足し、抜けたことを画面から知らせる

- 背景: research F2。エラー状態の置き場を core へ移すと、操作員エラー（画面の側）と分かれて二重になる。
- 決定: core は `systemMessage` がある間 WTD から後ろを溜め、`dismissHostError(seq)` で流す。画面の側は `exitErrorMode` で `dismiss-host-error` を送る。AID は core でも抜ける（MCP・古いクライアント）。
- 退けた案: エラー状態を丸ごと core へ移す——画面の側の規則（どのキーで抜けるか。`20260921-host-error-mode`）を core に写すことになり、操作員エラーと二重になる。

## D2: 自動操作の予約中は画面の側の知らせを受けない

- 予約（MCP が操作中）の間に見ている人が抜けると、自動操作の前提の画面が変わる。予約中は AID（予約の持ち主）で抜ける。

## D3: 工程の順
- 実装と実機の確認を先に行い、工程の文書は後から起こした（`20260927-error-msgline-wtd` の実測で振る舞いが確定していたため）。

## D4: 保留が始まったら AID の待ちはエラーの画面で解く

- 背景: 独立点検。同じレコードの READ まで溜まると `pendingAid` が時間切れまで解けず、画面の側は busy・MCP は 30 秒待つ。
- 決定: ホストはエラーで応えたので、その画面を AID の結果として返す。ACS で AID がいつ応答扱いになるかは未確認。

## D5: 画面の側の知らせが落ちても止まらないように、送り直す・キーでも抜ける

- 知らせ（`dismiss-host-error`）が張り直し中・予約中で落ちると、画面の側だけ隠れて止まる。画面が届くたびに「隠したエラーが残っていれば送り直す」。
  core は全てのキー（Attn・SysReq を含む）と、欄を書く前（ws・MCP）・HLLAPI の編集キー以外でも抜ける。

## D6: 保留が始まったら施錠を解く（ACS `initKeyboard`）——画面の側の並べ替えは取り消す

- 背景: review ラウンド 1 の must。~~画面の側でエラー状態の振り分けを先打ちより前に置く（施錠中でも抜けられるように）~~ は ACS と逆（ACS は施錠中は Reset 等だけを通す）。
- 事実（原典）: `DS5250.processWriteErrorCode` → `initKeyboard` はエラー状態なら施錠を解き、do-not-enter の表示だけ出す。
- 決定: core は保留が始まったらセッションを ready にする（次の AID は `sendAid` が抜けて止めた READ が流れてから送る）。画面の側は元の順（先打ち → エラー状態）に戻す。
- 残り（backlog）: 保留の無い WEC だけのレコード（READ 無し）でも ACS は施錠を解く——当 PJ は READ が来るまで施錠のまま（既存の差）。
