# 要件: 符号付き＋RZ の欄の埋め字を ACS と同じにする

## 背景 / 課題
- 台帳「キー編集の細部」の「符号付き＋RZ の埋め字」。DDS の `6 0 CHECK(RZ)` はワイヤ上で符号付き数値＋RZ（FFW=0x4705）。実機の ACS のコアは、これに `12` と打って Field− すると `000012-`
  （`'0'` 埋め）、素の `6 0` は `    34-`（空白埋め）だった（`scripts/acs-probe/field-minus-numeric-only.txt` の M1・M2。2026-09-21・社内機）。当 PJ は RZ でも `    12-`。
  原因は、tn5250 由来の「signed-num を ADJUST 指定より先に見て無条件で空白右寄せ」（R11 の調査で見つかった）。ACS `PS5250.performRightAdjustFill` は、符号付き数値なら埋め字を空白にしたうえで、
  RB なら空白・RZ なら `'0'` に**上書き**する。

## 目的 / ゴール
- 符号付き＋RZ の欄で Field Exit・Field±（Field−）をしたとき、ACS と同じ `'0'` 埋め（符号桁は動かさない）になっている状態。

## ユーザーストーリー
- US1: ACS から移る利用者として、CHECK(RZ) の数値欄で Field Exit・Field− をしたら、ACS と同じ 0 埋めで見えて送られてほしい。なぜなら、画面の見え方と送る数字桁のバイトが変わるから。（受け入れ: AC1〜AC3）

## スコープ
### 対象
- `fieldEdit.applyAdjust`（符号付き数値の埋め字）。
### 対象外
- 空きの数え方（NUL か空白か）・先頭の空白の扱い・DBCS 欄の右寄せ（未測定。台帳に残す）。

## 完了条件 (受け入れ基準)
- [ ] AC1: 符号付き＋RZ は `'0'` 埋め、符号付き＋RB は空白埋め。符号桁は動かさない（Field Exit・Field−・Field+）。
- [ ] AC2: 符号付きで調整の指定が無い（無指定・MF だけ）ときは、従来どおり空白右寄せ（符号桁は動かさない）。
- [ ] AC3: 順序・埋め字・符号桁の各分岐を外すとテストが落ちる（`verify-by-mutation`）。旧い決定（signed-num を優先）を破棄した証拠を残す。
