# 要件: 「保管場所」という見出しをやめる

## 背景 / 課題

利用者の問い——「システム設定の**保管場所**という表現は適切ですか？」

適切ではなかった。理由は 2 つ。

**1. 同じものを画面内で 2 通りに呼んでいた。**
ⓘ の詳細は同じ設定を**「区分」**と呼び（`ConfigCard.vue:592, 607`）、カードのチップは
**「サーバー設定」**と出す。編集フォームだけが「保管場所」だった。
作った側は同じと分かるが、使う側には**別の設定に見える**。

**2. 「保管場所」は実装の言葉。**
実際に決まるのは「どのファイルに書かれるか」だが、利用者に意味があるのは
**誰が見えるか**と**サービスにできるか**のほう。一番どうでもいい層を名前にしていた。
しかもセッション側では選べない（親に従う）ので、「場所を選ぶ設定」という印象自体がずれる。

**3. チェックにしたので見出しが余っていた。**
`保管場所` ＋ `サーバー設定にする` は、**見出しが選択肢を言い直しているだけ**だった。

利用者の答え——「**項目名がサーバー設定でよいのでは？**」

## 目的 / ゴール

**見出しをその設定の名前そのものにする。** 画面全体で 1 つの呼び方に揃える。

## 完了条件 (受け入れ基準)

- [ ] 見出しが `サーバー設定`（カードのチップ・ⓘ と同じ語）
- [ ] チェックの隣に言い直しが無い
- [ ] テスト・lint・ビルドが通る
