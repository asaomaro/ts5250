# 要件: host_call_program を正しいパラメータ列で成功させる

## 背景 / 課題

backlog `hostserver.md`:

> `host_call_program` を正しいパラメータ列で成功させる検証
> - 実機確認は `MCH0802`（パラメータ数不一致）までで、**呼び出し経路が通ることしか
>   確かめていない**（`20260719-hostserver-mcp-tools/test-result.md:49`。
>   `QGYOLSPL` にパラメータ 0 個で呼んだ）

MCP ツールの説明は「**出力パラメータは要求した順で返る前提**で位置合わせしている」と
書いているが、**成功例が一度も無い**ので、その前提も確かめられていない。

## 目的 / ゴール

**「呼べた」ではなく「正しく返った」を言える状態にする。**

## スコープ

### 対象

- 実機で読み取り専用の API を**正しいパラメータ列**で呼び、**返った中身を検証する**
- **出力の位置合わせ**（要求順・出力でない位置は null）の確認
- 再現スクリプト

### 対象外

- **書き込み系の API**（副作用が出る）
- MCP 経由での実行（ツール登録は同じ `conn.call` を呼ぶだけ。
  ライブラリ層で確かめれば足りる）
- `host_call_program` の入力スキーマ変更

## 機能要件

- 呼ぶ API は**読み取り専用**で、**返った値を外部の事実と突き合わせられる**こと
  （「エラーが出ない」だけでは、間違った位置を読んでいても気づけない）
- **書式の違う API を 2 つ以上**呼ぶ（1 つだと偶然合っている可能性を排除できない）

## 非機能要件 / 制約

- 実機に副作用を残さない
- 実資格情報を成果物・コミット・PR に書かない

## 完了条件 (受け入れ基準)

- [ ] 実機で API が `MCH0802` 等のメッセージ無しに成功する
- [ ] **返った中身が期待どおり**であることを検証している（名前・種別など）
- [ ] 出力パラメータが**要求順**に返り、**出力でない位置は null** であることを確認
- [ ] 書式の違う API を 2 つ以上通している
- [ ] 再現スクリプトがあり `scripts/README.md` に載っている
- [ ] `npm run build` / `npm run lint` / `npm test` が通る
- [ ] backlog が更新されている
