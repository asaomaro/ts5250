## 設計方針

### D1: 単体テストは足さない

出力の位置合わせ（`extractOutputs`）は内部関数で、テストするには
**応答バイト列を自分で組み立てる**ことになる。それは
**自分の理解を固定するだけ**で、ホストが本当にその形で返すことの証拠にならない
——通って当然のテストになる。

**証拠は実機**であり、それは `scripts/research-call-program.mjs` として
コミットされ、いつでも回せる。ここに偽の応答で作った緑を足さない。

### D2: 呼ぶ API は「返り値を外部の事実と突き合わせられる」ものにする

「エラーが出ない」だけの確認では、**間違った位置を読んでいても気づけない**。
`QUSROBJD` は呼んだ対象（`QSYS/QCMD *PGM`）そのものを返すので、
オフセットを間違えれば一致しない。

### D3: 書式の違う API を 2 つ通す

1 つだと偶然オフセットが合っている可能性を排除できない。`OBJD0100` と `USRI0100`。
