# 計画: host_call_program の実機検証

## subtask 分割の判定

**分割しない**。スクリプト 1 本と記録。

## 実装方針

**返り値を検証できる API を選ぶところが要**。副作用が無く、
呼んだ対象そのものを返すものにする。

## 作業順序と依存関係

1. **T1** 読み取り専用で返り値を検証できる API を選ぶ（`QUSROBJD` / `QSYRUSRI`）
2. **T2** 正しいパラメータ列で呼ぶスクリプトを書き、実機で通す（依存: T1）
3. **T3** 出力の位置合わせ（要求順・入力位置は null）を確かめる（依存: T2）
4. **T4** `npm run build` / `npm run lint` / `npm test`（依存: T2）

## リスク / 留意点

- **「エラーが出ない」で満足しない**。中身を突き合わせる
- **1 つの API で済ませない**。偶然オフセットが合っている可能性がある
- **書き込み系を呼ばない**（副作用）
- エラーコード構造の先頭 4 バイトは **0**（例外で知らせる）。ここを非 0 にすると
  エラーが構造体に入って**メッセージが出なくなり**、失敗を見逃す

## テスト方針

**実機のみ**。単体テストは足さない（spec D1——偽の応答で作った緑は証拠にならない）。
既存テストが無変更で通ることは確認する（`packages/` を触らないので当然だが、確かめる）。
