# 決定記録

## D1: RNL（0x06）・RFF（0x3A）は ACS と同じく何もしない（tn5250 の「改行・改ページ」を破棄）

- ACS `PrintSCS5250` は RequiredNewLine / RequiredFormFeed を `processUnsupportedControl`（警告だけ）にしている。当 PJ は tn5250 どおり
  改行・改ページにしていた。実採取の帳票（PUB400 の 2 件・日本語機の DSPLIBL）にはどちらも現れない。ACS が改行しない制御を
  ホストが帳票に使っていれば ACS の利用者が気づくはずなので、ACS に合わせる。

## D2: 透過（TRN）の本体の 0x40 未満は空白にする

- ACS は TPO（既定）ならプリンターへ生で流し、そうでなければ 0x40 未満を 0x40 にして印字する。等幅の帳票に生の制御は置けないので、
  後者に合わせた。

## D3: 0xFF は従来どおり読み飛ばす（未確認）

- ACS は 0x40〜0xFF を印字文字の範囲に入れる。当 PJ は tn5250 どおり読み飛ばしている。ACS で 0xFF が何に変換されて印字されるかは
  PDT とコードページ次第で確かめていないので、変えずに残す。

## D4: 既定の経路（JPS）に合わせ直す（D2 を破棄。D1 は JPS でも同じ）

- 背景: 最初の版は PDT 経路に合わせていたが、利用者の ACS（Windows）が HPT を外したときに使うのは JPS 経路だった（research F5・F6）。
- 決定: JPS の表と働きに合わせ直した——BS・GE・VCS は何もしない、HT は 1 桁、TRN の本体は `-`、SGEA・EPMP・下線と重ね打ちは長さで読む。
  ~~D2（TRN の本体の 0x40 未満は空白にして文字として置く）~~ は PDT の TPO でない経路の近似だったので破棄。D1（RNL・RFF は何もしない）は JPS でも同じ。
- 影響: PDT 経路（Linux の ACS の既定・`usePDT` を入れた設定）とは違う（BS・GE・VCS・SGEA・SA の DBCS 切り替え）。どちらかにしか合わせられない。
