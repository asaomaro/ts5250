# 要件: SCS の制御の読み方を ACS と同じにする

## 背景 / 課題
- 帳票（プリンターセッション・スプールの取得）の SCS を tn5250 の制御セットで読んでおり、ACS と違う:
  表に無い 0x40 未満の制御（LF 0x25・IRS 0x1E・BS 0x16・TRN 0x35 など）を**印字文字として桁に置く**（日本語機の帳票の先頭に「�」）、
  0x03 を EBCDIC の透過として読む（ACS では ASCII 透過）、長さの前置を持つ 2B のオーダーを固定長で読み（2B D1 06 で同期がずれる）、
  知らない 2B オーダーで**帳票の残りを打ち切る**。
- 台帳「【まとめ】SCS の解釈の差」の「1 バイトの制御」「0x2B オーダーの消費長」。

## 目的 / ゴール
- 帳票の制御を ACS と同じ表で読み、制御が文字として桁に出たり、帳票の途中で切れたりしない状態。

## ユーザーストーリー
- US1: 帳票を読む利用者として、余計な記号や欠けの無い帳票を見たい。なぜなら、今は制御が「�」などで桁に出て、知らないオーダーの後ろが消えるから。（受け入れ: AC1, AC2）

## スコープ
### 対象
- 1 バイトの制御の表（ACS `PrintSCS5250` の `scs_proc`）と 2B のオーダーの消費長。
### 対象外
- SO/SI の桁（台帳で要実測）・水平タブ位置（SHF）・垂直タブ位置（SVF）・重ね打ち・0xFF（tn5250 由来で読み飛ばす。ACS は印字文字の範囲。未確認）。

## 完了条件 (受け入れ基準)
- [ ] AC1: 1 バイトの制御が ACS の表どおり——Null・CR・LF・NL/IRS・FF・VT・BS・HT・PP・SA・VCS・GE・TRN・ATRN・2B は ACS と同じバイト数を読み、
  RNL・RFF ほか ACS が何もしない制御と表に無い 0x40 未満は印字しない。
- [ ] AC2: 2B のオーダーは表にあるクラスを長さ＋2 バイト（SGEA は 5）で読み、表に無いクラスは 0x2B だけを読み飛ばして続きを読む。
- [ ] AC3: 実採取の帳票（PUB400 の SBCS・DBCS）の復号が変わらない。各判定を外すとテストが落ちる（`verify-by-mutation`）。
