# 要件: HLLAPI の 3270 のセッションの Tab・Backtab を ACS の 3270 の規則にする

## 背景 / 課題
`.aidev/backlog/acs-parity.md`「節目の懸念の残り」: HLLAPI の `@T` / `@B` は 3270 のセッションにも 5250 の規則（`tabPosition` / `backtabPosition`）を当てている。ACS の 3270 のコア（`PS3270.processTabKey` / `processBacktabKey`）の規則は読み切れていなかった。

## 目的 / ゴール
3270 のセッションで HLLAPI の Tab・Backtab が ACS の 3270 のコアと同じ位置へ動く状態。

## ユーザーストーリー
- US1: HLLAPI で 3270 のセッションを操作する自動化の作者として、Tab・Backtab が ACS と同じ所へ動いてほしい。なぜなら行き先が違うと、後ろに続く字が別の欄に入るから。（受け入れ: AC1, AC2, AC3）

## スコープ
### 対象
- 3270（ホーム位置を持たないスナップショット）の `@T`・`@B`
### 対象外
- 3270 の Home・New Line・Backtab の「保護されていない欄が無い」場合（ACS の上位クラスの `getPreviousUnprotectedFieldPos` を読んでいない。未確認として残す）

## 完了条件 (受け入れ基準)
- [ ] AC1: 書式なし（欄が 1 つも無い）画面の Tab・Backtab は 1 行 1 桁へ（原典・単体）
- [ ] AC2: Tab は長さ 0 の保護されていない欄を飛ばす。保護されていない欄が無ければ今いる欄の先頭、保護されていない欄がどれも長さ 0 なら 1 行 1 桁。Backtab も長さ 0 の欄を飛ばす（原典・単体）
- [ ] AC3: 通常の画面（保護されていない欄がある）では従来と同じ行き先で、ACS の 3270 のコアとも一致する（実機・単体）
