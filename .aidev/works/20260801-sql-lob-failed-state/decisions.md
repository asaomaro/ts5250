# 自律実行中の判断記録

autonomous モードで人間ゲートを通さずに決めたことを残す（protocol「10.」逸脱記録）。

## D1: research 工程は挟まない（requirement 終了時）

**判断**: 任意工程 research をスキップし、requirement → spec へ直行する。

**理由**: protocol「4.5」の検知条件を照らすと、

- 「未確定事項」に残る 3 件（失敗理由の文字列を見せるか / CSV の文言 / サーバー・MCP 経路への漏れ）は
  いずれも**このリポジトリのコードを読めば決まる**もので、外部調査・実機・原典照合を要しない。
  spec の中で解消できる粒度。
- requirement が依拠する既存挙動（`query.ts:455-460` の catch 分岐、`db-decode.ts:39` の型、
  `SqlResultTable.vue:76-90` の表示分岐、`csv.ts:11-24`）は、requirement を書く前に
  **主エージェントが直読して確認済み**。未検証の仮定に立っていない。
- 実現性の仮定なし（optional な文字列 union に値を 1 つ足すだけ）。
- 横断はするが（hostserver / web-ui）、いずれも既に特定済みの数行。影響範囲は不明ではない。

**リスク**: 3 件の未確定を spec で拾い損ねると、表示だけ直してサーバー／MCP 経路が
`not-requested` のまま残る。spec の冒頭で該当経路を grep して棚卸しすることで塞ぐ。

**結果**: spec で 3 件とも解消した（D2 / D5 / 「対象範囲」の変更しない箇所）。
サーバー・MCP はどちらも行をそのまま JSON にしていたので、追加変更は不要と分かった。

## D2: design 工程は挟まない（spec 終了時）

**判断**: 任意工程 design をスキップし、spec → plan へ直行する。

**理由**: protocol「4.5」の検知条件のいずれにも実質当たらない。

- **複数コンポーネントにまたがる**——形式的には当たる（hostserver / web-ui）が、
  変更は**両側とも既に行番号まで特定済みの数行**で、間に新しい協調は生まれない
  （データは既存の JSON 経路をそのまま流れる）。
- **アーキ判断が必要**——不要。union に値を 1 つ足すだけで、新しい層・新しい境界を作らない。
- **インターフェース / データモデルが複雑**——`unavailable` の 1 フィールドのみ。
  むしろ「フラグを増やさず union に足す」（spec D1）ことで状態の組み合わせ爆発を避けている。
- **plan で分解するには粗い**——spec の「対象範囲」表が既にファイル単位まで割れており、
  そのままタスクにできる。

## D3: ログを `debug` から `warn` へ上げる（spec D2 の一部・スコープの拡張）

**判断**: requirement には「ログの情報量は減らさない」としか書いていないが、
`query.ts:458` の `log.debug` を `log.warn` に**上げる**ところまでやる。

**理由**: requirement が挙げた課題は「失敗したという事実がどこにも出ない」であり、
`unavailable: "failed"` を足しても**理由**はログにしか無い。その理由が `debug` のままだと
既定の sink 設定で消えるので、課題は半分しか解けない。
画面のツールチップで「サーバーのログに理由が出ます」と案内する以上、**出ていないと嘘になる**。

**スコープへの影響**: 1 行。`CoreLogger` は `warn` を持つ（`packages/base/src/log.ts:28`）ので
新しい依存も入らない。失敗理由の文字列を JSON に載せる案（`failureReason`）は
**採らなかった**——ホスト由来のデバッグ文字列を画面へ通す経路の新設は、必要になってから。

## D4: `npm run lint` は通らないが、原因は本 work の外（coding 工程）

**事実**: `npm run lint` はエラー 6 件で落ちる。すべて **未追跡の `scripts/*.mjs`**
（`build-empsfl.mjs` / `shot-buttons.mjs` / `shot-crt.mjs` / `shot-empsfl.mjs` /
`shot-fkey.mjs` / `shot-font.mjs`）の `no-unused-vars` で、
**本 work の着手前から作業ツリーにあった**（セッション開始時の git status に未追跡として並んでいる）。

**判断**: これらは**直さない**し、コミットもしない。本 work の変更ではなく、
別の実機調査で置かれた作業中のファイルと見られる。他人の未追跡ファイルを勝手に書き換えない。

**代わりに確認したこと**: 変更した 7 ファイルを名指しで `npx eslint` に掛け、**エラー 0**
（`packages/web-ui/test/*` は eslint の ignore 対象という警告のみ）。
コミット対象の木は lint 清潔なので、CI では通る見込み。

**申し送り**: この未追跡スクリプト群の扱い（コミットするか捨てるか）は本 work の外の課題。
