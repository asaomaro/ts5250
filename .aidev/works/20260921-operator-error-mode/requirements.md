# 要件: 操作員エラーでキーボードを施錠し、Reset キーで解く

## 背景 / 課題
型違反・符号桁・満杯の挿入などの操作員エラーで、当 PJ は**メッセージを出すだけ**で、
**次の打鍵でメッセージが消えて入力が続けられた**。ACS はエラー状態（`error_mode`・`inhibit=5`）に入り、
**欄を書き換えるキーを受け付けない**。打ち続けると、エラーに気づかないまま後続の文字だけが入る。
**Reset キーも無かった**。

利用者の判断（2026-09-21・`.aidev/backlog/acs-parity.md`「方針決定」）: **施錠する＋Reset キーを作る**。

## 目的 / ゴール
- 操作員エラーが出たら、**利用者が抜ける操作をするまで欄が書き換わらない状態**（ACS と同じ規則）。

## ユーザーストーリー
- US1: 端末の利用者として、エラーに**気づかずに打ち続けても欄が壊れない**ようにしたい。
  なぜなら ACS ではそうなっており、当 PJ ではエラー直後の打鍵がそのまま入るから。（受け入れ: AC1, AC2）
- US2: 端末の利用者として、ACS と同じ**左 Ctrl の Reset**でエラーを解きたい。
  なぜなら手に馴染んだ操作だから。（受け入れ: AC3）

## スコープ
### 対象
- web-ui の操作員エラー状態（入る・拒否する・抜ける）と Reset キー（左 Ctrl 単独）。
### 対象外
- 先打ち（施錠中・応答待ち中の打鍵を溜める）——別項目（③）。Reset が先打ちを捨てる働きはそちらで足す。
- ヘルプ（エラー中の Help でエラーコードの説明を出す）。

## 機能要件
- FR1: 操作員エラーの通知（`isOperatorError`）でエラー状態に入る。情報の通知では入らない。
- FR2: エラー中、欄を書き換えるキー（文字・Backspace・Delete）は拒否し、メッセージを残す。
- FR3: カーソル移動キー・AID・Reset・クリックで抜ける。移動キーはその働きもする。
- FR4: ~~抜けると挿入モードも解く。~~ **エラーに入った時点で挿入モードを解く。Reset はエラーでなくても解く**（D3）。
- FR5: Reset は左 Ctrl を**単独で**押して離したとき。他のキーを挟んだら Reset にしない。

## 非機能要件 / 制約
- 規則は実機で測った ACS に合わせる（`research.md` F3〜F5）。未測定のキーは推測で拒否しない。
- 利用者に見える文言は増やさない（既存の操作員メッセージを使う）。

## 完了条件 (受け入れ基準)
- [ ] AC1: エラー中、文字・Backspace・Delete が欄を書き換えず、メッセージが残る。
- [ ] AC2: 矢印・Tab・Home・AID・クリックで抜け、その後は入力できる。エラーに入った時点で挿入モードが解ける。情報の通知では施錠も挿入解除もしない。
- [ ] AC3: 左 Ctrl 単独の押下→解放で抜ける。エラーでなくても挿入モードを解く。他のキーを挟んだとき・右 Ctrl では働かない。
- [ ] AC4: 拒否・挿入解除・Reset の取り消し・クリックの各判定を外すとテストが落ちる（`verify-by-mutation`）。
