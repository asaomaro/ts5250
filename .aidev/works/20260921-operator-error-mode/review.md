# レビュー

## ラウンド 1（通過）

バッチ処理の 1 件。**指摘なし**。独立点検は利用者の指示どおり節目（①〜③の後）でまとめて行う。
- 通知の直接代入（`notice.value = …`）が `showNotice` / `clearNotice` 以外に残っていないことを確かめた
  （残るとその経路だけ施錠されない）。
- 拒否するキーは実機で拒否を確かめた 3 種に限った（D2）。

## ラウンド 2（通過）

D3（挿入モードが解ける時点の訂正）に伴う実装変更の再点検。**指摘なし**。
- `exitErrorMode` から挿入モードの解除を外し、`showNotice`（入る時点）と `resetKey`（常に）へ移した。
  情報の通知では解かないこと・Reset がエラー外でも効くことをテストと mutation（M5〜M7）で確かめた。
- `ECLPS.reset` の「施錠中なら先打ちを捨てて解錠」は先打ち（③）の範囲として残した（台帳に明記）。
