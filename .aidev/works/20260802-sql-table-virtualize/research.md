# 調査: SQL 結果表の初回描画コスト（実ブラウザ Chromium ＋ 実機）

再現: `scripts/research-sql-table-render.mjs`
（40 列の `SELECT` を `QSYS2.SYSCOLUMNS` から取る。**表を作らないので後片付けが要らない**）

計測は「**SQL の応答本文を読み終えた時刻 → tbody に行が出揃いレイアウトが確定した時刻**」。

## F1: backlog の数字は正しい。1000 行は実用に耐えない

| 行数 | セル数 | 描画 |
|---:|---:|---:|
| 50 | 2,000 | **52 ms** |
| 200 | 8,000 | **123 ms** |
| 1000 | 40,000 | **582 ms** |

backlog の「200 行 × 40 列で 100ms 前後」は**追認**。
`pageSize` は画面から 1000 を選べるので、**0.6 秒の固まり**は利用者が普通に踏む。

## F2: コストは**セル数に比例**する（レイアウトではない）

行数を固定して列だけ減らすと:

| | セル数 | 描画 | 1 セルあたり |
|---|---:|---:|---:|
| 1000 行 × 8 列 | 8,000 | 117 ms | **14.6 µs** |
| 1000 行 × 40 列 | 40,000 | 547 ms | **13.7 µs** |

**1 セルあたりがほぼ一定。** つまり支配しているのは行数でも表のレイアウトでもなく、
**セルを 1 つ作る仕事**（Vue の vnode 生成と DOM 挿入）。

### ここから決まること

- **`table-layout: fixed` にするだけでは速くならない。** レイアウトが律速ではない。
- **効くのは「セルを作らない」ことだけ**＝仮想化。
  ビューポート 900px・行高 ~24px なら見えるのは ~38 行。前後の余白を入れて ~60 行なら
  **2,400 セル ≒ 35ms** に落ちる見込み（総行数によらず一定）。

`SqlResultTable.vue` の既存コメント（「DOM を挿し直すだけなら 65ms なので、
大半は vnode の作り直し」）とも整合する。

## F3: いまは列幅がスクロールで動かない——**それは全行を描いているから**

```
DOM 行数: 先頭 1000 / 下 1000
列幅: 同じ    先頭 5 列: 48 / 96 / 128 / 160 / 192 → 48 / 96 / 128 / 160 / 192
```

`table-layout: auto` は**描いている行すべて**から幅を決めるので、全行が DOM にある今は安定する。
**行を間引いた瞬間にこの性質が失われる**——だから仮想化は幅の決め方とセットでしか解けない
（backlog / `20260723-sql-multi-statement` D1 の指摘は正しい）。

## F4: セルは**等幅・折り返しなし**（幅は文字数で決まる）

`SqlResultTable.vue` の CSS:

```css
td { font-family: var(--mono); white-space: pre; }
th { font-family: var(--mono); font-size: 12px; }  /* td は 13px */
```

ここから 2 つ効く:

1. **行の高さが揃う**（1 行・折り返しなし・固定フォントサイズ）。
   仮想化の位置計算が「行高 × 本数」で済む——可変高の面倒が要らない。
2. **列幅は文字数に比例する**。等幅なので、`max(表示幅)` を数えれば
   幅を**測らずに計算できる**（全角は 2 幅。`isFullWidth`＝`@as400web/base` が既にある）。

⚠ **`th` と `td` はフォントサイズが違う**（12px / 13px）ので、`ch` 単位は使えない
（`ch` は要素自身のフォント基準で、列見出しのほうが狭くなる）。
**1 文字ぶんの px を td から 1 回だけ実測**して換算する。

## F5: 現在の CSS に `max-width` は無い

`useColumnWidths.ts` のコメントは「既定は CSS 側（`th, td { max-width: … }`）が担う」と
書いているが、**`SqlResultTable.vue` には `max-width` が無い**（`TransferPane.vue` には
`max-width: 40ch` がある）。**コメントが実態とずれている**——共有部品なので、
片方の CSS を前提に書かれた説明が残っていた。

いまは中身の長さがそのまま列幅になる（実測 48〜192px＝ `CHAR(6)`〜`CHAR(30)` 相当）。
**幅を計算で決めるなら上限が要る**（1 セルに 32KB の CLOB が来ると表が壊れる）。

## 設計へ送る論点

1. **幅は全行の文字数から計算する**（`auto` の結果に近く、間引いても動かない）。
   標本（先頭 N 行）で決めると、後ろの長い値で列が足りなくなる——今の見え方が変わる。
2. **上限を入れる**（F5）。今は事実上無制限なので、入れると**狭くなる列が出る**。
   手動リサイズとダブルクリック復帰で救う。
3. **`table-layout: fixed` へ移す**（幅を宣言する以上、`auto` に再計算させない）。
4. 行高は**実測 1 回**（jsdom では測れないので既定値へ落とす）。
