# レビュー記録: 02-bridge

## ラウンド 1（2026-08-03）

差分: `crates/hllapi`（`lib.rs` / `json.rs` / `http.rs` / `b64.rs` / `selftest.rs`）、
`hllapi-cp932.ts`、`hllapi-ps.ts` の作り直し、`hllapi.ts` / `hllapi-types.ts` / `hllapi-routes.ts` の
バイト化、検証スクリプト、`docs/HLLAPI.md`、README。

### 指摘

- **[must]** **`Search PS` で日本語が引けなかった**（`01-server` から持ち越していた設計の誤り）。
  PS を「1 セル 1 文字」の文字列として連結していたため、全角の追従セル（`dbcs-tail`。`char` は空文字）が
  空白になり、**`サイン・オン` が `サ イ ン ・ オ ン`** になっていた。実機の出力で気づいた。
  **対応: PS をバイト配列（CP932）で扱う形に作り直した。** HLLAPI の「1 位置 = 1 バイト」と一致し、
  日本語の検索・切り出し・桁計算がすべて自然に通る。実機で `rc=34`（34 桁目）を確認。

- **[must]** **`tests/no_logic.rs` が一度も走っていなかった。**
  この環境では `cargo test` がテスト実行ファイルをリンクできない（`crt1.o` が無い）。
  **走らない検査は無いのと同じ**で、しかもこれは「薄さ」という最も守られるべき不変条件を見るもの。
  **対応: `packages/server/test/hllapi-bridge-thinness.test.ts` へ移した。**
  `npm test` に含まれ、Rust ツールチェーンも要らない（ソースを読むだけ）。7 件とも通過。

- **[should]** 検証スクリプトが**間違った理由で通っていた**。`Search PS` の判定が `rc > 0` だけで、
  **`rc=7`（見つからない）でも成功扱い**だった。加えて検索文字列のバッファを大きく取りすぎ、
  **NUL 埋めが検索語に混ざって**実際には見つかっていなかった。
  **対応: `rc !== 7` も要求し、バッファ長を CP932 の実バイト長にした。**

- **[nit]** `selftest` フィーチャは**出荷する共有ライブラリに入らない**（既定では無効）。
  検査を走らせるときだけ `--features selftest` を付ける。`docs/HLLAPI.md` に明記済み。

### 規約の確認

| 観点 | 結果 |
|---|---|
| **ロジックが Rust に無い** | ソース走査で固定（機能名・機能番号での分岐・状態・依存・戻り値の数） |
| **外部クレートがゼロ** | `Cargo.toml` の `[dependencies]` が空。テストで固定 |
| 状態を持たない | `static mut` / `OnceLock` / `Mutex` なし。**実機で別プロセスから叩き直せることも確認** |
| ヌルポインタで落ちない | `rc=2`。自己検査で固定 |
| バッファを溢れさせない | 容量を超えて書かない。超えたら `rc=6` |
| 秘密を出さない | ログは `function` と `rc` だけ。バッファの中身を出さない |
| ログは stderr のみ | Rust は `eprintln!` のみ（自己検査の失敗時だけ） |
| **この環境の回避策を焼き込まない** | `.cargo/config.toml` を置かず、環境変数で渡す。手順は文書に記載 |
| 既存の非退行 | 3,839 件緑 |

### 残る弱点（`test-result.md` にも記載）

- `Send Key` の**実機での AID 送信を試していない**（画面を変えるため。親の統合 test へ）。

### 判定

**must 2 件・should 1 件を修正**、nit 1 件は対応済み。**通過**。
