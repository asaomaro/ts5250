# 要件: DBCS の欄の挿入モードの余地を ACS と同じに数える

## 背景 / 課題
- 台帳「挿入モードの余地の残り」の前半と、R11 の調査（`key-edit-rest` (p)）。`20260921-insert-no-room` は DBCS の欄を「論理値＋バイト予算」のまま予算超過の拒否＋0012 に留め、「最終桁」という位置を持たないので写さないとした（同 D2）。
  R11 で、これは当たらない（論理値のまま直せる）と分かった。
- 実機の ACS のコアで測った（`scripts/acs-probe/dbcs-insert-room.txt`。DBCSFE の画面・930）:
  (1) J・G・E は末尾の全角空白（U+3000）を空きに数える（`あい□□□` の先頭・3 スロット目への挿入が成功する。当 PJ は 0012 で拒否していた）。
  (2) カーソルが欄の最終桁なら、空白があっても 0012（J・E は SI の桁、O は最終のセル。1 桁手前は入る）。当 PJ は受け付けていた。
  (3) O は全角空白を空きに数えない（末尾が全角空白の満杯欄は 0012）。

## 目的 / ゴール
- DBCS の欄の挿入で、入るか入らない（0012）かの判定が ACS と一致する状態。

## ユーザーストーリー
- US1: ACS から移る利用者として、全角空白で埋まった欄の途中に字を挿入したら入り、欄の最後の桁では ACS と同じく余地なしになってほしい。なぜなら、同じ操作で結果が違うと、打ち直しの手順が変わるから。（受け入れ: AC1〜AC4）

## スコープ
### 対象
- J・G・E の挿入（打鍵・IME の確定・貼り付け）の余地の数え方と最終桁の判定（`ScreenGrid.vue`）。
### 対象外
- 選択を置き換える打鍵が最終桁のときの規則（ACS の GUI の選択置換は未測定。従来どおり入れる）。
- G 欄の桁数（SO/SI を 2 桁足す別の差）。O の SO/SI を含む必要桁（測定 C3・C4 で ACS は 0012、当 PJ は成功する別の差）。継続欄への IME 確定（ACS 側が未測定）。

## 完了条件 (受け入れ基準)
- [ ] AC1: J・E で末尾の全角空白を空きに使って挿入できる（`あい□□□` の先頭・3 スロット目）。満杯なら 0012 で値を変えない。
- [ ] AC2: カーソルが最終桁（J・E は SI の桁、O は最終のセル）なら、空きがあっても挿入は 0012。1 桁手前は入る。上書きは変えない。
- [ ] AC3: O は全角空白を空きに数えない（末尾が全角空白の満杯欄は 0012）。
- [ ] AC4: 各分岐を外すとテストが落ちる（`verify-by-mutation`）。貼り付け・IME の確定にも同じ規則が掛かる。
