# 決定記録

## D1: J・G・E は末尾の全角空白を空きに数え、O は数えない
- 測定（2026-09-22・社内機・ACS のコア・930。`scripts/acs-probe/dbcs-insert-room.txt`）: J の `あい□□□`（全角空白 3 つ）の先頭・3 スロット目への挿入は成功（A1・A2）、G の全角空白で埋めた欄への挿入も成功（G1）。
  O の末尾が全角空白の満杯欄（`ABCDEFGH□`）への挿入は 0012（F1。O は SO/SI の桁で数え始めが止まる）。E は J と同じ。
- 決定: `absorbDbcs` に `wideBlank`（J・G・E で true）を足し、末尾の U+3000 も削れるようにした。O は従来どおり半角空白だけ。
- ~~`20260921-insert-no-room` D2 の「DBCS 欄は論理値＋バイト予算で最終桁という位置を持たないので写さない」~~ を破棄した。列ビューの位置（`dbcsViewLayout` の `columnsBefore(caretOf(cursor))`）で判定できる。

## D2: 挿入でカーソルが最終桁なら、空きがあっても 0012（J・E は SI の桁、O は最終のセル）
- 測定: J の SI の桁（B1）・O の最終のセル（B2）は inhibit=5（0012）。O の 1 桁手前は成功（B3）。
- 決定: `atLastColumn`（`columnsBefore(caretOf(cursor)) >= visLen(f) - 1`）を挿入のときだけ掛ける。上書きは掛けない（`dbcsType` の `e.insertMode` の条件）。
- G は対象外にした（カーソルが 2 桁の前半にしか止まらない）。ただし G 欄は当 PJ が SO/SI の 2 桁を数える別の差（R11 (j)）で、欄の終わり近くは予算で先に拒否されるので、この除外は今は観測できない（mutation の生き残り 1 件＝等価変異）。

## D3: 選択を置き換える挿入には最終桁の判定を掛けない（未確認のまま従来の挙動を保つ）
- 背景: 選択を打鍵で置き換えるときは、選択を消して挿入モードで入れ直している（`onDbcsKeydown` の `replaced`）。O で最終のセルを選んで打つと、消した後のカーソルが最終桁になる。
- ACS の GUI の選択置換は実機のコアでは測れない（選択は GUI 側）ので**未確認**。従来（この work の前）は入っていたので、挙動を変えない（`replaced` を `dbcsType` に渡して外した）。IME の確定も同じ。
- 未確認を推測で埋めない。台帳に残した。

## D4: 貼り付けの繰り返しで挿入が拒否されたら通知を出す
- 貼り付けは 1 字ずつの打鍵と同じ規則（`20260921-insert-no-room` の測定）。事前の検査（`insertInto`）は欄全体の余地だけを見るので、O の最終のセルへ 1 字貼る場合などは通ってから最終桁の拒否に当たる。
  従来は黙って止まった（`break`）ので、挿入なら `MSG_NO_ROOM` を出す。拒否の後の続き（ACS が残りの字をどうするか）は未確認で、当 PJ は止まる。
