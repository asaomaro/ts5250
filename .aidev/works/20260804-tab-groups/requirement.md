# 要件: タブグループ（タブを重ねてまとめる）

## 背景 / 課題

ワークスペースは 1 ペインに何枚でもタブを並べられる（5250 セッション・プリンター・SQL・IFS・
スプール・監視……）。実際の使い方では **1 つの作業に複数のタブが関わる**——「PUB400 で検証」なら
5250 セッション＋SQL＋IFS を行き来する、といった具合になる。

いまタブ帯にあるのは**平坦な並び**だけで、まとまりを表す手段が無い。

- タブが増えると**どのタブがどの作業のものか**が分からなくなる。並べ替えて隣同士に置いても、
  隣接は視覚的な手掛かりにならない（折り返せば離れる）。
- 作業ごとにペインを分ければまとまりは表せるが、**画面が狭くなる**。まとめたいだけで
  同時に見たいわけではない場合に、分割は割に合わない。
- まとめて閉じる手段が無い。作業が終わったらタブを 1 枚ずつ閉じることになる。

タブに**システムカラーの帯**が付いた（`20260802-tabs-own-system`）ことで「どのシステムか」は
見分けられるようになったが、これは**接続先の軸**であって**作業の軸**ではない。同じシステムの中で
別々の作業をしているとき、システム色は何も区別しない。

## 目的 / ゴール

タブを**作業の単位でまとめられる**ようにする。まとまりには**名前と色**を付けられ、
**まとめたまま移動・解除・一括クローズ**ができる。

- ペインを増やさずにまとまりを表せる（画面を削らない）。
- まとまりは**ユーザーが明示的に作る**（自動で束ねない）。作り方は「タブを重ねる」D&D。
- まとまりが意味を失ったら（残り 1 枚になったら）**自動で解ける**。空の器を残さない。

## スコープ

### 対象

- タブを別のタブへ**重ねてドロップ**することでタブグループを作る。
- タブグループへのタブの**参加**（グループ内のタブへ重ねる）と**離脱**（グループ外へ D&D）。
- **残り 1 枚になったらグループを自動解除**（離脱・タブを閉じた場合の両方）。
- タブグループの**名前**の設定・変更。
- タブグループの**色**の設定（パレットから選ぶ）。
- タブグループの**カラーチップ**（色アイコン）の表示と、クリックで開く**ポップアップ**。
  ポップアップから: グループ解除 / グループ内のタブをすべて閉じる / 名前を変更 / 色を設定。
- **タブグループごと移動**する D&D:
  - 別ペインのタブ帯へ落とす → グループのまま合流する。
  - ペインの端（4 ゾーン）へ落とす → **ペインを分割**し、新ペインへグループごと移る。
- グループ内タブは**タブ帯の中で連続して並ぶ**（参加時に隣へ寄せる）。
- タブグループの**折りたたみ（collapse）／展開**——畳むとグループ内のタブが隠れ、チップだけが残る。

### 対象外

- **新規タブの自動所属**——新しく開いたタブは従来どおりペインの末尾（グループ外）に開く。
  グループへの参加は常に D&D で明示的に行う。
- **永続化**——リロード後の復元はしない。ワークスペースのレイアウト（分割・タブの配置）自体が
  現状 localStorage に保存されておらず、タブグループだけ復元しても復元先が無い。
- **入れ子のグループ**（グループの中のグループ）。
- **グループ単位のキーボード操作**（グループ間の移動ショートカット等）。既存の `cycleTab` は
  グループを意識せず従来どおりタブを順に巡る。
- サーバー側の変更。タブグループはブラウザ内の表示状態であり、API・設定ファイルには持たせない。

## 機能要件

### 作成・参加・離脱

1. タブを**別のタブの上（中央）へ**ドロップすると、その 2 枚でタブグループを作る。
   - タブの**左右の端**へのドロップは従来どおり**並べ替え**（挿入位置の指定）として扱う。
     重ねる操作と並べ替えを、落とす位置で区別できること。
2. **グループ内のタブへ重ねる**と、そのグループに参加する。
3. グループ内のタブを**グループの外**（同ペインのグループ外の位置・別ペインのタブ帯・
   ペインの端＝分割）へ D&D すると、グループから離脱する。
4. **残り 1 枚**になったらグループを自動解除する。契機は次の 2 つ:
   - タブの離脱（D&D による移動）
   - タブを閉じたこと（タブの ✕・セッション切断など、グループからタブが消えるすべての経路）
5. グループ内タブは**タブ帯の中で連続**する。参加したタブはグループの隣へ寄り、
   グループの途中にグループ外のタブが入り込まない。
6. 1 ペインに**複数のタブグループ**を置ける。

### 表示

7. グループの左（先頭）に**カラーチップ**を出す。名前が設定されていれば**名前も**チップに出す。
   チップは**タブと同じ行に、グループ先頭タブの左**へ横並びで置く（Edge のタブグループと同じ形）。
8. グループ内のタブは**グループ色の薄い背景**でまとまりを示す。
   **タブ帯の高さを増やさない**——タブを囲む枠を上下に回すと 1 行ぶん背が高くなり、
   エミュレータ画面に回す領域が削れる。まとまりは**同じ行の中**で表す
   （チップ＋背景の連なり、グループの端の丸め、境界の区切りなど）。
   **タブ左端のシステムカラー帯は残す**——「どのシステムか」と「どのグループか」は別の軸で、
   どちらも同時に要る（`20260802-tabs-own-system` の見分けを潰さない）。
9. 色は**パレットから選ぶ**（配色の実体はテーマ側の CSS 変数。設定に hex を持たせない。
   システムカラーと同じ方針＝`composables/systemColor.ts`）。
10. 名前は任意。未設定でも色チップだけでグループとして機能する。

### 操作（ポップアップ）

11. カラーチップをクリックすると**ポップアップ**が開き、次を呼び出せる（4 項目）:
    - **名前を変更**（入力欄。未設定なら「このグループに名前を付ける」相当の誘導）
    - **色を設定**（パレットから 1 つ。選択中が分かること）
    - **グループ化を解除**（タブは残す。並びも保つ）
    - **グループ内のタブをすべて閉じる**（セッションを持つタブは通常のクローズと同じ経路＝切断を伴う。
      結果としてグループも消えるため、Edge の「グループの削除」に相当する操作は別立てにしない）
12. ポップアップは既存の規約に従う（外側クリック／再クリックで閉じる。`docs/UI-DESIGN.md`
    「情報ポップオーバー」）。

### 折りたたみ（collapse）

13. グループを**折りたたむ**と、グループ内のタブがタブ帯から隠れ、**チップだけ**が残る。
    展開すると元どおり現れる。
14. 折りたたみは**チップのクリックとは別の操作**に割り当てる（クリックはポップアップを開く）。
15. 折りたたんでも**タブは閉じない**（`tabs` の並びもグループの所属も変えない。隠すだけ）。
16. 折りたたんでも**アクティブタブは変わらない**。畳んだグループの中のタブがアクティブなら、
    そのタブの内容を**そのまま表示し続ける**（折りたたみは**タブ帯の見せ方**だけの操作で、
    どのタブを見ているかには干渉しない。利用者の判断）。
    タブ帯からタブが消えても中身が出ている理由が読めるよう、その場合はチップに印を出す。
17. 折りたたみ中でも、グループのタブが 1 枚になれば通常どおり自動解除される
    （解除されたタブは折りたたみに関係なく現れる）。

### グループごとの移動

18. **カラーチップをドラッグ**するとグループ全体を掴む。
19. 別ペインのタブ帯へ落とすと、**グループのまま**（名前・色・並び・折りたたみ状態を保って）
    そのペインへ移る。
20. ペインの端（left/right/top/bottom の 4 ゾーン）へ落とすと**ペインが分割**され、
    新しいペインへグループごと移る。
21. 移動元のペインが空になったら、従来どおり片付ける（`pruneEmpty`）。

## 非機能要件 / 制約

- **既存の語彙と衝突しない命名にする。** コード上の `GroupNode` は既に**ペイン**を指す
  （`stores/workspace.ts`）。新概念には別の語を割り当て、両者が混ざらないようにする
  （具体名は spec 以降）。
- **ペインの状態を壊さない。** タブがグループへ出入りしても、ペインの実体は `PanePool` が
  `<Teleport>` で差し込む方式のまま保つ（`20260802-keep-pane-state-move`）。
  グループ化・移動でペインが作り直され、SQL の入力・IFS の居場所が消えることがあってはならない。
- **狭幅（`narrow`）・最大化中**でも破綻しないこと。これらは分割を抑止する既存の分岐があり、
  グループごとの端ドロップも同じ扱い（分割せず合流へフォールバック）に合わせる。
- **タブ帯の高さを変えない。** 現状の高さはヘッダーと共有する `--chrome-row-h`（最低 28px）で、
  ここを削って画面へ回した経緯がある（`PaneTabs.vue`「ACS 相当の余白に」）。グループの表現で
  1px も背を高くしない。
- **タブの折り返し（`flex-wrap`）**があるため、グループの表現は折り返しても壊れないこと
  （途中で折り返しても、続きがグループの一部だと分かること）。
- 表示は light / dark / system の 3 テーマに追従する（`docs/UI-DESIGN.md`）。
- 利用者に見えるメッセージは日本語・です／ます調で、`composables/opMessages.ts` に定数として置く。
- ファイルの D&D（データ転送ペインの CSV）と競合しない（`isFileDrag` の既存分岐を保つ）。
- 変更はブラウザ内で完結する（`packages/web-ui`）。サーバー API・設定スキーマは変更しない。

## 完了条件 (受け入れ基準)

- [ ] タブを別のタブの中央へドロップするとタブグループが作られ、左右端へのドロップは
      従来どおり並べ替えになる（重ねると並べ替えが落とす位置で区別できる）。
- [ ] グループ内のタブへ重ねると参加でき、グループ外へ D&D すると離脱できる。
- [ ] グループのタブが 1 枚になると自動解除される（離脱による場合・タブを閉じた場合の両方）。
- [ ] グループ内のタブがタブ帯で連続して並び、途中にグループ外のタブが割り込まない。
- [ ] グループのカラーチップがタブと同じ行の左に表示され、名前を付けるとチップに名前が出る。
- [ ] グループを作ってもタブ帯の高さが変わらない（グループ無しのときと同じ高さ）。
- [ ] チップのクリックでポップアップが開き、名前変更 / 色設定 / グループ化を解除 /
      グループ内のタブをすべて閉じる、が行える。外側クリックで閉じる。
- [ ] グループを折りたたむとグループ内のタブが隠れてチップだけが残り、展開すると元どおり現れる
      （タブは閉じない・並びも所属も変わらない）。
- [ ] アクティブタブを含むグループを折りたたんでも、アクティブタブは変わらず内容が出続け、
      チップにその印が出る。
- [ ] チップをドラッグして別ペインのタブ帯へ落とすと、グループのまま移動する。
- [ ] チップをドラッグしてペインの端へ落とすと、ペインが分割され新ペインへグループごと移る。
- [ ] グループへの出入り・グループごとの移動で、ペインの内部状態（SQL の入力内容など）が
      失われない。
- [ ] タブ左端のシステムカラー帯が、グループ内でも従来どおり出る。
- [ ] 1 ペインに複数のグループを置け、それぞれ独立して名前・色・解除が効く。
- [ ] 既存のタブ操作（並べ替え・別ペインへの移動・端ドロップでの分割・最大化・狭幅）が
      グループ導入後も従来どおり動く（回帰なし）。
- [ ] 上記を検証するコンポーネント／ユニットテストが追加されている
      （`cd packages/web-ui && npx vitest run` で緑）。

## 未確定事項 / 確認したいこと

spec 以降で決める（実装手段に属するもの・調査で潰すもの）。

- **データモデルの持ち方**——`GroupNode.tabs`（`string[]`）にグループの範囲をどう表すか。
  タブ ID → グループ ID の対応表を別に持つか（`tabSystem` と同じ形）、`tabs` を
  「タブまたはグループ」の配列にするか。連続性の強制・移動・解除の実装しやすさで決める。
- **重ね（中央）と並べ替え（左右端）の境界**——タブ幅のどこまでを中央と見るか。
  現状の並べ替えは `clientX` が中点より右か左かの 2 分岐（`PaneTabs.vue`）で、そこへ
  第 3 のゾーンを足すことになる。ドロップ先の予告表示も含めて spec で決める。
- **グループ色のパレット**——システムカラー（`--sys-1`…`--sys-8`）を流用するか、
  専用の変数を起こすか。流用すると「同じ色＝同じシステム」の読みが崩れる恐れがある。
- **名前の入力 UI**——ポップアップ内のインライン入力か、別ダイアログか。
  文字数上限とチップでの省略の扱い。
- **チップのドラッグと既存の D&D の共存**——現状 `draggingSession` は単一のタブ ID を持つ
  （`stores/workspace.ts`）。グループを掴むときの表現（`dataTransfer` の型を含む）を決める。
> 以下は spec 工程の冒頭で利用者に確認して確定した（spec.md「設計方針」に反映済み）:
> **折りたたみの操作**＝チップ内の ∨ ボタン（チップ本体のクリックはポップアップのまま）/
> **折りたたみとアクティブタブ**＝干渉しない（上の 16 に反映）/
> **畳んだチップへのドロップ**＝畳んだまま参加させる /
> **一括クローズ**＝`window.confirm` で枚数を示して確認する。
