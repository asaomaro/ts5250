# 決定記録

## D1: 「前の欄の末尾へ移る」を破棄する（SBCS）

- GNU tn5250 の動きを「実機」として採っていたが、ACS は 0005 で動かない（F1・F2 の実測 2 回）。ACS が正典。
  EDTMSK の欄（行をまたぐ欄）は、区切りの先頭なら前の区切りの末尾を消す——これは従来どおり（ACS と同じ）。

## D2: ~~DBCS の欄は残す~~（D3 で破棄）

- ACS は原典の手順上 0101（SO の前が属性の桁）。0101 の文言と実機の動きを確かめていないので、推測で文言を作らずに従来の動きのまま台帳に残す。

## D3: DBCS の欄も 0005 にする（D2 を破棄。マイルストーン 8 の独立点検）

- 証拠: DSM で O・J の欄の画面を出させ、ACS のコアで欄の先頭の Backspace を測った（`scripts/acs-probe/backspace-dbcs-field-start.txt`）。
  O の欄の先頭（5,10）も、J の欄の SO の後ろ（7,11。Tab の着地）も「画面の保護域にカーソルがある。」（0005）でカーソルそのまま。
- 原典の手順の読み（0101）は実測と違った。DBCS の欄も SBCS と同じく 0005 で止め、前の欄へ移る経路を撤去した。
