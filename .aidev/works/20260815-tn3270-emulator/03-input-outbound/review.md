# レビュー記録: 03-input-outbound

## ラウンド 1（2026-08-15T10:05:22Z）

差分: `session/aid-keys.ts` / `session/emitter.ts` / `session/session.ts` /
`protocol/outbound.ts` を追加、テスト 3 本（単体 2・照合 1）。

### 実測で確定させたこと

02 と逆向きの手法——**`mini3270` を受信側に立て、`s3270` に実際にキーを押させて
送ってきたバイトを捕まえた**。`s3270` 自身のトレース（送信側も復号する）とも突き合わせている。
採取は `artifacts/aid.trc`。

- **AID 29 個すべて**: enter=7D / pf1-9=F1-F9 / pf10-12=7A-7C / pf13-21=C1-C9 /
  pf22-24=4A-4C / pa1=6C / pa2=6E / pa3=6B / clear=6D。ホスト起動の読み取りは **60**。
- **PA1〜PA3 と Clear は AID 1 バイトだけ**。`spec.md` には「AID とカーソルアドレスのみ」と
  書いていたが**カーソルアドレスすら送らない**。spec を訂正した。
- **Read Modified の形**: `AID + カーソル + (SBA + 欄の中身の先頭 + データ) × 変更欄`。
  SBA が指すのは属性桁の**次**（実測 `11 40c1` = 属性桁 0 の欄、`11 4b5b` = 属性桁 730 の欄）。
- **非フォーマット画面では SBA を出さない**（`AID + カーソル + 画面の中身`）。

### 指摘と対応

- [must] `protocol/outbound.ts` — **SBA を出さない実装になっていた（誤り）**。
  最初の探針でキーを総当たりした際、**末尾で `Clear()` を押していた**。Clear は画面を消すので
  以後は**非フォーマット画面**になり、そこへの入力は SBA 無しで送られる。その状態を測って
  「s3270 は SBA を出さない」と結論しかけ、実際にそう実装した。
  入力を伴う照合テストを足したところ `7d4b5d **1140c1** c1c2 **114b5b** e9e9` が出て発覚。
  / 対応: **修正済**。フォーマット画面では欄ごとに SBA を前置し、非フォーマット画面では出さない。
  両方の単体テストを追加し、**s3270 との送信バイト一致**で裏を取った。
  `outbound.ts` のコメントに「**測った状態が何だったかを確かめる**」という教訓として残した。

- [must] `session/session.ts` `attach()` — **`negotiating` へ遷移させていなかった**ため、
  `connect()` を経由しない入口（trace の replay・テスト）では交渉が終わっても
  `disconnected` のままで `ready` にならなかった。単体テスト 10 件がまとめて落ちて発覚。
  / 対応: **修正済**（`attach()` の冒頭で遷移）。理由をコメントに明記。

- [should] 照合テストが**空振りで緑になりうる**形だった（両側とも空文字なら一致してしまう）。
  / 対応: **修正済**。各バイト列が非空であることと、探針で得た既知値
  （`pa1` = `6c`、入力ありは `^7d.{4}11.{4}c1c211.{4}e9e9$`）との一致を足した。

- [should] T9 の範囲を plan から変更した。**TK4- には入力を受け付ける画面が無い**——
  TSO（`IKJ54012A ENTER LOGON`）も Hercules コンソールも**キーボードがロックされたまま**で、
  `String()` が `Keyboard locked / Operator error` を返す。
  / 対応: 実ホストでは「接続 → 画面受信 → Enter → **ホスト応答でロック解除**」までを確認し、
  **入力を伴う送信バイトの照合は自前のホスト役サーバで s3270 と突き合わせた**。
  照合の厳密さは落ちていない（むしろ決定的になった）。

- [nit] `session.test.ts` の未使用 import（`TT_IS`）を lint が検出。/ 対応: **修正済**。
