# レビュー記録

## 前提そのものが誤っていた

4 件とも「実機で届かないので確かめられない」で止まっていたが、**IBM 自身が発行する API を
出荷していた**（DSM）。**「届かない」と「出させられない」は別の話**だった。

`QsnPutInpCmd` / `QsnPutOutCmd` は第 1 引数がコマンドバイトそのものなので、
**ここに無いコマンドも同じやり方で出せる**。この道具は今後も効く。

## 実装するかどうかを「待つか」で決めた

- **`0x83`**：出させたら**ホストが API から戻ってこなかった**。実装 → `rc=1 / 欄数=1` で受理
- **`0x66`**：同じく固まった。画面イメージを返す実装 → `rc=1024` で受理
- **未知の出力コマンド（0xFE）**：**待たなかった**（`rc=0`、セッションも継続）→ 入れない

## 実機でしか分からなかったこと

- **ROLL の方向ビット**が原典どおり（`0x80` 落ち＝上）だと裏づけられた。当方は以前逆で、
  原典を読んで直したが**未検証のままだった**
- **ROLL の引数の並び**は `(行数, 上端, 下端)`。`CPFA315` の本文が教えてくれた
- **`bytesRead` の意味が 0x72 と 0x83 で違う**（バイト数 / 欄の数）。ALT は欄の構造情報を返す
  形式で、`QsnRtvFldCnt` が使える（0x72 では `CPFA32E`）

## 転んだところ（すべて scripts/README.md に記録）

- **`CRTBNDC` は失敗しても戻りコード 0 で返る**。「OK」を信じて進み、実行して初めて
  「プログラムが見つからない」で気づいた
- **失敗メッセージを投げる前に出していなかった**ので、次は中身が見えないまま落ちた
- **`Q_Bin4` も `Q_Handle_T` も `long`**
- **DSM の引数はヘッダーで確かめる**（`QsnRtvDta` を 5 引数だと思って落とした）
- **C をテンプレート文字列に埋めない**（エスケープが二重になった）
