# 要件: READ の欄データの加工を ACS と同じにする（ALT は加工しない・末尾の実空白は送る）

## 背景 / 課題
`.aidev/backlog/acs-parity.md` の「【まとめ】DS5250 のその他の差」のうち「0x82/0x83 の欄データで、NUL と符号を加工する」。
R11 の調査で ACS は ALT（0x82・0x83）では NUL も符号も加工せず、末尾の NUL だけ落として実空白は送る、と原典から読めていた（未測定）。当 PJ は ALT も 0x52 と同じに加工し、末尾の空白を落とす。

## 目的 / ゴール
READ MDT FIELDS（0x52）・READ MDT FIELDS ALT（0x82）・READ MDT IMMEDIATE ALT（0x83）で、ホストが受け取る欄データが ACS と同じバイト列になっている状態。

## ユーザーストーリー
- US1: DSM（`QsnReadMDTAlt` 系）で ALT の読み取りを使うホストのプログラムの利用者として、ACS と同じ欄データを受け取りたい。なぜなら ALT は「加工しない生のデータ」を前提にした読み取りで、NUL が空白に化けたり符号が畳まれたりすると、プログラムが受け取る長さと中身が ACS と変わるから。（受け入れ: AC1, AC2）

## スコープ
### 対象
- tn5250 の READ 応答の組み立て（SBA 付きの形式 0x52・0x82・0x83）と、0x82 で待たされたときのセッションの選択
### 対象外
- 0x42・0x72（平坦形式。ACS も別の枝で、欄長そのまま NUL を空白にする。現状どおり）
- 未編集の DBCS 欄（SO/SI の構造を持つ欄。桁と字が対応しないので従来の末尾の空白を落とす形のまま。台帳に残す）
- 打鍵で書き換えた欄の「値の後ろにホストが書いていた実空白」（当 PJ の編集は値の後ろを NUL にする。ホストから見た意味は同じ。台帳に残す）

## 機能要件
- 0x52: 末尾の NUL を落とし、途中の NUL は 0x40、符号付き数値は符号の桁が NUL でないときだけ畳む（手前の桁のゾーンを 0xD・符号の桁は送らない）。末尾の実空白は送る
- 0x82・0x83: 末尾の NUL を落とすだけ。途中の NUL・符号の桁はそのまま
- 0x82 で待たされているときの AID は 0x82 の形で返す

## 非機能要件 / 制約
- 実機の試験プログラム（DSM）は測った後に消す
