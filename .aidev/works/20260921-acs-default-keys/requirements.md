# 要件: 既定のキー割り当てと End の行き先を ACS と同じにする

## 背景 / 課題
- 台帳「【まとめ】キー編集の細部が ACS と違う」の低「既定のキー割り当ての違い（Esc=Attn、Shift+Insert=Dup ほか）」と「End の行き先」。
- ACS は既定で Esc に Attn、Shift+Insert に Dup などを割り当てている。当 PJ は Attn / SysReq に既定の割り当てが無く（README に「既定のバインドは付いていません」）、
  ACS に慣れた利用者が Esc を押しても何も起きない。
- 当 PJ の既定 Ctrl+F1（表示コード）・Ctrl+F3（SO/SI 表示）は「ACS で使い慣れた」として入れたが、向きを原典で確かめていない。

## 目的 / ゴール
- ACS に慣れた利用者が、設定しなくても ACS と同じキーで同じ操作ができる状態。

## ユーザーストーリー
- US1: 5250 の利用者として、ACS と同じキー（Esc・Shift+Insert・Pause など）で同じ操作をしたい。なぜなら、体が覚えたキーが効かないと操作が止まるから。（受け入れ: AC1, AC2, AC3）
- US2: 既に割り当てを変えている利用者として、自分の割り当てを奪われたくない。なぜなら、既定の追加で手になじんだ設定が壊れると困るから。（受け入れ: AC4）

## スコープ
### 対象
- 既定の割り当ての追加（既存の機能に当たるキー）と、向きを誤っていた既定の訂正。欄の input が自分で処理するキー（Insert・End）に割り当てがあればペインへ委ねること。
  IME の変換中のキーを割り当てで拾わないこと。欄の中での End の行き先。
### 対象外
- 当 PJ に無い機能のキー（Test Request・Field Mark・ルーラー・単語単位の Tab・切り取り / 元に戻す・ジャンプ ほか）。台帳に残す。
- 欄の外で押した End の行き先（ACS は次の入力欄の末尾へ。当 PJ は最後の入力欄の先頭へ）。台帳に残す。

## 完了条件 (受け入れ基準)
- [ ] AC1: 既定で Esc = Attn・Shift+Esc = SysReq・Alt+End = Erase Input・Shift+Insert = Dup・Pause = Clear・Ctrl+Pause = Print・Alt+F1 = Help・Ctrl+F1 = SO/SI 表示・Ctrl+F3 = 表示コード。End には割り当てない。
- [ ] AC2: 欄の中の Shift+Insert は挿入モードを切り替えずに Dup、割り当てのある End はペインの割り当てへ（SBCS・DBCS とも）。IME の変換中の Esc は Attn にしない。
- [ ] AC3: 欄の中の End は、入力の直後（最後の桁まで埋まっていれば最後の桁）へ移る。
- [ ] AC4: 版 4 より前に保存した割り当ては、足した既定より優先される。Ctrl+F1 / Ctrl+F3 は、古い既定の組のままのときだけ入れ替える。
- [ ] AC5: 各判定を外すとテストが落ちる（`verify-by-mutation`）。
