# 要件: WTD の CC1=0xC0 で欄が消えない

## 背景 / 課題

CC1 の上位 3 ビットが `0xC0` のとき、**MDT の立った入力欄を消し、MDT を落とす**。
当 PJ は `applyCc` の `case 0xc0` で **`resetMdtNonBypass()` を先に**呼んでいた。
`nullNonBypass(true)` は**MDT の立った欄だけ**を対象にするので、
先に MDT を落とすと**対象が 0 件**になり、**1 欄も消えない**。
入力を消すべき画面で、打った値がそのまま残る。

### 原典で確かめたこと（`AGENTS.md` 判断の原則 1）

`acshod2.jar` の `DS5250.class` を `javap -c -constants` で読んだ。
`processWCC1` は `cc1 >> 5` の `tableswitch`（0〜7）で分岐し、**case 6（＝0xC0）**は offset 189:

```
199: clearNonbypassFields(true)   ← **先に消す**
207: resetMDTFields(true)         ← **後で MDT を落とす**
216: lockKeyboard(8)
```

**当方と順序が逆**。台帳の記述どおりだった。

## 目的 / ゴール
- **入力を消すべき画面で、打った値が残らない状態。**

## ユーザーストーリー
- US1: 端末の利用者として、ホストが「入力を消す」と指示した画面で**前の入力が残らない**でほしい。
  なぜなら、残った値をそのまま送ると**意図しないデータがホストへ行く**から。（受け入れ: AC1）

## スコープ
### 対象
- `packages/tn5250/src/protocol/wtd-applier.ts` の `applyCc` の `case 0xc0` の**呼ぶ順序**。
### 対象外
- 付随の差（継続欄の全区間・DBCS 専用欄の SO/SI 桁）——台帳の別項目。
- `0xa0` / `0xe0`（`nullNonBypass(false)`＝全欄が対象なので**順序で結果が変わらない**）。
- 実機で 0xC0 を出す DDS の特定（`ERASEINP MDTOFF` が候補。**未確認**）。

## 機能要件
- FR1: CC1=0xC0 で、**MDT の立った非バイパス欄の値が消える**。
- FR2: あわせて **MDT も落ちる**。
- FR3: 他の CC1 の挙動は変えない。

## 非機能要件 / 制約
- ACS の順序に合わせる（原典で確認済み）。**デコンパイル結果の行番号はコメントに書かない**。
- `AGENTS.md` のコーディング規約。
