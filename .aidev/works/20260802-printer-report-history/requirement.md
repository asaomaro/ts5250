# 要件: 常駐プリンターが受け取った帳票を画面から読めるようにする

## 背景 / 課題

`.aidev/backlog/hostserver.md` の **「常駐プリンターを画面から扱えるようにする」**。
起票時（`20260801-printer-session-residency`）は「UI が無い」と書かれていたが、
**着手前にリポジトリの現物で裏を取ったところ、大半は後続の作業で閉じていた**。

| 起票時の残件 | いまの実際 |
|---|---|
| 常駐中の一覧が見える | ✅ `ServicesPane.vue`（`20260801-services-pane`） |
| 出力の警告が読める | ✅ 同上（`自動出力の警告` 節） |
| 常駐がプロセス再起動で消える | ✅ `boot-autostart.ts`（`20260801-boot-autostart`） |
| **未読の帳票が読める** | ❌ **未実装。しかも配線は途中まで出来ている** |

### 配線が 1 ホップだけ繋がっていない

`20260801-printer-attach-by-ref`（PR）はサーバー側を完成させている。
その spec は D4 で**こう書いている**:

> `printer-opened.reports` に載せる。…これが無いと「繋がったが閉じている間のものは
> 見えない」になり、attach の意味が半分になる。

実際 `ws-handler.ts:493` は `reports` / `receivedTotal` / `outputStatuses` /
`outputWarnings` をすべて送っている。ところが受け手の
**`session-controller.ts` の `printer-opened` は `reports: []` と書いて `msg.reports` を捨てている**
（`msg.receivedTotal` も読んでいない）。

つまり**サーバーは正しく届けているのに、画面がその場で捨てている**。
`20260801-printer-attach-by-ref` の tasks は T1〜T4 がすべてサーバー側で、
**web-ui を触るタスクが 1 つも無い**——最後の一歩が計画から漏れていた。

結果として、いま起きていること:

- 常駐プリンターが夜のうちに 10 件受け取っていても、朝ブラウザで開くと**帳票は 0 件**。
- `ServicesPane` は `帳票 10 件（保持 10）` と出す。**あると書いてあるのに開けない**——
  これは「無い」より悪い。
- プリンターペインのツールバーは `受信 {{ reports.length }} 件` を出すので、
  **落ちた分（`REPORT_LIMIT` 50 超）を含む累計とも食い違う**。

### 受信時刻も嘘になる

`SpoolReportView.receivedAt` は**クライアントで押している**（`sessions.ts:238`
`report.receivedAt ??= Date.now()`）。サーバー側の `SpoolReport`（`printer-session.ts:16`）は
時刻を持たない。

このまま `msg.reports` を受け取ると、**閉じている間に届いたぶんが全部「いま届いた」**
ことになり、一覧の受信時刻が全件同じ時分秒で並ぶ。**帳票がいつ出たかは業務上の情報**なので、
黙って現在時刻を押すのは直さずに済ませられない。

## 目的 / ゴール

- **ブラウザを閉じている間に常駐プリンターが受け取った帳票を、開き直して読める。**
- 件数と受信時刻が**実際に起きたことと一致する**。
- サービス一覧に「帳票 N 件」と出ているなら、**そこから読みに行ける**。

## スコープ

### 対象

- `printer-opened` の `reports` / `receivedTotal` を web-ui が受け取る。
- 帳票の**受信時刻をサーバーで刻んで運ぶ**（クライアントの `Date.now()` に頼らない）。
- 累計（落ちた分を含む）と保持件数を**区別して**出す。
  「50 件受け取ったが手元にあるのは直近 50 件」という状態が読めること。
- **サービス一覧からその帳票を開く導線**（`ServicesPane` の行から該当プリンターへ）。

### 対象外

- **新しい通知基盤**。`20260801-printer-session-residency` の判断（ログ＋一覧 API＋
  再接続時の配り直しの 3 層）を維持し、プッシュ通知等は作らない。
- **常駐を数時間〜数日保てるかの実測**（backlog の別行。実機の長時間占有が要る）。
- `REPORT_LIMIT`（50）の変更・帳票のサーバー永続化。**プロセスが落ちれば消える**という
  性質は今回変えない（変えるなら保存先と権限の設計が要る）。
- 未読件数の**サーバー側管理**。未読はブラウザ側の概念のまま。

## 機能要件

### 帳票を捨てない

- `printer-opened` を受けたとき、`msg.reports` を `SessionState.reports` に入れる。
- `msg.receivedTotal` を保持する。
- **未読を水増ししない**——開いた時点で受け取るぶんは「閉じている間に届いた既存分」であって、
  タブのバッジを 10 件ぶん光らせる類のものではない。開いた瞬間に読んでいるので未読 0 で始まる。
- 既に開いているセッションへ二度目の `printer-opened` は来ない（attach は WS 1 本につき 1 回）。

### 受信時刻

- サーバーが帳票を受け取った時刻を刻み、`printer-opened.reports` と `report` の両方で運ぶ。
- 画面はサーバー由来の時刻を優先し、**無い場合だけ**従来どおりクライアントで押す
  （古いサーバーと繋いだときに時刻欄が空になるのを避ける）。

### 件数の表示

- プリンターペインのツールバーは**累計と保持を区別**する。
  同じなら 1 つだけ出す（常に 2 つ出すと普段の見え方が煩くなる）。
- サービス一覧の `帳票 N 件（保持 M）` は既にこの区別をしているので、**文言を揃える**。

### サービス一覧からの導線

- `ServicesPane` の各プリンター行から**そのプリンターを開ける**。
  既に開いていればそのタブへ移動する（ランチャーの `openedSession` と同じ判断）。
- 開くと `printer-opened` で保持ぶんが届き、そのまま読める。
- **操作権限（`editable`）とは別**。読むだけなので、開始/停止と同じ条件で隠さない。

## 非機能要件 / 制約

- 追加の依存を入れない。
- **`ws-messages.ts` の変更は後方互換にする**（`receivedAt` は任意）。
  Electron 同梱版など、サーバーと web-ui の版がずれる経路がある。
- 実機（）は**共用の本番機**。既存の `PRT_TEST` を借り、装置は作らない・消さない。
  `finally` で必ず `ENDWTR`、作ったスプールは消す、他人の OUTQ に触らない。

## 完了条件 (受け入れ基準)

- [ ] ブラウザを閉じている間に届いた帳票が、**開き直したプリンターペインの一覧に出る**。
- [ ] その帳票の**受信時刻が実際に届いた時刻**で表示される（開いた時刻ではない）。
- [ ] 累計（`receivedTotal`）と保持件数が違うとき、**両方読める**。
- [ ] サービス一覧のプリンター行から**そのプリンターを開いて帳票を読める**。
      既に開いていればそのタブへ移動する。
- [ ] 受け取った既存分で**未読バッジが光らない**。
- [ ] `receivedAt` を送らないサーバーと繋いでも時刻欄が壊れない。
- [ ] 実機で「待ち受けたまま WS を切り、帳票を出し、開き直すと読める」を通す。

## 未確定事項 / 確認したいこと

- サービス一覧からの導線を**ボタンにするか行クリックにするか**。spec で決める。
  現在の行は「開始/停止」ボタンだけを持ち、行自体は押せない。
- 累計と保持の**文言**（`受信 12 件（保持 10）` か `12 件受信・10 件保持` か）。spec で決める。
