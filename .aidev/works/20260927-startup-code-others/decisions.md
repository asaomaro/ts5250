# 決定記録

## D1: I906・装置名の入った表に無いコードは、今のまま（サインオン画面を処理して続け、装置名は採る）——装置名の扱いは**暫定**

- 背景: ACS `DS5250.processStartUpConfirmation` は I901・I902 以外（9906 など表に無い数）では開始の処理をしない（research F2）。画面の処理は続く（F3）。
- 決定: **セッションを続ける点は ACS と同じなので変えない**。**装置名を採らない ACS の扱いには、暫定で合わせない**。
  - ACS で装置名を採らないと効くのは、窓の題名・`IsWorkstationIDReady()`（状態 7 の印）・NEW-ENVIRON DEVNAME で読まれるセッションの装置名（F2・F4）。
    当 PJ は DEVNAME の送り直しに起動応答の装置名を使わない（`packages/tn5250/src/session/session.ts` の起動応答の分岐は `startupInfo` に控えるだけ）ので、この差は当 PJ に持ち込まれない。
  - 当 PJ で起動応答の装置名が効くのは**ジョブ名**（`packages/server/src/session-manager.ts` の `entry.job`。ⓘ の表示やジョブの操作の出どころ）。捨てると、ホストが割り当てた実際の装置（＝対話ジョブ名）が分からなくなる（AGENTS.md「ACS が情報を捨てているなら合わせない」）。
- **暫定である理由**: AGENTS.md はこの例外に実測の裏づけを求めるが、I906 は実機で出させられず（F5。*FRCSIGNON でも I902）、**I906 の起動応答に装置名が入るかも未確認**。backlog の未確認（I906 の実機での見え方）が閉じたら見直す。
- 範囲の限定: 「表に無いコード」は当 PJ の文字列の判定での話。ACS の数字の判定（F7）で拒否の表に当たる未知の文字列は、ACS は拒否・当 PJ は開く（実在するかは未確認）。
- 影響: コードは変えない。I906・未知コードの経路を単体テストで固定し、ACS のコアの測定資産（`AcsProbe.java` の dump に起動応答のコード・装置名・`wsidReady`、`startup-i906.txt`）を残す。
