## out / inout の実機往復（2026-08-04 に追加）— 11/11

`TESTLIB/PGMTST` を作って確かめた（`scripts/build-pgmtst.mjs`）。
**CL の `PARM` は参照渡し**なので、1 引数で inout をそのまま試せる:

```
&NUM（詰め 10 進 15,5） = &NUM * 2
&TXT（文字 20）        = 'ECHO:' + &TXT
```

```
OK  **inout の数値が往復する**（21 → 42） — "42.00000"
OK  **inout の文字が往復する**（ABC → ECHO:ABC） — "ECHO:ABC            "
OK  **負の値も往復する**（-1.5 → -3） — "-3.00000"
OK  **小数も往復する**（0.00003 → 0.00006） — "0.00006"
```

**負の値と小数を分けて見たのが要点。** 符号ニブルの取り違えは負でしか出ず、
桁合わせの取り違えは小数でしか出ない。正の整数だけだと両方すり抜ける。

## 値渡しの上限と戻り値の型（2026-08-04 に追加）— 18/18

**組み合わせを実機で試して、扱える範囲を確定した。**

| 試したこと | 結果 |
|---|---|
| 引数の形式 3 以上 | **`CPF226E`** で断られる（1 と 2 だけ） |
| 8 バイト整数を**値渡し** | **呼べてしまい結果が 0**（失敗しない） |
| 浮動小数を**値渡し** | **呼べてしまい壊れた値**（形式番号を変えても直らない） |
| 8 バイト整数の**戻り値** | 壊れた値 |
| 浮動小数の**戻り値** | 壊れた値 |
| **8 バイト整数を参照渡し** | **正しい（42）** |
| **浮動小数を参照渡し** | **正しい（3）** |

→ **値渡しは 4 バイトまで**、**戻り値は 4 バイト整数まで**。
それを超える型は**参照渡しの出力引数で受ける**——これは実機で動く。

```
OK  **8 バイト整数を参照渡しで往復**（20+22=42）
OK  **値渡しで 4 バイト超は拒否**（黙って壊れた値を返さない） — CONFIG_ERROR
```

**上限を超えたら断るようにした。** 通すと呼べてしまい、**結果だけが静かに壊れる**
——失敗しないので利用者は気づけない。

## ポインタの戻りと手続き名の長さ（2026-08-04 に追加）

### ポインタの戻り値は**扱えない**（確定）

受け取り域を 16 バイトにしても**書かれるのは先頭 4 バイトだけ**で、呼ぶたびに違う値になる
（`03044160` / `05002500` / `b5002500`）。IBM i のポインタは 16 バイトのタグ付きなので、
**そもそも運べない**。形式番号を 0〜4 で総当たりしても変わらない（2 は `MCH0602`、4 は `CPF226E`）。

→ `returns` は `none` / `int` のままでよい。**大きな戻り値は参照渡しの出力引数で受ける**。

### 手続き名に API 側の上限は**無い**（確定）

**4007 バイトの器**で渡しても正しく呼べた（`SRVADD` が 42 を返す）。
ヌル終端でも、器の長さちょうどでも読む。

→ こちらで設けていた 255 の上限は**API の制約ではなくこちらの都合**だったので、
4000 まで広げた（C++ の装飾名などは 255 を超えうる）。

> 当初は「存在しない長い名前」で試したが、**`CPF226E`（見つからない）は
> 「送れたが無い」と「拒否された」を区別できない**。
> **実在する名前の後ろにゴミを付ける**形に変えて決着した。
