# 要件: プログラム呼び出しを利用者に開く

## 背景 / 課題

**プログラム呼び出しは既に実装されているのに、利用者から届かない。**

`CommandConnection.call(program, library, params)` が
`packages/hostserver/src/command/command-connection.ts:176` にあり、
出力パラメータを呼び出し順の配列で返す。実機で戻り `0x0501` まで観測してある。

ところが:

| 経路 | プログラム呼び出し |
|---|---|
| MCP | **ある**（`host_call_program`。ただし**生バイト base64 専用**）※訂正 |
| web-ui | **無い**（機能一覧に無い） |
| REST | **無い** |

> ⚠ **当初「MCP にも無い」と書いたのは誤り**（`mcp-tools.ts` だけを見て、
> ホストサーバー系が別ファイルにあることを見落とした。詳細は `research.md` の訂正）。
> **本当の問題は「生バイトしか渡せないこと」**——呼ぶ側が EBCDIC と詰め 10 進を
> 自分で組む必要があり、実質使えない。

CL コマンドは実行できるのに、**RPG / COBOL のプログラムをパラメータ付きで呼ぶ道が開いていない**。
画面を経由しない連携（jt400 の `ProgramCall` に相当）は IBM i の現場で最も使われる形のひとつ。

## 目的 / ゴール

**画面を経由せずにプログラムを呼び、結果を受け取れる。**
パラメータは**利用者が書ける形**（文字・数値）で指定でき、生のバイト列を組まなくてよい。

## スコープ

### 対象

- パラメータの**型付き変換**（文字 / 詰め 10 進 / ゾーン 10 進 / 2 進 / 生バイト）
- MCP ツール
- REST（web-ui とスクリプトの共通の口）
- web-ui の導線

### 対象外

- **サービスプログラムの呼び出し**（`ServiceProgramCall`。手続き名と戻り値の扱いが別物）
- パラメータの構造体定義（DDS / RPG の外部記述からの自動生成）
- **非同期実行**（呼んで待つだけ）

## 機能要件

- パラメータは **in / out / inout / null** を指定できる（既存の型に合わせる）
- **型で書ける**——`{ kind: "char", value: "ABC", length: 10 }` のように。
  バイト列も直に渡せる（逃げ道）
- 出力は**型に従って戻す**（EBCDIC → 文字、詰め 10 進 → 数値）
- **ライブラリは明示**（`*LIBL` を含む）
- 失敗はホストのメッセージ付きで返る（`CommandResult` が既に持っている）

## 非機能要件 / 制約

- **既存の `call()` の振る舞いを変えない**（下位層は無改変で通す）
- 変換は**純粋な関数**（Node API に依存しない）——スクリプトからも使える
- 既存の 3,967 件を壊さない
- **実機で確かめる**（実機に呼べるプログラムを用意する）

## 完了条件 (受け入れ基準)

- [ ] MCP から**パラメータ付きでプログラムを呼べる**
- [ ] 出力パラメータが**型に従って読める**（文字・数値）
- [ ] REST から同じことができる
- [ ] web-ui から呼べる
- [ ] **実機で往復を確認**（入力を渡し、加工された出力が返る）
- [ ] 失敗時にホストのメッセージが読める

## 未確定事項 / 確認したいこと

- 実機に呼べるプログラムがあるか。無ければ**この作業で作る**
  （`scripts/build-*.mjs` に前例がある）
- 変換の型をどこまで用意するか（最低限: 文字・詰め 10 進・2 進・生）
