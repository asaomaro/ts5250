# レビューガイド: プログラム呼び出し

**画面を経由せずに RPG / COBOL / システム提供のプログラムを呼ぶ。**

## 30 秒で分かる要約

下位層（`CommandConnection.call`）と MCP ツール（`host_call_program`）は**既にあった**。
足りなかったのは**型付きの引数**——生バイトだけだと、`QCMDEXC` に長さを渡すのに
詰め 10 進を手で組むことになり、実質使えない。

```
{ type: "char",   dir: "in", value: "DSPLIBL", length: 7 }
{ type: "packed", dir: "in", value: "7", digits: 15, decimals: 5 }
{ type: "char",   dir: "out", length: 100 }
{ type: "bytes",  dir: "inout", value: "<base64>", length: 8 }   // 逃げ道
```

## 見てほしい 4 点

### 1. 数値を文字列でやり取りする

`number` は 2^53 を超えると精度を失い、金額のような値が静かに誤る。
**既存の読み取りが文字列を返すのはそのため**（`db-decimal.ts` の注記）で、
書く向きも揃えないと**往復で値が変わる**。

検査は**往復**で固定してある——読む向きは既に実機で使われているので、
往復が合えば書く向きも正しい。符号ニブルの位置と奇数桁の詰め方は取り違えやすく、
**間違えても「それらしいバイト列」になる**ので、往復以外では気づけない。

### 2. 黙って切らない・黙って化けさせない

| | 挙動 |
|---|---|
| 文字が長すぎる | **拒否**（切ると誤った値がホストへ渡る） |
| CCSID で表せない文字 | **拒否**（置換文字がそのまま渡る） |
| 桁があふれる | **拒否** |
| 丸めが要る小数 | **拒否**（落ちるのが 0 だけなら通す） |
| 文字が短い | **空白で埋める**（IBM i の作法。NUL ではない） |

### 3. 逃げ道を残した（**最初の検証で既に要った**）

型で表せない構造体は必ず出てくる。実機の `QWCRSVAL` は**エラーコード構造体**を取るので、
`bytes`（base64）が**最初の検証時点で既に必要**だった。

### 4. 既存の `params` を壊していない

MCP ツールは元から**生バイト専用**の `params` を持っていた。
`args`（型付き・推奨）を足し、**出力の形も入力に合わせる**——型で書いたなら型で返す。

> **一度これを壊した。** 既存ツールを重複と誤認して削除し、全件テストで発覚した。
> `mcp-tools.ts` だけを見て「無い」と結論したのが原因で、
> **同種の機能が複数ファイルに散っている**ことを見落としていた。

## 実機で確かめたこと（7/7）

**フィクスチャを作らずに済んだ**——`QCMDEXC` と `QWCRSVAL` はどの機にもある。

```
OK  **QCMDEXC を呼べた**（文字 ＋ 詰め 10 進） — rc=0
OK  **長さが違えば失敗が返る** — CPD0030
OK  **出力引数が返る**（QWCRSVAL） — 長さ=100
OK  **長すぎる文字は拒否** — CONFIG_ERROR
OK  **画面から呼べた** — 成功（戻り 0）
```

## out / inout の往復（実機）

`TESTLIB/PGMTST` を作って確かめた（`scripts/build-pgmtst.mjs`）。
**CL の `PARM` は参照渡し**なので 1 引数で inout を試せる。

```
OK  **inout の数値が往復する**（21 → 42）
OK  **負の値も往復する**（-1.5 → -3）
OK  **小数も往復する**（0.00003 → 0.00006）
```

**負と小数を分けたのが要点**——符号ニブルの取り違えは負でしか、
桁合わせの取り違えは小数でしか出ない。正の整数だけだと両方すり抜ける。

## サービスプログラム（`QZRUCLSP` 経由）

**新しい電文は要らない。** IBM i は `QSYS/QZRUCLSP` という普通のプログラムを提供していて、
そこへ「どのサービスプログラムの、どの手続きを」を渡すと呼んでくれる
——**既存のプログラム呼び出しの上に載る**。

引数の配置は**資料が手元に無かったので実機で当てた**:

| 見つけたこと | 間違えるとどうなるか |
|---|---|
| **値渡し=1 / 参照渡し=2** | 逆でも**呼べてしまい、戻り値が 0 になる**（失敗しない） |
| **戻り値の器は戻り値が無くても渡す** | 省くと `MCH3601`（ポインタ不正） |

前者は特に厄介で、**エラーにならないので検査を書かないと気づけない**。

## 扱える範囲は実機で確定した

| | |
|---|---|
| 引数の形式 | **1（値渡し）と 2（参照渡し）だけ**。3 以上は `CPF226E` |
| 値渡し | **4 バイトまで**。超えると呼べてしまい**結果が 0 になる** |
| 戻り値 | **4 バイト整数まで**。8 バイト整数も浮動小数も壊れた値が返る |
| **逃げ道** | **参照渡しの出力引数**なら 8 バイト整数も浮動小数も正しく往復する |

**上限を超えたら断る。** 通すと呼べてしまい**結果だけが静かに壊れる**ので、
利用者は気づけない。

| **ポインタの戻り値** | **扱えない**。器を 16 バイトにしても先頭 4 バイトしか書かれず、呼ぶたびに違う値 |
| **手続き名の長さ** | **API 側に上限は無い**（4007 バイトの器で通る）。こちらの上限は 4000 |

> 「存在しない長い名前」で試すと `CPF226E`（見つからない）が返るだけで、
> **「送れたが無い」と「拒否された」を区別できない**。
> **実在する名前の後ろにゴミを付ける**形に変えて決着した。
