   出力スキーマの JSDoc と MCP 説明文の両方に書いた。

### nit

- `fetchAll` の終端判定を `want`（その回に要求した数）に変えたが、
  `want < blockSize` になるのは最後の要求だけなので**観測上は `blockSize` と等価**。
  それでも `want` と比べるのは意図として正しく、将来ブロック幅を動的に変えたときに壊れないため
  （decisions D2 に記録。ミュータントには数えていない）。
- `queryLimited` は `query` と組み立てが似ている（`acquire` → `prepareAndOpen` →
  `fetchAll` → `closeCursor`）。共通化はしていない——`query` は全件・LOB の順序・
  例外時の扱いが確立しており、共通化すると**両方の変更が互いに影響する**。

## 観点ごとの確認

| 観点 | 確認したこと |
|---|---|
| 要件適合 | requirement の完了条件 9 件すべてに対応（実機 8 項目＋単体 30 件） |
| 正確性 | 境界（0 行・上限未満・**ちょうど**・+1）／`limit <= 0`／LOB／打ち切り時の後始末／開けなかったときの占有 |
| 規約適合 | 実測を根拠にコメントへ残す・推測を書かない・**秘密を成果物に書かない**（検証は `passwordEnv`） |
| 保守性 | `query`（全件）とページング経路は**触らない**。新しい入口 1 つに閉じる |
| 影響範囲 | server 側の `query()` 直接呼び出しは**残っていない**（MCP と単発は `queryLimited`、ページングは `openQuery`）。`query` は core の公開 API とスクリプト・テストで使う |
