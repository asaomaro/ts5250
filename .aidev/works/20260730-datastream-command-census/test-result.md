# テスト結果: 実機で数え、0x13 の不備を直した

## 実機

| スクリプト | 確かめたこと | 結果 |
|---|---|---|
| `census-5250-commands.mjs` | 11 画面が使うコマンド | **83 レコード・未知 0 件**。`0x13` が QSH 退出で届く |
| `diag-qsh.mjs` | `0x13` の生バイトと、直した後の警告 | 形式を確認。**`expected ESC, got 0x0` が消えた** |

### 数えた結果（レコード先頭・正確）

`CLEAR_UNIT` 50 / `WRITE_TO_DISPLAY` 17 / **`SAVE_PARTIAL_SCREEN` 2** /
`WRITE_STRUCTURED_FIELD` 1 / **`RESTORE_PARTIAL_SCREEN` 1**。

**`ROLL`・`READ IMMEDIATE`・`READ SCREEN TO PRINT` は 1 件も届かなかった。**

### 見つけて直した不備

`0x13` の分岐が**パラメータ 5 バイトを読み飛ばしていなかった**ため、
続きを ESC と読み違えて**ホストが返した画像（WTD）と後続の READ を捨てていた**。

- 直す前: `QSH（退出）: expected ESC, got 0x0 — discarding rest of record`
- 直した後: 同じ操作で**警告なし**。F3 でメインメニューへ戻る（画面も確認）

**症状として見えていなかった理由**: F3 の直後にホストが別レコードで画面を描き直すため。
警告は出ていたが、E2E は画面の文字だけを見ていて気づけなかった
——**「画面が正しければ良い」では足りない**という例。
