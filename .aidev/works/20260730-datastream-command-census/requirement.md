# 要件: 未実装コマンドの一覧を「実機で数えて」進める

## 背景 / 課題

`.aidev/backlog/datastream-commands.md`（2026-07-30 新設）には、
**未実測**（`RESTORE PARTIAL SCREEN 0x13` / `ROLL 0x23` / `0x03` のパラメータの意味）と
**未実装**（`READ IMMEDIATE 0x72` / `0x83`、`READ SCREEN TO PRINT` 系）が並んでいる。

いずれも「実機で届いたのを見てから実装する」方針で止まっている。
**では実際に何が届くのか**——推測で実装を増やす前に数える。

## 目的 / ゴール

- **実機の画面が実際に使うコマンドを数え**、backlog の各項目に結論（届く／届かない）を書く
- 届いていた項目は**動作を確かめ、誤りがあれば直す**
- 届いていない項目は「この範囲では届かなかった」と根拠つきで残す（次の人が数え直さないため）

## スコープ

### 対象

- 実機の**読み取り専用の画面**を一巡し、コマンドの出現を数える
- 見つかった不備の修正とテスト
- backlog の更新（結論・根拠・再現手段）

### 対象外

- 届かなかったコマンドの**推測実装**（形式を推測で書かない方針を変えない）
- 利用者のデータを変える操作（DFU 等）

## 機能要件

- 数え方は**正確さの度合いを分けて出す**（先頭コマンド＝正確／実装の未知判定＝決定的／全走査＝参考）
- 相手は利用者の実機。**読み取り専用の画面だけ**を巡る
- 見つかった不備は、実機で採った**生バイトを根拠に**直す

## 完了条件 (受け入れ基準)

- [ ] 実機で一巡し、コマンドの出現を数えた（再現手段を残す）
- [ ] backlog の各項目に結論を書いた
- [ ] 届いていた項目の動作を確かめ、不備があれば直した
- [ ] 既存テストが通る

## 未確定事項 / 確認したいこと

- どの画面が `ROLL` を使うのか（そもそも使う画面があるのか）→ 数えて判断
