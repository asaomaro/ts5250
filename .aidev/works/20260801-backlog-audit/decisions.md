## D-B. 部分完了は `[x]` と `[ ]` を兄弟として並べる（親子にしない）

`aidev status` は行頭 `- [ ]`（`^- \[ \]`）を数える。
親子にすると**インデントした子は件数に入らず、残作業が backlog の集計から消える**。

「実装は済んだが実機確認が残っている」は別々に着手できる独立した作業でもあるので、
意味の上でも兄弟が正しい。

対象は 2 件——DES 経路（`hostserver.md:48`）と PUB400 以外での検証（`:172`）。

## D-C. `hostserver.md:283-284` の誤帰属を直した（**スコープの逸脱**）

⚠ **requirement の対象外に触れている。レビューで戻せるようにここに明記する。**

ロケーター解放の項目に、こういう子項目が付いている:

```
- [ ] ロケーターの明示的な解放（接続を閉じれば消えると見込んでいるが未確認）
  - 実機確認は `MCH0802`（パラメータ数不一致）までで、**呼び出し経路が通ることしか確かめていない**
```

`MCH0802` は `host_call_program` の実測結果で（`20260719-hostserver-mcp-tools/test-result.md:49`）、
ロケーター解放とは無関係。**別項目の内容が紛れ込んでいる。**

**判断**: `:268`（`host_call_program` の項目）へ移す。

**根拠**: requirement の対象外は「未着手と判定した項目の**内容の書き換え**
（優先度の付け直し・分割・削除・言い回しの改善はしない）」で、列挙されたどれにも当たらない。
子項目を**逐語のまま正しい親へ移す**だけで、内容は書き換えない。

**放置しなかった理由**: 「ロケーター解放は実機で途中まで確かめた」と読めてしまう。
台帳を正しくするのが本作業の目的なので、既知の誤りを残すのは目的と衝突する。

**戻し方**: この移動だけを revert すれば元に戻る（他の変更と独立している）。

## D-D. `AGENTS.md` の「DBCS 欄が行末をまたぐとき全角の右半分が描けない」は**触らない（保留）**

コードは ACS 準拠として書かれている:

- `ScreenGrid.vue:1381`「クリップされ左半分が行末に出る）、次スライスは空白 1 桁で始める**＝ACS の桁割りと一致させる**」
- `ScreenGrid.vue:3356`「対を失った全角セル。1 桁の箱に入れて左半分だけ見せる（**ACS と同じ分断された見え方**）」

つまり「右半分が描けない」は**不具合ではなく意図した挙動**とも読める。

**判断**: それでも閉じない。`20260726-dbcs-orphan-lead-clip` が扱ったのは
「**tail が上書きされた lead**」であって「**行末またぎ**」そのものではない。
行末またぎを実機で確かめた記録が見つからなかった。

requirement の制約「**実機が要る項目を推測で閉じない**」に従い、判定を保留する。
次に触る人へ: 実機で行末またぎを 1 画面確かめれば、閉じるか書き換えるかが決まる。

## D-E. 完了注記の書式はファイルごとの既存慣例に合わせる（全体で統一しない）

backlog には 2 書式が共存している——`hostserver.md:205` の `→` 継続行と、
`library-extraction.md:23` の `- **完了**` 子項目。

**判断**: 片方に寄せない。同じファイル内で書式が混ざるほうが読みにくく、
既に閉じてある項目の書き方を変えるのは**未着手でない項目に触る**ことになりスコープ外。

## D-F. 根拠は works slug ＋ PR 番号 ＋ リポジトリ内の裏取りの 3 点

PR 番号だけだと後から辿るのに GitHub が要る。**リポジトリだけで裏が取れる形**にする。
実測値がある項目は数値を書く（「速くなった」ではなく「1,407,469 → 358,354 バイト」）
——次に測る人が基準線を持てる。
