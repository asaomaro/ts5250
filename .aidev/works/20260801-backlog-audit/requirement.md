選んだ項目（`library-extraction.md` の「CCSID テーブルの同梱単位を見直す」）が
**既に実装済み**で、書くべき requirement が存在しなかった。

### これは全面的な腐りではない

未着手 41 件の大半は注記が丁寧に維持されており、「開いたままである理由」が書かれている。

- `hostserver.md:225`「`executeImmediate` が `-215` で拒まれる理由」→「実用上は不要。通す動機が無いので追っていない」
- `hostserver.md:233`「MCP の `host_sql` から非クエリ文を実行させるか」→「方針の判断なので勝手には広げていない」

つまり問題は個別の項目ではなく、**deliver 工程に backlog を閉じる経路が無い**ことである。
`20260726-ccsid-table-bundling` も `20260720-csv-upload-ui` も、成果を backlog に書き戻していない。
チェックボックスが実態から遅れる → 次に着手する人が**完了済みの項目を選んでしまう**。
今回まさにそれが起きた。

同じ性質の消し込みは過去にも単発で行われている（PR #209 `docs/field-input-backlog-sync`、
PR #74 `docs/backlog-after-sql`）。単発で気づいたときに直しており、仕組みになっていない。

## 目的 / ゴール

**backlog を「今の実装状況を正しく写した選択台帳」に戻し、同じ取りこぼしが再発しない形にする。**

- 未着手として並んでいる項目が、本当に未着手であること。
- 完了済みの項目は、チェック済みかつ**何によって完了したか**が追える形になっていること。
- 次に deliver する人が backlog を閉じる手順を持っていること。

## スコープ

### 対象

- `.aidev/backlog/*.md`（`archive/` を除く 8 ファイル）の**未チェック項目 41 件すべて**
  - 各項目をリポジトリの実装・テスト・works の deliver 状況と突き合わせて完了/未着手を判定する
  - 完了済みならチェックし、根拠（PR 番号 / works slug / ファイル:行 / 実測値）を併記する
- `AGENTS.md` の `## 残課題（retro → issue 候補）` の 5 項目（同じ性質の台帳なので併せて照合する）
- 再発防止の記述（deliver 時に backlog を閉じる手順を PJ 規約として残す）

### 対象外

- **コードの変更**（本作業は記録の同期であって実装ではない）
- **未着手と判定した項目の内容の書き換え**（優先度の付け直し・分割・削除・言い回しの改善はしない）
- **新しい backlog 項目の起票**（実装を照合する過程で気づいたことがあっても、
  ここでは足さない。必要なら `aidev-util-propose` で別途）
- `.aidev/backlog/archive/` の内容
- aidev harness 本体（`.claude/skills/aidev-*`）の変更——**リポジトリ外にあるため
  この PR には含められない**。PJ 側に置ける形（`AGENTS.md`）で残す
- 既にチェック済み（`- [x]`）の項目の再検証

## 機能要件

- 未チェック 41 件すべてについて、完了/未着手の**判定と根拠**が記録される
  （判定を保留した項目があるなら、保留した理由も残す）
- 完了と判定した項目は `- [ ]` → `- [x]` になり、直下に完了の根拠が書かれる
- 起票当時の記述で**事実と食い違うもの**は、消さずに経緯として残す
  （PR #209 の前例に倣い取り消し線を使う）
- 未着手と判定した項目は、チェック状態も本文も変わらない
- `AGENTS.md` に、deliver 時に backlog を閉じる規約が書かれる

## 非機能要件 / 制約

- **判定は実測で行う**。works の requirement/review に「完了」と書いてあっても、
  それだけを根拠にせず**リポジトリの現物**（ファイル・シンボル・テスト・ビルド出力）で裏を取る
  （今回、backlog の「2026-07-27 追記」を信じていたら誤った requirement を書いていた）
- **実機（IBM i）を要する検証項目は「未着手」のまま残す**。ここで閉じられるのは
  リポジトリ内で裏が取れるものだけで、実機確認が要る項目を推測で閉じない
- コード変更ゼロ（docs のみの PR）
- 秘密情報を書かない（AGENTS.md「セキュリティ」の `.aidev` 成果物に関する規約）

## 未確定事項 / 確認したいこと

本作業は autonomous のため、判断は `decisions.md` に根拠つきで記録し、PR をレビュー地点とする。

- **41 件のうち何件が実際に閉じられるか**は照合してみないと分からない。
  research 工程で全件を突き合わせ、その結果を spec の入力にする
- **「完了」の線引き**——項目が複数の要素を含む場合（例「テーブル選択 → CSV ダウンロード、
  CSV をドロップしてアップロード」）に、一部だけ実装済みならどう書くか。
  PR #209 は「未実装で残るのは Field− / Field+ だけなので、そこだけ未チェックにした」＝
  **項目を割って部分的に閉じる**やり方を採っている。これに倣うかを spec で決める
- **AGENTS.md のどこに規約を置くか**（`## 残課題` の近くか、新しい節か）
