# 要件: 定義ベースの一覧（プリンター／待ち行列）

## 背景 / 課題

`20260801-printer-session-residency`（PR #252）で入れた `GET /api/printers` は
**実行中のものしか出さない**。設計整理で決めたモデルでは、これでは足りない。

> **サービス ✅ ＋ 自動で待ち受け開始 ☐** の場合、サーバー起動直後は**何も動いていない**。
> それでも画面に出て「開始」を押せないと、そのサービスは永久に起動できない。
> つまり一覧は **定義 ＋ 実行状態** でなければならず、実行中インスタンスの列挙では足りない。

`20260801-service-start-stop`（PR #254）で `stopped` が実装され、
**停止しても一覧に残る**ようになったが、それは「一度開いたもの」に限られる。
**一度も開いていない定義**は依然として出てこない。

## 目的 / ゴール

**定義を行として並べ、それぞれの実行状態を添えて返す。**
画面がこれを土台に開始/停止ボタンを置ける状態にする。

## スコープ

### 対象

- `GET /api/printers` を**定義ベースに作り直す**（`sessionType === "printer"` の定義）
- `GET /api/watches` を**新設**（`sessionType === "dtaqwatch"` の定義）
- 各行に**実行状態**（`stopped` / `listening` / `reconnecting` / `error`）を添える
- **一度も開いていない定義**も `stopped` として出る
- 定義に**サービス ✅** と**自動で待ち受け開始**が付いているかを出す

### 対象外

- サーバー起動時の自動開始（次）
- 画面（その次）
- 定義の作成・編集（既存の `/api/sessions-config`）
- 待ち行列 UI の能動/受動の分離、サービスの sink

## 機能要件

- **定義が行**。一度も開いていないものも出る
- 実行中のものは**状態と実績**（受信数・警告など）が添う
- **信頼設定の中身は出さない**（`autoPdfDir` のパス・`autoPrint` のプリンター名）。
  「サービスか」「出力設定を持つか」までに畳む
- **所有で絞る**（定義の可視性は既存の `listSessions(user)` の規則に委ねる）
- 直接接続（定義を持たない）のプリンターは**この一覧に出さない**——
  画面のセッションタブが持つもので、サービスの一覧ではない

## 非機能要件 / 制約

- 認可はルートに条件分岐を書かず、既存の規則（`listSessions(user)` /
  `listPrinters(user)` / `WatchRegistry.list(user)`）に委ねる
- プリンターと待ち行列で**同じ形**にする（並べて読めること自体が価値）
- 既存テストが通ること

## 完了条件 (受け入れ基準)

- [ ] `GET /api/printers` が**定義**を返し、一度も開いていないものが `stopped` で出る
- [ ] `GET /api/watches` が同様に動く
- [ ] 実行中のものに状態と実績が添う
- [ ] 信頼設定の中身が出ない
- [ ] 一般ユーザーには自分に見える定義だけ
- [ ] 直接接続のプリンターが出ない
- [ ] `npm run build` / `npm run lint` / `npm test` が通る
