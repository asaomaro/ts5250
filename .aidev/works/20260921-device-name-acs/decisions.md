# 決定記録

## D1: 使用中は繋ぎ直さず、同じ接続の中で答え直す（`retryWithNextDeviceName` を破棄）

- 背景: `deviceNameRetry` は「ホストは理由を返さずソケットを閉じる」前提で繋ぎ直していた。実測ではホストは 8902 を返し、同じ接続で聞き直してくる（F4・F5）。
  ACS の `=` もこの聞き直しに答える作り。
- 決定: 繋ぎ直しの輪を撤去し、生成器が聞き直しに答える。8902 以外（誤ったパスワード等）は答え直さないので、サインオンの失敗回数を無駄に使わない。
  旧い前提（「理由を返さず閉じる」）は `session.ts`・`startup-reject.test.ts` の注記で取り消し線。

## D2: 記号の無い名前が使用中なら従来どおり拒否する

- ACS は同じ名前を送り直すだけで繋がらない（F5）。当 PJ は 8902 で理由つきの拒否を返す（繋がらないという結果は同じで、理由が見える）。

## D3: `&COMPN` / `&USERN` はサーバーの機械名と、開いた人の利用者名

- ACS は ACS が動く機械の名前と OS の利用者名。当 PJ で ACS の役をするのはサーバーなので機械名はサーバーの名前（Windows は `CLIENTNAME` を先に見る）。
  利用者名は、認証が有効なら開いた人のアプリの利用者名、無効ならサーバーの OS の利用者名（1 人で使う形＝ACS と同じ）。ブラウザの機械名はサーバーからは取れない。

## D4: `*` は `A`

- ACS の GUI はセッションに名前（A・B…）を付けるが、GUI を使わないコアでは測れない（プローブでは名前が無く `A`）。当 PJ のセッションには当たる名前が無いので `A` にした（未確認）。
  同じパターンで `*` だけを使うセッションを 2 本開くと同じ名前になる——`=` を足せば答え直しで分かれる。
