# 要件: 装置名を ACS と同じく展開・大文字化し、使用中なら同じ接続の中で答え直す

## 背景 / 課題
- 台帳「【まとめ】telnet・自動サインオン・装置名の差」の装置名（中）。ACS は装置名（Workstation ID）の置換記号（`*` `%` `=` `+` `&COMPN` `&USERN`）を
  展開して大文字にする（`AutoDeviceName5250`）。当 PJ は書いたとおりに送っていた。
- 当 PJ の `deviceNameRetry` は理由を問わず繋ぎ直して再試行していたので、誤ったパスワードで何度も繋いでサインオンの失敗回数（QMAXSIGN）を使い切る恐れがあった。

## 目的 / ゴール
- ACS の装置名の書き方がそのまま使え、ACS と同じ装置名で繋がる状態。使用中の装置名で、失敗回数を無駄に使わない状態。

## ユーザーストーリー
- US1: ACS から移る利用者として、ACS のセッション設定の装置名（`&COMPN*` など）をそのまま使いたい。なぜなら、装置名はホスト側の設定（印刷先・ジョブ名）に効くので変えられないから。（受け入れ: AC1, AC2）
- US2: 装置名を繰り上げる設定を使う利用者として、パスワードを間違えたときに何度も試されたくない。なぜなら、利用者プロファイルが使えなくなるから。（受け入れ: AC3）

## スコープ
### 対象
- 置換記号の展開・大文字化（表示・プリンター）、使用中（8902）で同じ接続の中で答え直す、`deviceNameRetry` を同じ経路に載せる、`&COMPN` / `&USERN` の値をサーバーから渡す。
### 対象外
- ACS の GUI のセッション名（`*`）の割り当て（GUI を使わないコアでは測れない。当 PJ は `A`）。3270・VT の装置名（LU 名は別の仕組み）。

## 完了条件 (受け入れ基準)
- [ ] AC1: 装置名は ACS と同じ規則で展開・大文字化して送る（実測した規則: 大文字化、`%`、`*`、`&` での文字落ち、`+` の左右、`=` の番号）。
- [ ] AC2: `=` を含む名前は、使用中（8902）のとき同じ接続の中で次の番号で答え直して繋がる。記号の無い名前は 8902 で断る。
- [ ] AC3: `deviceNameRetry` は 8902 のときだけ、同じ接続の中で繰り上げて答え直す（繋ぎ直さない。8902 以外は答え直さない）。
- [ ] AC4: 各判定を外すとテストが落ちる（`verify-by-mutation`）。
