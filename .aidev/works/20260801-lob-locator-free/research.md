# 調査: LOB ロケーターの解放（0x1819）

**実機（IBM i 7.3・平文）**。再現は `scripts/research-lob-free.mjs`
（表 `TESTLIB.LOBFREE` を作り直す）。

## F1. 解放は効く

```
ロケーター=256
解放前: 取得できた（200 バイト / ccsid=5035）
freeLob → true
解放後: PROTOCOL_ERROR ... rcClass=2, code=-815
```

解放後に同じロケーターを引くと **`-815`**（そのロケーターは無い）。
既存のエラー文言が「別接続で使った」ことを示唆するが、**解放後も同じコードが返る**
——`-815` は「接続をまたいだ」ではなく「**そのロケーターは無い**」という意味だと分かった。

## F2. 二重解放は `rcClass=2 / -816`——**原典のコメントとは違う値**

```
1 回目 → true
2 回目 → false（rcClass=2, code=-816）
```

原典（`JDLobLocator.free()`）のコメントは `7,-401` を「既に解放済み」の合図として挙げるが、
**実機は `2 / -816`**。原典自身が
`host now has various errors if locator is already freed` と書いており、
**ホスト・版数で変わる**。よって**どちらも「もう無い」として同じ扱い**にした。

## F3. 接続を閉じればロケーターは消える

```
### 3. 接続を閉じてから、別の接続で同じ番号を引く
  ロケーター=256（1 つ目の接続で採取）
  別接続: rcClass=2, code=-815
```

## F4. ロケーター番号は接続ごとに配り直される

```
### 4. 解放せずに接続を閉じる
  解放せずに閉じた（ロケーター=256）
  新しい接続で採り直すと 256
```

解放せずに閉じても、次の接続で**同じ番号 256 が配られる**。
ホスト側でロケーターが接続スコープの資源として管理され、**接続の終了で回収されている**証拠。

## 結論

**単発接続のこのプロジェクトでは、明示的な解放は要らない**（F3 / F4）。
ただし**長い接続の中で大量の LOB を引く**利用者には要る資源なので、
ライブラリの口として実装だけ残す。
