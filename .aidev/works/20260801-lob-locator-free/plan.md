# 計画: LOB ロケーターの解放

## subtask 分割の判定

**分割しない**。実装 3 ファイル・テスト 1・スクリプト 1。

## 実装方針

要求形式は PR #243 で原典から確定済みなので、**実装 → 実機で確かめる**の順で足りる。
確かめたいのは形ではなく**効果**（本当に解放されるか / 接続を閉じれば済むか）。

## 作業順序と依存関係

1. **T1** `DB_REQ.freeLob` と `freeLob` の実装
2. **T2** `index.ts` から公開（依存: T1）
3. **T3** 実機スクリプトで 4 点を測る（解放が効くか / 二重解放 / 別接続 / 番号の配り直し）（依存: T2）
4. **T4** 実測に合わせて「既に解放済み」の戻りコードを直す（依存: T3）
5. **T5** 単体テスト（依存: T4）
6. **T6** build / lint / test（依存: 全部）

## リスク / 留意点

- **自動解放を入れない**。入れると `20260801-sql-lob-failed-state` で決めた
  「ロケーターは取り直す手がかり」が死ぬ
- **原典のコメントを鵜呑みにしない**。「既に解放済み」の戻りコードは実測で確かめる
  （実際に違った）
- 実機に表を作るが、`TESTLIB` のフィクスチャなので既存の流儀どおり

## テスト方針

- **単体**: 要求の形（reqId・CP・ORS・4 バイトのハンドル）と、戻りの扱い
  （0→true / -816・-401 は静かに false / それ以外は warn / 例外も握る）
- **実機**: 解放の効果・二重解放の戻りコード・接続を閉じた後・番号の配り直し
- **回帰**: `fillLobs` に手を入れていないので既存テストは無変更で通る
