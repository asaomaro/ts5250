# 要件: WEA（0x12）の否定応答を ACS と同じにする

## 背景 / 課題
`.aidev/backlog/acs-parity.md` の「否定応答・受理の残り（WTD の中）」の「WEA の属性の値（0x1005012D / 0x1005012F / 0x1005012A）」と、【まとめ】DS5250 のその他の差の「WEA タイプ 5 の残り（SBCS のセッションの否定応答）」。
ACS `PS5250.writeExtAttribute` はタイプ 5（DBCS のセッションだけ）しか受けず、それ以外は否定応答で WTD を打ち切る。当 PJ は警告して読み飛ばし、後ろのオーダーを続けて適用する。

## 目的 / ゴール
WEA を受けたときの否定応答・画面・CC2 が ACS と同じになっている状態。

## ユーザーストーリー
- US1: 5250 端末の利用者として、ホストが扱えない WEA を送ったとき ACS と同じ否定応答を返してほしい。なぜなら ACS はそこで WTD を打ち切ってホストに誤りを知らせ、当 PJ だけが後ろを描き続けると画面とホストの認識が食い違うから。（受け入れ: AC1, AC2）

## スコープ
### 対象
- core `wtd-applier.ts` の WEA
### 対象外
- WEA タイプ 5 を受けたときの区間の扱い（`20260921-g-field-sosi` で済み）

## 機能要件
- 今の位置が画面の外 → 0x1005012A / タイプが 5 でない・SBCS のセッションのタイプ 5 → 0x1005012D / タイプ 5 の値が 0x81・0x80・0x00 でない → 0x1005012F（検査の順も ACS と同じ）
- いずれも WTD を打ち切り、CC2 は効かせる（既存の否定応答と同じ）

## 完了条件 (受け入れ基準)
- [ ] AC1: 実機の ACS のコアで 4 通り（タイプ 1・タイプ 5 の不正な値・EA の後の画面の外・SBCS のセッションのタイプ 5）のセンスと画面を採り、当 PJ の単体テストで固定する
- [ ] AC2: 実機で当 PJ を当てて同じ（`scripts/verify-wtd-order-sense.mjs`）
- [ ] AC3: 片付け（両方の実機の DSCMD と IFS）
