# 要件: J（DBCS 専用）欄の詰め物を全角空白にする（離れた空きへ打っても送れる）

## 背景 / 課題
- `20260921-g-field-sosi` の調査で見つかった。J の欄に `あ` が入っていて、離れた空き桁へ `い` を打つと、編集の値が `あ   い`（半角空白 3）になる（詰め物が半角空白）。
  実機に繋いだ core は J の欄の半角空白を「全角しか入力できない」（FIELD_TYPE）で弾く（`あ   い` は弾かれ、`あ　　　い` は通ることを確かめた）ので、送信で止まる。
- ACS の J の空きは全角空白（0x4040）で、打った字は 2 桁ずつの桁に入る（`20260921-g-field-sosi` で G と J を実機で確かめた）。

## 目的 / ゴール
- J の欄のどの空き桁へ打っても、値に半角空白が混ざらず、そのまま送れる状態。

## ユーザーストーリー
- US1: 日本語の入力欄を使う利用者として、欄の途中の空きへ字を打っても、Enter で送れてほしい。なぜなら、エラーで止まると、打ち直しになるから。（受け入れ: AC1〜AC3）

## スコープ
### 対象
- J の欄の編集の詰め物（`padDbcs`）と、値の末尾の詰め物の落とし方（`trimPad`）。
### 対象外
- E・O の欄（空きは半角空白。SBCS が混ざれる）。J の送信の形（ホストが整えるので変えない）。

## 完了条件 (受け入れ基準)
- [ ] AC1: J の離れた空き桁に打った値に半角空白が含まれない（`あ　　い`）。
- [ ] AC2: 空きが NUL のホストの J を触っただけでは編集にならない。値の末尾の詰め物は落ちる。
- [ ] AC3: E・O の詰め物・値の落とし方は変わらない。各分岐を外すとテストが落ちる（`verify-by-mutation`）。
