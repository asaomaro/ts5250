# 計画: 待ち行列サービスの非対称性を直す

## 作業順序と依存関係

1. `register()` を足し、`start()` をその上に組み直す
2. `resume()` の失敗を `error` として残す（依存: 1）
3. `service-reconcile.saveWatch` を「登録 → 開始」に（依存: 1, 2）
4. 既存テストの更新（状態イベントが 1 つ増える・失敗時に実体が残る）
5. 実機の通し

## リスク / 留意点

- **手動開始の契約を変えない**（最初の接続は待つ）。変わるのは実体が残ることだけ。
- **状態イベントが 1 つ増える**（`stopped` → `listening`）。既存テストが並びを見ているので、
  意図した変化として書き換える——数合わせにしない。
- `register` でイベントを配ると購読テストに雑音が入る。配らない。

## テスト方針

- **単体**: 失敗しても一覧に残り理由が読める／枠を食わない／状態の並び
- **実機**: `verify-browser-watch.mjs`（監視の通し 16 件）
