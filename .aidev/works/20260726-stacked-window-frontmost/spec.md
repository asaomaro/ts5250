# 仕様: 重なった窓から前面を選ぶ

## 概要

`detectWindowRect` の経路を「最初に当たった方を返す」から「**両方の候補を見て前面を選ぶ**」に変える。

```
1. gui.windows があればそれ（従来どおり最優先）
2. 罫線枠と反転枠の**両方**を探す
   - 両方あり かつ 反転枠が罫線枠の内側 → **反転枠**（前面）
   - それ以外 → 罫線枠 → 無ければ反転枠
```

## 設計方針

### 方針 1: 規則は実測で誤った 1 ケースだけに絞る

実測 5 パターンのうち誤るのは「**前面が後ろの内側に収まったとき**」だけ。前面が後ろの枠を壊す位置なら
壊れた側が検出されず、今のコードでも正しく前面が選ばれる。よって規則をそのケースに限定する。

**罫線経路の許容度（重なり率 80%・縦罫の半数以上）には触らない。** あれは実データ（F1 ヘルプ）で
上下端が対にならない問題を解くために入っており、締めると別の回帰を生む（既存コメントの経緯）。

### 方針 2: 「内側」は完全包含で判定する

```ts
const inside = (a: WindowRect, b: WindowRect): boolean =>
  a.row1 >= b.row1 && a.row2 <= b.row2 && a.col1 >= b.col1 && a.col2 <= b.col2;
```

部分的な重なりは扱わない。実測では Attn 窓（行18-23/桁24-78）がヘルプ窓（行6-23/桁17-78 等）に
完全に収まっていた。部分重なりのときは前面がどちらか判断できないので、従来どおり罫線枠を返して
**挙動を変えない**（安全側）。

### 方針 3: 反転枠の検出を常に走らせる

これまでは罫線枠が空振りしたときだけ走っていた。両方を比べるため常に走らせるが、
**反転が 1 つも無い画面は `runs.some(...)` で即 return** するので実測 14 画面のうち 13 画面は
コストがほぼゼロ（`#163` の実測）。

## 振る舞いの詳細

| パターン | 罫線枠 | 反転枠 | 内側? | 返す | 変化 |
|---|---|---|---|---|---|
| ヘルプのみ | あり | なし | — | 罫線枠 | なし |
| ヘルプ→Attn（file） | **壊れて無し** | あり | — | 反転枠 | なし |
| ヘルプ→Attn（lib） | あり | あり | **はい** | **反転枠** | **修正** |
| ヘルプ→Attn（opt） | あり | あり | **はい** | **反転枠** | **修正** |
| Attn→ヘルプ（逆順） | あり | **壊れて無し** | — | 罫線枠 | なし |
| Attn のみ | なし | あり | — | 反転枠 | なし |
