# 計画: メッセージ待ち行列の待ち受け

## 実装方針

**振る舞いを変えない作り替え（1〜2）→ 新機能（3 以降）**の順。
1〜2 の時点で既存 4,011 件が全部通ることを確認する——ここで落ちたら切り出しの誤り。

## 作業順序と依存関係

1. `WatchSource` / `WatchLink` を切り出し、dtaq を包む（依存: なし）
2. `WatchRegistry` を種類非依存にする（依存: 1）
3. `QMHRCVM` の組み立てと `RCVM0100` の読み取り（依存: なし）
4. `MsgqSource`（依存: 2, 3）
5. 設定・起動・反映の経路（依存: 4）
6. 画面（依存: 5）
7. 実機検証（依存: 6）

## リスク / 留意点

- **切り出しで既存の挙動を変えない**——特に `stopping` の印と `close()` の順序
- **本文の位置**を決め打ちしない（長さ項目から求める）
- **`QSYSOPR` を荒らさない**（`*SAME` で読むだけ。件数が変わらないことを確認する）
- 待ちが無限なので、**テストでは偽の `WatchSource`** を使う（実接続に依存しない）

## テスト方針

- 単体: `RCVM0100` の読み取り（境界・空・照会判定）、カーソルの前進、`onlyInquiry` の捨て
- 単体: `WatchRegistry` は**既存のテストがそのまま通る**こと（振る舞い不変の証明）
- 実機: 専用待ち行列で「届く / 二度出ない / 消えない / 照会だけ」、`QSYSOPR` は件数不変
