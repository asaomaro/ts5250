# ウォークスルー: メッセージ待ち行列の待ち受け

## 何ができるようになったか

**メッセージが届いたらブラウザへ push される。** 特に**照会**（応答しないとジョブが止まるもの）を
見落とさない。`QSYSOPR` を待ち受けておけば、誰かが画面を開くまで気づかない状態が無くなる。

## 使い方

セッション設定で種別に **メッセージ待ち受け** を選び、待ち行列を指定する:

```
ライブラリー   QSYS
待ち行列名     QSYSOPR
応答待ちだけ   [x]（照会だけ拾う）
既にあるぶんも [ ]（既定。始める前の数百件は流さない）
```

監視コンソールに並び、届いたものが履歴に出る。**応答待ちは色つきで目立つ**。
応答はメッセージ画面から（キーが付いているのでそのまま使える）。

## コミットの並び

1. `feat(hostserver): メッセージを 1 件受け取れるようにする` — `QMHRCVM` と `RCVM0200`
2. `refactor(server): 待ち受けの「待ち方」を差し替えられるようにする` — **振る舞い不変**
3. `feat(server): メッセージ待ち行列を待ち受けられるようにする` — 種類の追加
4. `feat(web-ui): 監視コンソールでメッセージの待ち受けを扱う` — 画面
5. `test(server): メッセージの待ち受けを実機で確かめる` — 27 項目

## 見どころ

### 1. 骨格を触らずに種類を足した

`WatchRegistry` の寿命・再接続・状態・履歴・所有・購読は**一切変えていない**。
種類ごとに違うのは「開く」「1 件待つ」だけなので、そこだけ `WatchSource` に切り出した。
**既存テスト 1,146 件が 1 行も変わらずに通る**のが、その証拠。

### 2. 消さない

`QMHRCVM` を `*SAME` で呼ぶ。**待ち受けは観測であって消費ではない**——
読んだメッセージは一覧に残り、照会には後から応答できる。
データ待ち行列の「消費するので本番に掛けるな」という注意は、**メッセージ側には出さない**
（出すと嘘になり、出し続けると本当に効く注意まで読み飛ばされる）。

### 3. 実機で 3 回設計が変わった

| 分かったこと | どうしたか |
| --- | --- |
| `RCVM0100` は**読める本文を返さない**（置換データだけ） | `RCVM0200` にした |
| **即時メッセージは置換データの側に本文が入る** | 長さが 0 なら置換データを本文として読む |
| **無限に待つと待ち行列が消せなくなる**（`CPF2451` が永久に続く） | 30 秒で区切る |

3 つ目が一番効いた。`DLTMSGQ` が通らなくなり、1 通投げたら解放された——
**待ち行列の保守が、誰かが待ち受けているだけで止まる**のは割に合わない。
通知の速さは変わらない（届いた瞬間に返る）ので、失うものは無い。

## 実機での確認（実機・27/27）

```
OK  **届いたら push される** — 届いたら知らせて
OK  **読んでもメッセージは消えない**（一覧に残る）
OK  **同じものが二度出ない** — 届いたら知らせて / 2 通目 / 3 通目
OK  **照会が照会として届く** — INQUIRY
OK  **照会だけに絞れる** — これは拾う
OK  **止めている間に届いたぶんも、再開すれば届く**
OK  **QSYSOPR の件数が変わっていない**（共有資源に触れていない） — 297 件
OK  **無い待ち行列は始まらない**（理由が返る） — CPF2403 / NOT_FOUND
OK  **待ち受けを止めたら待ち行列を消せる**（掴んだままにしない） — 30 秒で消せた
```

## ついでに直したもの

`host-message.ts`（PR #302）の制御文字判定に、**生の制御文字（NUL を含む）がそのまま埋まっていた**。
動いてはいたが、**`grep` がこのファイルを binary 扱いして黙って飛ばす**——
実際にこの作業中、当該ファイルの検索が空振りして混乱した。`\u0000` 形式のエスケープに直した。
