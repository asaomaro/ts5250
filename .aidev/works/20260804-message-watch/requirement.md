# 要件: メッセージ待ち行列を待ち受ける

## 背景 / 課題

`20260804-message-queue` で一覧・応答はできるようになったが、**気づく手段が無い**。

`QSYSOPR` に照会が入っても、**誰かが画面を開いて「読む」を押すまで分からない**。
応答しないとジョブは止まったままなので、**気づくのが遅れること自体が損害**になる。

既に**監視コンソール**（`WatchRegistry` / `WatchPane`）があり、データ待ち行列を
常駐で待ち受けて push している。**同じ仕組みに載せる**のが自然。

## 目的 / ゴール

**メッセージが届いたらブラウザへ push される。** 特に**照会**を見落とさない。

## スコープ

### 対象

- メッセージ待ち行列の待ち受け（`WatchRegistry` に 2 つ目の種類として足す）
- **照会だけを拾う**選択（雑音を減らす）
- 監視コンソールへの表示（既存の一覧・履歴に相乗り）

### 対象外

- 待ち受けからの**応答**（一覧の画面でできる）
- メール・Slack 等への転送
- プログラムメッセージ

## 機能要件

- **ポーリングしない**（既存の監視と同じ。無通信でブロックして待つ）
- 待ち受けても**メッセージを消さない**（一覧に残る。応答もできる）
- **同じものを二度出さない**（カーソルを進める）
- ブラウザを閉じても**待ち受けは続く**（サービス型。既存の規則）
- 落ちたら**指数バックオフで張り直す**（既存の規則）

## 非機能要件 / 制約

- 既存の 4,011 件を壊さない
- **`WatchRegistry` の寿命の規則を変えない**（明示停止かプロセス終了まで生きる）
