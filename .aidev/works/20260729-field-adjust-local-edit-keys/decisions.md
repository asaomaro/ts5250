# 決定記録

## D1. 右寄せは web-ui で行い、core では行わない

**決定**: FFW の ADJUST に基づく右寄せは端末側（`packages/web-ui`）で値を書き換えて実現し、
core は `snapshot().fields[].adjust` として**指定を伝えるだけ**にする。

**理由**: 実機で、英数字欄はホストが一切整形しないことを実測した
（`"12"` を送れば `"12    "` として格納される）。かつ実物の 5250 端末は**画面上の値を書き換える**。
core が送信時にだけ整形すると、画面には左詰めのまま出て送信値と食い違い、利用者から見て
「押したのに変わらない」状態になる。

**代替案**: `read-response.ts` の送信時に整形する。画面と送信値が食い違うので却下。

## D2. Erase EOF は右寄せしない（tn5250j と意図的に違える）

**決定**: Erase EOF は「カーソルから欄末尾までの消去」だけを行い、右寄せもフォーカス移動もしない。

**理由**: 唯一の参照実装である tn5250j は `ERASE_EOF` で `fieldExit()` をそのまま呼ぶため
右寄せまで走る（`Screen5250.java:951-979`）。しかしこれは `fieldExit()` の使い回しによる副作用に見える
——**消しただけで残った文字が右へ飛ぶのは操作として不自然**で、カーソルは元の位置に戻されるので
文字とカーソルの関係も崩れる。PJ の backlog は Erase EOF を「Field Exit の①だけ」と定義しており、
そちらを採る。

**リスク**: ACS の実挙動が tn5250j 側だった場合に食い違う。ACS で確かめられていないため、
backlog に「要実機確認」として残す価値はあるが、現状は不自然でない方を既定とする。

## D3. 符号付き数値欄は ADJUST 無指定でも空白で右寄せする

**決定**: `shift == signed-num（0x0700）` の欄は ADJUST 指定より優先して空白で右寄せし、
**最終桁（符号桁）は動かさない**。

**理由**:
- 参照実装 2 つが一致してそうしている（GNU tn5250 `display.c:1138-1141` は `mand_fill_type` を
  無条件で `RIGHT_BLANK` へ差し替え、tn5250j は `adj===0 && isSignedNumeric()` で同じ）
- **実機の DDS 数値入力欄は `6 0`（ゾーン）も `6S 0` も、ワイヤ上は signed-num・長さ = 桁数 + 1** で来る
  （実測）。この規則を入れないと、数値欄で Field Exit がまったく効かない
- **退行リスクが無いことを実測で確認した**: ホストは左詰めで送っても右詰めで送っても同じ値
  （`12`）に解釈する。つまり採用しても送信結果は壊れず、画面表示だけが実機に近づく

**適用範囲の限定**: 発火するのは**新設の Field Exit キーだけ**。Tab / Enter / 通常入力の経路は
変更していないので、既存の操作感は変わらない。

## D4. 数値欄の内容検証は trim してから判定する

**決定**: `field-validate.ts` の数値欄許容判定を `value.trim()` に対して行う。

**理由**: D3 と `right-blank` は値の左に空白を作る。従来の `/^[0-9.,+-]*$/` は空白を弾くため、
**自分で整形した値を自分で送信できない**（`FIELD_TYPE` になる）。前後の空白は桁合わせの padding で
あって入力文字ではない。埋め込みの空白（`"1 2"`）は `trim` で消えないので従来どおり拒否される。

## D5. 既定バインドは「版ごとの増分」で混ぜる（既存バグの修正を含む）

**決定**: `ADDED_BY_VERSION` を導入し、保存済み版より後に追加された既定だけを混ぜる。

**理由**: 従来の `load()` は版を上げると `{ ...DEFAULT_BINDINGS, ...saved }` で**全既定を混ぜ直す**ため、
既定を 1 つ足すだけで**利用者が消した既存の既定まで復活**していた（同ファイルの
「消したら消えたまま」というコメントに反する）。本 work は既定を 3 つ足すので、先に直す。

## D6. DBCS 欄では右寄せしない

**決定**: `dbcsType` を持つ欄では Field Exit の消去と欄移動だけを行い、右寄せしない。

**理由**: 全角は SO/SI と 2 バイトで桁を占めるため、桁単位で寄せると対を壊しうる。
実機で DBCS 欄に ADJUST が付く構成を確認できていないので、**分からないものを整形しない**側へ倒す。

## D7. `advanceIfFull`（打鍵で満杯 → 自動送り）は触らない

**決定**: 既存の自動送り経路に adjust を挟まない。

**理由**: 原典は満杯時にも adjust を通すが、**満杯の欄は右寄せしても 1 桁も動かない**
（末尾が非空白なら無変化、という原典のアルゴリズムそのもの）。実害が無いのに既存の
入力経路へ手を入れると退行リスクだけが増える。

## D8. `Field.signedNumeric` は optional にする

**決定**: `signedNumeric?: boolean` とし、true のときだけ付ける。

**理由**: 必須にすると `Field` を組み立てている既存テストのフィクスチャ約 40 か所へ
`signedNumeric: false` を足すことになり、本質的な差分が埋もれる。`dbcsType?` / `adjust?` と同じく
**当てはまるときだけ付ける**というこの interface の既存規約に合わせた（`false` は情報を持たない）。

## D10. Field Exit で MDT を立てるのは「値が変わったとき」だけ（原典と意図的に違える）

**決定**: Field Exit は `sync()` を通すので、**値が変わったときだけ** `emit("edit")` が出て MDT が立つ。
値が変わらない Field Exit（例: 欄末尾にカーソルがあり消すものも寄せるものも無い）は MDT を立てない。

**理由**: 原典は `tn5250_display_field_adjust` の末尾で `tn5250_field_set_mdt(field)` を**無条件に**呼ぶ。
しかしこの PJ には「**カーソル移動だけで MDT にしない**」という先行決定があり
（`ScreenGrid.vue` の `baselineValue` / `sync`）、理由も明確——MDT を立てると欄がホストへ送り返され、
**SEU の埋め込み色属性が失われる**という実害が過去に出ている。無条件 MDT はその実害を復活させる。

**影響**: 「何も変えずに Field Exit だけ押して欄を通過させ、ホストへ空の変更を通知する」という
使い方はできない。実用上これを必要とする画面は確認できていないため、実害のある側を避ける。

## D9. 修飾キー付きの Backspace / Delete / Home / End / Insert を欄内編集で消費しない

**決定**: `ScreenGrid` の欄内 keydown 処理に修飾キーガードを追加した（SBCS 欄・DBCS 欄の両方）。

**理由**: Ctrl+Delete / Ctrl+Backspace をローカル編集キーへ割り当てると、欄内ハンドラーが
素の Delete / Backspace として**先に処理してしまい二重に効く**（1 文字消えたうえに全欄が消える）。
矢印キーが以前から同じ理由で修飾キーを除外しているので、その扱いに揃えた。
これは本 work で新設したキーに限らず、**利用者が任意の修飾キー付きバインドを作ったときにも効く**修正。
