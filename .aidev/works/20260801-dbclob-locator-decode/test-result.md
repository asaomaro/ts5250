## 触っていないことの確認

**混在 CCSID の CLOB（5035）は元から正しく、修正後も同じ**:

| 値 | 返り値 | byteLength | 申告長 |
|---|---|---|---|
| `日本語` | `"日本語"` | 8 | 8（バイト数。SO/SI 込み） |
| `全角混在ab` | `"全角混在ab"` | 12 | 12 |
| `a` | `"a"` | 1 | 1 |

**インライン経路（PR #245）にも回帰なし**——しきい値 65,536 で
`日本語` / `全角混在ab` が正しく返ることを再確認した。

## 受け入れ基準ごと

- [x] 実機で 3 値すべて**文字列として正しく**返る
- [x] `byteLength` が実バイト数（6 / 12 / 2）
- [x] CCSID 判定が 1 か所（`db-decode.ts`）に集約された。`query.ts` のローカル実装は削除
- [x] CLOB / BLOB の既存挙動が変わらない（実機・単体の両方）
- [x] 単体テスト 8 件が単位と復号を固定
- [x] build / lint / test 通過

## 未検証の穴

- **純 DBCS の DBCLOB（CCSID 16684 / 300 など）は実機で試していない**。
  `isTwoByteCcsid` は含めているが、実際にその CCSID の DBCLOB 列を作って測っていない
  （単体テストは判定関数のみ）
- **64KB を超える DBCLOB で分割受信が跨いだ場合**は試していない。
  今回の値はすべて 1 応答に収まる。`perChar` は繰り返しの中で毎回求めるので
  破綻しないはずだが、**実測していない**
- **打ち切り（`too-large`）が DBCLOB で正しく出るか**は測っていない。
  `totalLength` の単位を直したので改善しているはずだが、確かめていない
- PUB400（7.5）では未確認
