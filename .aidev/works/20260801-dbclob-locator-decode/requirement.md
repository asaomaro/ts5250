# 要件: ロケーター経由の DBCLOB が壊れているのを直す

## 背景 / 課題

`20260801-lob-threshold-realhost`（PR #245）の F5 で見つけた欠陥。
**既定経路（しきい値 0＝ロケーター経由）で DBCLOB の中身が壊れる。**

実機（CCSID 1200 の `DBCLOB`）で生バイトまで確かめた:

| 値 | 期待 | 実際の返り |
|---|---|---|
| `日本語` | 3 文字 / 6 バイト | **`<bytes 3>`** |
| `全角混在ab` | 6 文字 / 12 バイト | **`<bytes 6>`** |
| `a` | 1 文字 / 2 バイト | **`<bytes 1>`** |

原因は 2 つ:

1. **長さの単位を取り違えている。** `lobData`（CP `0x380f`）の宣言長は
   **文字数**で届く（本体は 2 倍のバイト数で来ている）のに、`retrieveLob` は
   バイト数として `subarray(6, 6 + dataLength)` するので**半分に切っている**
2. **UTF-16 を復号していない。** `query.ts` の `decodeLob` は
   `codecForCcsid(1200)` を試して失敗し、バイト列のまま返す。
   `db-decode.ts` は同じ CCSID を `UTF16_CCSIDS` ＋ `decodeUtf16Be` で扱えており、
   **同じ判定が 2 か所にあって片方だけ正しい**

`20260801-lob-threshold-realhost` では**インライン経路**（しきい値以下）の
同じ取り違えを直した。**ロケーター経路にも同じ欠陥が残っていた。**

## 目的 / ゴール

ロケーター経由でも DBCLOB が**正しい文字列**で返るようにし、
**単位の判定と復号を 1 か所に集約**して同じ食い違いが再発しないようにする。

## スコープ

### 対象

- `retrieveLob` の長さの単位（2 バイト/文字の CCSID では文字数として扱う）
- `decodeLob` の UTF-16 / 純 DBCS 対応
- 判定の重複解消（`db-decode.ts` と `query.ts` に同じ CCSID 判定を書かない）
- 実機での検証と再現スクリプト
- 単体テスト

### 対象外

- **インライン経路**（PR #245 で対応済み）
- `errorFromReply` の CPF メッセージの CCSID（**別項目**として backlog にある）
- BLOB（CCSID 0）の扱い——バイト列のままで正しい

## 機能要件

- CCSID 1200 / 13488（UTF-16）と純 DBCS の DBCLOB が**文字列**で返る
- **バイト長が正しい**（`byteLength` が実バイト数）
- CLOB（SBCS / 混在）と BLOB の既存の挙動を変えない
- **打ち切り（`too-large`）の判定が単位の取り違えで狂わない**

## 非機能要件 / 制約

- 実資格情報を成果物・コミット・PR に書かない
- 既存テストが通ること

## 完了条件 (受け入れ基準)
