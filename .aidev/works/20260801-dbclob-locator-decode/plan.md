# 計画: ロケーター経由の DBCLOB を直す

## subtask 分割の判定

**分割しない**。実装 3 ファイル・テスト 1・スクリプト 1。

## 実装方針

**測る → 直す → 両経路で回帰を見る**。単位の取り違えは
「半分に切れる」という静かな壊れ方をするので、**生バイトを見てから**直す。

## 作業順序と依存関係

1. **T1** 実機で生バイトを採り、単位を確定する（DBCLOB と**混在 CLOB の両方**）
2. **T2** `isTwoByteCcsid` / `decodeLobBytes` を `db-decode.ts` に新設（依存: T1）
3. **T3** `lob.ts` の長さ換算（依存: T2）
4. **T4** `query.ts` のローカル `decodeLob` を削除（依存: T2）
5. **T5** 実機で再検証＋**インライン経路に回帰が無いこと**（依存: T3,T4）
6. **T6** 単体テスト（依存: T5）
7. **T7** build / lint / test（依存: 全部）

## リスク / 留意点

- **混在 CCSID の CLOB を壊さない**。元から正しいので、`perChar=1` で素通りすることを実機で確認する
- **インライン経路（PR #245）に回帰を出さない**。`research-lob-threshold.mjs` を回す
- **SBCS だけで確かめない**。単位の取り違えは全角でしか出ない（**2 回目の罠**）
- `totalLength` は CCSID より先に読まれる。**換算の順序**を間違えない
