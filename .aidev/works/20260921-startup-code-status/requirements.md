# 要件: 表示セッションの開始を ACS と同じく起動応答のコードつきで知らせる

## 背景 / 課題
- 台帳「起動応答 I901 を表示セッションで知らせる」（`20260921-associated-printer` research F7 から割った）。関連付けたプリンターの装置名が存在しないと、
  ホストは起動応答を I901 にして接続を通す（実測）。当 PJ の表示セッションは起動応答のコードを画面へ一切渡しておらず、利用者は何も知れない。
- ACS は接続のたびに状態行へ「<コード> - セッションを開始しました」の意味の文言を 3 秒出す（`AcsOnly.displayResponseCode`。I901・I902 とも。
  I901 では状態 37 で「仮想装置の機能が元の装置より少ない」の意味の文言も出すが、同じ処理の中ですぐ開始の文言に上書きされ、3 秒後に状態行は消える）。

## 目的 / ゴール
- 表示セッション（5250）が繋がったとき・繋ぎ直したときに、ACS と同じく起動応答のコードつきの開始の文言が一時的に見え、ⓘ でもコードを確かめられる状態。

## ユーザーストーリー
- US1: ACS から移ってきた利用者として、繋がったときに起動応答のコード（I902 / I901）を見たい。なぜなら、I901（関連付けたプリンターが無い等）に気づけるから。（受け入れ: AC1, AC2, AC3）

## スコープ
### 対象
- server: 表示セッション（5250）の `opened`（開く・後から入る）と `host-reconnected` に起動応答のコードを載せる。
- web-ui: 受けたら「<コード> - セッションを開始しました」の意味の文言を 3 秒だけ通知に出す（エラー状態には入らない）。ⓘ（セッション情報）にコードを出す。
### 対象外
- 失敗のコード（ACS の「応答コード: <意味>」）——当 PJ は開く前に日本語の理由で出している（`20260921-startup-codes-japanese`）。
- 3270・VT（起動応答が無い）。プリンター（既にサービス画面・ⓘに出している）。
- 状態行に出すソケットの情報（ACS の `getSocketResolveInfo`）。

## 非機能要件 / 制約
- ACS の文言は写さない（意味だけ借りて当 PJ で書く）。利用者に見える文言は `opMessages.ts` に 1 か所。

## 完了条件 (受け入れ基準)
- [ ] AC1: 5250 の表示セッションの `opened`（開く・後から入る）と `host-reconnected` に起動応答のコードが載る（起動応答が無ければ載らない）。
- [ ] AC2: web-ui は開いたとき・繋ぎ直したときに「<コード> - セッションを開始しました」の意味の文言を 3 秒出して消す（その間に別の通知が出たら消さない）。エラー状態には入らない。
- [ ] AC3: ⓘ に表示セッションの起動応答のコードが出る。
- [ ] AC4: 実機で I902・I901（存在しない装置名を関連付け）のコードが画面まで届くことを確かめる。
- [ ] AC5: 各判定を外すとテストが落ちる（`verify-by-mutation`）。
