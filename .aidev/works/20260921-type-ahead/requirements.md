# 要件: 施錠中・応答待ち中の打鍵を捨てずに溜め、解錠で再生する（先打ち）

## 背景 / 課題
Enter の直後に次のコマンドを打ち始めたり、Enter を続けて押したりすると、応答待ちの間の打鍵が
黙って捨てられ、入力の頭が欠ける（熟練者ほど踏む）。ACS は溜めて解錠後に再生する（既定で有効）。
利用者の判断: **A）ACS と同じく溜めて、解錠時に再生する**（台帳「方針決定」）。

## 目的 / ゴール
- 応答待ちの間に打ったキーが**失われず、打った順に効く状態**。

## ユーザーストーリー
- US1: 端末の利用者として、応答を待たずに次の入力を打ち始めたい。
  なぜなら ACS ではそうでき、当 PJ では頭が欠けて打ち直しになるから。（受け入れ: AC1, AC2）
- US2: 端末の利用者として、溜めた打鍵を取り消したい。なぜなら打ち間違えたまま再生されると困るから。（受け入れ: AC3）

## スコープ
### 対象
- web-ui のペインでの溜め・再生・破棄（キーボード・機能キーボタン）。
### 対象外
- ペースト・IME の変換中の打鍵（ACS 側が未確認）。
- READ の無いアンロック（台帳の別項目）。

## 機能要件
- FR1: 応答待ち（busy）・ホスト施錠（keyboardLocked）の間の端末のキーを溜める。解錠したら打った順に再生する。
- FR2: 再生中に AID を送って再び施錠したら止め、残りは次の解錠で続きから。
- FR3: Reset・Attn・SysReq・Help で溜めを捨てる。切断でも捨てる。Attn・SysReq はそのまま送る。
- FR4: 自動操作の予約中・マクロ再生中・システム要求行では溜めない（従来どおり捨てる）。
- FR5: Insert は溜めずにその場で挿入モードを切り替える（ACS と同じ）。

## 非機能要件 / 制約
- アプリの操作（Ctrl+C・タブ切替等）は溜めない。溜める量に上限を設ける。

## 完了条件 (受け入れ基準)
- [ ] AC1: 応答待ち・ホスト施錠の間に打った文字が、解錠後に欄へ入る。溜めた Enter・機能キーボタンが解錠後に送られ、打った値が載る。
- [ ] AC2: AID を再生して施錠したら止まり、残りは次の解錠で新しい画面へ入る。Enter の連打の 2 回目が送られる。
- [ ] AC3: Reset・Attn で捨てる（Attn は送る）。予約中は溜めない。切断で捨てる。Insert はその場で切り替わる。
- [ ] AC4: 各判定を外すとテストが落ちる（`verify-by-mutation`）。旧テスト（施錠中は打てない）を方針に合わせて見直す。
