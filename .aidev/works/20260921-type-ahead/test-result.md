## 受け入れ基準ごとの判定
- AC1: pass — 応答待ち・ホスト施錠の間の文字が解錠後に欄へ入る。溜めた Enter が解錠後に送られ、打った値が載る。
  キー一覧（パレット）のキーも溜まる。（機能キーボタンは施錠中に押せないので対象外。D10）
- AC2: pass — AID の再生で再び施錠したら止まり、残りは次の解錠で新しい画面へ入る。Enter の連打の 2 回目が送られる。
  解錠から再生までの隙間に打ったキーは溜めの後ろに入る。再生中の Tab で欄を出れば続く Enter は 0020 にならない。
  再生中に 0020 が出たら続く文字は拒否される。
- AC3: pass — Reset・Attn で捨てる（Attn は送る）。予約中は溜めない・予約開始で捨てる。切断（markLost）で捨てる。
  Insert はその場で切り替わる。タブを切り替えても別のセッションへ流れない。よそのペインにフォーカスがある間は流さない。
- AC4: pass — mutation（1 回目 T1〜T10、独立点検の対応後 N1〜N10）。検出できなかったのは等価な 2 通り:
  T3（施錠の判定。件数の打ち切りと合わせて振る舞いが同じ）・N10（再生中のセッション確認。溜めがセッションごとなので冗長）。
  N10 の条件は外した。旧テスト（`keyboard-locked-input.test.ts`・`escape-during-busy.test.ts`）の注記を方針に合わせた。

## 失敗の証跡
1 回目の mutation で、施錠の判定を外した T3 が**テストごと固まった**（再生した合成 keydown が溜めに積み直され、
同期ループが終わらない）。スクリプトごと止めることになった:

```
T1 溜めない
      Tests  5 failed | 23 passed (28)
T2 再生しない
      Tests  6 failed | 22 passed (28)
T3 施錠しても止めない

[exited with code 144]
```

→ 合成 keydown は溜め直さない形にした（D3・D9）。

節目の独立点検（別コンテキスト）で ③ に must 3・should 3・nit 2 の指摘（`review.md` ラウンド 1）。
対応後に足したテストは、直す前の実装では成り立たない筋書き（タブ切替・非フォーカス・再生中の 0020）を固定している
（mutation N1・N3 等で、外すと落ちることを確かめた）。
