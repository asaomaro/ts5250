# 決定記録

## D1: PR #388 の「施錠中は打鍵を捨てる」を破棄し、溜めて再生する

- 背景: PR #388 は「打てるのに Enter が効かない」壊れた状態を避けるため、施錠中の打鍵を捨てた。
- 決定: 利用者の判断（A 溜めて再生）と ACS の実測（research F2）に従い、捨てずに溜めて解錠後に再生する。
  #388 が避けたかった状態は、Enter も溜めて解錠後に送ることで、入力を失わずに避けられる。
- 影響: `escape-during-busy.test.ts` の「従来どおりプロテクト」を「すぐには送らない」に改めた（送らないことは同じ）。
  `keyboard-locked-input.test.ts`（ScreenGrid は施錠中に欄を書き換えない）は安全網として残した。

## D2: 再生は合成 keydown を同じ入口へ投げる

- 別の再生経路（値を直接書く等）を作ると、欄の型検査・操作員エラー・キー割り当て・0020 を二重に持つことになる。
  合成 keydown なら、利用者が今打ったのと同じ処理を通る。

  積み直しを拾い続けて終わらない（mutation で施錠の判定を外したとき、テストが固まって実際に起きた）。~~

## D4: Insert は溜めない。表示の切り替えは従来どおり

- ACS の `SendKeys` は `[insert]` `[altview]` `[dspsosi]` 等を溜めずにその場で処理する（research F1）。
  Insert を溜めると、新しい画面で上書きへ戻った後に効いてしまうので、その場で切り替える。
- 表示の切り替え（キー設定の `view:*`）は施錠中は従来どおり効かない（ACS はその場で処理する）。
  入力の中身に影響しないので、この work では扱わない。

## D5: 予約中・マクロ再生中は溜めない

- 自動操作の予約中に溜めると、利用者の打鍵が自動操作の画面へ流れる。マクロ再生中も同じ。
  ACS に対応物は無いので、当 PJ の都合として従来どおり捨てる。

## D6: 溜めないもの・未確認

- IME の変換中の打鍵・ペーストは溜めない（ACS 側が未確認）。施錠中の Help は溜めを捨てるだけで送らない
  （ACS はその場で処理するが、施錠中に Help AID が送られるかは未確認）。上限 1000 キー（ACS の上限は未確認）。

## D7: 再生するのは、このペインがフォーカスを持つときだけ

- 背景（独立点検の指摘）: ペインを分割して他方にフォーカスがあると、合成 keydown がペイン自身に届いて
  保護領域への入力エラーに化け、AID は `isFocused()` で握り潰されていた。
- 決定: 解錠していても、このペインにフォーカスが戻るまで流さない。戻ったら流す。
- ACS との差: ACS はセッションの窓が前面でなくても流す（`keyBuffer` はセッションの PS にある）。
  当 PJ の欄の編集は DOM のフォーカスに乗っているので、よそのペインに居る間に流すには
  フォーカスに依らない入力経路が要る。**送り先を間違えるよりは待つ**ほうを採った。

## D8: 溜めはセッションごとに持つ（`SessionState.typeAhead`）

- 背景（独立点検の指摘）: ペインはタブの切り替えで使い回され、`sessionId` だけが差し替わる。
  ペインに溜めを持つと、A で溜めたキーが B で再生されて B へ送られた。
- 決定: 溜めをセッションの状態に置く。切断（`applyLink` で connected 以外へ）と予約開始（`setReserved`）で
  ストアが捨てる。操作員エラーの状態と通知も、`sessionId` が替わったら持ち越さない（①側の修正）。

## D9: 再生は 1 キーごとに Vue の反映を待ち、溜めが残る間は生の打鍵も後ろへ積む

- 背景（独立点検の指摘）: 同期ループで流すと、0020 の待ちを外すカーソル監視・操作員エラーへ入る通知の監視・
  Erase Input の着地（いずれも次の tick）が反映されず、「12 Tab Enter」の Enter が 0020 で止まり、
  「12 Enter 3」の 3 がエラー中なのに入った。解錠から再生までの隙間に打ったキーは溜めを追い越しうる。
- 決定: 再生を非同期にし、1 キーごとに `await nextTick()`。溜めが残っている間（再生待ち・再生中）は
  生の打鍵も溜めの後ろへ積む。合成 keydown を配っている最中だけは溜めない（`dispatchingReplay`）。

## D10: 機能キーボタンの溜めは撤去した

- 施錠中は ScreenGrid の `onFkeyClick` が送らず、応答待ちの間は重ね板（`.busy-overlay`）がクリックを遮るので、
  ペイン側の溜めの分岐には到達しなかった（テストはイベントを直接出して空振りしていた。独立点検の指摘）。
- キー一覧（パレット）は capture を通らないので、`onPaletteKey` で溜める。
