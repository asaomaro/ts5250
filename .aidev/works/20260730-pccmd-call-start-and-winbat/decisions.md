# 決定記録

## D1: 置換は**全体**に効かせる（原資料は 1 回だけ）

- 背景: 持ち込まれた修正の正規表現は `/\bCALL(\s+)START\b/i` で、**フラグに `g` が無い**
  ＝最初の 1 つだけ置換する。`&` で 2 つ以上並べた形では 2 つ目が残る。
- 決定: `/\bCALL\s+START\b/gi` にする（`g` を追加。使っていない捕獲括弧も外した）。
- 理由 / 代替案: `&` で繋ぐ形は**原資料の実例そのもの**（`NET USE … & call start …`）で、
  2 つ並ぶ書き方は現実に起こりうる。残った 2 つ目は同じ不具合（起動直後に消える）を起こすので、
  1 つだけ直すのは**同じ欠陥を半分残す**ことになる。手元で挙動を確かめてから変えた（research F4）。
- 影響: 置換の意味は変わらない（1 つのときの結果は同じ）。テストで 2 つ並んだ場合を固定した。

## D2: 置換は `isAllowed` の**後**に置く

- 背景: 置換をどこに挟むかで、**許可パターンの照合対象**が変わる。
- 決定: 許可判定は利用者が書いた文字列（`CALL START …`）で行い、
  置換は `spawn` の直前だけに効かせる。記録・ログ（`session-manager`）も元の文字列のまま。
- 理由 / 代替案: 逆順にすると「`CALL START …` を許可したのに `START …` で照合されて弾かれる」
  （またはその逆に、`CALL` 付きを禁じたのに置換後の文面で通る）。
  ホスト起点の任意コード実行なので、**許可した文面と実際の判定がずれる**のは信頼境界の問題。
- 影響: `runPcCommand` の順序をテストで固定（許可あり／置換後だけ許可の 2 方向）。
  空振り検証のミュータント「置換を許可判定の前に移す」で回帰を止める。

## D3: `detached: true` も残す（原資料の判断を踏襲）

- 背景: 原資料は「`detached` 単独では実機で効かなかったが、単体の再現では効果が見えた。
  実機で効いているのは主に `stripCallBeforeStart` と考えられるが、両方残す方が安全側」。
- 決定: 入れる。ただし**何が効いているのかの理解**をコメントに書く
  （「主に効いているのは置換の方」と明記し、`detached` を万能薬と誤解させない）。
- 理由 / 代替案: 落とす案もあったが、起動したアプリを親から切り離す意図自体は
  この機能（GUI アプリを起動して待たない）と合っている。
  既存の挙動（終了コード・上限打ち切り・作業ディレクトリー）が変わらないことは
  **実行して確かめた**（research F6・既存 11 件が通る）。
- 影響: `wait: true` の `child.kill()` が殺せる範囲は変わらない
  （もともとシェルだけで、孫は残る）。プロセスグループを殺す変更は**していない**。

## D4: 引用符の中の `CALL START` も落とす（既知の限界として受け入れる）

- 背景: `echo "CALL START"` のように**引用符の中**に現れた場合も置換される。
- 決定: 見分けない。docstring に限界として書く。
- 理由 / 代替案: 見分けるには cmd の構文解析（引用符・エスケープ・`^` の扱い）が要る。
  PC コマンドとして `echo "CALL START"` を送る業務 CL は考えにくく、
  **釣り合わない**（誤爆したとしても `echo` の出力が変わるだけで、実行は壊れない）。
- 影響: なし（テストで挙動を明示的に固定はしていない——限界の記述はコメントに置いた）。

## D5: Windows 実機での再検証は**この作業では行わない**（できない）

- 背景: この環境に Windows が無い。原資料（別環境の実測）が唯一の実機の裏付け。
- 決定: ここで確かめるのは (a) 置換の結果、(b) 許可判定との順序、
  (c) **実際に渡される文字列が置換後であること**（シェルに書かせて読む）、
  (d) Linux の実行経路が壊れないこと（既存テスト）まで。
  「Windows でアプリが生き残る」ことは**未検証の穴**として PR と backlog に明記する。
- 理由 / 代替案: 実機が無い状態で「検証済み」と書くのは腐りの元。
  代わりに **backlog へ「Windows 実機での回帰確認の自動化」を項目として起こした**。
- 影響: `start.bat` の変更は**テストで守れない**（Windows 専用スクリプト）。
  空振り検証でも「`--auto-secret-key` を落とす」ミュータントは検出できない
  ——そのことを test-result に正直に記録した。
