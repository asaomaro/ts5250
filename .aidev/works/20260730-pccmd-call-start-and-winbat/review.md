# レビュー: Windows 実機で見つかった 2 件を直す

## ラウンド 1（自己レビュー・autonomous）

### must

なし。

### should

このラウンドで**直してから**記録している（差し戻しは発生していない）。

1. **置換が最初の 1 つだけだった**（decisions D1）。持ち込まれた正規表現に `g` が無く、
   `&` で 2 つ並ぶと 2 つ目が残る（＝同じ欠陥を半分残す）。手元で挙動を確かめて `gi` にした。
2. **置換の位置**（decisions D2）。`isAllowed` の後に置くことを明示し、
   テストで両方向（許可あり／置換後だけ許可）を固定した。
   ホスト起点の任意コード実行なので、許可した文面と判定がずれるのは信頼境界の問題。
3. **空振り 1 件**。「置換を呼ばない」が単体では検出できなかった（`stdio: "ignore"`）。
   **シェルに書かせて読む**テストで塞いだ。
4. **テストのコードが読めない書き方になっていた**。空白違いの検証で
   `'CALL\tSTART "T"'.replace("\\t", "\t")` という**何もしない置換**が残っていたので、
   タブと改行をそのまま書く形に直した。
5. **`start.bat` の行末**。既存が LF のみだったので**混在させない**ことを確かめた
   （.bat で行末が混ざると解釈が変わりうる）。

### nit

- `detached: true` は「主に効いているのは置換の方」とコメントに明記した（decisions D3）。
  万能薬と誤解されると、次に似た問題が出たときに `detached` を足して終わりにされる。
- 引用符の中の `CALL START` も落とす（decisions D4）。cmd の構文解析は釣り合わないので取らない。
