## 実機で測ったこと（`verify-browser-watch.mjs`・待ち行列側）

**停止ボタンを置ける根拠**をここで測った。監視は「取り出して消す」ので、止めている間に
送られたものが消えるなら停止は危険な操作になる。

```
OK   待ち受け中は「停止」ボタンが出る
OK   **停止しても一覧に残る**（消えると再開できない） — watches=1
OK   行の状態が「停止中」になる
OK   **操作列が「開始」に変わる**
OK   停止中は履歴に現れない（消費していない）
OK   **再開すると、止めていた間に届いたものを受け取れる**
OK   再開後は「停止」ボタンに戻る

16/16 passed
```

**この既存スクリプトは壊れていた。** 2 か所:

1. `import { DtaqConnection } from "@as400web/tn5250"` — `20260801` の
   パッケージ改名（#237/#238）で `@as400web/hostserver` へ移っており、**起動時に落ちていた**。
2. 最後の検査が `停止すると一覧から消える`（`watches.list().length === 0`）——
   #254 で「停止しても残る」に**意図して変えた**ので、いまは偽。

どちらも直した。**回帰スクリプトは走らせないと腐る**（テストと違い `npm test` に乗らない）。

## 新規の単体テスト（`packages/server/test/printer-config-roundtrip.test.ts`・9 件）

| 群 | 内容 |
|---|---|
| 露出 | 編集者には中身ごと返る／編集できない相手にはフラグだけ／返した `printer` は実体と別物 |
| 往復 | 読んで送り返せば残る／送らなければ消える（置き換え更新の仕様）／`service` だけ外しても出力設定は残る |
| API | `GET /api/sessions-config` が編集権限で出し分ける |
| `autoStart` | フラグだけの相手にも返る。未設定はキーごと無い |

**途中で前提を 1 つ取り違えた。** 「一般ユーザーにはフラグだけ返る」を検査しようとしたが、
**サーバー設定は読むのも admin だけ**（`assertProfileAccess`）なので一般ユーザーには
そもそも 1 件も返らない。「フラグだけ」の相手は *admin だが `canEditServer` が false*
（設定ファイルの裏付けが無く保存できない）場合である。テストとコメントを直した。

## 未検証（穴）

- **認証を有効にした状態での通し確認をしていない。** 実機 E2E は認証オフで走らせている
  （`buildApp` に認証を渡していない）。認可そのものはサーバー側の既存の層
  （`assertProfileAccess` / `canEditServer` / `assertOwner`）で、この PR は条件を足していない。
- **サービス一覧の画面が無い**ので、「ブラウザのタブを開かずにサーバー側サービスを操作する」
  経路は測っていない（API は #256 で出来ている。画面は次の PR）。
- **`error` 状態の見え方**を実機で作っていない（装置使用中を意図的に起こしていない）。
  文言と色は `stopped` と同じ経路なので、描けることは確認済み。
