# 要件: サービスの操作を画面から行う

## 背景 / 課題

サーバー側は 5 本の PR で揃った（`20260801-service-lifecycle-model` #253 /
`20260801-service-start-stop` #254 / `20260801-printer-attach-by-ref` #255 /
`20260801-definition-based-listing` #256 / `20260801-boot-autostart` #257）。

**しかし画面が無い。** 利用者から見ると、いまはこうなっている:

| できること | いまの状態 |
|---|---|
| サービスとして常駐させる | **設定フォームに ✅ が無い**ので設定できない（`profiles.json` を手で書くしかない） |
| 開いた直後に待ち受けない | **設定フォームに ✅ が無い**ので設定できない |
| 待ち受けを止める | **プリンターに停止ボタンが無い** |
| 止めたものを再開する | **プリンターに開始ボタンが無い**／監視は停止すると再開できない |

利用者の言葉:

> サーバーではありますが、画面側で待機と停止を指示したいです。その上で、定義に自動起動の設定を
> 追加し、自動起動に✅されていれば、サーバー起動で自動的に立ち上がるようにしたいです。
> WS版の現在のプリンターセッションも開いたと同時に待機になりますが、自動起動の設定に従い、
> ✅されていなければ開いた直後に待ち受けを開始せず、ユーザーの開始ボタンの操作を待つようにします。
> 自動起動、手動起動のどちらもであってもユーザーの停止ボタン操作で待ち受けを停止出来るようにもします。
> **これはプリンターも待ち行列も同じです。**

サーバーはこの通りに作った。**残っているのは画面だけ**。

## 目的 / ゴール

**設定と操作を画面から完結させる。** `profiles.json` を手で書かずにサービスを設定でき、
待ち受けの開始/停止をボタンで指示できる状態。

## スコープ

### 対象

1. **設定フォーム**（`ConfigCard.vue`）
   - `自動で待ち受け開始` ✅（`printer` / `dtaqwatch`）
   - `サービスとして常駐する` ✅（`printer` の信頼設定欄＝サーバー設定＋編集権限のときだけ）
2. **プリンターの開始/停止**（`PrinterPane.vue`）— 状態表示を含む
3. **監視の停止/再開**（`WatchPane.vue`）— いまは停止のみで再開できない
4. **`printer-state` の反映** — サーバーは push しているのに画面が捨てている

### 対象外

- **サービス一覧のペイン**（ブラウザのタブを開かずにサーバー側サービスを見る画面）。
  API（`GET /api/printers` / `/api/watches`）は #256 で出来ているので、**次の PR**で作る。
- 待ち行列の「サービスとして利用する」✅ — 待ち行列は**種別そのものがサービス型**なので
  設定に ✅ は要らない（`config-types.ts` / `host-printers.ts` の判断を引き継ぐ）。
- 待ち行列のサービス実行内容（コマンド実行等）— 独自の信頼設計が要る（別途）。

## 機能要件

- サーバー設定のプリンター定義に **`サービスとして常駐する`** を設定できる。
- プリンター・監視の定義に **`自動で待ち受け開始`** を設定できる。
- `自動で待ち受け開始 ☐` の定義を開くと、**待ち受けずに開始ボタンを待つ**（画面がそう見える）。
- プリンターの待ち受けを**開始・停止**できる。停止しても**受信済みの帳票は消えない**。
- 監視の待ち受けを**停止・再開**できる。
- 状態（`待ち受け中` / `再接続中` / `停止中` / `エラー`）が**画面に出る**。エラーは理由も出る。

## 非機能要件 / 制約

- **信頼境界を動かさない**（AGENTS.md）。`サービス` ✅ は printer スキーマ＝**サーバー設定だけ**が
  持てるので、`canEditPrinter`（サーバー設定 かつ 編集権限）と同じ条件で出す。
- **押しても 403 になるボタンを出さない**（`ConfigCard.vue` の既存方針）。
- 出力設定（`autoPdfDir` / `autoPrint`）の**中身を非編集者に見せない**。

## 完了条件 (受け入れ基準)

- [ ] 設定フォームで `サービスとして常駐する` / `自動で待ち受け開始` を保存・再読込できる
- [ ] **保存でほかの printer 設定が消えない**（後述の未確定事項）
- [ ] `自動で待ち受け開始 ☐` のプリンターを開くと `停止中` で、開始ボタンで待ち受けが始まる
- [ ] プリンターの停止ボタンで `停止中` になり、受信済みの帳票が残る
- [ ] 監視の停止ボタンのあとに再開ボタンが出て、押すと `監視中` に戻る
- [ ] `vue-tsc` を含むビルドと全テストが通る

## 未確定事項 / 確認したいこと

- **printer 設定が保存で消える既存の欠陥**。`GET /api/sessions-config` は printer の中身を
  返さない（`hasOutput` フラグのみ）ので、フォームは空から始まる。更新は**オブジェクトごと
  置き換え**（`config-store.ts` の `updateSession`）なので、**名前を直して保存しただけで
  `autoPdfDir` が消える**。`サービス` ✅ を同じブロックに足すと**この欠陥に乗る**ので、
  spec で扱う。
