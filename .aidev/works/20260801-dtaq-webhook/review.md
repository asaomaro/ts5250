# レビュー: 待ち行列サービスの Webhook 転送

## ラウンド 1（自己レビュー）

### 実装中に直したもの

**`stop()` で未送分を捨てていた。** 最初は「監視を止めたら転送も止める」と書いたが、
**読み取り済みのエントリはホスト側から既に消えている**——そこで捨てれば**ただのデータの喪失**。

「待ち受けを止める」は「**これ以上読まない**」であって「読んだものを配らない」ではない
（`stopPrinter` が受信済みの帳票を残すのと同じ）。捨ててよいのは**プロセスを畳むとき
（`closeAll`）だけ**に直した。`update` で転送先を差し替えるときも、古い方は配り切らせる。

### 実機検証が見つけたもの

**「未達」の数が次の到着まで古いままだった**（`test-result.md` に詳細）。

到着時に写し取る形だと、受け手が落ちて諦めても**キューが静かなら「未達 0 件」に見え続ける**。
**失敗は「何も起きない」ときにこそ起きる**ので、写しを持つと一番見たい場面で嘘になる。
読むたびに実体へ聞く形に直した。

これは**実機で通さないと出なかった**——単体テストは `stats` を直接読むので、
写しの古さが現れない。

## 判断の記録

### なぜ「諦め方」を設定に持つのか

**監視は消費する。** 転送の失敗はデータの喪失なので、

- 永久に再試行する → キューが溢れ、後続が全部詰まる
- 1 回で捨てる → 一瞬の不調でデータが消える

どちらも危ない。`maxAttempts` を設定に出し、**どこで諦めるかを運用が決められる**ようにした。

### なぜ二重送信を我々が防がないのか

「送ったが応答が届かなかった」を**我々は区別できない**。防ごうとすると「送ったかもしれない」
ものを送らない選択になり、**確実な喪失**と引き換えに**不確実な重複**を避けることになる。

`X-As400-Delivery`（再送でも変わらない id）を付けて**受け手に冪等性を委ねる**のが唯一正しい。
設計文書に書いてあるが、**受け手の実装者が読むのは PR とヘッダー名**なので、
本文の JSDoc にも同じことを書いた。

### なぜ URL に許可リストを持たないか（design D2）

この設定を書けるのは admin だけで、admin は既に**サーバー機でのコマンド実行**（`pcCommand`）と
**任意パスへの書き込み**（`printer.autoPdfDir`）ができる。**新しい権限を与えるわけではない**。

掛けるのは `http:` / `https:` とリダイレクト不追従まで。許可リストは**要件が出てから足す**
——使われない設定は、あるだけで判断を鈍らせる。
