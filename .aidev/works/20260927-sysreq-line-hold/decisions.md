# 決定記録

## D1: 対象外にしたもの（台帳の「ホストのエラーの保留の残り」のうち）

- 背景: `20260927-wec-only-unlock` の decisions D2 が残した `pending_read` まわりと、ACS の施錠・溜めの扱い。
- 決定: 次は実装しない。台帳の行は理由つきで閉じる。
  - **オペコード（INVITE・PUT/GET）だけで READ が出たとする扱い・WSF で下ろす扱い**: 実機のトレースに、READ の無い PUT/GET も READ の前の WSF も現れない（`scripts/acs-probe/*` と当 PJ の実機トレース）。測れない分岐を足さない。
  - **溜めた AID の間も ACS は施錠しない**: 当 PJ は `sendAid` の Promise（応答を待つ）を保つために施錠の形を取る。画面の見た目以外に差が出ない（キーは溜めに入る）。
  - **Attn / SysReq で溜めを捨てるか**: 実機で溜めを作った状態から Attn / SysReq を送る手順が DSM で組めない（READ が出ていない間に押す必要があり、押すとホストがそのまま応える）。未確認。
  - **早い Enter の後の F3 に ACS が欄を付けない**: 原典で説明できる経路が見つからない。未確認。
- 理由: AGENTS.md「判断の原則 2」——確かめられないものは「未確認」と明記して残し、推測で埋めない。

## D2: 画面を持たない呼び出し（MCP・HLLAPI）の AID は、行を閉じてから送る（ACS は 0006 で拒否）

- 背景: ACS は SysReq の行の間に Enter 以外の AID が来ると行を閉じて操作員エラー 0006 にし、送らない（`processAIDCode`）。
- 決定: 画面（`EmulatorPane` / `StatusBar`）は ACS と同じく 0006 にして送らない。コア（`Session5250.sendAid`）は行を閉じて溜めを流してから送る。
- 理由: 自動操作は画面の行を知らないので、0006 で拒むと理由の分からない失敗になる。行は画面の側の状態で、コアは「止めている理由」として持つだけ。
- 影響: `session.ts` の `sendAid` の先頭にコメントで逸脱を明記。

## D3: SysReq の送信は、行を閉じる前にレコードを送る

- 背景: ACS は行から SysReq を送るとき、SRQ を送ってから `clearSysreqMode`（止めた出力が流れる）。
- 決定: 同じ順にする（`sendAid` で SRQ を書き出してから `setSysReqLine(false)`）。
- 理由: 先に流すと、止めていた READ への応答が SRQ より先に出うる。実機（`verify-sysreq-line-hold.mjs SUBMIT`）で、送信で閉じても戻った画面に LATE があることを ACS と合わせた。

## D4: 独立点検で見つかった変異のうち、殺せないものが 1 件ある（等価な変異）

- `handleRecord` の `isRemainder && this.heldCc2 !== undefined` から `isRemainder` を外しても、どのテストも落ちない。
- 持ち越し（`heldCc2`）は保留が始まったときに立ち、残りのレコード（溜めの先頭に `unshift` する）が終わったときに消える。保留の間の他のレコードは溜めに入り、残りより後に流れるので、**残り以外のレコードが持ち越しを見る状態に届かない**。等価な変異として残し、条件は防御として保つ。

## D5: 残した差（review ラウンド 1 の nit）

- **行の間にキーボードで押した F キー**: ACS は行を閉じて 0006。当 PJ の画面は行の間ペインのキー処理を止めるので（行の入力欄へのバブルで AID が二重に走らないため。`sysreq-line.test.ts`「行が開いている間は 5250 のキー処理が止まる」）、黙って捨てて行は開いたまま。ホイールとフッターのボタンは 0006 にする。利用者は Esc か実行キーで行を閉じられるので、出力が止まり続けることはない。
- **同じセッションを複数の接続で見ているとき**: 行はセッションに 1 つ（ACS も端末に 1 つ）なので、片方の取り消し・切断で閉じる。もう片方の画面の行は残るが、確定すれば SRQ は送られ、取り消しは冪等。複数の画面から同じ端末を操作する形は ACS に無い。
