# 要件: 純 DBCS と BLOB の 64KB 超を実機で確かめる

## 背景 / 課題

`20260802-lob-multi-segment`（PR #289）で、LOB の分割受信がホストの単位（文字）と
食い違っていた不具合を直した。実機で確かめたのは **UTF-16（CCSID 1200）と混在 CLOB** の 2 系統で、
残る 2 系統は「同じ道を通るはず」という**判断で押した**:

| 系統 | 押した理由 | 実測 |
|---|---|---|
| 純 DBCS（CCSID 300 / 16684） | `isTwoByteCcsid` が 1200 と**同じ枝** | **無し** |
| BLOB（CCSID 0） | `perChar=1` で混在 CLOB と**同じ経路** | **無し** |

**押した判断は事実ではない。** しかも LOB の長さの単位はこれで 3 度踏んでいる
（#245 インライン / #248 ロケーター / #289 分割）。いずれも
「**別の系統で通ったから同じはず**」という同型の推論がすり抜けを許している。

利用者の指示により、backlog へ回さず**実機で解消する**。

## 目的 / ゴール

- **純 DBCS（CCSID 300）の 64KB 超**を実機から取り、中身が一致することを確かめる。
- **BLOB の 64KB 超**を実機から取り、中身が一致することを確かめる。
- 差異が出たら直す。

## スコープ

### 対象

- 実機での 64KB 超フィクスチャの作成と取得。
  - 純 DBCS: `DBCLOB(1M) CCSID 300`。**直接の変換が無い**ので
    `20260801-pure-dbcs-dbclob` の**1200 経由の二段キャスト**を使う。
    倍々に伸ばす経路（`G = G || G`）でその手が通るかは未確認。
  - BLOB: `BLOB(1M)`。CCSID の概念が無いので `perChar=1`。
- 分割が跨ぐ場合（上限を上げる）と、打ち切り（`too-large`）の両方。
- 見つかった差異の修正と、実機なしで止められる回帰テスト。

### 対象外

- **CCSID 16684**。`20260801-pure-dbcs-dbclob` で「この実機に変換表が無い」
  （1200 経由でも `-332`）と実測済み。**作れないものは測れない**。
- インライン経路（LOB フィールドしきい値）。#245 で別途確認済み。
- 書き込み（`0x1817`）。読みだけ。

## 機能要件

- 純 DBCS の 64KB 超が、**先頭から連続**して取れる（中抜けが無い）。
- BLOB の 64KB 超が、**バイト単位で一致**する。
- どちらも**上限（`lobMaxBytes`）を超えて保持しない**。
- 打ち切ったときに `too-large` が立ち、中身は**先頭から連続**している。
- **BLOB は文字列に復号しない**（`decodeLobBytes` は CCSID 0 でバイト列を返す）。
  復号されてしまうと、任意のバイト列が壊れる。

## 非機能要件 / 制約

- 追加の依存を入れない。
- **実機は共用の本番機。** 表は自分のライブラリーに作り、`finally` で必ず消す。
  他人のオブジェクトに触らない。
- 検証スクリプトに内部 IP を書かない（`process.env.AS400_HOST`、既定値なし）。
- 資格情報は `.env` のみ。

## 未確定事項 / 確認したいこと

- **CCSID 300 の値を倍々に伸ばせるか。** `G || G` は同じ CCSID どうしの連結なので
  変換は要らないはずだが、実機で確かめる。通らなければ別の作り方
  （1200 で大きく作ってから一度だけキャスト）を試す。
- **BLOB の中身をどう作るか。** `X'...'` の 16 進リテラルは文の長さ制限に当たるので、
  こちらも倍々に伸ばす。
