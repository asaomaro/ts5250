## D1: 「作らない」判断（`20260730-input-assist-datetime` の D1）を覆す

- 背景: 当時「`EDTMSK` は欄を分解しない」と実測して datepicker を作らないと決めた。
- 決定: **覆して作る。**
- 理由: 当時の実測が誤りだった（2026-08-25 訂正）。`EDTMSK` の `&` を数字の桁に置いていたため
  `CRTDSPF` が `CPD7494` / `CPD7520` でキーワードごと無視しており、「分解しない」は
  **EDTMSK が効いていない状態の観測**だった。正しい向きで書き直した実機測定では**分解して届く**
  （`research.md` F1）。D1 の推論（材料が無ければ作らない）は正しく、**前提のほうが誤っていた**。
- 影響: `.aidev/backlog/input-assist.md` の「作らない」を書き直す（AC9）。

## D2: 判定は「形が先・区切りが後」。区切りだけでは決めない

- 背景: requirement F1 は「区間の間の保護された 1 文字の区切り」を 1 段の判定材料に置いていた。
- 決定: **区間の桁数で先に絞り、区切りは後段の確定にだけ使う。**
- 理由（いずれも 2026-08-26 の実機実測）:
  - **区切りは欄に値があるときしか届かない**。空の `TMW` では `:` が 1 桁も刷られない
    （編集ワードのゼロ抑制）。しかもローカル打鍵では現れない＝**空欄の間ずっと届かない**。
  - **`-` は日付にも SSN にも出る**（`SSN` に値を入れると `123-45-6789`）。区切りを先に見ると
    SSN を日付と誤る。
- 影響: requirement F1 の表は spec の判定表で置き換わった（`spec.md`「判定表」）。

## D3: 曖昧な形（`2,2,2` / `2,2` ＋ 区切り空白）は「両方選べるピッカー」を出す

- 背景: 区切りが届かないと `YY/MM/DD` と `HH:MM:SS` は完全に同形で届く（`DMA` と `TMW`）。
- 決定: **日付 / 時刻のタブを出し、利用者に選ばせる**（`kind: "both"`）。
- 理由 / 代替案:
  - *出さない*: 嘘はつかないが、**空欄＝ピッカーが最も要る場面**で出ない。
    値の有無で機能が現れたり消えたりする（前 work の D1 が「無いより悪い」と警戒した形）。
  - *日付と決め打つ*: 空の時刻欄に日付ピッカーが出る。**推測を真実として扱う**ため却下。
  - *採用案*: UI が「分からない」ことを表明したまま役に立つ。値が入って区切りが見えたら
    タブが消えて確定種別だけになる——**曖昧 → 確定の単調な絞り込み**で、機能は消えない。
- 影響: ピッカーに 2 タブの状態が増える。テストで `both` の 2 件を固定する。

## D4: `2,2,4`（`DD/MM/YYYY` 系）は扱わない

- 背景: 実測資材の `D8Y` は `0/00/0000`＝`2,2,4` 形（ただし分割されていない単独欄）。
- 決定: **判定表に入れない**（ピッカーを出さない）。
- 理由: 先頭 2 区間が「日・月」か「月・日」かを決める材料が届かない。利用者が合意した妥協は
  **`YMD` 順に固定する**ことで、`DMY` / `MDY` を推測することではない。**推測しないほうを採る。**
- 影響: 欧州式の日付欄ではピッカーが出ない。将来やるなら `QDATFMT`（引けることは実測済み・
  前 work の D2）か欄ごとのオプトインが要る。

## D5: 区切りの許容集合に `.` を入れる（未実測と明記して）

## D9: `.crt-pop` は `styles.css`（グローバル）に置く（D7 の実装形の確定）

- 背景: D7 は「`.opt-hints` の意匠を括り出して共有する」と決めたが、`ScreenGrid.vue` の
  `<style>` は **scoped**。scoped CSS は子コンポーネント（`DateTimePicker.vue`）の**内側の要素に届かない**
  （届くのは子のルート要素だけ）。
- 決定: 共通の「面」（枠・角丸・背景・影・端末調）を **`src/styles.css`** に `.crt-pop` として置き、
  意匠の選択は要素の **`data-pop`** 属性で切り替える。位置・並び・寸法は各部品の scoped 側に残す。
- 理由 / 代替案:
  - *ScreenGrid にピッカーの markup を直接書く*: scoped 問題は消えるが、`ScreenGrid.vue` は既に
    3900 行超で、カレンダー 1 つぶんをさらに積むのは読めなくなる。
  - *CSS カスタムプロパティで受け渡す*: 動くが、意匠 1 つにつき変数が増えて追いにくい。
  - 採用案は `styles.css` 末尾の注記（「.grid-input と同じ scope に置く」）の趣旨とも矛盾しない
    ——あちらは**詳細度で勝たせたい**もの、こちらは**複数の scope から使いたい**もの。
- 影響: `.opt-hints` は `crt-pop` クラスを**足した**うえで重複宣言を削り、意匠は `data-pop` へ移した。
  クラス名は残したので既存のセレクタ・テスト（`opt-hints-ui.test.ts` 17 件）は緑のまま。

## D10: `pasteFrom` に `forceOverwrite` を足す

- 背景: ピッカーは**欄長ちょうどの数字列**を offset 0 へ流す。挿入モードのままだと
  `insertInto` が「入り切らない」を返し **`MSG_NO_ROOM` で弾かれる**。
- 決定: `pasteFrom(..., forceOverwrite = false)` を足し、ピッカーからは `true` で呼ぶ。
- 理由: ピッカーは**カーソル位置への貼り付けではなく欄の値の置き換え**なので、挿入・上書きの
  区別が意味を持たない。挿入モードの設定そのものは変えない（打鍵の挙動は従来どおり）。
- 検証: `insertInto` は base の末尾空白を落とすので**空欄では溢れない**。溢れるのは
  **既に値が入っているとき**——テストはそちらで書いた（`"2020"` の 4 桁欄へ `"2026"`）。
  `forceOverwrite` を外すと実際に落ちることを確認済み。
- 影響: 既存の 4 か所の呼び出しは既定値のままで挙動不変。

## D11: 画面下部の欄ではピッカーを上向きに開く

- 背景: 実機の `DTMDSPF` は日付欄が行 20・23 にある。24 行画面で下向きに開くと**画面外**へ出る。
- 決定: `row + 11 > rows` なら `translateY(-100%)` で**欄の上端に下端を合わせる**。
- 理由: 中身（カレンダー / 時刻の列）で高さが変わるので、行数で位置を計算すると必ずずれる。
  変換なら高さを知らずに済む。
- 影響: 位置計算は `optBtnStyle` の共有を続ける（係数を二重に持たない）。

## D12: `Esc` は `EmulatorPane` の既存ハンドラで閉じる

- 背景: `Alt+↓` で開くと**フォーカスは欄に残る**（値を書くと `sync` が欄へフォーカスを戻すため、
  時刻の連続選択でも同じ）。ピッカー自身の `keydown` だけでは `Esc` が届かない。
- 決定: `EmulatorPane` の**既存の 1 つの keydown ハンドラ**に「ピッカーが開いていれば閉じて return」を足す。
  ピッカー自身の `keydown`（フォーカスが中にあるとき）も残す。
- 理由: 「**グリッドに新しい keydown リスナーを足さない**」という制約は守っている——足したのは
  既存ハンドラ内の分岐 1 つ。`optHints` が「開いている間は他の Esc 割当を発火させない」のと同じ扱い。
- 影響: ピッカーが開いている間、`Esc` は矩形選択の解除に使われない（`optHints` と同じ）。

## D13: ホストのゼロ抑制で区間の値は先頭空白で返る（実測・test 工程で判明）

- 背景: E2E で時刻欄 `TMW` に `09:30:15` を入れて Enter すると、**` 9:30:15`** で返ってきた。
- 事実: `TMW` の編集ワードは `'  :  :  '` で**先頭に `0` が無い**ため、ホストは時の先頭ゼロを
  刷らない。`D8U` の `'0   /  /  '` は先頭 `0` が抑制を打ち切るので `2026/08/15` がそのまま返る。
- 決定: **実装は変えない。** 数値欄は右詰めなので `joinedDigits` の右詰め解釈（`padStart`）が
  そのまま効き、`" 9"` は 9 として読める。E2E の期待値を抑制の掛からない値（13 時）へ直し、
  **先頭空白を読めること**を単体テストに固定した。
- 影響: 「区間の値は必ず 0 埋めで届く」と考えて実装すると壊れる、という落とし穴を記録に残した。
  **書き込むほうは 0 埋め**（`formatDate` / `formatTime`）で、読むほうだけが空白を許す。

## D14: 判定は snapshot だけに依存させ、実効値は「開いた時点」で捕まえる

- 背景: review M2（ピッカーが未送信のローカル編集を見ておらず、打った日付と違う月で開く）を
  直すため、判定関数へ `logicalValue` を渡して実効値から初期選択を作るようにした。
- **その修正が回帰を生んだ**: `logicalValue` は `props.edits` を読むので、判定の computed が
  **編集のたびに作り直される**。それを監視して「画面が変わったら閉じる」watch が走り、
  **ピッカーが自分の書き込みで閉じる**——時刻の列を 1 つ選ぶと閉じてしまい使えない。
  **実機 E2E が捕まえた**（時刻タブのクリックがタイムアウト）。
- 決定: **判定（`detectDateTimeFields`）は snapshot だけに依存させる**（欄の値を見ない）。
  実効値は**開くときに 1 度だけ捕まえて**（`openDtFor` → `dtOpenValues`）ピッカーへ props で渡し、
  `parseDate` / `parseTime` の任意引数として受ける。
- 理由: 「何が日付欄か」は画面の構造（区間の桁数・区切り）で決まり、**欄の値とは無関係**。
  値に依存させたのは初期選択という別の関心事のためで、混ぜたのが誤りだった。
  捕獲を明示にすると、開いている間に値が変わっても閉じない・作り直されない。
- 影響: `DateTimeTarget` から `values` を外し、`parseDate(t, values?)` / `parseTime(t, values?)` に。
  単体テストで固定した（3 列とも選べること）。
- **テストの作り方の教訓**: 最初この回帰を単体テストで再現できなかった。原因は
  テストの `edits` が**素の `Map`** だったこと——アプリ側は `sessionsStore`（`reactive`）配下なので
  `set` が依存を発火する。`reactive(new Map())` に直して初めて再現した。
  **「本番の反応性」を模していないテストは、反応性起因の不具合に対して無力**。

## D15: deliver の start を記録し遅れた（メトリクスの注記）

- 事実: `aidev approve deliver` を先に打ち、`aidev event deliver start` を**その後**に記録した。
  そのため `metrics.yml` の deliver は **start の ts が approved より後**になっている。
- 決定: **ts を書き換えない**（protocol「タイムスタンプを捏造して埋めない」）。
  **deliver の所要時間は導出しない**——この work の集計では deliver 区間を無効として扱うこと。
- 原因: 工程 skill の手順が「台帳の同期 → 計測 → approve → verify → コミット」と定めており、
  その並びに `event start` が現れない（`verify` の WARN で事後に気付いた）。
  他工程は冒頭で `event start` を打つ形になっているので、deliver だけ抜けやすい。
- 影響: retro / insights で deliver のリードタイムを見るときはこの work を除外する。

## D16: デザイン候補の見本を `optHints` にも足す（利用者要望・deliver 後の追補）

- 背景: PR 提出後、利用者から「ドロップダウン・datepicker・timepicker に見本を付けて」。
  調べると **`optHints` には元から見本（`.pal-prev[data-kind=…]`）が無く**、
  `dtPicker` もそれに揃っていた（`controls` / `buttons` / `windowFrame` / `windowBackdrop` にはある）。
  候補名だけでは「パネル」「枠」「端末調」の違いを選ぶ前に見分けられない。
- 決定: **両方に見本を足す。** `optHints` と `dtPicker` は同じ意匠（`.crt-pop`）を着るので、
  見本の規則も **1 組にまとめて共有**する（片方だけ直して食い違うのを防ぐ）。
  見本の値は `.crt-pop` の実体と同じものを使う——**見本が本体と違う見た目を見せたら意味が無い**。
- **datepicker と timepicker は 1 つの設定（`dtPicker`）**なので見本も 1 組。
  2 つは同じポップオーバーの面を共有しており、日付・時刻で意匠を別々にする理由が無い。
- 再発防止: **「展開できる設定はどれも見本の規則を持つ」を一般の契約としてテストで固定**した
  （`view-settings-palette.test.ts`）。scoped CSS は vitest の DOM に効かないので
  **ビルド後の CSS を直接検査**する（`view-cycle-ui.test.ts` の CRT 検査と同じ作法）。
  これが無いと、次に設定を足す人が同じ穴を開ける。
- **踏んだ罠 2 つ**（テストを書くとき）:
  - **ビルド後は属性値の引用符が落ちる**（`[data-kind=controls]`）。`includes('[data-kind="controls"]')`
    では全件 miss になる。両方の綴りを許す。
  - **`group` を持つ項目は 1 行にまとまる**（ウィンドウ設定＝ウィンドウ／背景）。項目名で行を探すと
    「背景」という行が無くて落ちる。`MENU_ROWS` と同じ組み立てをテスト側でも行う。

## D17: 開いたらフォーカスをピッカーへ移す（キーボードだけで完結させる）

- 背景: 利用者指摘「ドロップダウン同様、表示した後フォーカスを picker に移して。
  キーボードのみで操作を完結できるように」。**当初の実装は 2 か所で欠けていた**:
  1. 開いてもフォーカスが欄に残る（`optHints` は `openOptAt` でリストへ移していた）。
     矢印も `Enter` も欄へ行ってしまい、マウスが要る。
  2. **時刻は列を選ぶたびにフォーカスを欄へ奪われる**——`pasteFrom` の focus 経路で
     `sync` が欄へ `focus()` するため。時刻は「選んでも開いたまま」なので、
     1 列決めた時点で分・秒へ進めなくなっていた。
- 決定:
  - **フォーカスの移動はピッカー自身が行う**（`onMounted` / タブ切替時）。中のどこへ置くか
    （選択済みの日 ＞ 今日 ＞ 1 日 / 現在の時）はピッカーしか知らないため、親からは指示しない。
    `optHints` は親（`openOptAt`）で DOM を引いているが、あちらは平坦なリストなので済んでいる。
  - **書き込みの前後でピッカー内のフォーカスを保存・復帰する**（`writeDateTime`）。
    ピッカーの外から書いたときだけ欄へ戻す。
  - 矢印の割り当て: カレンダーは**左右で 1 日・上下で 1 週**（並びと同じ動き）、月の端では月送り。
    時刻は**列内が上下で巡回**（0 時の上は 23 時）・**左右で列を渡る**。タブは左右で切替。
  - **グリッドには相変わらず keydown を足していない**——購読しているのはピッカー自身の root だけ。
- 検証: 単体 9 件（すべて teeth 確認済み——初期フォーカスと復帰を外すと 9 件とも落ちる）＋
  実機 E2E ⑧（`Alt+↓` → 矢印 → `Enter` → `Esc` → `Enter` の**マウス不使用**で `12:31:16` が
  ホストへ届くことを確認）。
- 残る制約: `both`（日付/時刻のタブが出る欄）で**タブへ戻るには `Shift+Tab` を数回**要する
  （DOM 順が タブ → 月送り → 日 のため）。標準的な移動で到達はできるので今回は変えない。

## D18: `Tab` は部品の中で巡回させる（トラップ）＋ 一覧はロービング tabindex

- 背景: 利用者指摘「ドロップダウンや picker でタブ移動する場合、内部でタブが循環するように」。
  抜けてしまうと、**開いたままの部品へキーボードだけでは戻れない**（外側クリックでしか閉じられない）。
- 決定:
  - **`composables/focusTrap.ts` に 1 か所置き、オプション選択肢とピッカーで共有する**
    （2 か所に書くと片方だけ直して挙動が食い違う）。出口は `Esc` と選択——キーで明示的に踏む。
  - **日のグリッド・時刻の列はロービング tabindex**（現在の 1 つだけ 0・残りは -1）にして
    「まとまりで 1 停止点」にする。ARIA の複合ウィジェットの作法。
    **これが無いと `Tab` が 60 個の分を 1 つずつ辿る**ことになって使えない。
    追従は `focusin` で行う（クリックでも矢印でも同じように効く）。
  - タブ（日付/時刻）も同じ作法で**選択中だけ tabindex 0**、左右で切り替える。
- **テストで踏んだ罠**: 「何度 `Tab` を押しても外へ出ない」という書き方は**素通りする**。
