# 要件: EDTMSK 分割欄から日付欄・時刻欄を見分けて、DatePicker / TimePicker を出す

## 背景 / 課題

**この作業は、2026-07-30 に「作らない」と決めた判断（`20260730-input-assist-datetime` の
decisions D1）の再訪である。前提が誤っていたことが後に判明したため。**

- 発端は 2026-07-28 の要望「5250 の入力欄に datepicker / timepicker を出したい」。
- 2026-07-30 に実機で「`EDTMSK` は欄を分解しない」と結論し、判定材料が無いとして **D1「作らない」**
  で決着した（`.aidev/backlog/input-assist.md` を閉じた）。
- **2026-08-25、その実測が誤りだったと判明した。** 当時の検証 8 通りはすべて `EDTMSK` の `&` を
  **数字の桁**に置いており（`'&&/&&/&&'` 等）、実機の `CRTDSPF` は `CPD7494` / `CPD7520` で
  **キーワードごと無視**していた。`&` は「保護する桁」＝**区切りの桁**に置くのが正しい書き方。
- 正しい向きで書き直して実機（IBM i 7.3）で採り直した結果、**`EDTMSK` は欄を分解して届く**:

  | DDS | 届いた形 |
  |---|---|
  | `EDTCDE(Y)` ＋ `EDTMSK('  &  &  ')` | **3 区間**（2+2+2）・FCW `8601`/`8603`/`8602`・区切り `/` |
  | `EDTWRD('0   /  /  ')` ＋ `EDTMSK('    &  &  ')` | **3 区間**（4+2+2）・同上 |
  | `EDTWRD('  :  :  ')` ＋ `EDTMSK('  &  &  ')` | **3 区間**（2+2+2）・区切り `:` |
  | `EDTWRD('   -  -    ')` ＋ `EDTMSK('   &  &    ')` | **3 区間**（3+2+4）・区切り `-`（SSN） |
  | `EDTWRD` のみ（対照） | **1 欄**・分解なし |

- 継続入力フィールド（FCW `0x86xx`）そのものは実装済み（`feat/continued-entry-field`, PR #371）。
  区間の並びを 1 つの入力欄として扱う UI 側の対応（色・下線・編集・Tab 停止点）も
  PR #377 / #378 / #379 で着地している。**材料は既に UI の手元にある。**
- backlog は訂正を入れたうえで「**datepicker の判定材料としては使えるが、採否は別途判断すること**」
  と保留にしてある。**今回がその採否判断であり、結論は「作る」。**

## 目的 / ゴール

**日付欄・時刻欄と分かる欄で、利用者が桁の並びと区切りの位置を頭に置かずに値を入れられる状態。**

- 「この 6 桁は `YYMMDD` だったか `DDMMYY` だったか」を思い出さずに済む。
- カレンダー / 時刻の一覧から選んだ値が、区間をまたいで正しい桁に入り、ホストへ 1 つの欄として送られる。
- **勝手には出ない。** 推測を含む機能なので、利用者が画面設定で有効にしたときだけ現れる。

（`.aidev/charter.md` は無いため charter ゴールの紐づけは行わない）

## ユーザーストーリー

- **US1**: 5250 の画面で日付を入力する利用者として、**カレンダーから日付を選んで入れたい**。
  なぜなら、欄が `nn/nn/nn` に割れていても各区間が年・月・日のどれかは画面に書いていないことが多く、
  打ち間違えると業務データが 1 年ずれるから。（受け入れ: AC1, AC3, AC5, AC7）
- **US2**: 同じ利用者として、**時刻欄でも同様に一覧から選びたい**。
  なぜなら、`HH:MM:SS` の秒まで打つ場面で 0 埋めの桁数を間違えやすいから。（受け入れ: AC2, AC3, AC5, AC7）
- **US3**: 日付・時刻**ではない**分割欄（SSN のような `3-2-4`）を使う利用者として、
  **そこにピッカーが出ないでほしい**。なぜなら、誤検出したピッカーは正しい値を入れる邪魔にしかならず、
  「出たり出なかったりする支援」は無いより悪いから。（受け入れ: AC4）
- **US4**: 端末画面をそのまま扱いたい利用者として、**ピッカーが矩形選択・コピー＆ペースト・
  キー操作を一切妨げないでほしい**。なぜなら、画面に部品を重ねる機能で既に同じ指示を出しており
  （`optHints`）、そこを壊すと端末として使えなくなるから。（受け入れ: AC6）
- **US5**: 既定の見た目を変えたくない利用者として、**既定では出ないでほしい**。
  なぜなら、推測を含む判定の誤りが、有効にした覚えのない利用者の画面に見えてしまうから。（受け入れ: AC5）

## スコープ

### 対象

- **継続入力フィールド（`Field.continued`）の並び**＝`EDTMSK` で分割された欄を対象に、
  区間の桁数と区間の間の区切り文字から「日付らしい欄 / 時刻らしい欄」を判定する。
- 判定した欄に **DatePicker / TimePicker** を出し、選んだ値を欄へ書き込む。
- 画面設定（`ViewSettings` / `VIEW_ITEMS`）に項目を足し、**既定は無効**にする。
- 実機（`TESTLIB/DTMDSPF`）での回帰検証を、既存の E2E スクリプトに足す。
- backlog `.aidev/backlog/input-assist.md` の該当項目を、**D1 を覆した経緯つきで**書き直す。

### 対象外

- **単独欄（`EDTMSK` の無い 1 欄の日付欄）の検出。** 材料が無い＝D1 の「材料が無ければ作らない」は
  この範囲では今も正しい。現在値に `/` があるかで判定する案も、新規入力の空欄では材料ゼロになるため採らない。
- **システム値（`QDATFMT` / `QDATSEP` / `QTIMSEP`）による桁順の解決**（decisions D2 のまま据え置く）。
  引けることは実測済みだが、セッションごとのホスト往復と配線が要る。今回は下記の固定解釈で足りる。
- **欄ごとのオプトイン記憶**（利用者が「この欄は日付」と指定して覚えさせる仕組み）。
- 数値スピナー（backlog で「作らない」に決着済み）。
- 3270 / VT の画面。`EDTMSK` 由来の材料は 5250 固有。

## 機能要件

- **F1 判定**: 継続入力フィールドの並びについて、次をすべて満たすとき日付欄 / 時刻欄とみなす。
  - 並びの全区間が非保護かつ数値欄であること。
  - 区間の間の桁が**保護された 1 文字の区切り**で、並びの中で**同一の文字**であること。
  - 区間の桁数の並びが下表のいずれかに一致すること。
  - 区切り文字が下表のいずれかに一致すること。

  | 種別 | 区間の桁数 | 区切り | 解釈 |
  |---|---|---|---|
  | 日付 | `4,2,2` | `/` `-` `.` | `YYYY`→`MM`→`DD` |
  | 日付 | `2,2,2` | `/` `-` `.` | `YY`→`MM`→`DD` |
  | 日付 | `2,2` | `/` `-` `.` | `MM`→`DD` |
  | 時刻 | `2,2,2` | `:` | `HH`→`MM`→`SS` |
  | 時刻 | `2,2` | `:` | `HH`→`MM` |

- **F2 妥協（利用者合意済み）**: 上表の解釈は**固定**とし、桁順の曖昧さは解決しない。
  - `YYYY/MM/DD` / `YY/MM/DD` / `MM/DD`（`YY/MM` かもしれない）を区別しない。
  - `HH:MM:SS` / `HH:MM`（`MM:SS` かもしれない）を区別しない。
  - `2,2,2` ＋ `/` が `DD/MM/YY` や `MM/DD/YY` である可能性は**採らない**（YMD 順に固定）。
  - **UI は解釈を隠さない**——どの区間に何を入れるつもりかが利用者から見えること。
    直接打鍵での入力は常に従来どおり可能で、ピッカーはそれを置き換えない。
- **F3 書き込み**: ピッカーで選んだ値は、**区間の並び全体を 1 つの欄として**書き込む
  （既存の継続欄の編集経路をそのまま使い、書き込み経路を新設しない）。
  各区間は 0 埋めで桁を満たす。MDT と送信の畳み方は既存実装（先頭区間に連結）に従う。
- **F4 設定**: `ViewSettings` に項目を 1 つ足し、`VIEW_ITEMS` に定義を足す（**メニューとキー設定の
  単一の出どころ**なので 2 か所に書かない）。既定は無効。
- **F5 保護欄**: 保護された（出力専用の）分割欄にはピッカーを出さない。

## 非機能要件 / 制約

- **矩形選択・コピー＆ペーストを妨げないこと**（利用者指示。`optHints` と同一の制約）。
  ピッカーの開閉部品は伝播とフォーカス移動を止め、**キーイベントを購読しない**。
- **同じ事実の導出元を 2 つ持たない**。区間の並びの導出は既存の `continuedRunOf`
  （`packages/web-ui/src/composables/continuedRun.ts`）を使い、判定ロジックを再実装しない。
- **ホストが送る情報を UI 側で上書きしない**。ピッカーは値を入れるだけで、欄の属性・区切りの
  静的文字・色・下線には触れない。
- 判定は**画面スナップショットから同期的に**導けること（ホストへの追加往復を発生させない）。
- 既存の継続欄の挙動（Tab 停止点・区間をまたぐ Backspace / Delete・区切り込みペースト）を壊さないこと。
