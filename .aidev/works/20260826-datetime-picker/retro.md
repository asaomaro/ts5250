## 課題 / 手戻り

### C1: 相互作用モデルを規範と突き合わせないまま作った（最大の原因）

deliver 後の 8 コミットは**ほぼ全部これ**——開いてもフォーカスが移らない／`Tab` が抜ける／
`Enter` で確定しない／確定前に値が入る／ホイールで閉じる／月をまたぐとフォーカスを失う。

- requirement の受け入れ基準は**判定の正しさ**と**既存を壊さないこと**に寄っており、
  **「どう操作するか」の AC が 1 つも無かった**（開く・確定・取り消し・キーボード・ホイール）。
- research は**ホストのプロトコル事実**を徹底的に測ったのに、**UI の規範（WAI-ARIA APG 等）は
  1 行も調べていない**。作っているものの 9 割は UI なのに。
- 規範を調べたのは、**利用者に「一般的ですか？」と聞かれてから**だった。そして調べたら
  「逐次反映しながら `Esc` で戻さない」はどの流儀にも当てはまらない、と分かった（D21）。
- **前段で防げた。** spec の時点で APG の該当パターンを 10 分読めば、
  「開いたらフォーカスを移す」「`Enter`/`Space` の役割」「確定するまで書かない」は全部出ていた。

### C2: 遅い層（実機 E2E）でしか出ない不具合が 5 件あった

`ScreenGrid` 単体テストも `EmulatorPane` ごとの単体テストも通り、**実機 E2E だけが落ちた**もの:

| # | 症状 | jsdom で出ない理由 |
|---|---|---|
| D14 | 自分の書き込みでピッカーが閉じる | テストの `edits` が素の `Map`（本番は `reactive`） |
| D20 | `Enter` の AID がホストへ漏れる | ホストの再表示が無いと症状が見えない |
| D22 | ホイールでピッカーが閉じる | 同上 |
| D24 | 月またぎでフォーカスが外れる | **要素が消えてもフォーカスを `body` へ落とさない** |
| M2 | 「現在値から開く」の偽の緑 | 期待値が**実行日と偶然一致**していた |

D24 は原因の特定に**実ブラウザで `focusin`/`focusout` の順と `focus()` の呼び出し元スタックを
採る**まで至った。推測を 3 周した後だったので、**最初から実測すべきだった**。

### C3: 「壊れないこと」を見るテストは素通りする

- 「何度 `Tab` を押しても外へ出ない」→ jsdom は合成 `keydown` でタブ移動を起こさないので、
  トラップが無くても成立していた。**停止点を一周して先頭へ戻る**まで見て初めて効いた。
- 「挿入モードでも入る」→ `insertInto` は末尾空白を落とすので**空欄では溢れない**。
  既に値のある欄で書いて初めて効いた。
- **教訓: 不変条件ではなく「そのとき起きるはずの変化」を書く。**

### C4: review の指摘を直した修正が回帰を生んだ（D14）

M2（未送信の編集を見ていない）の修正で判定関数に実効値を渡したところ、判定が `edits` に
依存して**自分の書き込みで閉じる**ようになった。**指摘への修正にも本体と同じ検証を掛ける**
必要があった（このときは E2E を回さずに次へ進みかけた）。

### C5: spec が実在しない API を名指しした

spec に `cellStyle(...)` と書いたが、実際は `optBtnStyle` だった。`unplanned_lookups` 4 のうち
1 回はこれ。**spec でシグネチャを書くなら、実在を確かめてから書く。**

### C6: 記録の穴

- `aidev event deliver start` を打ち忘れ、**deliver の所要時間が導出できない**（D15）。
  他工程は冒頭で打つ形だが、deliver skill の手順に `event start` が現れない。
- AGENTS.md 違反（実機のシステム名）を 3 ファイルに書いた。review で捕まえたが、
  **同じ名前が既存の backlog にもあった**（機械的な検知が無い）。

## 改善提案

### 製品 / コード（→ issue 候補）

- **P1 実機資材の穴を埋める**: 区切り `.`・`2,2` の 2 区間欄・`-` 区切りの日付欄が
  `DTMDSPF` に無く、単体テストのみ。`scripts/build-dttest.mjs` に 3 ケース足して実測する。
- **P2 `both` の欄でタブへ戻りにくい**: 日から日付/時刻タブへ `Shift+Tab` を数回要する。
  月送り `‹ ›` をタブ順から外す（`tabindex="-1"`・矢印で足りる）と 1 停止点に縮む。
- **P3 オプション選択肢の実機 E2E が無い**: 今回入れた `Tab` 巡回・ホイールの除外は
  ドロップダウン側では**単体テストのみ**。`WRKOBJPDM` を使う E2E を 1 本用意する。
- **P4 欧州式の日付欄（`2,2,4`）**: 対応するなら `QSYS2.SYSTEM_VALUE_INFO` の `QDATFMT` を
  引く配線が要る（引き方は実測済み・前 work の D2）。要否は利用実態しだい。

### PJ プロセス / 規約（→ AGENTS.md）

- **A1 UI 部品を作るときは、確立したパターンと突き合わせてから spec を書く。**
  WAI-ARIA APG の該当パターン（combobox / dialog / grid / listbox）を読み、
  **開く・確定・取り消し・キーボード・フォーカスの行き先**を spec に書く。
  今回の 8 コミットはこれを怠った代償（C1）。
- **A2 テストに teeth があることを確かめる。** 直した箇所を一時的に戻し、**落ちること**を
  見てから採用する。「壊れないこと」ではなく「起きるはずの変化」を書く（C3）。
- **A3 jsdom で測れないものは実ブラウザ E2E へ回す。** 一覧として明記する:
  フォーカスの喪失（要素が消えたとき）／native の `Tab` 移動／ホイールによるスクロール／
  scoped CSS の適用。**ここは単体テストが緑でも保証にならない。**
- **A4 `EmulatorPane` ごと立てるテスト層を持つ。** `ScreenGrid` 単体ではペインの配線
  （キーマップ・カーソル調停・ホイール）が見えない。`datetime-picker-pane.test.ts` が雛形。
- **A5 テストの `edits` は `reactive(new Map())` で作る。** 本番は `sessionsStore`（`reactive`）
  配下なので、素の `Map` では**反応性起因の不具合が再現しない**（D14 で実際に取り逃した）。
- **A6 画面に重ねる部品は、扱うイベントを端末へ漏らさない。** キーは `stopPropagation`、
  ホイールは `OVERLAY_SELECTOR` の除外。**「ペイン側に早期 return があるから大丈夫」は
  要素の生存に依存した推論**で、作り直しの瞬間に破れる（D24）。
- **A7 期待値を実行日に依存させない。** 「今日」と偶然一致して偽の緑になった（M2）。
  日付を扱うテストは**固定の年**で書く。

### ハーネス自体（→ `aidev-*` への提案・適用は人間）

- **H1 UI を伴う work では、requirement に「相互作用の受け入れ基準」を要求する。**
  `aidev-10-requirement` のテンプレートに、UI 作業のときだけ埋める節を足す:
  「開く手段 / 確定 / 取り消し / キーボードだけで完結するか / 既存の入力を妨げないか」。
  **今回はここが空白だったせいで、AC を全部満たしたまま使えないものが deliver を通った。**
- **H2 `aidev-15-research` の対象に「UI の規範」を明記する。**
  現在の手順は「既存コード・外部ドキュメント・実現性」で、事実上プロトコル調査に寄る。
  **作るものが UI なら、確立したパターン（APG 等）の調査を同じ重みで課す。**
- **H3 deliver 後の追補が metrics に入らない。** 今回、経過時間の 76%・実装行の 47% が
  パイプラインの外にある。insights で「規模あたりの手戻り」を見ると**この work は
  異常に優秀に見える**。deliver 後の指摘を記録する口（`aidev event followup` 等）か、
  「PR がマージされるまでを 1 work とする」かの整理が要る。
- **H4 `aidev-70-deliver` の手順に `aidev event deliver start` が無い。**
  他工程は冒頭で打つ形になっているが deliver だけ抜けており、実際に打ち忘れた（D15）。

- **H5 review の指摘に対する修正を、本体と同じゲートに通す規約を明記する。**
  「差し戻し → 修正 → 再 review」の間に test を通す義務が読み取りにくい。
  今回は修正が回帰を生み、E2E で拾えた（C4）。
- **H6 環境の固有名詞の機械的な検知。** `.env.verify` は追跡外だが**エージェントは読んでよい**
  ので、その値を差分から grep するチェックを `aidev verify` か Stop フックに置ける。
  今回は review で捕まえたが、3 ファイルに書いた後だった（C6）。
