# 要件: テンキーの ± と Field− の可否・符号付き数値欄の文字を ACS と同じにする

## 背景 / 課題
- 台帳「【まとめ】キー編集の細部が ACS と違う」のテンキーの ±（中〜低）と、低の「Field− の可否、数値専用欄での Field−」。
- ACS はテンキーの − / ＋ をすべての欄で Field− / Field+ にし（既定の割り当て `B109` / `B107`）、メイン行の `-` `+` は文字として扱う。
  Field− は符号付き数値・数値専用の欄でしか通らない（他はエラー 0022）。符号付き数値欄は数字しか受けない（エラー 0016）。
- 当 PJ は物理キーを見分けず、数値欄（数字専用を除く）の `-` `+` をすべて Field± にし（`signKeyHack`）、Field− はどの欄でも Field Exit として通り、
  符号付き数値欄に `.` `,` 空白が入った。

## 目的 / ゴール
- ± のキーと Field− で、欄の値とエラーが ACS と同じになっている状態。

## ユーザーストーリー
- US1: 5250 の利用者として、テンキーの − で ACS と同じくどの欄でも Field− が効き、使えない欄ではエラーで止まってほしい。なぜなら、
  英数字欄で Field− を押して値が消えて次の欄へ進むと、ACS に慣れた手順で入力が壊れるから。（受け入れ: AC1, AC2, AC3）

## スコープ
### 対象
- テンキーの ± の振り分け（`classifyKey`）と、欄の input での素通し（SBCS・DBCS）。Field− の可否（0022）。符号付き数値欄は数字だけ。`signKeyHack` の撤去。
### 対象外
- 数値専用欄の Field− で最終桁のゾーンを D にする（表示のコード変換が絡む。台帳に残す）。Field± の ME・MF・入出力欄の検査（0033・0020・0004）。

## 完了条件 (受け入れ基準)
- [ ] AC1: テンキーの − / ＋（修飾なし）はどの欄でも Field− / Field+ で、文字としては入らない。メイン行の `-` `+` は文字。
- [ ] AC2: Field− は符号付き数値・数値専用の欄でだけ通り、他（英数字・数字専用・継続欄）ではエラー 0022（操作員エラー）で値もカーソルも変えない。Field+ はどの欄でも Field Exit と同じ。
- [ ] AC3: 符号付き数値欄は数字だけを受ける（`-` `.` `,` `+` 空白はエラー）。
- [ ] AC4: 各判定を外すとテストが落ちる（`verify-by-mutation`）。
