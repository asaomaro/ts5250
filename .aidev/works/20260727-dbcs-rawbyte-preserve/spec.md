# 仕様: DBCS 欄を編集しても SO/SI・全角のバイトを壊さない

## 設計方針

### D1. 生バイトのセンチネル化から `!dbcs` ゲートを外す

```ts
s += c.char === UNDISPLAYABLE && c.rawByte !== undefined ? rawSentinel(c.rawByte) : c.char;
```

PR #173 が属性について行った修正と**同じ形**。送信側（`read-response`）は
センチネルを生バイト 1 つとして書き出すので、DBCS 欄でも安全。

### D2. `dbcs` ローカル変数を削除する

属性・生バイトの両方から DBCS 例外が消えた結果、この変数は未使用になる（lint が検出）。
**「DBCS 欄かどうかで値の作り方を変える」という考え方自体が無くなった**ことを、
変数の消滅で示す。

## 受け入れ基準との対応

| 完了条件 | 満たし方 |
|---|---|
| 他のバイトがそのまま送られる | D1 |
| SUB が現れない | D1（U+FFFD を経由しなくなる） |
| 修正前に落ちるテスト | `dbcs-embedded-attr.test.ts` に追加し、ゲートを戻して落ちることを確認 |
| 実機 round-trip | 実機の SEU で編集・保存し、メンバーのバイトを SQL で照合 |
