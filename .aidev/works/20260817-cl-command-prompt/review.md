# レビュー

## 作ったもの

**実機の F4 に当たる画面**——コマンド名を入れると定義が引かれ、パラメータが説明つきで並び、
埋めて実行できる。

| 層 | 追加 |
|---|---|
| `server` | `host-command.ts`——`/template`・`/build`・`/run` の 3 ルート |
| `web-ui` | `CommandPane.vue`（`cmd:` ペイン）・ランチャーの入口 |
| 検証 | `scripts/verify-browser-command-prompt.mjs`（実ブラウザ・実機） |

実機の画面（`CRTLIB`）:

```
CRTLIB  Create Library (__LIBL)
キーワード 説明                     値              既定 / 制限
LIB *      Library                 [TPLUI      ]   / 10 桁
TYPE       Library type            [ ▾（既定）]    既定 *PROD / 10 桁
AUT        Authority               [           ]   既定 *LIBCRTAUT / 10 桁
…
CRTLIB LIB(TPLUI) TEXT('It''s a prompt test')   ← サーバーが組んだ文字列
成功（戻りコード 0）
・CPC2102 Library TPLUI created.
```

## 効いた判断

### 1. 組み立てと検証は**サーバー**（spec D1）

引用の規則は `hostserver` の `buildCommand` にしかない。画面側に写すと**二重管理になり、
片方だけ直る**。UI は値の入れ物に徹し、**判定は 1 か所**。

### 2. 「確かめる」を足した（途中で気づいて追加）

最初は画面側で**下書き**を作って見せるだけにしていたが、実機で撮った画面を見て気づいた
——**下書きは `TEXT(It's a prompt test)`、実際に走るのは `TEXT('It''s a prompt test')`**。
**見えている文字列と走る文字列が別物**では、F4 の値打ち（実行前に目で確かめる）が消える。

そこで**組むだけの口**（`/build`）を足し、「確かめる」で**サーバーに組ませた文字列**に
差し替えるようにした。**値を触ったら消える**——古い文字列を見せない。

> 規則を画面へ写せば下書きは正確になるが、それは D1 を捨てることになる。
> **1 往復増やす方を選んだ。**

### 3. 既定値は欄に入れない（spec D3）

CL は**空欄＝ホストの既定**。欄に入れてしまうと「消したのに既定が効かない」ことになる。
既定は**脇に出す**（`既定 *PROD`）。

### 4. 扱えないパラメータは名前を挙げる（spec D4）

`ELEM`（入れ子）は欄を出さない——出すと「入れたのに効かない」。
代わりに**名前を挙げて**「この画面では扱えない」と出す。黙って落とさない。

## 前作業の裏付け（教わった資料）

`blue-red.ddo.jp` の「Java から RPG や CL を呼び出す」で、jt400 の CL 実行が
**`CommandCall.run(文字列)` だけ**であること、**PCML はプログラム呼び出しのテンプレート**で
あることを確認した。「テンプレートから CL を組む」は jt400 に無く、
前作業（`20260817-cl-command-template`）がその足し前だった、で正しい。

なお **PCML に当たるもの**は既にある——`ProgramArg`（型つき引数）と `pgm:` ペイン。

## 残っていること

- **`ELEM` の入れ子**——前作業と同じ範囲で止めた
- **コマンド名の補完**（`*CMD` の一覧）——別作業。今は名前を知っている必要がある
- **実機の F4 と同じ配置**（ページ送り・F9 で全パラメータ）——1 画面に並べる形にした
