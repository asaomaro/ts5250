# 要件: 窓の誤検出を入力欄で切る（backlog `window-detect.md` の補助条件）

## 背景

窓装飾の範囲は、ホストが `CREATE_WINDOW(51)` を送らない場合**罫線から推測**している
（`fkeyLegend.ts` の `detectWindowRect`）。条件が緩く、**左右に `:` が並ぶ帳票を窓と誤る**
（backlog の実測 ③）。

backlog には補助条件の案が「**未着手**」として残っていた——「入力欄が全て矩形内に
収まっているか。③ のような表は枠外にも入力欄があるので弾ける。安価なわりに効く」。

## 未着手だった理由と、今回それを潰したこと

案には**懸念**が併記されていた: 実機 5 パターンで調整済みの前面判定と干渉しうる。
さらに**もっと根本的な問題**があった——**既存の実機 fixture はテキストと `lastWrite` しか
持たず、`fields` を含まない**。つまり「本物の窓が開いているとき背景の入力欄が残るか」を
既存資産では答えられず、**残るなら案そのものが没**だった。

そこで**測りに行った**（`scripts/diag-window-fields.mjs`。実機 / IBM i 7.3）。

## 目的

誤検出を減らす。**本物の窓を殺さないことを実データで示したうえで**足す。

## スコープ

- `fkeyLegend.ts` に `hasInputOutside` を足し、罫線・反転の両経路で選ばれた候補に掛ける
- 実機 4 画面を `fields` 込みで採り、fixture にする
- 採取スクリプトを残す

### 対象外

- 判定そのものの作り直し（`gui.windows` を使う道／core 改修）。backlog の本筋は別項目
- ③ を全部消すこと。**入力欄の無い画面には掛からない**ので、これは補助にとどまる

## 完了条件

- [ ] 実機の F1 ヘルプ窓（2 例）が**検出されたまま**である
- [ ] 枠外に入力欄がある帳票が `null` になる
- [ ] 保護欄では切らない／欄が無ければ従来どおり
- [ ] 既存の web-ui テストが全て緑（実機 5 パターンの前面判定を含む）
- [ ] `npm run build` / `npm run lint` が通る
