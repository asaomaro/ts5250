# 要件: 再順序付け（SOH＋FCW 0x80nn）で READ の欄の並びを ACS と同じにする

## 背景 / 課題
`.aidev/backlog/acs-parity.md`「DS5250 の残り」の FCW 0x80xx: ACS は SOH の本体 3 バイト目（先頭の欄の番号）と各欄の FCW 0x80nn（次の欄の番号）で欄の鎖を作り、
READ の応答の欄をその順に送る。当 PJ は FCW 0x80xx を読み飛ばし、画面順で送る。実機（DSM の RESEQ）で ACS と当 PJ の並びが違うことを確かめた。

## 目的 / ゴール
再順序付けのある画面で、ホストへ届く欄の並び（と、どの欄が届くか）が ACS と同じ状態。

## ユーザーストーリー
- US1: 再順序付けを使う画面の利用者として、ACS と同じ並びで値が届いてほしい。なぜなら平たい形（READ INPUT）は位置で値を切り出すので、並びが違うとホストの受け取る値が入れ替わるから。（受け入れ: AC1, AC2, AC3）

## スコープ
### 対象
- SOH の再順序付けの番号・FCW 0x80nn の読み取り、READ MDT 系・READ INPUT 系の欄の並び、再順序付けとカーソル送りの組の断り
### 対象外
- Tab の順（ACS も画面順のまま）

## 完了条件 (受け入れ基準)
- [ ] AC1: READ MDT 系は SOH の番号の欄から FCW の番号を辿り（0xFF で終わり）、辿った先が MDT でなければそこで止まる（実機・単体）
- [ ] AC2: READ INPUT 系は同じ鎖を MDT を問わず辿る（FCW が 0 なら表の次の欄）（単体。原典）
- [ ] AC3: 再順序付けのある画面ではカーソル送りの欄を表に入れない（否定応答 0x10050125）。CLEAR 系・SOH で再順序付けを 0 に戻す（単体。原典）
