# 決定記録

## D1: `20260927-wtd-sense-rest` decisions D7（再順序付けとカーソル送りの組は「当 PJ が再順序付けを持たないので見ない」）を破棄する

- 背景: この work で再順序付けを持つようになった。D7 の前提（持たない）が崩れた
- 決定: ACS `FFT5250.isValidCursorProgressField` どおり、SOH で再順序付けを申告した画面のカーソル送りの欄は表に入れず 0x10050125（`wtd-applier.ts` の `applySf`。コメントの記述は取り消し線で残した）
- 証拠: 原典（research F4）。実機では出させていない（単体のみ）

## D2: ACS が例外になる形（MDT 系の番号 0・範囲外・一巡）は「そこで終わり」にする

- 背景: ACS `nextModifiedField` は番号 0 で `elementAt(-1)`、範囲外でも例外になり、応答を作れない
- 決定: 当 PJ は例外にせず、そこまでの欄を送る（ホストが待ち続けるより安全）。差として残す
- 影響: 等価の変異 2 つ（0xFF の判定・一巡の判定）は、表が 255 欄に満たない・送る側が重複を落とすので出力が同じ。一巡の判定は無限ループの防御

## D3: 番号は欄の表の順（番地の順）で数える

- 背景: ACS の番号は FFT の要素の順（定義の順）。当 PJ の `orderedFields()` は番地の順
- 決定: 昇順でない SF は ACS も表に入れない（`FFT5250.checkNewField`。当 PJ も同じ）ので、定義の順と番地の順は一致する。そのまま番地の順を使う
