# 要件: Attn・ヘルプから戻ったときに打鍵と MDT を失わない（SAVE/RESTORE SCREEN と画面イメージ応答を ACS に合わせる）

## 背景 / 課題

- **打ったまま送っていない入力が、黙って消える。** メインメニューのコマンド行に `WRKACTJOB` を打ち（送らない）、
  Attn → F12 と押して戻ると、当 PJ ではコマンド行が空欄になり MDT も落ちる。ACS では `WRKACTJOB` が残り、
  カーソルも元の位置（20 行 16 桁）へ戻る（`20260919-backlog-acs-triage` research N1。実機で ACS と並べて実測。
  優先度 高・深さ ◎）。
  - **データが黙って失われる**ので、利用者は「打ち直せばよい」と気づくまで、消えたことにも気づけない。
  - **ヘルプ（F1 → F12）でも同じ経路を通る。** SysReq も同様。
- **原因の見立て**（着手時に両側を再確認する。以下は起票時点の記述）:
  - ホストは F12 に `ESC 12`（RESTORE SCREEN）の後ろへ、**こちらが SAVE SCREEN 応答として送った積荷**
    （`ESC 11 …` の WTD）を付けて返してくる。
  - `packages/tn5250/src/protocol/wtd-applier.ts:204` の `RESTORE_SCREEN` は、ローカルの退避スタックから
    戻したあと `break` する。同じレコードに続く積荷を、**次のコマンドとして適用してしまう**。
  - 積荷を組み立てる `packages/tn5250/src/protocol/save-screen.ts:243` の `writeCell` は `rawByte ?? 0x40` なので、
    打鍵した文字は空白になる。SF は元の FFW を使うので MDT も落ちる。
  - `save-screen.ts:17-22` は「こちらの RESTORE SCREEN はホストの積荷を読まず、ローカルの退避スタックから
    復元する」と書いているが、**実装がそう read していない**（食い違っている）。
- **退避している状態が足りない。** `packages/tn5250/src/screen/buffer.ts:514` の `savedStack` が持つのは
  サイズ・セル・フィールド・カーソル・引き継ぎ終端・GUI の 4 種だけ。**CA マスク（`aidNoDataMask`）・
  メッセージ行（`systemMessage`）・保留中の READ は入っていない**。
  - ACS は `DS5250.processSaveScreen` が状態一式（欄・全プレーン・カーソル・施錠・保留中の READ・
    メッセージ行・CA マスク）を `Save5250Net` で直列化し、0x12 で丸ごと戻す。
  - CA マスクが戻らないと、**F12 で欄データを送ってしまう**（`CAnn` は「欄データを送らない」キーなので、
    ホストの期待と食い違う）。
- **同じ根から、画面イメージ応答（READ SCREEN）にも差がある**（research N14。優先度 中・深さ △）。
  - 当 PJ は `save-screen.ts:106-117` でカーソル 2 バイトを前置し、opcode を PUT_GET にし、未書き込み桁を
    0x40 にする。ACS（`DS5250.processReadScreen`）は**前置なし・opcode は受信したものの写し・NUL はそのまま**。
  - 打鍵した SBCS 文字が 0x40 になるのも同じ `writeCell` 由来。
  - **ただし到達するかが未確認**。READ SCREEN EXTENDED（0x64）は実機で 9 通り試して形式を確定させた経緯があり
    （`save-screen.ts:160-176`）、0x62 系も**実機で確かめずに変えると、ヘルプが返らなくなる回帰**を招く。
- 本 PJ は ACS / 5250 端末の**代替**である。規格上どうであれ、ACS と挙動が違えば利用者には不具合に見える
  （`AGENTS.md`「既存クライアントと同じ挙動を優先する」）。

## 目的 / ゴール

- **Attn・SysReq・ヘルプから戻っても、打鍵した文字と MDT が残っている**状態。ACS と並べて同じに見える。
- **退避と復元が状態一式を往復する**状態。CA マスクが戻るので、F12 が欄データを送らない。
  メッセージ行・保留中の READ も ACS と同じ扱いになる。
- **自分が送った積荷を、自分で次のコマンドとして適用しない**状態。`save-screen.ts` の「積荷は読まない」という
  記述と実装が一致している。
- **画面イメージ応答（READ SCREEN 系）について、ACS との差が実測で決着している**状態。
  ACS に合わせたか、到達しないことを確かめて対象外にしたかのどちらかが、根拠付きで記録されている。

（`.aidev/charter.md` は無いので、charter ゴールとの紐付けは行わない）

## ユーザーストーリー

- US1: 5250 端末の利用者として、Attn やヘルプを開いて戻ったときに、打ちかけの入力がそのまま残っていてほしい。
  なぜなら、消えたことに気づけないまま Enter を押すと、意図しない内容（空欄・古い値）をホストへ送ることになるから。
  （受け入れ: AC1, AC2, AC3）
- US2: DDS で `CAnn` を定義したアプリケーションの利用者として、F12 で欄データが送られないでほしい。
  なぜなら、`CAnn` は「入力を捨てて戻る」ための定義で、欄データが届くとホスト側の処理が
  「入力があった」と誤って分岐するから。（受け入れ: AC4）
- US3: ヘルプ（F1）を使う利用者として、背面の画面が元どおりに再現されてほしい。
  なぜなら、ホストは画面イメージ応答をそのまま描き直して背面を作るので、応答の形式が違うと
  ヘルプが出ない・背面が壊れるという形で表に出るから。（受け入れ: AC5, AC6）
- US4: この PJ の保守者として、退避・復元の経路に回帰テストが残っていてほしい。
  なぜなら、SAVE/RESTORE は SEU・PDM・QSH・窓の各経路が共有していて、片方を直すと別の経路が
  黙って壊れる（実際に F1→F12 の画面崩れ・QSH の固まりが起きている）から。（受け入れ: AC7, AC8）

## スコープ

### 対象

- **RESTORE SCREEN（`ESC 0x12`）/ RESTORE PARTIAL SCREEN（`ESC 0x13`）の復元経路**
  - 同じレコードに続く積荷の扱い（読み飛ばす／名指しで引く等。手当ての選択は design で決める）
  - `packages/tn5250/src/protocol/wtd-applier.ts` の `RESTORE_SCREEN` / `RESTORE_PARTIAL_SCREEN`
- **SAVE SCREEN（`ESC 0x02`）/ SAVE PARTIAL SCREEN（`ESC 0x03`）で退避する状態の範囲**
  - CA マスク（`aidNoDataMask`）・メッセージ行（`systemMessage`）・保留中の READ・施錠状態
  - `packages/tn5250/src/screen/buffer.ts` の `savedStack` / `saveScreen()` / `restoreScreen()`
- **打鍵した文字と MDT が往復で保たれること**
  - 保たれる仕組みが「積荷を読まない」で足りるのか、退避側に手が要るのかを含めて決める
- **画面イメージ応答（READ SCREEN `0x62` / `0x66` / `0x6A`）の ACS との差**
  - カーソル 2 バイトの前置・opcode（PUT_GET か受信の写しか）・未書き込み桁（NUL を 0x40 にするか）
  - 打鍵した SBCS 文字が 0x40 になる件（`writeCell` の `rawByte ?? 0x40`）
  - **実機で到達性を確かめる**。到達しないなら「対象外」と根拠付きで記録して閉じる
- **実機での A/B 検証**（`scripts/acs-probe.mjs` で ACS のコアを当て、当 PJ と並べる）
- 回帰テストの追加（`packages/tn5250/test/` と、必要なら `packages/web-ui/test/`）

### 対象外

- **【まとめ】DS5250 のその他の差のうち、画面イメージ応答以外**——台帳に残す。
  - WEA タイプ 5（拡張 NLS 区間）・ROLL の空いた行の扱い・CLEAR 系の付随処理・WSF D9/72 と
    WDSF 0x52/0x54/0x55・FCW 0x80xx/0x84xx・負応答・0x82/0x83 の欄データでの NUL と符号の加工
- READ SCREEN EXTENDED（`0x64`）の形式。実機で確定済みで、今回の差の対象に入っていない
  （`save-screen.ts:160-176`）。ただし**壊さないことは確かめる**（AC7）。
- 施錠中の先打ち（type-ahead）の扱い。別項目（`acs-parity.md`「施錠中・応答待ち中の打鍵」。要判断）。
- 挿入モードのあふれ、Erase Input、CC1=0xC0 など、他の acs-parity 項目。
- TN3270 / VT。

## 機能要件

- FR1: ホストが RESTORE SCREEN（`0x12`）/ RESTORE PARTIAL SCREEN（`0x13`）で返してくる積荷を、
  **次のコマンドとして適用しない**。積荷は不透明な保管物として扱う。
- FR2: SAVE SCREEN / SAVE PARTIAL SCREEN で退避する状態に、少なくとも次を含める
  （ACS `DS5250.processSaveScreen` と `Save5250Net` の範囲に合わせる）。
  - CA マスク（SOH の「欄データを送らない AID キー」の申告）
  - メッセージ行 / エラー状態
  - 保留中の READ（種別と、それに伴う施錠状態）
- FR3: 復元後、**打鍵した文字と MDT が退避前の状態で残る**。カーソル位置も退避時の位置へ戻る。
- FR4: 画面イメージ応答（READ SCREEN `0x62` / `0x66` / `0x6A`）について、次のどちらかを満たす。
  - ACS（`DS5250.processReadScreen`）と同じ形式で返す（前置・opcode・未書き込み桁の扱い・打鍵文字）
  - **実機でそのコマンドが到達しないことを確かめ**、変更しない理由として記録する
- FR5: 既存の実機経路を壊さない。少なくとも SEU の F1 → F12、PDM の F1、QSH の SAVE PARTIAL、
  窓（CREATE WINDOW / ASSUME 付き WINDOW）の往復を確かめる。
- FR6: 変更した経路に回帰テストを足す（`AGENTS.md`「変更ごとにユニット/コンポーネントテストを追加し回帰資産化する」）。

## 非機能要件 / 制約

- **`AGENTS.md` のコーディング規約に従う。** とくに次の 3 点が今回の変更箇所に掛かる。
  - ログは stderr のみ（`console.*` は lint で禁止）。ライブラリ側は `@ts5250/base` の `log` の sink 経由。
  - ピュアロジック層は Node API 非依存（`node:*` の import は `transport/` のみ）。
  - コメントは「なぜ」を書く。出所（`file:line`・ACS のクラス／メソッド名・work slug）を添える
    （条項 `comment-provenance`）。
- **ACS の原典をリポジトリに入れない**（`AGENTS.md`「ライセンスと出典」）。ACS のクラス・メソッド名と、
  振る舞いを自分の言葉で書く。逐語の引き写しをしない。デコンパイル結果は scratchpad に置く。
- **実機の作法**（`AGENTS.md`「実機の識別子」・`scripts/README.md`）。
  - 識別子は `.env.verify` から採る。`.env` は**読まない**（`--env-file` で渡すだけ）。
  - 装置名は使い回す。作った検証用オブジェクトは片付ける。
  - 実機の固有名詞（システム名・ライブラリ名・装置名・IFS パス・ユーザー名）をリポジトリに書かない。
- **実測値を記録に残すときは、計測器そのものを疑う**（条項 `measurement-sanity`）。
- 秘密（パスワード・鍵）をコミットしない。`.aidev` の成果物にも書かない。

## 未確定事項 / 確認したいこと

- **積荷をどう避けるか**（design で決める）。候補は 3 つ:
  長さで読み飛ばす／レコードの残りを捨てる／退避スタックを名指しで引く（積荷に識別子を載せる）。
  「ホストが積荷を改変して返すことがあるか」を research で確かめる必要がある。
- **打鍵した文字はどこに在るか。** サーバー側の `ScreenBuffer` が打鍵を保持しているのか、
  web-ui 側だけが持っていて RESTORE の全画面書き込みで上書きされるのかで、手当ての場所が変わる。
- **保留中の READ・施錠状態を、当 PJ のどこが持っているか**（`ScreenBuffer` か、セッション層か）。
  退避の対象に加えるには、まず持ち主を確かめる。
- **画面イメージ応答（`0x62` / `0x66` / `0x6A`）が実機で到達するか。** 拡張 5250 を申告している当 PJ には
  `0x64` が来ている可能性が高い。到達しないなら FR4 は「記録して閉じる」で済む。
- **ACS の退避に「全プレーン」が含まれる**という記述の範囲（色・拡張属性のプレーンを指すか）。
  当 PJ のセル表現との対応を research で確かめる。
