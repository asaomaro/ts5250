# 要件: 実機の版数とパスワードレベルを実測で確定し、誤った前提を正す

## 背景 / 課題

2026-08-01 に利用者から社内機 **実機** の資格情報の提供を受け、初めて接続した。
接続しただけで backlog の 2 項目に答えが出て、うち 1 つは**前提そのものが誤り**だった。

### 1. パスワードレベル 0/1 の実機認証（`hostserver.md:67`）— 通った

「PR #109 の本文が自ら挙げた穴——この環境から到達できないため未検証。参照実装とバイト単位で
一致しているので確度は高いが、**実機のハンドシェイクは通していない**」として残っていた項目。
実機は `password level : 0` で、**DES 経路のサインオンが実機で通った**。

### 2. 「実機も 7.5」は誤り（`hostserver.md:197`）— 実際は 7.3

backlog は「PUB400 も実機も 7.5。**バージョン差による違いには当たっていない**」と
書いているが、実機は **IBM i 7.3** だった。

**この誤りはリポジトリ全体に広がっている**——`.aidev/works/*` の research / walkthrough、
`.aidev/backlog/*.md`、`packages/web-ui/test/*.ts` のコメントなど**約 20 か所**が
「実機・IBM i 7.5」と書いている。2026-07-26 以降の作業はほぼすべて実機で
実測しているので、**「7.5 で確かめた」と読める記録が大量に残っている**。

実害は「バージョン差の検証が済んでいるのに未着手に見える」ことだけではない。逆に
**「7.5 で確認済み」と信じて 7.5 固有の挙動を判断すると誤る**。プロトコル実装では版数が
挙動を左右する（AGENTS.md「実機検証を単体テストの代替にしない」の裏側）。

## 目的 / ゴール

実測した事実を台帳に反映し、**誤った前提を読み手が踏まないようにする**。

- パスワードレベル 0 の認証成功を根拠つきで記録し、当該項目を閉じる
- 実機の版数を訂正し、「バージョン差の検証」の状態を実態に合わせる
- **どの実機がどの版数か**を、次に実測する人が最初に見る場所に残す

## スコープ

### 対象

- `.aidev/backlog/*.md` の**生きた台帳**の訂正（`hostserver.md` / `input-assist.md` / `window-detect.md`）
- 版数を事実として書いている**ソースコードのコメント**（`packages/web-ui/test/window-write-extent.test.ts`）
- 実機の一覧（どの機械が何版か・どう確かめたか）を `scripts/README.md` に追記
- 実測記録を `test-result.md` に残す

### 対象外

- **`.aidev/works/*` の過去の成果物 15 件超の書き換え**。あれは**その時点の記録**であり、
  全面改訂は履歴を濁す（AGENTS.md「手法や経緯の記録は残す価値がある」）。
  代わりに**生きた台帳と実機一覧に訂正を集約**し、過去記録を読む人がそこへ辿り着ける形にする
- **PUB400 の版数**（`V7R5M0` の実測が `20260718-hostserver-command/test-result.md:19` にある。正しい）
- **7.3 と 7.5 の差分そのものの調査**（何が違うかは別途。本 work は「どちらで測ったか」を正す）
- 資格情報の恒久的な保管方法の変更

## 機能要件

- 版数の訂正は**2 経路以上の実測**に基づく（1 つの表示を信じない）
- パスワードレベルの記録は、backlog が指定した**検証手順そのもの**を通した結果に基づく
- 誤っていた記述は**取り消し線で残す**（消さない）。AGENTS.md「誤解を招く事実主張だけを消す」
- 実機一覧には、次の人が**自分で確かめ直せる手順**を書く

## 非機能要件 / 制約

- **実資格情報を成果物・コミット・PR に書かない**（AGENTS.md）。
  パスワードは `.env`（`.gitignore` 済み・未追跡）にのみ置く。
  ログ・出力を貼るときは伏字にする
- 実機に**副作用を残さない**。読み取り専用の確認に留める
- コードの振る舞いは変えない（コメントと文書のみ）
