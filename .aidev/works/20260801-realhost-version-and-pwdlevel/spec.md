# 仕様: 実機の版数とパスワードレベルを実測で確定し、誤った前提を正す

## 概要

コードの振る舞いは変えない。**実測結果を残し、生きた台帳とコード上の事実記述を訂正し、
実機の一覧を作る**。

## 設計方針

### D1: 版数は 2 経路の実測で確定する（表示 1 つを信じない）

| 経路 | 結果 |
|---|---|
| サインオンサーバーの VRM（`CP.version` を `formatVersion` で整形） | **`V7R3M0`** |
| `QSYS2.GROUP_PTF_INFO` の累積 PTF グループ | `SF99730` = **`CUMULATIVE PTF PACKAGE C9116730` / `C3257730`** |

累積 PTF パッケージ ID は `Cyyddd<rrr>` の形で、**末尾 3 桁が版数**（`730` ＝ 7.3.0）。
群番号 `SF99730`（7.3 の累積群）とも一致する。同機の他の群も 7.3 系
（`SF99703` DB2 FOR IBM I / `SF99727` TECHNOLOGY REFRESH / `SF99729` GROUP HIPER）。

補強: `QSYS2.ENV_SYS_INFO` が `SQLCODE=-204`（存在しない）。

**採らなかった案**: サインオンの VRM だけで断定する。**同じ誤りの繰り返しになる**
——「実機は 7.5」も、おそらく誰も測らずに書かれた。1 経路で断定しない方針をここで作る。

### D2: 過去の works 記録は書き換えない。導線を 1 か所に集約する

「実機・IBM i 7.5」は `.aidev/works/*` の research / walkthrough / requirement など
**15 件超**に散っている。全面改訂は
- 履歴を濁す（AGENTS.md「手法や経緯の記録は残す価値がある」）
- 差分が巨大になり、本当に直したい場所が埋もれる

ので**やらない**。代わりに訂正を**生きた面**に集約する:

| 面 | 扱い | 理由 |
|---|---|---|
| `.aidev/backlog/*.md` | **訂正する**（取り消し線＋事実） | 次に着手する人が読む。判断を歪める |
| ソースのコメント | **訂正する** | コードを読む人が事実として受け取る |
| `scripts/README.md` | **実機一覧を新設** | 実機で測る人が最初に開く |
| `.aidev/works/*`（過去） | **触らない** | その時点の記録。訂正は上の 3 面から辿れる |

**導線**: `scripts/README.md` の実機一覧に「**2026-08-01 以前の記録は実機を 7.5 と
書いているが誤り**」と明記する。過去記録を読んだ人がここへ突き当たる。

### D3: パスワードレベルは backlog 指定の手順そのもので確かめる

backlog（`hostserver.md:70`）は検証手順を書いている:

```
AS400_USER=xxx AS400_PASSWORD=yyy npm run cmd -w @as400web/hostserver-check -- --host <実機> [--tls]
```

**この手順を通した結果**を記録する（別の経路で通しても「手順どおり確かめた」とは言えない）。
実行結果は `成功 rc=0x0`（読み取り専用の `CHKOBJ` を投げた）。
サインオン単体（`main.js`）でも `認証成功 / password level : 0` を確認した。

### D4: 資格情報は差分に一切出さない

- パスワードは `.env`（`.gitignore:7` で除外・未追跡）にのみ置く
- 記録に貼る出力は**伏字**（`***`）にする。ユーザー ID `USER` は
  リポジトリに既出（`TESTLIB` / `/home/USER`）なので伏せない
- ホスト IP `192.0.2.1` も既出（`screen-export.test.ts` 等）。新たな露出ではない
