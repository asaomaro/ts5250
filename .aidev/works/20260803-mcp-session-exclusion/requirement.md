# 要件: MCP の操作を、見ている人が居るときだけ排他する

## 背景 / 課題

**1 つの 5250 セッションを、ブラウザ・MCP・HLLAPI の 3 つが同時に触れる。**
5250 は入力欄の値を AID と一緒に送るので、ブラウザは Enter を押すまで打ちかけを手元に持つ。
その最中に別の書き手が画面を変えると、打ちかけの行き先が消える。

HLLAPI 側は `20260803-hllapi-bridge` で塞いだ（`Reserve` / `Release`）。**MCP 側が残っている。**

2026-08-04、利用者のブラウザセッションを MCP から操作して見せた際、
**その間ブラウザから同じ画面へ打てる状態だった**ことを実地で確認している。

| | 予約できる | 予約中に締め出される |
|---|---|---|
| HLLAPI | ✅ | — |
| **MCP** | **❌** | ✅ |
| ブラウザ | ❌（解除だけ） | ✅ |

## 目的 / ゴール

**MCP の書き込みが、見ている人が居るときだけ自動的に排他される。**
利用者には「MCP が自動操作中です」と出て、入力が止まり、解除の口がある。

## スコープ

### 対象

- **見ている人の在席**を `SessionEntry` が持つ（ws-handler が付け外し）
- MCP の書き込みツールが、在席時に予約してから書く（`holder = "mcp:<user>"` / `label = "MCP"`）
- 予約の期限を**用途別に持てる**ようにする（HLLAPI の 2 分と、MCP の短い期限）
- `list_sessions` に予約状態を載せる

### 対象外

- **ブラウザから既存セッションを開く（attach）** — 単数枠フックの作り直しを伴うので別作業
- ブラウザ側から人間が予約する手段
- HLLAPI 側の挙動変更（既に入っている）

## 機能要件

- **判定は「ブラウザと疎通があるか」だけ。** セッションの出どころで判断しない
- MCP が自分で開いたセッション（誰も見ていない）では**予約しない**——儀式にしない
- **エージェントに囲わせない。** `reserve_session` のようなツールは作らない（囲い忘れる余地を作らない）
- 連射でちらつかない（短い期限＋呼び出しごとの延長）
- 表示側は**変更しない**（`label` がそのまま出る仕組みが既にある）

## 非機能要件 / 制約

- 既存の 3,909 件を壊さない
- 締め出しの検査は `assertWritable` / `assertKeyAllowed` の内側に据え置く（経路ごとに書かない）
- `console.*` を使わない（PJ 規約）

## 完了条件 (受け入れ基準)

- [ ] ブラウザが見ているセッションを MCP が書くと、**画面に「MCP が自動操作中です」が出る**
- [ ] その間、ブラウザから打てない
- [ ] MCP の連射で覆いが**点滅しない**
- [ ] MCP が終われば短時間で自然に解ける
- [ ] **誰も見ていないセッションでは予約しない**（MCP が開いた場合を含む）
- [ ] `list_sessions` で予約状態が分かる
- [ ] 実機 E2E（`verify-hllapi-browser.mjs` の拡張）で目視確認できる

## 未確定事項 / 確認したいこと

- MCP 用の期限を何秒にするか（案: 5 秒）。実機の 1 往復は 1〜7 秒かかることがあるので、
  **`Wait`/`Pause` 系の長い操作でどう見えるか**を測ってから決める
