# 決定記録

## D1: UI はキーイベントを 1 つも購読しない（利用者指示への対応）

- 背景: 利用者から「**矩形選択やコピー＆ペーストに影響を与えないように**」との指示（2026-07-29）。
  spec の初版は `Esc` で閉じる・欄の右端に印を置いてクリックで開く、としていた。
- 実装を読んで確認した干渉点:
  - `@mousedown="onGridMousedown"` は**グリッド直下**にあり、`cellAt()` は座標から桁を算出する。
    **グリッド内のどこを押しても** `clearRectSel()` が走り矩形選択が消える
  - 貼り付けは入力欄の `@paste`。**フォーカスを奪うと貼り付け先が変わる**
  - コピー（`onDocCopy` → `rectText()`）は `charAtForClipboard`＝**モデル**から組むので、
    DOM にオーバーレイがあってもクリップボードには混入しない（この経路は安全）
- 決定:
  - **開閉はフォーカスにのみ従属**させる。キーイベントは 1 つも購読しない（`Esc` すら捕まえない）
  - ポップオーバーと項目に **`@mousedown.stop.prevent`**（伝播と既定のフォーカス移動を両方止める）
  - 選択は `click`。**グリッド内に導線（印）を置かない**
- 理由 / 代替案: `Esc` を捕まえると 5250 側のキー経路と競合しうる。印を置くと桁割りを侵し、
  mousedown のヒット領域も増える。**矩形選択が始まると `onGridDragMove` が入力欄を blur する**ので、
  フォーカス従属にしておくだけで選択開始と同時に自然に閉じる——余計な仕掛けが要らない。
- 影響: 開く操作が「Opt 欄にフォーカスする」だけになり、キーボードでの明示的な開閉は無い。
  設定 OFF が既定なので、ONにした利用者は出ることを期待している前提。

## D2: 選択の反映はフォーカス経路の `pasteFrom` を通す

- 背景: 当初 `pasteFrom(at, value)` を焦点文脈なしで呼んでいたが、テストで欄の値が入らなかった。
- 判明: `pasteFrom` は焦点文脈が無いと `emit("edit")` の非フォーカス経路へ落ち、
  親が edits を適用するまで DOM に反映されない。
- 決定: `pasteFrom({row,col}, value, { f, el, startOffset: 0 })` と**焦点文脈を渡す**。
- 理由: Opt 欄はフォーカス中なのだから、打鍵と同じ扱い（edit モデルの更新・`sync`）が正しい。
  渡さないとカーソルと編集状態が食い違う。
- 影響: なし（より正しい経路になった）。

## D3: 負のテストが規則を突けていなかった（空振り検証で判明）

- 背景: `wrkmsgq` / `menu` を「Opt 列が無ければ凡例があっても null」の根拠にしていた。
- **空振り検証で発覚**: Opt 列の条件を無効化しても 10/10 が通ってしまった。
  この 2 画面は**そもそも凡例が無い**ので、`options.length === 0` で null になっていただけ。
  「両方揃ったときだけ発火する」という規則そのものは**1 つもテストされていなかった**。
- 決定: 実機 PDM（凡例あり）から**入力欄だけを取り去った** snapshot と、
  **短い欄が 2 行しか並ばない** snapshot を足す。
- 効果: 条件を無効化すると**この 2 件が落ちる**ことを確認した。
- 教訓: 負のケースは「なぜ null になるのか」まで確かめないと、別の理由で通っているだけになる。

## D4: フォーカスだけでは開かない。ボタン＋`Alt+↓` の明示操作にする

- 背景: 利用者指摘「**フォーカスだけでドロップダウンが表示されるのは、視覚的に邪魔になります**」。
  D1 の実装は Opt 欄にフォーカスした時点でリストを開いていたため、一覧を Tab で降りるたびに
  リストが視界を塞いでいた。**設計の誤り**。
- 決定:
  1. フォーカス時に出すのは**右隣 1 桁のボタン（▾）だけ**。リストは開かない
  2. 開くのは**ボタン押下**または**`Alt+↓`**（コンボボックスの慣用キー）
  3. ボタンを**タブ順に入れるのは開いている間だけ**（`tabindex` を `-1` ↔ `0`）
- 理由 / 代替案: ボタンを常時タブ順に入れる案もあったが、リストは Opt 欄ごとに出るため
  **一覧を Tab で降りるときの停止数が倍**になり、既存の使い勝手を損なう。
  ARIA APG がコンボボックスのトリガーをタブ順に入れないのも同じ理由。
  開いている間だけ入れれば、キーボードのみでの完結と既存の Tab の意味を両立できる。
- 影響: 開く操作が 1 手増えるが、視界と Tab の挙動は既定のまま保たれる。

## D5: ペイン・タブ移動を `Alt+矢印` から `Alt+Shift+矢印` へ移す

- 背景: `Alt+↓` を D4 のドロップダウンに使いたいが、**`Alt+矢印` はペイン間移動に割当済み**
  （`App.vue` の `onGlobalKey`）だった。
- 決定: ペイン移動を `Alt+Shift+矢印`、タブ切替を `Alt+Shift+PageUp/PageDown` へ移す。
- 理由 / 代替案（利用者と検討）:
  - `Ctrl` … `Ctrl+PageUp/Down` はブラウザのタブ切替、`Ctrl+Tab` も同様で奪えない
  - `Shift` 単独 … `Shift+矢印` は矩形選択が使用中（`keyboardBlockSelect`）
  - `Meta`（⌘/Win）… Windows の `Win+矢印` は OS のウィンドウスナップに奪われブラウザまで届かない
  - `Ctrl+Alt+矢印` … Linux デスクトップのワークスペース切替と衝突しがち
  - → **`Alt+Shift`**。Alt の指の形を残したまま Shift を足すだけで移行が小さい
- **訂正**: 検討中に「現状の `Alt+←/→` はブラウザの戻る/進むと衝突している」と述べたが**誤り**。
  `App.vue` は単一ペインでも `preventDefault` しており、既に潰されていた（コメントに明記あり）。
- 影響: 既定キーの変更。README を更新した。旧 `Alt+矢印` は**残さない**
  （残すとどちらが動くか環境依存になる）。`global-shortcuts.test.ts` に
  「Shift 無しの `Alt+↓` はここで消費しない」を足して取り残しを防いだ。

## D6: 画面スクリーンショットの指摘 6 点を反映

利用者から実画面のスクリーンショット付きで指摘（2026-07-29）。

1. **ボタンの表示位置がずれていた** — `optHintStyle` が `top: row + "em"` としていたが、
   このグリッドは **1 行 = 1.25em**（`winRectStyle` と同じ係数）。係数の付け忘れ。
   → `optBtnStyle` で `(row - 1) * 1.25 + "em"` に修正
2. **▼ボタンを各 Opt 行に常時表示** — フォーカス中の行だけに出していた。
   → `optButtons` が Opt 列の全行を返す（右隣が埋まっている行だけ除く）
3. **リストが入力エリアに重なっていた** — `left` が Opt 列と同じ桁だった。
   → `optListStyle` で **Opt 列とボタンの右側**（`col + length + 1`）から始め、
   縦は開いた行の 1 行下（ボタン自身も隠さない）
4. **開いても項目にフォーカスが移らない** — `openOptAt` で `nextTick` 後に
   選択中（無ければ先頭）の項目へ `focus()`
5. **既存の入力値を選択状態にする** — `optSelectedValue` が欄の現在値と一致する選択肢を返し、
   `aria-selected` と枠線で示す
6. **Esc で閉じる。閉じるまで他の Esc 割当を発火させない** —
   `onOptListKeydown` が `preventDefault` ＋ `stopPropagation` して閉じる。
   加えて `EmulatorPane.onKeydown` の先頭で「リストが開いていて target がリスト内なら早期 return」
   のガードを置き、ペイン側の Esc（矩形選択の解除等）が先に走らないようにした

- **D1 の「キーイベントを 1 つも購読しない」は撤回**。あれは矩形選択・貼り付けへの非干渉が目的で、
  リストが**明示操作で開いていてフォーカスもリスト内にある**状態なら、そこでキーを扱っても
  グリッドの操作を妨げない。非干渉の担保（`mousedown.stop.prevent`）はそのまま維持している。
- **blur では閉じない**に変更。リストへフォーカスを移す時点で欄は blur するため、
  blur で閉じると開いた瞬間に閉じてしまう。閉じるのは Esc・選択・画面更新のとき。

## D7: 実画面の追加指摘（ホイール・テーマ・意匠設定）

1. **リスト上のホイールがホストへ Roll を送っていた** — `onWheel` は無条件に
   `preventDefault` してから `PageDown`/`PageUp` を送る（ACS 準拠のページ送り）。
   リストの上でも同じ経路に入るため、**リストが動かずに画面が送られる**という明らかな誤り。
   → target が `.opt-hints` の内側なら早期 return（native スクロールに任せ、Roll も送らない）。
   PageUp/PageDown **キー**は `onKeydown` 先頭のガード（D6）で既に届かない。

2. **背景が常に黒だった** — `--panel-bg` / `--fg` / `--border` / `--hover-bg` という
   **このリポジトリに存在しない変数名**を使っており、フォールバックの黒が常に適用されていた。
   → `styles.css` の実在する変数（`--card` / `--ink` / `--line` / `--accent` /
   `--accent-soft` / `--muted`）に載せ替え。ライト/ダーク/システムの 3 テーマに追従する
   （`docs/UI-DESIGN.md` の「配色は CSS 変数で一元化」）。

3. **意匠を設定から選べるように** — `optHints` を `boolean` から
   `OptHintStyle`（`none` / `panel` / `outline` / `crt`）へ変更。`buttons`（ボタン設定）と
   同じ `wide` + `expandable` の形にしたので、**画面設定メニューとキー設定の両方に自動で出る**。
   既定は `none`（推測を含む機能は勝手に有効化しない、を維持）。
   CSS は `.grid[data-opt-hints="…"]` で当てる。
