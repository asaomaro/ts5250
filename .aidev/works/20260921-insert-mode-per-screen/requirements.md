# 要件: 挿入モードが画面をまたいで残る

## 背景 / 課題

前の画面で挿入モードにしたまま次の画面で打つと、**意図せず挿入になる**。
直前の work（`20260920-insert-mode-overflow`）で「挿入で欄が満杯なら弾く」規則を入れたため、
**残った挿入モードのせいで次の画面で打てない**という形でも出る。

当 PJ の `insertMode`（`packages/web-ui/src/components/EmulatorPane.vue:95`）は
**利用者の切り替えでしか変わらない**。Reset キーも無い。

### ACS（`AGENTS.md` 判断の原則 1）

台帳の記録（`20260919-backlog-acs-triage` research N8）:
ACS は `DS5250.initKeyboard`（`resetInsertMode` を呼ぶ）を、
**書式の開始・WEC・`processClearFMT`** から呼ぶ。つまり**新しい画面は上書きモードで始まる**。

## 目的 / ゴール
- **画面が変わったら、挿入モードが持ち越されない状態。**

## ユーザーストーリー
- US1: 端末の利用者として、**次の画面は既定（上書き）で始まって**ほしい。
  なぜなら、前の画面の挿入モードが残っていると、打った文字が押し出しになったり弾かれたりして、
  **原因が分からないまま手が止まる**から。（受け入れ: AC1）

## スコープ
### 対象
- 新しいホスト画面が来たときに `insertMode` を上書きへ戻す。
### 対象外
- **Reset キーの実装**（ACS は Reset でも戻す）。キー割り当ての話なので台帳の
  【まとめ】キー編集の細部に属する。
- 画面の種類による出し分け（WEC だけ・書式開始だけ等）。
  当 PJ は**新しいスナップショットが来たら戻す**で足りる（下記 design）。

## 機能要件
- FR1: 新しいホスト画面が来たら `insertMode` が false になる。
- FR2: 利用者の切り替えは従来どおり効く（同じ画面の中では保たれる）。

## 非機能要件 / 制約
- 既存の「新しい画面が来たらリセットする」監視に**合流させる**（監視を増やさない）。
- `AGENTS.md` のコーディング規約。
