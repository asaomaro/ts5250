# 仕様: 設定フォームの見直し

## 1. 保管場所はチェック 1 つ

2 択の select より、**既定（自分の設定）に対して「サーバー設定にする」を入れる**ほうが
意思が読みやすい。保存経路は従来どおり `source` を見るので、`computed` で橋渡しする。

### 表記を直す

**「全員が使える」は誤り。** サーバー設定は `assertProfileAccess` により**読むのも管理者だけ**。
一般利用者に見えるのは「サービスが動いているか」だけ（`ServiceDef`）。

> 管理者だけが参照・編集できる共有の設定です。**サービス（常駐）にできるのはこちらだけ**
> ——プリンターの自動出力・待ち行列の転送も、サーバー設定のセッションにしか置けません。

## 2. 信頼設定はセッションカードだけ

`canEditPcCommand` は `sesForm.sessionType === "display"` を見ていたが、
**`sesForm` の初期値が `display`** なので、**システムカードでも真**になっていた。

3 つとも `props.kind === "session"` を条件に足す。PC コマンドは 5250 画面の標識で届くもので、
**システム（接続先）の設定ではない**。

## 3. 「サーバー既定に従う」を外す

選択肢を消す。**未設定の定義は「切らない」として開く**——出荷時のサーバー既定が
「切らない」なので、開いた時点の意味は変わらない。画面から保存した定義は必ず明示値を持つ。

`--idle-timeout` は残る（手書きで未指定のままの定義にだけ効く）。

## 4. チェックボックスをトグルに

`styles.css` に**全体で効く**意匠を置く（複数のペインで使われているため）。
select の矢印を自前で描いているのと同じ理由——ネイティブのままだと**配色が OS 任せ**で、
自前で描いた欄と並ぶと浮く。

**入り/切りが形でも分かる**ようにする（つまみが左右に動く）——色だけに頼らない。

## 受け入れ基準との対応

| 完了条件 | 満たし方 |
|---|---|
| 保管場所がチェック 1 つ・表記 | 方針 1 |
| システムに PC コマンドが出ない | 方針 2 |
| 「サーバー既定に従う」が無い | 方針 3 |
| チェックの意匠 | 方針 4 |
