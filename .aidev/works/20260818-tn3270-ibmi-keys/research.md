# 調査

## A. IBM i の見分け（実測）

交渉の生バイトを採った。

```
RX  ff fd 27 ff fd 18            ← DO NEW-ENVIRON(0x27) / DO TERMINAL-TYPE(0x18)
TX  ff fb 27                     ← WILL NEW-ENVIRON
TX  ff fb 18
RX  ff fa 27 01 03 49 42 4d 52 53 45 45 44 …  ← SB NEW-ENVIRON SEND（IBMRSEED …）
TX  ff fa 27 00 03 KBDTYPE 01 JKB 03 CODEPAGE 01 290 03 CHARSET 01 1172 ff f0
TX  ff fa 18 00 IBM-3279-2-E ff f0
RX  ff fd 19 ff fb 19 ff fd 00 ff fb 00      ← EOR / BINARY
```

**IBM i は `DO NEW-ENVIRON` を出し、5250 流のシード（`IBMRSEED`）まで送ってくる。**
TK4- / z/OS は出さない（既存の試験と実測で確認済み）。**これを見分けに使う。**

`DO TN3270E` は**出さない**。だから TN3270E の有無では見分けられない。

## B. IBM i のキー対応表（IBM i 自身が持っている）

3270 で繋いで `PF2` を押すと「ヘルプ－ 3270 キーボード・マッピング」が出る。
**推測ではなくホストの記述**なので、これを正とする（`requirement.md` の表）。

肝は 2 行:

```
PA1 PF1..PF12 → F1..F12
PA2 PF1..PF12 → F13..F24
```

## C. `PA1` の後は施錠される（実測）

`PA1` を送った直後に `PFn` を送ろうとすると、こちらの `assertUnlocked` が
`KEYBOARD_LOCKED` で止める。3270 では AID を送ると施錠され、
ホストが `WCC` の復旧ビットで解く——**正しい振る舞い**。

**解けるまで 31 ミリ秒**（実測）。待てば `PFn` が通る:

```
PA1 →（解錠待ち 31ms）→ PF4  → 「活動ジョブ処理 (WRKACTJOB)」   ← F4
PA1 →（解錠待ち）      → PF12 → メインメニューへ戻る            ← F12
```

つまり **F キー 1 つの送信が 2 往復**になる。ここが設計上の肝。

## D. F13〜F24 は素の PF13〜PF24 でよい（実測）

```
素の PF13   → 「INFO 情報援助オプション」   ← F13
PA2+PF1     → 同じ
```

**短い方（素の PF13〜24）を採る。** 往復が 1 回で済む。

## E. ページ送りは素の PF7 / PF8

対応表で `PF7 = 前ページ・キー` / `PF8 = 次ページ・キー`。
実機の一覧画面で素の `PF8` が次ページへ進むことを確認した。

⚠ **いまの `aidFor3270` は PageUp を「F7」に読み替えている。**
これまでは F7 がそのまま `pf7` に落ちて**たまたま**正しかったが、
F1〜F12 を `PA1`+`PFn` にすると **PageUp が F7 になってしまう**。
ページ送りは**素の PF7 / PF8** として送る必要がある。

## F. 装置名（別項目だが、ここで分かったこと）

`DEVNAME` は**既に NEW-ENVIRON で送っている**（`telnet.ts` の `sendEnviron`）。
backlog に「送っていない」と書いたのは**誤り**——訂正する。

本当の問題は**端末タイプにも `@名前` を付けている**こと（`telnet.ts:377`。
Hercules の流儀で、TK4- 向けに実測して入れたもの）。実機で試すと:

```
装置名の指定＝なし      → 表示装置: QPADEV000D
装置名の指定＝AS3270A   → **3270 negotiation timed out after 15000ms**
```

IBM i は `IBM-3279-2-E@AS3270A` を解さず、交渉が進まない。
**IBM i のときは `@名前` を付けない**——それだけで済む見込み。

## G. 決めたこと

1. **見分けは「NEW-ENVIRON を交渉したか」**。TN3270E の有無は使えない
2. **F キーの送信は `Tn3270Session` に置く**（施錠の状態を持っているのはここ）。
   非同期（解錠待ちがある）にする
3. **F13〜24 は素の PFn**（往復 1 回）
4. **ページ送りは素の PF7 / PF8**。F7 / F8 とは別物として扱う
5. **判断は 1 か所**（サーバー側）。画面側は 3270 用の読み替えをやめ、
   使えないキーは**サーバーが理由を返す**
