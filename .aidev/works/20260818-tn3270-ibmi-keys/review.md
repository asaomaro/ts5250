# レビュー

## 満たしたこと

| 受け入れ基準 | 結果 |
|---|---|
| 交渉から IBM i を見分ける | **済**（`isIbmI`。実機で true） |
| 実機で F3 が効く | **済**（直す前は「機能キーは使用できません」） |
| F4 / F12 / F13 | **済** |
| ページ送り | **済**（素の PF7 / PF8） |
| Attn / SysReq / Help / Print | **済**（単体。IBM i で PF9 / PF11 / PF1 / PF4） |
| メインフレームは素の PFn | **済**（TK4- 試験を 1 件も書き換えていない） |
| 実ブラウザ | **済**（4/4） |

## 設計で効いたところ

**表を 1 か所に置いた。** 画面側（`aidFor3270`）の読み替えを消してサーバーへ寄せた。
残していたら、`PageUp → F7` の読み替えと `F7 → PA1+PF7` が重なって
**ページ送りが F7 になって壊れていた**。実際、要件を書く前の設計では見落としていて、
research の E で気づいた。

**`send()` は同期のまま、`sendFunctionKey()` だけ非同期にした。**
既存の呼び出し（`enter` / `clear` / `pa1` など）は 1 つも変わらない。

## 残した弱いところ

### 1. Attn / SysReq / Help / Print は実機で「効く」ところまで見ていない

対応表（IBM i 自身の画面）に従って割り当てたが、**実機で押して期待どおりの画面が出る**
ところまでは確かめていない。メインメニューで `PF9` / `PF11` を押しても画面が変わらず、
拒否もされなかった——「何も起きないのが正しい」のか「届いていない」のかを分けられていない。
アテンションやシステム要求が意味を持つ画面（実行中のジョブなど）で測り直したい。

### 2. `isIbmI` の根拠は 1 つだけ

「NEW-ENVIRON を交渉したか」。実測では IBM i だけが出すが、**NEW-ENVIRON を出す
別の 3270 ホストがあれば誤判定する**。素の事実（`negotiatedNewEnviron`）と解釈（`isIbmI`）を
分けてあるので、手がかりを足すときに事実の方は汚さずに済む。

### 3. F13〜F24 は素の PF13〜24 に賭けている

実機で F13 が効くことは確かめた（`PA2`+`PF1` と同じ画面が出た）。
F14〜F24 は 1 つずつ試していない。対応表がそう書いており、F13 で裏が取れたので同じ扱いにした。

### 4. 2 往復ぶんの待ちが入る

IBM i の F1〜F12 は `PA1` を送って解錠を待ってから `PFn`。実測 31 ミリ秒なので
体感には出ないが、**ホストが重いときは待ちが伸びる**。5 秒で時間切れにして理由を返す。

## 秘密の確認

- 資格情報はコードにも `.aidev` にも無い（`passwordEnv` で環境変数を指す）
- 実機の画面名（メインメニュー・情報援助）は機微ではない。システム通番は出していない
