# 決定記録

## D1: MCP・HLLAPI から開く表示には関連付けを効かせない
- 背景: ACS の関連付けは画面の層（`AssociatedPrinterSession5250`）の機能で、ECL のコア（自動操作が使う層）には無い。
- 決定: ブラウザから開く表示だけに効かせる（`open_session` は従来どおり）。

## D2: 常駐のプリンター（サービス ✅）は表示に合わせて止めも閉じもしない
- 背景: ACS にはサーバーに常駐するプリンターが無い。常駐の待ち受けは自動出力やほかの利用者が頼っている。
- 決定: 起動・使い回し・装置名の取得は同じだが、表示の切断・終了での停止・破棄はしない。
- 理由 / 代替案: 1 つの表示の都合で共有の待ち受けを止めると、ACS に無い種類の事故になる。

## D3: T6・T7 は test 工程で消化する

## D4: ~~待ち時間切れでもプリンターの設定の装置名で関連付ける~~ → 関連付けなしで開く（節目 10 の独立点検 C-S1 で破棄）
- 背景: 最初の実装（研究 F2・design）は、ACS の待ちループ（コンストラクタの 166〜177 行）だけを読み、時間切れなら `getWorkstationID()`（設定の値のまま）で関連付ける、と書いた。
- 決定: ACS の**タイマーのスレッド**（`run`→`createAndRunTerminal`）まで読み直し、時間切れなら**関連付けなしで表示を開く**ことを確認した（`Icon5250.start` が `associatedDeviceName` を消してある）。
  当 PJ も同じにした。組は残し、`opened.associatedPrinterIssue: "timeout"` で利用者へ知らせる（ACS は知らせない〔ポップアップは設定が使えないとき〕が、関連付けが効いていないのを黙って見せるのは当 PJ の「黙って落とさない」に反するので足した）。
- 破棄した根拠: 原典の直読（`AssociatedPrinterSession5250.run` / `startTheTimer` / `createAndRunTerminal` / `createTerminal`、`Icon5250.start`）。
- ACS の GUI 層は `acs-probe` で動かせないので、実機の GUI での確認は**未確認**（原典の読みまで）。

## D5: 開く待ちと起動の待ちを 1 つの期限にし、接続中の開始には相乗りする
- 背景: `PrinterSession.connect` は起動応答が来るまで戻らないので、待ち時間を待ちループにだけ掛けると `open()` の中で止まる。接続中の `state` は `stopped` のままで、2 本目の呼び出しが二重に接続を張った（C-S2）。
- 決定: `prepareAssociatedPrinter` は最初に 1 つの期限を決め、開く・起こす・待つの全部に掛ける。`PrinterEntry.starting` に接続中の結果を持ち、2 本目はそれに相乗りする。

## D6: 表示の開始・接続失敗・準備中の切断でも、起こしたプリンターを片付ける
- 決定: 表示を開けなかった・準備の間にブラウザが切れたときは、表示を閉じたときと同じ処置（ほかに使う表示が無ければ止め、指定があれば閉じる）を `abortAssociatedPrinter` で行う。
  準備の間に切れたときは表示も作らない（`WsConnection.disposed`）。開く待ちの間に切れた場合（以前からある窓）も同じ。

## D7: REST は参照を受けて id に直し、参照されているプリンターは消せない・種別を変えられない（節目 10 の独立点検 C-M1・C-M2）
- 背景: UI は `own:…`/`srv:…` の参照を送るが REST は `system` しか直さず、プリンターを指した表示は画面から保存も編集もできなかった。削除は指されているプリンターを消せて、次の起動の整合検査でサーバーが立ち上がらなくなった。
- 決定: `stripSource` が `associatedPrinterSession` も参照→id に直す（同じ保存先の参照だけ。違う保存先・存在しない・プリンターでないものは 400）。`removeSession`・`updateSession` は、参照されているプリンターの削除・種別変更を FORBIDDEN にする（`removeSystem` と同じ考え方）。
- 見逃した理由（`paired-artifact-sync`）: サーバーのテストは id、web-ui のテストは fetch のモックで参照を送る形を固定し、REST を通すテストが 1 本も無かった。

## D8: 指したプリンターは必ず起こす・掃除しない・空欄の待ち時間は既定に直す（C-S8・C-S10・C-S7）
- 決定: `autoStart: true` で開く（「自動で待ち受け開始 ☐」でも初回から起こす）。`sweepIdle` は組のあるプリンターを飛ばす（何も届かないのが本来の姿で、アイドルは「使われていない」の合図にならない）。待ち時間の空欄・数字でない・負は既定（5）に直す（ACS `DataPanel5250ConAssocPrinter.propertyChange` の空・不正・負は 5）。

## D9: 関連付けなしで開いたときは、理由を `opened.associatedPrinterIssue` で知らせる（C-S5）
- 決定: `invalid`（指した設定が使えない）・`failed`（プリンターを開始できなかった）・`timeout`（待ち時間内に装置名が決まらなかった）。ACS は設定が使えないときポップアップで知らせる。当 PJ は 3 種とも 3 秒で消さずに通知欄へ出す（関連付けが効いていないのを黙って見せない）。
