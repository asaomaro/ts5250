# 計画: 何も無い状態からサービス開始までを通しで確かめる

## 実装方針

**検証を先に書いて、詰まったところを直す。** 直しから入ると「たぶん通る」で終わる。

## 作業順序と依存関係

1. 通しの検証スクリプト（空のディレクトリで起動 → 画面操作）
2. 詰まった箇所を直す（依存: 1）
3. 直したものに単体テストを添える（実機スクリプトは `npm test` に乗らない）（依存: 2）
4. `scripts/README.md`

## リスク / 留意点

- **実機の資格情報をサーバーの作業ディレクトリに置かない**（呼び出し側の環境変数から渡す）。
- 実機の装置は借りるだけ（作らない・消さない）。
- **セレクタの取り違えを「製品の不具合」と誤診しない**——落ちたら、まず画面の中身を出す。

## テスト方針

- **実機 E2E**: 0（起動）→ 1（システム）→ 2（セッション）→ 3（待ち受け開始）→ 4（一覧）
- **単体**: 立ち上げに失敗しても実体が残る（＝一覧に理由が出る）
