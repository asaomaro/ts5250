# レビュー: エミュレータ画面の余白を ACS 相当に詰める

## ラウンド 1（自己レビュー）

### 同じ数字が 3 か所にあった

余白を詰めたのに**字が大きくならなかった**。フィット計算が旧余白（`- 20` / `- 16`）を
定数で持っていたため。さらにクリックの桁逆算も `- 10` / `- 8` を持っており、
**そのまま出していたらクリック位置がずれていた**。

CSS・フィット・当たり判定の 3 か所に同じ数字があると、**片方だけ直せば必ず壊れる**。
`fitFont.ts` に 1 つ置き、CSS へは `:style` で流し込む形にした。

テストも 3 ファイルが座標を数字で組み立てていたので、同じ定数を使わせた
——ここを直さないと、次に余白を触った人が同じところで詰まる。

### 測ってから削った

「どこに余白があるか」を推測せず、実機で `getBoundingClientRect` と `getComputedStyle` を
取った。4 か所に散っていて、`.grid` の 14px が一番大きかった——見た目からは
`.group` や `.statusbar` のほうが目立つが、実際に画面を削っていたのは内側だった。

### 字は 1 段上がらなかった

高さは +25px 増えたが、この viewport では 19.93 → 19 に丸められる。
**整数フォントは滲みを避けるための既存の判断**なので変えていない。
別の大きさでは 1 段上がる。ここを無理に合わせにいくと、特定のウィンドウ幅にだけ
最適化した数字が残る。

## nit（直していない）

- **`.group` の余白を 0 にした。** 分割表示のときペイン同士が接するが、
  枠線が仕切りになるので問題ないはず——ただし撮って確かめていない。
