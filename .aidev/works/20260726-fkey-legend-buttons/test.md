## 桁ずれの実測（#8）

`vitest` の DOM はレイアウトしないため、文字列比較だけでは**桁ずれを検出できない**。
実ブラウザ（Chromium）でビルド後 CSS を読み込み、`F3= 終了` `F12= 取り消し`（DBCS 含む）を
「素のテキスト」と「ボタンに分割」で並べ、**後続文字の x 座標**を比較した。

```
none       素:217.00px  ボタン:217.00px  差:0.00px
underline  素:217.00px  ボタン:217.00px  差:0.00px
filled     素:217.00px  ボタン:217.00px  差:0.00px
rich       素:217.00px  ボタン:217.00px  差:0.00px
```

4 意匠すべてで**差 0.00px**。桁は動いていない。

> 途中経過: 最初の測定で 13.66px のずれが出たが、原因は**測定スクリプトが古い scoped 属性
> （`data-v-…`）をハードコードしていた**ため、`.fkey-btn` のルールが 1 つも当たっていなかった。
> ビルド成果物から scope id を読み取る形に直して再測定し、0.00px を確認した。実装側の欠陥ではない。

この実測は CI では回せないため、**回帰を捕まえる静的ガード**を追加した
（`.fkey-btn` が `padding/border/margin` を持たず `font` を継ぐこと、意匠側も桁を動かす指定を
足さないこと）。`padding: 2px` を仕込むとこのガードが落ちることを確認済み。
