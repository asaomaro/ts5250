# 決定記録

## D1: 検出結果を `rows` とは別の computed に分けた

- 背景: spec では「`rows()` の中で検出する」とは決めていなかったが、`rows` は `props.edits`（打鍵）にも
  依存して再評価される。
- 決定: 凡例検出を `legendsByRow` という独立した computed にし、`props.snapshot` だけに依存させた。
- 理由 / 代替案: `rows` の中で検出すると**打鍵のたびに画面全体を走査**することになる（24×80 の全セル）。
  凡例はホスト画面が変わったときにしか変わらないので、依存を snapshot に絞る方が素直。
- 影響: なし（spec の振る舞いは変えていない）。

## D2: `initViewSettings()` を「読み込み or 既定へ戻す」に変えた

- 背景: 保存値が無いとき何もしない実装で、**前の状態が残った**。テストで実際に検出した
  （同一ファイル内の別テストが設定した値が次のテストへ漏れた）。
- 決定: 保存値が無ければ `FALLBACK` へ戻すようにした。
- 理由 / 代替案: 起動時は元から `FALLBACK` なので**実挙動は変わらない**が、「init」の名前どおり
  再初期化に強くなる。テスト側で毎回明示的に戻す回避策も可能だが、同じ罠を後の人が踏む。
- 影響: なし（プロダクトの挙動は同一）。

## D3: `global-input-scope` のガードでコメントを除去するようにした

- 背景: `.grid-input…{…}` を正規表現で拾うガードが、**コメント中の `.grid-input` という記述**を
  選択子と誤認し、無関係な次のブロック（`.fkey-btn`）の中身を検査して落ちた。
- 決定: 走査前に CSS コメントを除去する。あわせて紛らわしいコメント表現も書き換えた。
- 理由 / 代替案: ガードの検査対象（`.grid-input` が色・背景を奪わないこと）は**一切緩めていない**。
  自分のコメントを書き換えるだけでも通るが、同じ罠が残るため、ガード側を実 CSS だけ見るように直した。
- 影響: `test/global-input-scope.test.ts`。検査の意図は不変。

## D4: 意匠 CSS の検査を「ビルド後の CSS」で行う

- 背景: scoped CSS は vitest の DOM に適用されないため、DOM からは意匠の掛かりを検証できない。
- 決定: `dist/assets/*.css` を読み、4 意匠が `.fkey-btn` と `.gui-choice` の**両方**を対象にしていることを検査する。
- 理由 / 代替案: 直前の作業（CRT の滲み）で「一部の要素に掛け忘れる」取りこぼしを実際に踏んでおり、
  同じ方式の回帰テストが有効だった実績がある。未ビルド時はスキップする。
- 影響: `test/fkey-button-ui.test.ts`。

## D5: ボタンをタブ順に含め、Space で押せるようにした（spec B2 の変更）

- 背景: spec B2 では `tabindex="-1"` として**タブ順から外していた**（Tab はフィールド間移動に使うため）。
  実装後、ユーザーから「ボタンなら Tab で到達でき、フォーカス中の Space で押せるべき」「矩形選択に
  影響を与えないこと」との要求があった。
- 決定:
  1. `tabindex` を落とさない（普通のボタンとしてタブ順に入る）。
  2. ペインの Tab 巡回（`focusByOffset`）の停止点を**入力欄＋機能キーボタン**にした（`tabStops()`）。
     Tab はペイン側で `preventDefault` するため、これをしないとブラウザ既定のタブ順は使われず
     ボタンへ到達できない。入力欄が 1 つも無い画面（ヘルプ等）でもボタンへ入れる。
  3. フォーカス中のボタンで **Space を押すとクリック**する。明示処理が要るのは、`isProtectedEdit` が
     Space を preventDefault して native の Space 起動を潰すため。
  4. **Enter は 5250 の AID のまま**にした（普通のボタンは Enter でも起動するが、端末で最も重要な
     キーを「たまたまボタンにフォーカスがある」という理由で奪わない）。
  5. `mousedown` の `preventDefault` は**維持**。マウス操作ではフォーカス（＝5250 のカーソル位置）を
     奪わず、`.stop` していないのでグリッドのドラッグ矩形選択もそのまま始まる。
- 理由 / 代替案: Tab を native 任せにする案は、5250 のフィールド間移動（ACS 準拠）を壊すため採らない。
  Enter もボタンに割り当てる案は、Enter が最も使われる AID であることを踏まえて退けた。
- 影響: `spec.md` B2 の `tabindex="-1"` は無効。`ScreenGrid.vue` / `EmulatorPane.vue`。
  矩形選択（マウスドラッグ／Shift+矢印）とフォーカス非奪取は回帰テストで固定した。
