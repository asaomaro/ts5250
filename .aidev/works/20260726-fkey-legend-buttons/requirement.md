# 要件: 機能キー凡例のボタン化

## 背景 / 課題

5250 画面の下部やヘルプウィンドウ下部にある `F3=終了` `F12=取消` といった**機能キー凡例**は、
利用者から見れば「押せる操作」だが、**ホストからは単なるテキストとして送られてくる**。
そのため画面上ではクリックできず、利用者は F キーを覚えているか、OIA（画面下部）の
F キーバーを使う必要がある。「画面に見えているのに押せない」状態になっている。

一方で、この凡例は**機械的に認識できる**ことを実機キャプチャで確認済み（`packages/core/test/fixtures/`
の PUB400 トレースを再生して検証）。

- main メニュー・ジョブ情報画面の下部から、キー番号・ラベル・桁位置まで抽出できた
  （`F3[Exit]@2 F4[Prompt]@12 F9[Retrieve]@24 F12[Cancel]@38 F13[Information Assistant]@51` / `F23[Set initial menu]@2`）。
- これらの画面は `gui`（拡張5250 の GUI 構造）が **null** で、ホストはボタンとして宣言していない。
- 凡例行は `blue`、周囲は green/white と**色でも分かれていた**（IBM i の慣例。ただしアプリ独自配色が
  ありうるので必須条件にはしない）。
- サインオン画面（URL や広告文が並ぶ）では**検出ゼロ**＝誤検出しない。

## 目的 / ゴール

画面上の機能キー凡例をその場でクリックできるようにし、**5250 の桁レイアウトを崩さずに**
「押せるものは押せるように見える」状態にする。これまで進めてきた「Web アプリらしい操作感」の
延長線上にある改善。

## スコープ

### 対象

- 画面テキスト中の機能キー凡例（`F<n>=<ラベル>`）の検出。
- 検出した凡例のボタン化（クリックで対応する AID を送信）。
- **ボタン意匠**の設定を新設し、「押せるもの」の見た目を統一する。
- 拡張5250 がボタンを宣言している領域との重複回避。

### 対象外

- 凡例以外のテキストのボタン化（メニュー選択肢の番号、コマンド名など）。
- ホストが送っていない機能キーの推測・補完（画面に無いキーは出さない）。
- OIA の F キーバー（既存機能）の変更・置き換え。
- 桁レイアウトの変更（桁ずれを起こす表現は採らない）。
- 機能キー以外の AID（Enter・PageUp/Down 等）の凡例化。

## 機能要件

| ID | 要件 |
|---|---|
| FR-1 | 画面テキストから `F<n>=<ラベル>`（n は 1〜24）を検出する。ラベルの区切りは**空白2つ以上**（1つの空白は日本語ラベル内に出るため）。 |
| FR-2 | **保護セルのみ**を検出対象とする。入力欄（非保護セル）の内容は対象外。 |
| FR-3 | 語境界を見て `REF3=ABC` `XF1=9` のような文字列を弾く。 |
| FR-4 | ウィンドウ（ヘルプ窓等）の**罫線をラベルに含めない**。 |
| FR-5 | ボタンをクリックすると、対応する AID をホストへ送る（キーボードの F キー押下と同じ結果）。 |
| FR-6 | **ボタン意匠**を画面設定に新設する。選択肢は「なし / 下線 / 塗り / 枠」。**既定は「なし」**（従来の見た目を変えない）。 |
| FR-7 | ボタン意匠は、**機能キーボタンと拡張5250 のボタン（`gui.selectionFields` の pushbutton/menu）の両方**に効く。押せるものの見た目を1つに統一する。 |
| FR-8 | **ホストの宣言を優先**する。`gui` が pushbutton/menu を宣言している領域では、テキスト検出によるボタン化を行わない（同じ場所に二重にボタンが出ない）。 |
| FR-9 | 検出範囲は**画面全体**（位置で絞らない）。ヘルプ窓の中も、見出し行に凡例を置くアプリも拾える。 |
| FR-10 | **桁位置とホストが送った色を変えない**。ボタン化しても以降の桁がずれない。 |
| FR-11 | 設定は保存され、全画面・再読み込み後にも効く（既存の画面設定と同じ扱い）。 |

## 非機能要件 / 制約

- **桁揃えの前提を崩さない**：桁位置は `ch` 単位・DBCS=2ch の仮定に依存する（AGENTS.md / docs/UI-DESIGN.md）。
  この前提を壊す表現（フォント変更・padding による桁の押し出し等）は採らない。
- **テーマ・スキン追従**：light / dark / system と 11 種のスキンで破綻しない（色は CSS 変数経由）。
- **誤検出を出さない**：入力値・データ行を凡例と誤認しない。誤検出は「押すと意図しない AID が飛ぶ」
  という実害に直結するため、取りこぼし（未検出）より優先して避ける。
- **通信を増やさない**：クリックは既存の `sendKey` 経路に載せる。ホストへの余計な問い合わせをしない。
- **ビルド・テスト**：`npm run build -w @as400web/web-ui`（vue-tsc 込み）を通す。テストは
  `cd packages/web-ui && npx vitest run` で実行し、回帰資産としてテストを追加する（AGENTS.md）。
- **アクセシビリティ**：ボタンはキーボード focus 可視・`aria` を適切に付ける（docs/UI-DESIGN.md）。

- [ ] ボタンをクリックすると対応する AID が送信される。
- [ ] ボタン意匠「なし / 下線 / 塗り / 枠」を切り替えると見た目が変わり、**拡張5250 のボタンにも効く**。
- [ ] 拡張5250 が pushbutton/menu を宣言している領域に、二重にボタンが出ない。
- [ ] ボタン化の ON/OFF で**桁がずれない**（DBCS を含む行で確認）。

## 決定事項（この工程で確定したもの）

| 論点 | 決定 |
|---|---|
| コントロール表現との共存 | **独立した設定軸**を持つ。「コントロール表現」＝入力欄の見せ方、「ボタン意匠」＝押せるものの見せ方、と役割で分ける。 |
| 拡張5250 との関係 | **ホスト宣言を優先**。宣言のある領域はテキスト検出しない。宣言の無い画面（大多数）をテキスト検出で補完する。 |
| 意匠の統一 | 機能キーボタンと拡張5250 ボタンの**両方**を、同一の「ボタン意匠」設定に従わせる。 |
| 検出範囲 | 画面全体（位置で絞らない）。 |
| 既定値 | **OFF（意匠「なし」）**。従来の見た目を黙って変えない。 |

> **解釈の注記**：ヒアリングで「機能キーの意匠は独立して持つ」と「拡張5250 のボタンと見た目を揃える」の
> 両方が選ばれた。そのままでは軸が矛盾するため、**「押せるものは統一する」という意図**と読み、
> 「コントロール表現とは別の独立設定を1つ設け、それを機能キーと拡張5250 の両方に効かせる」と解釈した。
> 意図と異なる場合はこの工程を差し戻すこと。

## 未確定事項 / 確認したいこと

- **拡張5250 の pushbutton/menu の実データが手元に無い**。手元のキャプチャは全て `gui=null`。
  FR-7・FR-8 は既存の `gui.selectionFields` の構造と描画（`.gui-choice`）に依存するため、
  実物での確認が要る（→ research 候補）。
- **既存 `.gui-choice` を設定連動に変える影響**が未調査。現在は固定意匠（`--t-green` 系）で、
  選択済み・利用不可の状態表現を持つ。意匠を設定で切り替えたとき、これらの状態が
  区別できるかは未検証（→ research 候補）。
- ラベル内に**全角空白**が含まれる場合の境界判定（実データ未確認）。
- ボタン意匠「なし」のときも**クリックはできる**べきか（見た目は変えずに機能だけ有効）。
  → spec で決める。現時点の想定は「なし＝ボタン化しない（クリックもしない）」。

## 追加要件（walkthrough 後・2026-07-26）

設定の**名称が実態と合っていない**という指摘を受けて追加する。

- **FR-12 名称の是正**
  - 「コントロール表現」→ **「入力項目設定」**（実際は入力欄に対する設定なので、名が実態を表すようにする）
  - 「ボタン意匠」→ **「ボタン設定」**（有効/無効とデザインが混在しているため、意匠だけを指す名前をやめる。
    有効/無効を別項目に切り出すのは設定が増えて無駄なので、**ラベルを緩い名前にして 1 項目に留める**）
  - ボタンの無効値のラベル: 「なし」→ **「無効」**
- **FR-13 デザインの選択肢を増やす**
  - 入力欄・ボタンとも、代表的なデザインのパターンを複数用意し、選べるようにする。
- **FR-14 「その他」からデザインを選ぶ**
  - セグメントの「枠」を **「その他」** に置き換える（入力欄・ボタンとも）。
  - 「その他」をクリックすると、**選択できるデザインの候補を一覧表示**する。
  - 現在の値が候補側（セグメントに出ていないもの）のときは「その他」が選択状態に見えること。

### 追加の完了条件

- [ ] 設定ラベルが「入力項目設定」「ボタン設定」になっている
- [ ] ボタンの無効値が「無効」と表示される
- [ ] セグメントは「よく使う 3 つ ＋ その他」になっている
- [ ] 「その他」を押すとデザイン候補の一覧が開き、そこから選ぶと即座に反映される
- [ ] 候補側のデザインを選んでいるとき、「その他」が選択状態に見える
- [ ] 追加したデザインでも**桁が動かない**（既存の完了条件を維持）
