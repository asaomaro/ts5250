# 決定記録

## D1: Unicode の CCSID の申告も ACS と同じく返す

- フラグ 0x40 の応答は CCSID 13488・17584・1200 を申告する。当 PJ は Unicode の欄（FCW 0x90xx〜0x93xx＝CCSID・最大の戻りデータ長。ACS `Field5250` の `FCW_CCSID_*`）を扱わない（読み飛ばすだけ）ので、申告した後に
  ホストが Unicode の欄を送ってくると正しく扱えない恐れがある（**未確認**。台帳「DS5250 のその他の差」）。それでも応答しないとホストは
  待ち続けて施錠されたままになる（実測）ので、ACS と同じ応答を返す。ACS 自身もこの応答は Unicode の設定に関係なく返す（原典の条件はフラグだけ）。

## D2: ~~フラグ 0x80 は返さない~~ → 否定応答を返す（`20260921-negative-responses` で破棄）

- ACS は否定応答（センス・コード 0x10050112）を返す。~~当 PJ は否定応答を持たないので、警告だけ出して返さない（ホストは待つ——以前と同じ）。~~
  → `20260921-negative-responses` で否定応答を持ち、ACS と同じく返すようにした（節目 9 の独立点検が記録の同期漏れとして指摘）。

## D3: WSF は最初の SF だけを読み、応答は起きた順に全部送る（節目 9 の独立点検）
- 背景: SF を全部読み、応答も Query と D9/72 のどちらか 1 本だったので、同じレコードの 2 つ目の WSF の応答が落ち、D9/72 の後ろの READ も効かなかった。
- 決定: ACS `processCommand` の ESC 0xF3 と同じく最初の SF の長さだけ進め、応答は `wsfReplies` に積んで順に送る。WSF だけのレコードでなければ READ まで処理する。
- 写していないもの: ACS は WSF の後に READ の保留を下ろす（`pending_read = 0`）。同じレコードで WSF より前に来た READ の扱いは実機で見ていないので変えていない（台帳へ）。
