# 決定記録

## D1: SAVE SCREEN の退避の本体は直さない

- 背景: 実機の ACS は SAVE SCREEN の本体も命令の時点で組む（`[SAVE][WTD]` に OLD）。当 PJ は適用し終えてから組む
- 決定: 直さない。ACS の本体は Java の直列化＋zlib で、当 PJ の本体（WTD の並び）とは形が別で、バイト列の一致は元から目指していない。ホストには不透明な保管物で、
  当 PJ の RESTORE はローカルの退避スタック（SAVE の命令の時点で取る）から復元する（research F3）ため、中身のタイミングは画面に出ない
- 影響: 台帳に「画面に出ない差」として残す

## D2: EXTENDED・IMMEDIATE 系は測っていないので変えない

- 決定: 同じ仕組みだと推測できても、実機で確かめるまで変えない（原則 2）。台帳に未測定として残す
