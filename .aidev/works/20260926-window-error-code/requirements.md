# 要件: WRITE ERROR CODE TO WINDOW（0x22）のメッセージを ACS と同じ行・桁に出す

## 背景 / 課題
ホストは窓（WINDOW キーワード等）が開いている間のエラーを WRITE ERROR CODE TO WINDOW（0x22）で送れる。0x22 は WRITE ERROR CODE（0x21）に「開始桁・終了桁」の 2 バイトが付いた形。
ACS は 0x22 の本文を、メッセージ行の**指定の桁範囲**に書くと読める（原典 `DS5250.processWriteErrorCode`。どの行か・範囲の端は**未確認**——research で原典と実測で確かめる）。
当 PJ は 2 バイトを読み捨て、0x21 と同じく本文を画面の**最下行に重ねて**出す（`packages/tn5250/src/protocol/wtd-applier.ts` の `COMMAND.WRITE_ERROR_CODE_WINDOW`）。
窓の外の桁まで最下行を覆うので、窓の中の入力と見比べにくく、ACS と見た目が違う。台帳は「0x22 が実機で観測できていない」ので保留していたが、DSM で出させられる（decisions D1）。

## 目的 / ゴール
0x22 が届いたとき、当 PJ がメッセージを ACS と同じ行・同じ桁範囲に出し、エラー状態の入り方・抜け方（メッセージの消え方）も ACS と同じになっている状態。
紐づく charter ゴール: ACS の代替として、同じ操作で同じ結果になること（AGENTS.md「判断の原則」1）。

## ユーザーストーリー
- US1: 窓の画面で入力エラーを受ける利用者として、エラーメッセージが ACS と同じ位置（窓の桁の範囲）に出て、ACS と同じ操作で消えてほしい。なぜなら ACS と同じ見た目・操作で、窓の外の表示を覆わずに読めるため。（受け入れ: AC1, AC2, AC4）
- US2: 開発者として、0x22 の ACS の振る舞いを実機で測った記録が欲しい。なぜなら「観測できない」を理由に保留していた判断を、事実で置き換えるため。（受け入れ: AC3, AC5）

## スコープ
### 対象
- 0x22 の本文を出す行と桁範囲（ACS に合わせる）。
- 0x22 のエラー状態の入り方・抜け方が ACS と同じであることの確認（違えば直す）。
- 実機の ACS のコアと当 PJ に同じ 0x22 を当てる測定手段（DSM の試験プログラムの 1 モード）。

### 対象外
- 0x21（WRITE ERROR CODE）の行（SOH のメッセージ行と最下行の違い）——測定で差が見つかれば別項目に割る。
- 窓（CREATE WINDOW）の描画そのもの。

## 機能要件
- 0x22 の開始桁・終了桁を読み、本文を ACS と同じ行・桁範囲に出す（範囲の外は変えない）。
- エラー状態の入り方・抜け方（キーボードの拒否・Reset 等で消えるか、次の画面で消えるか）を ACS と同じにする（ACS が 0x21 と同じメソッドで扱うと確かめられれば、当 PJ も 0x21 の経路を流用する）。
- 本文が桁範囲より長いときも ACS と同じ扱いにする（research で確かめた扱い）。

## 非機能要件 / 制約
- ACS の原典は事実の確認に使い、表現は写さない（AGENTS.md「判断の原則」1 の ⚠）。
- 実機で作った試験プログラム・IFS のファイルは測定後に片付ける（AGENTS.md・`scripts/README.md`）。

## 完了条件 (受け入れ基準)
- [ ] AC1: DSM で出させた 0x22（窓を開いた画面・SOH によるメッセージ行の申告なし＝既定の行・開始桁 12〜終了桁 29）で、当 PJ のメッセージの行・桁範囲が実機の ACS のコアと同じになり、
  範囲の外の桁（同じ行の範囲外・窓の外）の内容は変わらない（当 PJ は core の snapshot と画面の描画の両方で確かめる）。本文が範囲より長い場合（30 字）も ACS と同じ扱いになる。
- [ ] AC2: 0x22 の後、エラー状態に入る（文字キーを拒否する）こと、Reset でエラー状態を抜けるとメッセージが消える（元の行の内容が見える）ことが ACS と同じ。既存の 0x21 のテストが通る。
- [ ] AC3: 0x22 の ACS の振る舞い（行・桁範囲・本文の長さの扱い）を原典と実機の測定で記録し、測定の手順を再実行できる形（DSM のモード・acs-probe の手順・当 PJ の検証スクリプト）で残す。

- [ ] AC4: 0x22 の後に次の画面（WTD・CLEAR UNIT）が来たとき、メッセージが消えるかが ACS と同じ（原典で確かめ、単体テストで固定する）。
- [ ] AC5: 測定で実機に作った試験プログラム（`DSCMD`）と IFS のソース・ログを、測定の後に消す（`test-result.md` に消したことを記録）。
