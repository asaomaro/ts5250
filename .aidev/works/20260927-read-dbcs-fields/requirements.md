# 要件: READ の欄データの残り（DBCS の欄・平坦な形の符号・PC コマンドの応答）

## 背景 / 課題
`.aidev/backlog/acs-parity.md` の「READ の欄データの残り」: 未編集の DBCS 欄（SO/SI の構造を持つ欄）と G の欄は末尾の空白を落とす・0x40 で埋める（ACS は末尾の NUL だけ落とし、ALT は途中の NUL もそのまま）。
打鍵で書き換えた欄の後ろは NUL になる。0x42/0x72 の `flatValue` は符号の手前が数字のときだけ畳む。PC コマンドの応答は待たされている READ の種類を見ずに 0x52 の形で返す。

## 目的 / ゴール
ホストが書いた DBCS の欄を送り返すとき、ホストが受け取るバイト列が実機の ACS と同じになっている状態。

## ユーザーストーリー
- US1: 日本語の業務画面の利用者として、ホストが表示した DBCS の欄をそのまま Enter で返したとき、ACS と同じ値がプログラムへ届いてほしい。なぜなら末尾の空白の有無で比較・更新の結果が変わるプログラムがあるから。（受け入れ: AC1, AC2）

## スコープ
### 対象
- 未編集の DBCS 欄（O・G・J・E）の欄データ（0x52・0x82・0x83）
- 平坦な形（0x42・0x72）の符号付き数値の畳み方
- PC コマンドの応答の形

### 対象外
- 打鍵で書き換えた欄の後ろ（当 PJ は NUL、ACS はホストが書いた実空白が残る）: 送る値の意味は同じで、ホストは欄長まで空白で埋めて受け取る。直すには編集の値にホストの原本の桁を残す作りが要る
- 奇数長の G 欄（ACS は未測定。従来どおり偶数へ丸める）

- [ ] AC2: 平坦な形の符号付き数値は、手前の桁が数字でなくてもゾーンを 0xD にする（原典・単体）
- [ ] AC3: PC コマンドの応答は待たされている READ の種類で組む（単体）
