# 計画: オフライン回帰を CI で回す

## 作業順序と依存関係
1. **T1** `lint` / `build` / `test` が手元で通ることを確かめる（依存: なし）
2. **T2** ワークフローを書く（依存: T1）
3. **T3** 揺れの観測を記録する（依存: T1）

## リスク / 留意点

| リスク | 対応 |
|---|---|
| **未コミットの作業を巻き込む** | 作業ツリーに 6 ファイルの未コミット変更がある（SO/SI 表示の続き）。**`git add` はワークフローだけ**にする |
| 赤い CI で始まる | 揺れは低頻度（フルスイートで 1 回のみ、単体・単独スイートでは再現せず）。**隠さず記録**して判断を残す |
| 資格情報の要求 | 実機テストは skip される。`.env` を置かない |
| 計測が汚れた木の上 | 未コミット変更が入った状態で測った。揺れたテストは変更対象外だが、**その旨を書く** |

## テスト方針
- **手元で CI と同じ 3 コマンドを実行**して通ることを確認する。
- CI 上でも通ることを PR で確認する。
