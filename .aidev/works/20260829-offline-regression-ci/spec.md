# 仕様: オフライン回帰を CI で回す

## 設計方針

### D1: `lint` → `build` → `test` の 1 ジョブ

ワークスペースが 11 個（`packages/*` ＋ `tools/*`）あるが、`npm test` が
`--workspaces --if-present` で束ねているので**分ける必要が無い**。
分けると `npm ci` を何度も走らせることになる。

### D2: 実機に触らない

`.env` / `.env.verify` は CI に置かない。実機を要するテストは
**もともと skip される**（`npm test` の出力で 14 ファイル / 38 テストが skip）。
資格情報を CI に持ち込まないのは AGENTS.md「実資格情報・秘密を成果物に書かない」と同じ線。

### D3: Node は `engines` に合わせる

`package.json` の `engines.node` は `>=20`。CI も 20 で回す。

### D4: Rust は対象外

`crates/hllapi` は npm のビルド経路に入っていない（`package.json` の scripts に
cargo が無い）。**今回は触らない**——入れるなら Rust ツールチェーンの用意が要り、
「オフライン回帰」の範囲を超える。

### D5: 不安定なテストは隠さない

フルスイートで `web-ui` の `tab-visibility.test.ts` が **1 回落ちた**（5333ms）。
単体では 3/3 通り、`web-ui` 単独でも 2/2 通る。**既定のタイムアウト 5000ms を
負荷下で超えた**もので、論理の誤りではない。

**テストには手を入れない。** このリポジトリには `test:flake-hunt` という
専用の道具があり、揺れは既知のカテゴリとして扱われている。
外から来た変更で他人のテストのタイムアウトを黙って伸ばすのは筋が悪い。
**観測した事実を残し、判断は残す。**

**コードは変更しない。**
