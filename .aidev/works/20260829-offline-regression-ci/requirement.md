# 要件: オフライン回帰を CI で回す

## 背景 / 課題

このリポジトリには **CI が無い**（`.github/workflows/` が存在しない）。
約 5,400 のテストと `lint` / `build` が揃っているのに、**PR で自動的に回っていない**。

起票元は `as400-coding-helper` の backlog「CI を整える — 本 PJ の lint core と
as400-web-emulator（＝このリポジトリ）のオフライン回帰を CI で」。
あちら側は済んでおり、残っていたのがこちら側。

## 目的 / ゴール

**PR を出したら、実機に触らない範囲の回帰が自動で回っている状態。**

## ユーザーストーリー

- US1: **PR を出す人**として、壊したかどうかを push しただけで知りたい。
  なぜなら、いま**手元で回すのを忘れると誰も気付かない**から。（受け入れ: AC1, AC2）

## スコープ

### 対象
- `lint` / `build` / `test` を PR と `main` への push で回す。
- **実機に触らない**（資格情報を CI に置かない）。

### 対象外
- 実機を要するテスト（`.env.verify` を使うもの）。
- Rust（`crates/hllapi`）。npm のビルド対象外。
- Windows / macOS。まず Linux で回す。

## 完了条件 (受け入れ基準)

- [ ] AC1: PR と `main` への push で `lint` / `build` / `test` が回る。
- [ ] AC2: **資格情報を要しない**（`.env` / `.env.verify` が無くても通る）。
- [ ] AC3: 手元で同じ手順を実行して通ることを確認している。
- [ ] AC4: 既知の不安定なテストがあれば**隠さず記録**している。
