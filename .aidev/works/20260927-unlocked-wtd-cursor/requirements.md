# 要件: 解錠中に届いた WTD のカーソルと、溜めた AID のカーソル・捨てる時機を ACS と同じにする

## 背景 / 課題
`.aidev/backlog/acs-parity.md` の【まとめ】キー編集の細部の (f)「解錠中に届いた WTD でカーソルが動く」。`20260921-cursor-per-wtd-acs` D2 は原典の条件（解錠中の WTD は動かさない）を
実測（DSPFMT）と合わないとして入れず未確認に残した。`20260927-wec-only-unlock` の実機でも、溜めた AID のカーソルが ACS（5,12）と当 PJ（5,10）で違った。

## 目的 / ゴール
解錠中の WTD の後のカーソルと、溜めた AID が送るカーソル・溜めを捨てる時機が、実機の ACS と同じになっている状態。

## ユーザーストーリー
- US1: 5250 端末の利用者として、エラーの後に打って押した Enter が、ACS と同じ位置・同じ条件でホストへ届いてほしい。なぜならカーソルの位置で動くプログラムが違う動きをするから。（受け入れ: AC1, AC2）

## スコープ
### 対象
- core のセッション（溜めた AID のカーソル・CC1 の施錠で捨てない）
### 対象外
- 解錠中の WTD のカーソル（実測で ACS も動かすと分かったので変えない。(f) は差ではなかった）

## 完了条件 (受け入れ基準)
- [ ] AC1: 実機の ACS のコアで、解錠中の WTD（IC あり・なし・CC1 0x20）の後のカーソルと、溜めた AID の送り方（ワイヤ）を測り、単体テストで固定する
- [ ] AC2: 実機で当 PJ を当てて同じ（`verify-unlocked-wtd-cursor.mjs`・`verify-wec-only-unlock.mjs` の 3 モード）
- [ ] AC3: 片付け
