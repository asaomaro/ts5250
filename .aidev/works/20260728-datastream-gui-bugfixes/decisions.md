## D1: `.win-title` にも padding 補正を足した（原典に無い 1 行）

**原典の記述**: 修正C の根本原因説明で、padding 補正は
「`.cursor`・`.rect-sel`・`.win-deco`/`.win-smoke`・`.gui-window`・**`.win-title`**・`.gui-scrollbar`
にはすでに入っていたが、罫線関連の 3 つ（`.grid-line`・`.win-frame`・`.gui-window-border`）だけ
この補正が抜けていた」としている。

**当リポジトリの現物**: `<style scoped>` 内の `position: absolute` なルールを機械的に洗い出したところ、
**`.win-title` にも補正が入っていなかった**（`ScreenGrid.vue:3350`）。

```
OK   .cursor          OK   .grid-line*        MISS .cell-ruler     ← 計測用・不可視
OK   .rect-sel        OK   .win-frame*        MISS .input-overlay  ← .input-cell.overlaid 基準
OK   .gui-window      OK   .gui-window-border*  MISS .gui-thumb    ← .gui-scrollbar の内側
OK   .gui-selection   OK   .gui-scrollbar     MISS .win-title      ← ★ 補正漏れ
OK   .win-smoke/.win-deco                     （* は本作業で追加した 3 つ）
```

**なぜ足す必要があるか（修正C の一部として必須）**:
`.win-title` は `hostTitle()` が `left`/`top` を直に指定する `.grid` 基準の絶対配置で、
**窓の枠（`.gui-window-border`）の辺に載る文字**である。

- 変更前: 枠も見出しも補正なし → **両方が同じだけずれていたので、互いには揃っていた**
- 修正C を枠だけに当てると: 枠が +8px/+10px 動き、見出しは動かない
  → **見出しが枠から外れる（本作業が新たに作り込む表示崩れ）**

つまりこれは「原典に無い変更を混ぜた」のではなく、**修正C を正しく成立させるために不可欠な一行**である。
`requirement.md` 非機能要件の「現行コードと前提が食い違う場合は原典より現物を優先し、差異をここに記録する」
に従って適用した。

**別環境へ戻すときの注意**: 原典を書いた環境では `.win-title` に既に補正が入っていた可能性がある。
その環境にこの変更を持ち帰る場合は、**先に `.win-title` の現物を確認**すること
（既に入っていれば二重に足さない。CSS の同一プロパティなので二重指定しても値は同じだが、規約上は 1 か所）。

**検証**: 自動テストでは担保できない（jsdom はレイアウトを計算しないため画素位置が出ない）。
修正C 本体と同じく**実ブラウザでの目視確認が要る**（`review.md` の残課題 R1）。

## D2: 修正G と修正H を 1 か所に統合した

原典は `0x1C` の実装を 2 段階で記録している。

1. 修正G: `buf.setChar(addr++, "*", b)` — `"*"` を書く（`rawByte` に `b`=0x1C を渡す）
2. 修正H: 上記から `rawByte` を外す（`buf.setChar(addr++, "*")`）

**修正H は修正G の実装をそのまま上書きする**ため、中間状態（カナ表示モードで化ける版）を
経由せず、最初から最終形だけを入れた。コメントには両方の経緯（`"*"` と確定した理由・
`rawByte` を渡さない理由）を残している。

同様に、原典が修正G の diff で行った「未知オーダーテストの例バイト `0x1c` → `0x16` 差し替え」も、
修正F のテストを書く時点で最初から `0x16` にした。
