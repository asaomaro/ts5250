# 要件: 編集で作った死んだ桁を AID のあとも残す（継続した O 欄・ACS と同じ）

紐づく charter ゴール: charter.md なし（`.aidev/backlog/acs-parity.md`「継続した O 欄の残りの差」(f)。利用者の指示「上の２項目に対応して」）

## 背景 / 課題
継続した O 欄の編集は、区間の終わりに字を置けない桁を「死んだ桁」として残す（ACS の DBCSPlane 8）。ACS は死んだ桁を、ホストが画面を書き直さない限り AID のあとも保ち、次の詰め直しで捨てる。
当 PJ は AID のときに死んだ桁を空きの NUL として core に置き、次の編集では中身として扱っていた。台帳は「ホストが AID の後に画面を書き直すので観測できない」として閉じていたが、
実機の ACS のコアで、書き直さない場合（解錠だけの WTD）に差が出ると測った。

## 目的 / ゴール
編集で作った死んだ桁が、ホストが書き直さない限り AID のあとも死んだ桁として残り、次の詰め直しで ACS と同じに捨てられる状態。

## ユーザーストーリー
- US1: 継続した O 欄を続けて編集する利用者として、AID のあとホストが画面を書き直さない場合も、ACS と同じ並びになってほしい。（受け入れ: AC1, AC2）

## スコープ
### 対象
- core: 死んだ桁のセル（`dead`）を保ち、バイトとしては NUL に見せる（`cellAt`・`dbcsRawCell`）。snapshot に `dead` を出す
- web-ui: snapshot の `dead` を値の死んだ桁の印に読み戻す

### 対象外
- 継続でない欄（死んだ桁は継続した O 欄の鎖だけに生じる）

## 完了条件 (受け入れ基準)
- [ ] AC1: 死んだ桁のセルは送信ではバイトとして NUL で、ホストが同じ桁へ書くか消せば消える
- [ ] AC2: 実機の ACS の E1・E2（解錠だけの WTD をはさんだ 2 回の READ）が一致する
