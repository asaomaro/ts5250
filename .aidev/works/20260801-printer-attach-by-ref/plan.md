# 計画: attach と帳票バッファの上限

## subtask 分割の判定

**分割しない**。3 ファイル＋テスト。

## 実装方針

**上限を先に入れる。** attach はバッファ済みの帳票を渡すので、
先に上限が無いと「無制限の配列をそのまま送る」形になる。

## 作業順序と依存関係

1. **T1** `REPORT_LIMIT` と `receivedTotal`（落としたら `delivered` もずらす）
2. **T2** `ref` を持たせ、`openPrinter` で attach 判定（依存: T1）
3. **T3** ws-handler で `ref` / `autoStart` を渡す（依存: T2）
4. **T4** `printer-opened` にバッファ済みの帳票を載せる（依存: T1,T3）
5. **T5** テスト（依存: T1〜T4）
6. **T6** 実機で「二度開いても 1 本」（依存: T5）
7. **T7** build / lint / test

## リスク / 留意点

- **`delivered` のずらし忘れ**。落とした分を引かないと位置が配列の外を指す
- **attach で状態を変えない**。止めたものを勝手に再開すると利用者の意思を無視する
- **所有をまたがない**。他人の常駐に相乗りしない
- **直接接続（`ref` 無し）の挙動を変えない**
