# 要件: サーバー起動時にサービスを立ち上げる

## 背景 / 課題

ここまでで「サービス」の要件はほぼ揃ったが、**プロセスを再起動すると何も動いていない**。

| work | 実現したこと |
|---|---|
| `20260801-printer-session-residency` | **一度開いたら残る** |
| `20260801-service-start-stop` | 開始/停止・`stopped` |
| `20260801-printer-attach-by-ref` | 開き直したら繋がる |
| `20260801-definition-based-listing` | 定義が一覧に出る |

利用者の要件:

> 定義に自動起動の設定を追加し、自動起動に ✅ されていれば、
> **サーバー起動で自動的に立ち上がる**ようにしたい

**「一度開いたら残る」と「定義があれば上がる」は違う。** 後者が入って初めて
「設定が仕事をする」＝サーバーになる。

## 目的 / ゴール

**サーバーを起動したら、✅ の付いた定義が勝手に待ち受けを始める。**

## スコープ

### 対象

- 起動時に定義を読み、**サービス ✅ ＋ 自動で待ち受け開始 ✅** のものを立ち上げる
- **失敗しても起動を止めない**（1 台の設定ミスで全部が止まらない）
- 失敗は状態として残り、一覧から気づける

### 対象外

- 画面（次）
- 待ち行列 UI の能動/受動の分離、サービスの sink
- 定義の変更を検知して動的に上げ下げする（起動時 1 回だけ）

## 機能要件

- **サーバー設定の定義だけ**を立ち上げる。個人設定は上げない
- **サービス ✅ でないプリンターは上げない**（対話型は人が開くもの）
- **自動で待ち受け開始 ☐ は上げない**（開始ボタンを待つ）
- `dtaqwatch` は**種別そのものがサービス型**なので `service` を見ない
- **HTTP の口を開けるのを待たせない**（繋ぎに行くのに時間がかかる）

## 非機能要件 / 制約

- 起動が**失敗で巻き添えにならない**
- 既存テストが通ること

## 完了条件 (受け入れ基準)

- [ ] サービス ✅ ＋ 自動 ✅ のプリンター定義が起動時に立ち上がる
- [ ] サービス ☐ / 自動 ☐ / 個人設定 は上がらない
- [ ] `dtaqwatch` は `service` を見ずに上がる
- [ ] 1 台が失敗しても残りは立ち上がる
- [ ] **例外を投げ返さない**
- [ ] `npm run build` / `npm run lint` / `npm test` が通る

## 未確定事項

- **個人設定を上げるか**。所有者が居ない起動時にその人として繋ぐことになる。**spec で決める**
