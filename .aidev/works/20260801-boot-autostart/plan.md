# 計画: 起動時の自動開始

## subtask 分割の判定

**分割しない**。2 ファイル＋テスト。

## 作業順序と依存関係

1. **T1** `startAutoServices()` を新設（対象の絞り込みと失敗の扱い）
2. **T2** `main` で `WatchRegistry` を作って `buildApp` に渡す（依存: T1）
3. **T3** `serve` のコールバックから呼ぶ（依存: T2）
4. **T4** テスト（依存: T1）
5. **T5** build / lint / test

## リスク / 留意点

- **起動を巻き添えにしない**。1 台ごとに囲み、例外を投げ返さない
- **個人設定を上げない**。本人が居ない起動時にその人として繋がない
- **HTTP を待たせない**。`serve` の後に呼ぶ
- 実機での確認は**やらない**——起動時の処理を実機で試すには
  `profiles.json` にサービス定義を置いてサーバーを再起動する必要があり、
  共有機の設定を書き換えることになる。**単体テストで対象の絞り込みと
  失敗の扱いを固める**方が実がある

## テスト方針

- 何を上げて何を上げないか（サービス ☐ / 自動 ☐ / 個人設定 / display）
- `dtaqwatch` が `service` を見ないこと
- **1 台が失敗しても残りが立ち上がる**・**例外を投げ返さない**
- 監視レジストリが無くても落ちない
