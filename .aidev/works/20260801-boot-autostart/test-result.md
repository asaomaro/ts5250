## 実機で確かめていない理由

起動時の処理を実機で試すには、**`profiles.json` にサービス定義を置いて
サーバーを再起動する**必要がある。共有機に対して設定ファイルを書き換える作業で、
得られるのは「定義を読んで `openPrinter` を呼ぶ」という**単体テストで固められる部分**の確認。

繋いだ先の挙動（帳票が届く・PDF が出る）は
`20260801-printer-session-residency` / `20260801-service-start-stop` で
**実機で確認済み**なので、そこは重ねて測らない。

## 未検証の穴

- **実機で起動 → 自動で上がる、を通していない**（上記の理由）
- **画面が無い**。起動時に上がったサービスを見るには一覧 API を叩くしかない
- **定義の変更を検知しない**。起動時 1 回だけなので、
  定義を足しても**サーバーを再起動するまで上がらない**
- **停止したサービスは再起動で復活する**。`stopped` は永続しないので、
  「止めておいたのに再起動で動き出す」ことになる——**意図的な停止が消える**
- **多数の定義があるときの起動時間**を測っていない。直列に繋ぐので、
  1 台 4〜7 秒（PUB400 相当）× 台数かかる
