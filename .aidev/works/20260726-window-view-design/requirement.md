# 要件: ウィンドウ表示の見せ方を選べるようにする

## 背景 / 課題

5250 のウィンドウ（ヘルプ窓・アプリの WINDOW DSPF）は、**枠の文字か細い線が引かれるだけ**で、
下の画面との区別が弱い。前面に何が出ているのかが一目で分からず、Web アプリのモーダルに
慣れた目には「重なっている」ことが伝わりにくい。

直前の作業（機能キー凡例のボタン化）で、**両方の種類の窓の矩形を得る手段が既に整った**
（`detectWindowRect()`: 拡張5250 は `gui.windows`、文字で描かれた窓は罫線から）。
これを使えば、桁レイアウトを崩さずに窓の見せ方を足せる。

## 目的 / ゴール

ウィンドウが出ていることが**一目で分かる**ようにする。見せ方は好みが分かれるので、
既存の「入力項目設定 / ボタン設定」と同じ流儀で**選べる設定**にする。

## スコープ

### 対象
- ウィンドウの見せ方の設定を新設（既定は従来どおり＝何もしない）。
- 代表的なパターン（枠の影・背景のスモーク 等）を用意して選べるようにする。
- 拡張5250 の窓と、文字で描かれた窓（ヘルプ等）の**両方**に効かせる。

### 対象外
- 窓の中身（テキスト）の変更・再配置。
- 窓の移動・リサイズ（5250 にその概念は無い）。
- 窓の検出ロジックそのものの変更（直前の作業の成果をそのまま使う）。

## 機能要件

| ID | 要件 |
|---|---|
| FR-1 | 画面設定に「ウィンドウ設定」を新設する。**既定は無効**（従来の見た目を変えない）。 |
| FR-2 | 代表的なパターンを複数用意し、「開く」から見本つきで選べる（入力項目設定・ボタン設定と同じ UI）。 |
| FR-3 | 少なくとも「枠に影」「背景をスモーク」を含む。 |
| FR-4 | **拡張5250 の窓と文字で描かれた窓の両方**に効く。 |
| FR-5 | **桁位置・文字・ホスト色を変えない**（重ねて描くだけ）。 |
| FR-6 | 窓の中の操作（入力・クリック・矩形選択）を妨げない。 |
| FR-7 | 設定は保存され、全画面・再読み込み後にも効く。 |

## 非機能要件 / 制約

- 桁は `ch` 単位・DBCS=2ch の前提を崩さない（AGENTS.md / docs/UI-DESIGN.md）。
- light / dark / system と 11 スキンで破綻しない（色は CSS 変数経由）。
- `prefers-reduced-motion` を尊重する（アニメーションを入れる場合）。
- ビルドは `npm run build -w @as400web/web-ui`（vue-tsc 込み）、テストは `cd packages/web-ui && npx vitest run`。

## 完了条件 (受け入れ基準)

- [ ] 既定（無効）では従来と同じ見た目（重ねる要素が 1 つも出ない）
- [ ] パターンを選ぶと窓の見せ方が変わる
- [ ] **文字で描かれた窓（F1 ヘルプ）でも効く**
- [ ] **拡張5250 の窓（アプリの WINDOW DSPF）でも効く**
- [ ] 窓が無い画面では何も出ない
- [ ] 桁がずれない（重ねた要素がレイアウトに影響しない）
- [ ] 窓の中の入力・クリック・矩形選択が従来どおり効く
- [ ] `npm run build` 成功・テスト追加のうえ全テストパス

## 未確定事項

- スモークの濃さ（読みやすさを損なわない範囲）。
