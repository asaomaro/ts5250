# レビュー記録

## ラウンド 1（2026-07-26）

差分: core 4 / server 3 / web-ui 4（新規 2）/ docs 1。原典照合（tn5250j 逆アセンブル結果との突き合わせ）を
含むため主エージェントがインラインで実施（protocol 2.6）。

### 良かった点（記録）

- **原典との一致が検証可能な形で残っている**。`buildCancelInviteAck()` = `000a12a000000400000a` は
  tn5250j `tnvt#cancelInvite` の `writeGDS(0, 10, null)` と同形、データ付き SRQ は実機採取値
  `001012a0000004040000c4e2d7d1d6c2` と hex 一致でテスト化。AGENTS.md「事実に基づく書き起こし」に沿う。
- **ack を無条件に返す**判断とその理由（ホスト都合の取り消しでも要る）がコード上のコメントに残っている。
- 別メッセージ型を作らず `key` 経路に相乗りさせたことで、readOnly ゲート（`assertKeyAllowed`）・監査・
  busy 対応付けが**二重化していない**。`READONLY_ALLOWED_KEYS` は未変更で、閲覧専用セッションでは
  従来どおり Attn / SysReq が弾かれる（AGENTS.md「認可はサーバーで担保する」と整合）。

### 指摘

- **[should]** `packages/web-ui/src/components/EmulatorPane.vue:551`（`onKeydown` のガード）
  **ホスト画面のプッシュでフォーカスを奪われると、システム要求行が開いたまま端末が固まって見える。**
  `ScreenGrid` は `watch(() => props.snapshot)` で新しい画面が来るたび `focusCursorField()` を呼び、
  キーボード解除中なら入力欄へフォーカスを移す（`ScreenGrid.vue:1117-1126`）。同 `EmulatorPane` の
  snapshot watcher も入力欄が無い画面ではペインへ focus する。システム要求行を開いている最中に
  ホスト発の非同期プッシュ（メッセージ表示灯・ブレークメッセージ・遅延応答）が来ると、
  行の `<input>` からフォーカスが外れる。一方 `onKeydown` は `sysReqOpen` が真である限り**全キーを
  早期 return** するため、以後キーボードが一切効かず、**マウスで行をクリックし直すまで復帰できない**。
  行を出したまま端末を止めるのは ACS 準拠で正しいが、そのときフォーカスが行の外にあってはならない。
  → 対応: coding へ差し戻し。
- **[should]** `README.md`
  Attn / SysReq が利用者向け文書に無い。README の「使い方」はローカル編集キー・キーバインド編集まで
  書いてあるのに、今回足したフッターの 2 ボタンとシステム要求行が未記載で、利用者が辿り着けない。
  → 対応: coding へ差し戻し。
- **[nit]** `packages/web-ui/src/components/EmulatorPane.vue`（`onSysReqSubmit`）
  `sendKey(..., "SysReq", cursor.value, text)` とカーソルを渡しているが、SysReq はフラグレコードで
  カーソルを使わない（core の `buildAidRecord` が `cursor` を見ない）。害は無いが「カーソルも送られる」と
  読めてしまう。→ 許容（他の AID と呼び出し形を揃える利点の方が大きい）。

### 判定

must 0 / should 2 / nit 1 → **coding へ差し戻し**。

## ラウンド 2（2026-07-26）

ラウンド 1 の should 2 件を確認し、修正で入った新たな問題を 1 件検出した。

### ラウンド 1 指摘の解消確認

- **[should] フォーカス奪取で端末が固まる** → 解消。`SysReqLine` の `@focusout` で行がフォーカスを取り戻し、
  `EmulatorPane` の snapshot watcher は行が開いている間ペインへ focus しない。
  回帰テスト「ホスト画面がプッシュされてもシステム要求行がフォーカスを保つ」を追加し、
  **`@focusout` を外すと落ちること**まで確認済み（テストが実際に欠陥を捕まえる）。
- **[should] README 未記載** → 解消。機能一覧と「使い方 2.（キー操作）」に追記。
  既定バインドを付けない方針（D2）ゆえ**文書が唯一の導線**なので、`Esc → Attn` の割り当て例、
  SysReq 行はオプション専用で CL コマンドは Attn 側、取り消しでは何も送らない旨まで明記した。

### 指摘

- **[should]** `packages/web-ui/src/components/SysReqLine.vue`（`onFocusOut`）
  **フォーカス保持がタブ・ペイン切替と喧嘩する。** Alt+PageUp/Down（タブ切替）と Alt+矢印（ペイン移動）は
  ペインではなく **`App.vue` のグローバルハンドラ**が担う（`App.vue:144`）ため、システム要求行が開いていて
  `onKeydown` が早期 return していても発火する。切替後、離れたペインの `@focusout` が発火して
  **フォーカスを引き戻してしまい、切替先のペインがキーボードを取れない**。
  他ペインをクリックした場合も同様。
  → 対応: coding へ差し戻し。ペインがフォーカスを失ったら行を畳む（どのみち何も送っていないので、
  切替で取り消し扱いにするのが素直）。

### 判定

must 0 / should 1 / nit 0 → **coding へ差し戻し**。

## ラウンド 3（2026-07-26）

### ラウンド 2 指摘の解消確認

- **[should] フォーカス保持がタブ・ペイン切替と喧嘩する** → 解消。`props.focused` が false になったら
  行を畳む（＝取り消し扱い。まだ何も送っていないので副作用なし）。切断時に畳むのと同じ考え方に揃えた。
  回帰テスト「ペインがフォーカスを失ったら行を畳む（＝取り消し扱い・何も送らない）」を追加。

### 全体の再点検

- **要件適合**: requirement の完了条件 9 件すべてに対応する検証がある（test.md の対応表）。
  対象外と決めた 3 点（Esc の既定バインド / ATNPGM の窓の描画 / ロック中の SysReq）は
  decisions D2・D5 に理由付きで残っており、実装が勝手に踏み込んでいない。
- **正確性**: ack は opcode を見て無条件に返し、送ったキーで条件分けしていない（原典と同じ）。
  データ付き SysReq は実機採取バイト列と hex 一致。空 SysReq のバイト列も従来どおりでテスト済み。
  `sysReqText` の誤用は `PROTOCOL_ERROR` で弾く（黙って捨てない）。
- **規約適合**（AGENTS.md）:
  - コメントは意図中心。「なぜ無条件に返すか」「なぜ ack 後に return しないか」「なぜキュー破棄を
    移植しないか」「なぜ `.sysreq` 由来で判定するか」がコード上にある。
  - 原典は逐語移植せず、参照クラス／メソッド名（`tnvt#cancelInvite` / `#systemRequest(String)`）を
    コメントに残している。原典ソースはリポジトリに取り込んでいない。
  - core のピュアロジック層に `node:*` の追加 import なし。
  - UI は CSS 変数（`--crt` / `--crt-bezel` / `--crt-line` / `--t-green` / `--mono`）のみで生色なし。
    ボタンは CRT ペインの `.fk` 意匠に合わせた（D3）。
  - 認可はサーバー側のまま。`READONLY_ALLOWED_KEYS` は未変更＝閲覧専用では従来どおり拒否。
    新メッセージ型を作らず `key` 経路に相乗りさせたので、歯止めが二重化していない。
- **保守性**: `onAid` に入口を 1 本化（キーバインド経由・フッターボタン経由が同じ道を通る）。
  `sysReqOpen` は参照元より前で宣言し、依存の向きが読める。

### 判定

must 0 / should 0 / nit 0 → **通過**。
