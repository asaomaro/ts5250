# 要件: 挿入モードで欄が満杯のとき、黙って文字を捨てない

## 背景 / 課題

- **挿入モードで満杯の欄に 1 文字打つと、末尾が黙って消える。** `typeChar`
  （`packages/web-ui/src/composables/fieldEdit.ts:29-43`）が `splice` で押し込んだあと
  `chars.length = len`（同 `:36`）で**欄長に切り詰めている**。溢れた文字は通知なく失われる。
  - **欠陥が出るのは `cursor < len` のときだけ。** `typeChar` は `cursor >= len` で早期 return する
    （同 `:31`。`field-edit.test.ts:23-30` が固定済み）ので、caret が末尾にある形では今も値は変わらない。
- **符号付き数値欄では、消えるだけでなく値が化ける疑いがある。** 台帳の例
  （`.aidev/backlog/acs-parity.md:110`。出典 `20260919-backlog-acs-triage` research N2）:

  ```
  右寄せの "   12-"（−12）の `1` の前（cursor=3）に `9` を挿入
    → "   912"   末尾の符号 `-` が押し出されて落ちる
    → 送信は 91（符号が消えて正の 91）… とされる
  ```

  **画面上の値が `"   912"` になることは現物で確かめた**（`cursor=3` は後述 `isSignPosition` に
  掛からないので到達する）。**「送信が 91 になる」は台帳の記述で、まだ実測していない**
  ——符号桁の落とし込みは `packages/tn5250` 側（`read-response.ts` 系）なので、
  web-ui 単体では確かめられない。**research / 実機で確かめる**（AC2b）。
- **ACS が正典**（`AGENTS.md` 判断の原則 1）。台帳は
  `PS5250.insertChar` → `reserveRoomForInsert` が「最終桁（符号付き数値は符号桁の手前）から
  空きを数え、足りなければ操作員エラー 0012 を出して値を変えない」としているが、
  **これは前 work の research の要約であって原典ではない**。
  - ~~**エラー番号 0012 も要確認。**~~ → ~~**確認した結果、誤りだった**（research F5）~~
    → **さらに訂正（research F9/F10。実機）**: **台帳のほうが正しかった**。
    実機で満杯の欄へ挿入すると `データを挿入する余地がありません。`（ACS の
    `"No room to insert data."`）が出て **`inhibit=5`（施錠）**し、値は 1 桁も変わらない。
    F5 は `PS5250` の 1 経路だけを読んで「出ない」と断定した**私の誤り**で、
    実機では**継続欄・単独欄のどちらでも出る**。**コードの読みで断定したのが原因**（原則 2）。
  - 一方、**当 PJ には既に ACS 由来の文言がある**——`MSG_NO_ROOM`
    （`packages/web-ui/src/composables/opMessages.ts:58`＝「挿入する余地がありません」、
    doc コメントに `ACS: "No room to insert data."`）。**ACS がこの状況で出す文言は
    既に調べ済み**で、番号のほうが不確かという非対称がある。

### 既にある「余地が無ければ変えない」——ただし貼り付けの挿入モードだけ

当初「貼り付けは既に正しい」と書いたが、**現物を見ると経路が 4 つに割れている**
（doccheck 指摘。条項 `comment-provenance`）:

| 経路 | 場所 | いまの挙動 |
|---|---|---|
| 貼り付け・**挿入**モード | `ScreenGrid.vue:3231-3251`（`pasteFrom` → `insertInto`） | **何も書かず `MSG_NO_ROOM`**（ACS と同じ向き） |
| 貼り付け・**上書き**モード | 同上 | 予算で切り詰め（エラー無し。コメントが「ACS もそう」と記す） |
| `fieldEdit.paste()` | `fieldEdit.ts:202-210` | `typeChar` を回すので**切り詰める**（`:202` に「超過は切り詰め」） |
| **打鍵**（この work の主題） | `fieldEdit.ts:29-43` | **切り詰める** |

**正しいのは 1 つだけ**で、「打鍵だけがおかしい」という当初の理解は誤り。

### 符号桁は「打ち込み」だけ既に塞がれている

`isSignPosition`（`packages/web-ui/src/composables/fieldValidate.ts:334-336`＝
`signedNumeric && cursor >= visLen - 1`）＋ `MSG_BY_REASON["sign-position"]` により、
**符号桁そのものへの打鍵**は既に弾く（`ScreenGrid.vue:2733-2736`）。
**欠けているのは「符号桁より前への挿入が、符号を押し出す」経路**。
design はこの既存の仕組みを**二重化しない**こと。

### 既存テストがこの面を見ていない

`packages/web-ui/test/field-edit.test.ts:33-41` の挿入ケースは `initEdit("AB   ", 5, 1)`
——**満杯でない欄**。満杯のテストは**上書きモード側（`:23-30`）にしかない**。
条項 `test-input-shape` の言う「形を振っていない」実例。

（`.aidev/charter.md` は無いので、charter ゴールとの紐付けは行わない）

## 目的 / ゴール

- **挿入モードで、利用者の打鍵が値を黙って壊さない状態。** 入り切らないなら
  **値を変えずに弾き、弾いたことが利用者に分かる**。
- **符号付き数値欄で、送信される値が利用者の意図と食い違わない状態**（符号が押し出されない）。
- **欄からあふれたときの規則が、打鍵・貼り付け・IME のどの経路でも揃っている状態**。

## ユーザーストーリー

- US1: 5250 端末の利用者として、挿入モードで欄を直すときに**打った内容が黙って消えない**でほしい。
  なぜなら、消えたことに気づかずに送ると**ホスト側のデータが壊れる**から。（受け入れ: AC1）
- US2: 数値欄を扱う利用者として、**符号が勝手に落ちない**でほしい。
  なぜなら、−12 のつもりで 91 を送るような**符号の反転**は、金額や数量で実害が大きいから。
  （受け入れ: AC2a, AC2b）
- US3: 端末の利用者として、**弾かれたことがその場で分かる**でほしい。
  なぜなら、無反応だと「キーが効かない不具合」と区別が付かず、原因を探して手が止まるから
  （同じ理屈で `wsErrorNotice` を足した実例——`20260920-field-error-no-value`）。（受け入れ: AC3）
- US4: この PJ の保守者として、**経路ごとに規則が割れていない**でほしい。
  なぜなら、片方だけ直す修正が繰り返し起きており（条項 `paired-artifact-sync`。
  直前の work だけで 3 回）、割れているとまた片方だけ直すから。（受け入れ: AC4）

## スコープ

### 対象

- **挿入モードの打鍵**（`fieldEdit.ts` の `typeChar`）が、欄に入り切らないときの扱い。
- **空きの数え方**——ACS の `reserveRoomForInsert` に合わせる。**原典で確かめてから決める。**
- **符号付き数値欄で、符号桁を取り置くこと**。打鍵側だけでなく
  **貼り付け側（`insertInto`。`ScreenGrid.vue:3090-3103`）も対象**
  ——現状は base の末尾空白を落として `dbcsByteLength(out) > visLen` で見るだけで
  **符号桁を取り置いていない**ので、打鍵側だけ直すと規則が割れる（doccheck 指摘）。
- **`fieldEdit.paste()`**（`:202-210`）——`typeChar` を回すので、打鍵を直せば連動する。
  連動しない場合は明示的に合わせる。
- **弾いたときの通知**。**既存の `MSG_NO_ROOM` を再利用する**
  （新しい定数を作らない。`AGENTS.md`「定数は 1 か所」）。
  **利用者の判断（2026-09-20）で「打鍵にも `MSG_NO_ROOM` を出す」方向に確定。**
  ~~ACS は音を鳴らすだけでメッセージを出さないが、当 PJ は貼り付けで既に出しているので揃える~~
  → **実機で測り直したら ACS も同じメッセージを出していた**（research F9/F10）。
  **つまりこれは ACS からの逸脱ではなく一致**で、「違える理由」は要らない（decisions D1 改訂）。
- **DBCS 欄の打鍵経路**（`ScreenGrid.vue:2000-2007` `absorbDbcs` / `:2844-2845`）
  ——余地が無いと `undefined` を返し、**値は変えないが通知も出さない**。
  FR1 は満たすが FR3 を満たさない既存経路なので、通知を揃える。
- **IME 確定経路**（`ScreenGrid.vue:3419-3428`。コメント「超過分は切り捨てる」）。
- **継続欄（複数行にまたがる欄）での空きの数え方**（FR6）。

### 対象外

- **IME の選択置換で、確定が拒否・取り消されたときに、合成開始で消した選択を戻すこと**
  （2026-09-21 追記・利用者の判断・`decisions.md` D16）。
  HEAD からの**既存欠陥**（選択置換の IME 確定が入り切らないと 1 文字欠けて確定する）。
  この work で戻す仕組みを 3 回作って 3 回壊し、**別欄の値が混入する欠陥**まで作ったため、
  時間をまたぐ状態の寿命管理として **design から見直す**。台帳（`acs-parity.md`）へ起票済み。
  **打鍵経路の選択置換の復元は対象内**（同期的な構造で、検証済み）。

- **貼り付けの上書きモード**の切り詰め。コメントが「ACS も予算で切り詰める」としており、
  挿入モードとは ACS 側の規則が別。**research で裏を取ったうえで**触らない
  （裏が取れなければ未確認として残す）。
- **選択範囲の置換**（`ScreenGrid.vue:2738-2743` の `chars.length = visLen(f)`）。
  選択を消してから挿すので**あふれが起きにくい**。触らないが、research で
  「あふれうるか」を 1 度だけ確かめる（起きるなら別項目として台帳へ）。
- **複数行ペーストの帯幅を文字数で切っている件**（`AGENTS.md` 残課題）。全角の桁ずれの話で原因が別。
  FR6 の結論として副次的に閉じるなら、その旨を記録するに留める。
- 操作員エラーの**番号そのものの表示**（OIA に `0012` 等）。既存の通知の枠組みに乗せるところまで。
- **キーボードの施錠**。ACS は満杯の挿入で `inhibit=5` にする（research F9/F10。実機）が、
  当 PJ は操作員エラーで施錠しない作りで、**変えると全ての操作員エラーに波及する**
  （型違反・符号桁・Dup など）。**この work では施錠しない**まま通知だけを出し、
  施錠の要否は**実測を添えて台帳へ**。
- **上書きモードの打鍵**。欄長を超える書き込みが起きない。

## 機能要件

- FR1: 挿入モードで、挿入すると欄に入り切らないとき、**欄の値を 1 文字も変えない**。
- FR2: 空きの判定は **ACS の `reserveRoomForInsert` と同じ数え方**にする。
  **原典で確かめた事実に基づく**こと（要約を実装しない）。
- FR3: 弾いたときは**利用者に分かる形で知らせる**。**既存の `MSG_NO_ROOM` を使う**
  （新設しない。必要なら理由を残して新設）。
- FR4: 符号付き数値欄では、**挿入によって符号桁が押し出されない**。
  打鍵と貼り付けの**両方**で成り立つこと。
- FR5: 入り切る場合の挙動は**変えない**。
- FR6: **継続欄（複数行の欄）で、空きを欄全体の予算で数えるか行ごとに数えるかを決め、
  そのとおりに実装する。** どちらかは ACS の原典で確かめる（現状は「欄全体の予算」を見ている）。
- FR7: あふれたときの規則が、**打鍵・`fieldEdit.paste()`・貼り付け（挿入）・DBCS・IME** の
  各経路で一致していること。

## 非機能要件 / 制約

- **`AGENTS.md` の判断の原則に従う。**
  - 原則 1: **ACS が正典**。`PS5250.insertChar` / `reserveRoomForInsert` の実物を
    `acshod2.jar` のデコンパイル結果で読む。**台帳の要約で代替しない。**
    読んだ結果は事実として書き起こし、**逐語移植はしない**。
  - 原則 2: **実機で確定できることは実機で確かめる**（符号桁の落とし込み・送信結果）。
  - 原則 3: 原典・実測が過去の決定と矛盾したら、**過去の決定を疑う**。
- 条項 `measurement-sanity`——**1 回の観測で決めない**。別の経路でもう一度取る。
- 条項 `verify-by-mutation`——回帰テストを足したら**実装を戻して落ちることを確かめる**。
- 条項 `test-input-shape`——**入力の形を振る**（満杯 / 残り 1 桁 / **中間に空白がある満杯でない欄** /
  符号桁だけ空き / 継続欄 / 全角混在 / caret が末尾）。
- 条項 `paired-artifact-sync`——上の「経路が 4 つに割れている」表がそのまま対の一覧。
- 条項 `comment-provenance`——出所は work slug ＋ `file:line` ＋ ACS のクラス／メソッド名。
- **ACS の規則を原典で確かめてから実装する**（目的ではなく進め方の制約としてここに置く）。
- `AGENTS.md` のコーディング規約（`console.*` 禁止・web-ui のテストはパッケージ dir から実行）。
