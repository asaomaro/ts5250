# 要件: 画面の欄を、経路をまたいで同じ言葉で指せるようにする

## 背景 / 課題

入力欄の指し方が経路ごとにばらばらで、しかもどれも脆い。

| 経路 | いまの指し方 | 弱さ |
|---|---|---|
| スクリプト / MCP | `{index}` か `{row,col}` | `index` は**手前の欄が増減すると全部ずれる** |
| web-ui の DOM | `data-field-index` | 同上（連番） |
| **Playwright** | **無い** | 座標で当てるしかない。`20260803-hllapi-bridge` の E2E で実際に困った |

**5250 には安定した識別子が無い**（調査済み）。電文が欄の名前を運ばず、GUI 構造体の `id` すら
ts5250 が `++this.guiIdSeq` で振っているだけ。つまり**導出した id はどれもレイアウト変更に
耐えない**——設計の巧拙ではなくプロトコルの性質。

そのうえで**壊れ方を選ぶ**のがこの作業。

## 目的 / ゴール

1. **機械的な id** — 決定的で画面内で一意。DOM のセレクタ・重複検出に使う
2. **意味的な指定** — 見えている文字に錨を打つ。レイアウト変更に耐えるのはこれだけ
3. スクリプト・MCP・HLLAPI・Playwright が**同じ言葉で欄を指す**

## スコープ

### 対象

- `Field` に `(row,col)` 由来の id（`@ts5250/tn5250` の snapshot 生成時。**ブラウザ連携より手前**）
- 一意性を**検査で担保**する
- web-ui の `<input>` に id を出す
- **ラベル錨の検索**を共有層へ（いま `packages/server/src/hllapi-ps.ts` に閉じている）
- 検索は**厳格モード**——複数当たったら例外＋候補一覧

### 対象外

- **`nth`（一覧の N 番目）は作らない**（順序依存で事故の元。2026-08-04 に方針決定）
- `fieldSignon` の作り直し（サインオン画面に特化した便宜として据え置く）
- HLLAPI のバイト位置ベースの検索（CP932 のバイト位置が要るので固有のまま）

## 機能要件

- id は**位置由来だと読んで分かる形**（意味的な安定を主張しない）
- 連番にしない——`Field.index` の脆さがこの作業の動機
- **1 つの欄が複数の `<input>` になる**（行をまたぐ欄は `data-slice` で分割）。id は**欄**を指す
- 検索が複数当たったら**黙って先頭を取らない**。例外にして候補を見せる
- 絞り込みは**重ねられる**形（行の内容・列・領域）

## 非機能要件 / 制約

- `@ts5250/tn5250` は Node API に依存しない（PJ 規約）
- 既存の 3,909 件を壊さない
- `Field` は中核の型なので**追加のみ**（既存の属性を変えない）

## 完了条件 (受け入れ基準)

- [ ] `Field.id` がスクリプト・MCP・ブラウザのすべてに届く
- [ ] **一意性が検査で担保されている**（実機の画面群で確かめる）
- [ ] Playwright が `[data-field="…"]` で欄を指せる
- [ ] ラベルから欄を引ける（共有層。スクリプトからも MCP からも使える）
- [ ] **曖昧なら例外＋候補一覧**（実機の `WRKSPLF` で確かめる）
- [ ] HLLAPI が壊れていない（実機 33/33）
