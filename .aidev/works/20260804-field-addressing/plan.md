# 計画: 欄の指し方

## 実装方針

**下から積む。** 型 → 共有層 → 既存の呼び出し側の付け替え → 画面 → 実機。
`Field` は中核の型なので**追加のみ**にし、各段で全件を回す。

design は挟まない——spec で構造が決まっており、新しいアーキテクチャ判断が無い。

## 作業順序と依存関係

1. `Field.id` と一意性の検査（依存: なし）
2. `screen/search.ts` — 桁位置・欄の関数を持ち上げ（依存: なし）
3. `screen/search.ts` — 文字列検索と厳格モード（依存: 2）
4. `hllapi-ps.ts` を再輸出に付け替え（依存: 2）。**HLLAPI の呼び出し側は触らない**
5. web-ui が `data-field` を出す（依存: 1）
6. 実機で確かめる（依存: 4,5）— HLLAPI 33/33、Playwright が id で欄を指せる

## リスク / 留意点

- **HLLAPI を壊す**（4 が本丸）→ 実機 33/33 で確かめる。持ち上げは**振る舞いを変えない**
- **`Field` の追加で MCP が壊れる** → `.passthrough()` 済みだが、検査で確かめる
- **一意性の破れ** → 検査で固定。実機 8 画面 49 欄では 0 件だった
- 既存 3,909 件を壊さない
