# 決定記録

## D1: プリンターの申告を ACS の組にする（`printer-session.ts` の旧い組を破棄）

- 背景: 当 PJ は SBCS / DBCS とも `IBM-3812-1` に KBDTYPE / CODEPAGE / CHARSET・IBMFONT=12・IBMSENDCONFREC を載せていた
  （`terminal-type.ts` の旧コメント「DBCS でも別型番（IBM-5553 系）は不要」）。日本語機では装置が 3812 にされ、IGC 属性の帳票が
  CPA3303 で止まっていた。`docs/HOST-PRINT-TRANSFORM.md` §2 は「5553-B01 は 8925」と書いていたが、PUB400 で測り直すと 8925 は
  **当 PJ の変数の組**のせいで、ACS の組なら I902 だった（research F3）。
- 決定: ACS の 4 通りの組（DBCS / SBCS × HPT あり / なし）をそのまま並べて送る（`printerDeclaration`）。旧コメントと文書の誤りは
  取り消し線で残した。
- 影響: **英語機で DBCS のプリンターを開くと、日本語は置換される**（CODEPAGE / CHARSET を送らないので装置の文字セットがシステムの
  既定になる。PUB400 の `verify-printer-dbcs.mjs` で確認）。以前は英語機で届き日本語機で止まっていたのが、逆になる。
  **ACS と同じバイトを送っている**（テストで固定）ので ACS でも同じになるはずだが、ACS そのものを PUB400 に当ててはいない（未確認）。
  利用者の実機（日本語機）では、ACS と同じく IGC の帳票が届くようになる。
- 影響: 既にある装置名で繋ぐと、ホストが装置の型を申告に合わせて作り変える（3812 → 5553。ACS でも同じ）。README に書いた。

## D2: 応答は「いまの応答」を持ち越す（ACS `response_string`）

- ACS は応答を消さないので、CLEAR の後はデータを書くまで CLEAR_PROCESSED を返し続け、起動直後はデータを書くまで何も返さない。
  当 PJ も同じ形にした。以前は「CLEAR 以外の全レコードに印刷完了」で、CLEAR には何も返していなかった。

## D3: 印刷先の失敗で応答を保留するのは別の work にする

- ACS は印刷先への書き込みに失敗すると応答を保留し、利用者の再試行・取り消しを待つ（`PSNVT5250P.processPrinterError`）。
  当 PJ の印刷先（PDF・自動印刷）はジョブの終わりにサーバーが行うので、保留には tn5250 とサーバーと画面の 3 か所の設計が要る。
  台帳の「受信した瞬間に印刷完了を返す」の残りとして割って残した。
