# 要件: READ IMMEDIATE（0x72）に応答する

## 背景

`wtd-applier.ts` の未実装コマンドは、**捨てた後ろに READ があると入力待ちに入り、
利用者には「待機中・ホストから応答がない」としか見えない**。この形で 3 回踏んでいる
（`SAVE SCREEN` / `WRITE ERROR CODE TO WINDOW` / `SAVE PARTIAL SCREEN`）。

`READ IMMEDIATE`(0x72) は**本来こちらが応答すべき読み取り要求**だが、応答していなかった。
理由は「実機で届いたことが無く、応答の正しさを確かめられない」。

## 判断

**入れる。** 形式は推測ではなく**原典で確定している**——届いたときにホストを待たせるより、
原典どおりに返す方が良い。ただし**実機の裏取りはできない**ので、その旨を残す。

## スコープ

- `0x72` の応答（`buildReadImmediateResponse` ＋ セッションからの即送信）
- **`0x83`（ALT）は入れない**——2 実装で扱いが割れている

- [ ] 原典を**直に読んで**から書く（要約や記憶で代替しない）
- [ ] 2 実装を突き合わせ、**一致する点だけ**を実装する
- [ ] セッションが実際にレコードを書き出すところまで試験する
- [ ] 既存の試験が緑（`0x72` の扱いを固定していた試験は更新する）
