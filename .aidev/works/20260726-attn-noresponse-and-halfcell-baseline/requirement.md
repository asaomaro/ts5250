# 要件: Attn 窓の高さずれと、応答しない Attn で固まる問題

利用者から 2 件の報告を受けた。いずれも実測で原因を特定済み。

## 課題 1: コマンド入力窓に高さ方向のずれが出る（**直前の変更による回帰**）

PR #159 で入れた `.half-cell`（対を失った DBCS セルを 1 桁に切り詰める箱）が
**`overflow: hidden`** を使っており、これが **インラインブロックのベースラインを変える**。

CSS の規定では、インラインブロックのベースラインは通常「最後の行ボックスのベースライン」だが、
**`overflow` が `visible` 以外だと「下マージン端」**になる。結果、その桁だけが上下にずれ、
行ボックスの高さも変わるため**その行全体が縦にずれて見える**。

実ブラウザで測定した（`display:inline-block; width:1ch` の箱を隣の文字と比較）:

| 指定 | 隣の文字とのずれ |
|---|---|
| `overflow: hidden` | **-2px** |
| `clip-path: inset(0)` | 0px |
| 指定なし | 0px |

利用者のスクリーンショットでずれて見える行は、まさに DBCS が窓の属性に潰されて `.half-cell` が
出ている行（「選択項目またはコマン」「F4= プロ」）で、症状と一致する。

## 課題 2: 窓が出ている状態で再度 Attn を押すと読み込み中のまま固まる

実機で採取した結果、**2 回目の Attn にホストは 1 バイトも返さない**
（ATNPGM が既に前面にあるため無視される）。

```
>>> Attn（1 回目）  <<< 0x0a(Cancel Invite) → 0x04(SAVE SCREEN) → 0x03(PUT_GET)   timedOut=false
>>> Attn（2 回目）  （受信ゼロ）                                                   timedOut=true 経過=20008ms
```

`sendAid` は「キーボードのアンロックまで待つ」契約なので、**既定 30 秒**待ち続ける。その間
web-ui は busy（読み込み中オーバーレイ）で入力を止めるため、利用者には固まったように見える。

**Attn / SysReq はホストが応答しないことが正常にあり得る**（今回のように既に ATNPGM が動いている、
システム要求を無視する構成 等）。画面を返す前提の AID と同じ待ち方をしているのが誤り。

## 目的 / ゴール

- 窓が出ても**行が縦にずれない**（PR #159 の回帰を取り除く）。
- Attn / SysReq がホストに無視されても**画面が固まらず、無視されたことが利用者に分かる**。

## スコープ

### 対象

1. `.half-cell` の切り詰めを、ベースラインを変えない方法（`clip-path`）へ置き換える。
2. **フラグレコード（Attn / SysReq）の待ち時間を短くする**。画面を返さないことがある操作として扱う。
3. タイムアウトしたとき、**操作員メッセージで「応答が無かった」ことを知らせる**（無言で戻さない）。

### 対象外

- `sendAid` 全体の待ち方の作り替え（通常の AID は従来どおり既定 30 秒）。
- 5250 の Reset キー（入力禁止の手動解除）の実装。今回は「勝手に戻る」ことで解決し、
  Reset は必要になったら別 work で扱う。
- ホストが 2 回目の Attn を無視すること自体への介入（ホスト側の正しい動作）。

## 機能要件

- `.half-cell` は 1 桁幅に描画をクリップしつつ、**隣の文字とベースラインが一致**する。
- Attn / SysReq の応答待ちは短い既定値にする。**時間切れはエラーにせず**、キーボードを解放して
  現在の画面を返す（既存の `timedOut` の扱いを踏襲）。
- 時間切れになったら web-ui が操作員メッセージを出す。ホストが後から画面を送ってきた場合は
  従来どおり screen イベントで反映される（早く戻しても取りこぼさない）。
- 通常の AID（Enter・F キー等）の待ち時間と挙動は**変えない**。

## 非機能要件 / 制約

- `clip-path` はグリフの描画だけを切る。レイアウト（桁幅 1ch）は変えない。
- 変更は web-ui と core の待ち時間既定に閉じ、プロトコルのバイト列は変えない。
- `vue-tsc` 込みでビルドが通ること。

## 未確定事項 / 確認したいこと

- **短い既定値を何秒にするか**。早すぎると遅いホストで「応答なし」を誤表示し、遅いと固まって見える。
  実機での 1 回目の応答時間を基準に spec で決める。
- **ACS は 2 回目の Attn でどう振る舞うか**（入力禁止のまま Reset 待ちか、すぐ戻るか）。
  タップで採るには利用者の操作が要るため、まずは「勝手に戻る＋メッセージ」で実装し、
  ACS と違うと分かれば追随する。
