## 課題 1（高さずれ）の検証

### 手法の是正

最初は「`.half-cell` と同じ行の素の文字の `bottom` 差」を測ったが、**インラインブロックと
素のインライン要素では箱の高さがそもそも違う**ため -2px が出て判定に使えなかった。
症状そのもの（**行が縦にずれる**）を測る指標に変えた——`.grid-row` の高さと間隔の均一性。

### 結果（実機の Attn 窓・`.half-cell` が 19 行目に出る画面）

```
行の高さ（種類）: [25]     ← 全 24 行が 25px。ばらつきなし
行間隔（種類）  : [25]     ← 全ての行間が 25px。ずれなし
half-cell のある行: [19]
```

### CSS 技法そのものの裏付け（実ブラウザ計測）

`display:inline-block; width:1ch` の箱を隣の文字と比べた:

| 指定 | ずれ |
|---|---|
| `overflow: hidden` | **-2px** |
| `clip-path: inset(0)` | **0px** |
| 指定なし | 0px |

インラインブロックのベースラインは `overflow` が `visible` 以外だと下マージン端になる、という
CSS の規定どおりの結果。`clip-path` は描画だけを切るのでレイアウトに影響しない。

## 課題 2（無応答で固まる）の検証

実機で Attn を 2 回続けて押した（2 回目は窓が出ている状態＝ホストが無視する）:

```
2 回目 Attn: 入力プロテクトが解けるまで 5349ms
操作員メッセージ: "ホストから応答がありませんでした"
```

**修正前は 30 秒**（`sendAid` の既定）だったものが 5.3 秒になり、かつ「無視された」ことが
利用者に伝わるようになった。1 回目の Attn は従来どおり正常に窓が出る。
