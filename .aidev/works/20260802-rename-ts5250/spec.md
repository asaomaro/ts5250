# 仕様: `@ts5250` → `@ts5250` の改名

## 概要

**`ts5250` は一意の語**なので、対象ファイルで一括置換すれば済む。
`@ts5250/` だけでなく、テスト内の**正規表現リテラル `@ts5250\/`** も同じ置換で拾える
（`/` の前の `\` を跨がない形で置換すると片方が残る——**語だけを置換する**のが要点）。

## 設計方針

### 1. 置換は「語」で行う（`ts5250` → `ts5250`）

`@ts5250/` を狙って置換すると、テストの正規表現 `@ts5250\/hostserver` が**残る**。
そこが残ると、依存の向きを見張る検査が**新しい import に当たらなくなり、
緑のまま何も見ていない状態**になる（この repo で最も避けたい失敗の形）。

対象から外すもの:

| 除外 | 理由 |
|---|---|
| `.aidev/` | **過去の記録**。その時点の事実なので書き換えない |
| `node_modules/` `dist/` | 生成物 |
| `package-lock.json` | **手で書き換えず `npm install` で作り直す** |

### 2. 名前の対応

```
@ts5250/base      → @ts5250/base
@ts5250/ebcdic    → @ts5250/ebcdic
@ts5250/tn5250    → @ts5250/tn5250
@ts5250/scs       → @ts5250/scs
@ts5250/hostserver→ @ts5250/hostserver
@ts5250/server    → @ts5250/server
@ts5250/web-ui    → @ts5250/web-ui
as400-web-emulator  → ts5250            （ルート）
as400-5250-desktop  → ts5250-desktop    （Electron）
```

`@ts5250/tn5250` は一見くどいが、**スコープ＝製品、パッケージ＝役割**という
読み方で一貫している（`@ts5250/scs` `@ts5250/ebcdic` と並ぶ）。

### 3. 利用者に見える名前

| 場所 | これから |
|---|---|
| README 見出し | `# ts5250` |
| Electron `productName` | `ts5250` |
| Electron `appId` | `com.asaomaro.ts5250` |

⚠ **`appId` を変えると、既にインストールされているものとは別のアプリ扱いになる**
（設定と利用者データの置き場が変わる）。開発段階なので変えるが、
**配布済みのものがあるなら据え置く判断もある**——PR 本文に明記して判断を仰ぐ。

### 4. 依存の向きの検査が**空振りしていないこと**を確かめる

`dependency-direction` / `import-from-owner` / `ebcdic-not-reexported` /
`hostserver-not-reexported` / `log-independence` は**ソースを正規表現で走査**する。
置換後も同じ数の import を拾えているかを、**わざと違反を入れて落ちること**で確認する
（緑を見るだけでは「見ていない」と区別が付かない）。

## 対象範囲

| 種別 | 数 |
|---|---|
| `src` の下 | 150 ファイル |
| `test` の下 | 169 ファイル |
| `scripts` | 1 ファイル |
| `package.json`（ルート＋7＋electron） | 9 ファイル |
| `README.md` ほか docs | 実測して置換 |

合計 639 箇所（`.aidev` の 184 ファイルは除く）。

## 振る舞いの詳細

**何も変わらない。** これが受け入れ基準そのもの。

## 受け入れ基準との対応

| 完了条件 | 満たし方 |
|---|---|
| `@ts5250` が消えている | 方針 1（語で置換）＋ 走査で確認 |
| build / lint / test が通る | 方針 2（lock を作り直す） |
| 依存の検査が空振りしていない | 方針 4（わざと落とす） |
| `.aidev` が変更されていない | 方針 1 の除外 ＋ `git diff --stat` で確認 |
| 利用者に見える名前 | 方針 3 |
