# 計画: `@ts5250` → `@ts5250` の改名

## 実装方針

**機械的な置換 1 回**で本体は終わる。危ないのは「置換の取りこぼし」ではなく
**「取りこぼしたのに緑になる」**こと——依存の向きを見張るテストは正規表現でソースを
走査するので、そこだけ旧名のまま残ると**何も検査しないまま通る**。

だから最後に**わざと違反を入れて落ちることを確認**する。

## 作業順序と依存関係

1. 語 `ts5250` を置換（`.aidev` / `node_modules` / `dist` / lock を除く）
2. `package.json` の name（ルート・7 パッケージ・electron）と Electron の表示名（依存: 1）
3. README ほかドキュメント（依存: 1）
4. `npm install` で `package-lock.json` を作り直す（依存: 2）
5. build / lint / test（依存: 4）
6. **依存の検査が空振りしていないことを確認**——わざと違反を入れて落とす（依存: 5）
7. `.aidev` が変更されていないことを確認（依存: 1）

## リスク / 留意点

- **正規表現リテラル内の `@ts5250\/`**。`@ts5250/` を狙うと残る。**語で置換する。**
- **`package-lock.json` を手で書き換えない**（不整合の元）。`npm install` で作り直す。
- **`.aidev` を巻き込まない**。過去の記録は事実の記録なので変えない。
- `appId` の変更は**既存インストールと別扱い**になる。PR で明示する。
- 置換対象が 639 箇所と広いので、**差分の行数ではなく「振る舞いが変わっていないこと」**で
  レビューする（テストが唯一の門番）。

## テスト方針

- `npm run build` / `npm run lint` / `npm test` が**全数緑**（3,619 件）。
- **依存の向きの検査 5 本が生きていること**を、わざと違反を入れて落ちることで確認する。
- `git diff --stat -- .aidev` が**空**であること。
- ステージ済み差分の秘密走査（従来どおり）。
