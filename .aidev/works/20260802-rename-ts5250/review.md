# レビュー: `@as400web` → `@ts5250` の改名

## ラウンド 1

### 見た観点

要件適合 / 正確性 / 規約適合。差分は 469 ファイルだが、**中身は 1 種類の置換**。

### 確認したこと

- **本当に名前だけか。** コードの追加・削除行を機械で抽出し、
  `as400web` / `ts5250` を含まない行が**1 行も無い**ことを確かめた。
  差分が広いときに「読んで確認した」は成立しないので、**形で示す**。
- **テスト件数が動いていないか。** 3,619 → 3,619。名前の変更で件数が動いたら、
  それ自体が異常（テストが消えた／増えた）。
- **検査が空振りしていないか。** 依存の向きを見張る 5 本はソースを正規表現で走査する。
  スコープ名が変われば**緑のまま何も見ない**状態になりうる。わざと違反を入れて
  3 件落ちることを確認した。**これがこの PR で最も重要な検証。**
- **過去の記録を書き換えていないか。** `.aidev/works/*` は**その時点の事実**なので
  改名の対象外。185 件が巻き込まれていたので全部戻した。
- **秘密の混入。** 陽性対照つきで走査。パスワード 0 / ホスト 0。
  ホスト IP は `screen-export.test.ts` に**以前から入っている**が
  （`20260801-realhost-version-and-pwdlevel` で「既出。新たな露出ではない」と判断済み）、
  今回の差分の追加行には**含まれない**。
- **lock を手で書き換えていないか。** `npm install` で再生成。旧名 0 件。

### 指摘

**must**: なし
**should**: なし

**nit（対応済み）**:
- 一括置換が 1 ファイル（`db-pool.ts`）を取りこぼしていた。置換コマンドは
  **成功したように見えていた**——気づいたのはビルドの失敗。全走査で残り 0 を数える形に変えた。
- `.aidev` の除外フィルタが効かず、過去の記録 185 件を書き換えていた。全件復元。

### 自分の検証手順の欠陥（記録として残す）

**2 つの検査が「緑に見える形で」壊れていた。**

`cd packages/tn5250` した後、cwd が残ったまま検証を流したため:

| 検査 | 実際に見ていたもの | 出た結果 |
|---|---|---|
| `git status --short .aidev` | `packages/tn5250/.aidev`（存在しない） | 空＝「無変更」と誤認 |
| `. ./.env` → 秘密の走査 | `.env` が無く変数が空 | `grep -F ""` が全行一致（18,849 件） |

**前者は嘘の安心を、後者は嘘の警報を出した。** どちらも
**陽性対照**（既知の値を 1 件数える）を入れて初めて検出器の生死が分かった。

この作業に限らず、**走査で「0 件」を根拠にするときは陽性対照を必ず添える**。
0 件は「無い」とも「見ていない」とも読めるため。

### 残した制限（PR 本文にも書く）

- **GitHub のリポジトリ名は変えていない**（`as400-web-emulator` のまま）。
  PR では変えられない設定変更で、外向きの操作になるため**別途確認**。
- **Electron の実ビルドは未確認**（`appId` / `productName` がインストーラに載るか）。
- **`appId` の変更は既存インストールと別扱いになる**（設定と利用者データの置き場が変わる）。
  配布済みのものがあるなら据え置く判断もある。
