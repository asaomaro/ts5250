# 計画: プリンターの常駐

## subtask 分割の判定

**分割しない**。design の段階 1（常駐）と 2（見える化）は
**1 が入らないと 2 に意味が無い**（常駐しないなら一覧に出すものが無い）ので、
単独でデリバリできる切れ目になっていない。実装も 4 ファイル。

## 作業順序と依存関係

1. **T1** `PrinterEntry.resident` と `openPrinter` の判定（依存: なし）
2. **T2** `size` から常駐を除き、`maxResidentPrinters` を足す（依存: T1）
3. **T3** `sweepIdle` で常駐を飛ばす（依存: T1）
4. **T4** `isResident()` と `dispose()` の分岐（依存: T1）
5. **T5** `GET /api/printers`（依存: T1）
6. **T6** 単体テスト（依存: T1〜T5）
7. **T7** 実機で通しの確認（依存: T6）
8. **T8** build / lint / test（依存: 全部）

## リスク / 留意点

- **信頼境界を緩めない**。常駐の条件を `output` の有無にしているので、
  新しい判定軸を足さない限りずれない
- **切れなくなるものを作らない**。`close()` の経路は残す（明示停止）
- **常駐が表示の枠を食わない**ことを必ずテストで固定する（食うと
  「帳票を待たせておくと画面が開けない」という説明しにくい失敗になる）
- **一覧に信頼設定の中身を出さない**。警告文にはパスが載りうるので所有で絞る
- 実機の確認では**装置は借りるだけ**（作らない・消さない）。
  ライターは止め、スプールは消す

## テスト方針

- **単体**: 常駐の条件（出力設定の有無）・アイドル掃除・上限（別枠）・
  一覧の中身（信頼設定を出さない・所有で絞る・新しい順）
- **実機**: 出力設定つきで開く → **購読を外す（ブラウザを閉じた状態）** →
  スプールを流す → **帳票を受信** → **PDF が保存される** → 未読が残る
- 既存の対話型プリンターの挙動が変わらないこと
