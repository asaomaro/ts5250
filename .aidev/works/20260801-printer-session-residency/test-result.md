## 実機で踏んだこと

- **ライターは自動では上がらない。** プリンターセッションを繋いだだけではスプールが
  `READY` のまま溜まる。`STRPRTWTR` が要る
- **前の実行の残骸が装置を掴む。** 古いライターが生きていると、新しいセッションには
  何も届かない（3 回連続で「受信 0 件」になった原因）。
  スクリプトは**開始時に `ENDWTR` ＋ `CLROUTQ`** してから繋ぐ
- **用紙タイプをずらすと MSGW で止まる**（そちらを狙うのは `research-msgw.mjs`）。
  常駐の確認では素通しさせる

## 未検証の穴

- **ブラウザからの通し確認はしていない**。WS の切断・再接続は
  `dispose()` の分岐と単体テストまで。**画面で「開き直したら未読が見える」ところは未確認**
- **プロセス再起動をまたぐ復元は無い**（requirement の対象外）。
  サーバーを再起動すると常駐は消える。設定から起動し直す仕組みは別の話
- **一覧 API を画面から使っていない**。口を作っただけで、UI は無い
- **常駐が長時間（数時間〜数日）保つか**は測っていない。
  `20260723-dtaq-watch-notify` で 45 分のアイドルは越えられることが分かっているが、
  プリンターで同じ確認はしていない
- **出力の失敗（PDF 保存先が消えた等）が常駐中に起きたときの見え方**は実機で作っていない。
  警告は溜まり一覧に出る作りだが、**実際に失敗させてはいない**
- PUB400（7.5）では未確認
