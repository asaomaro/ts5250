# 要件: 自動出力付きプリンターセッションを常駐化する

## 背景 / 課題

backlog `hostserver.md` の最後の大物。

**プリンターセッションは「設定が仕事をする」サービス型**なのに、いまは対話型と同じ寿命で動く:

- **WS が切れると切断される**（`ws-handler.ts:513` の `dispose()` が `sessions.close()` を呼ぶ）
- **アイドル掃除の対象**（`session-manager.ts:845-850`）
- **上限 8 の枠を表示セッションと取り合う**（`size` は両者の合計）

つまり**ブラウザを閉じると帳票が届かなくなる**。`autoPdfDir` / `autoPrint` を設定して
「勝手に PDF が溜まる」ことを期待する使い方が成立しない。

`20260723-dtaq-watch-notify` で**常駐の一般形は入っている**（`watch-registry.ts`。
WS から独立し、明示停止かプロセス終了までしか止まらない）。プリンターは
「後から乗せられる形」として `kind` が用意されている。

### backlog が付けた前提条件

> 残る論点: プリンターは**受信したスプールの出力（PDF・印刷）まで常駐で行う**ので、
> 監視より「失敗の見せ方」が重い（出力の失敗は `outputWarnings` に溜まるが、
> **ブラウザが居ないと誰も見ない**）。**通知の置き場を決めてから着手すること**

## 目的 / ゴール

**ブラウザを閉じても、設定されたプリンターが帳票を受け取り、PDF 保存・印刷を続ける。**
そして**失敗が誰にも届かないまま溜まる状態にしない**。

## スコープ

### 対象

- **常駐の条件**: `autoPdfDir` / `autoPrint` を持つ**サーバー設定由来**のプリンターセッション
  （`config-resolver.ts:123` が信頼境界の 5 層目として供給する `printerOutput` がある場合）
- **WS 切断で切らない**（`dispose` の対象から外す）
- **アイドル掃除の対象外**にする
- **上限 8 の枠の扱い**を決める
- **ブラウザを開き直したとき**に、常駐中のセッションと**閉じている間に受信したスプール**を参照できる
- **失敗の見せ方**（前提条件）——通知の置き場を決めて実装する

### 対象外

- **直接接続（ブラウザ指定）のプリンター**。出力設定を受け付けない経路なので常駐させる意味が無い
  （任意パス書込・任意コマンド実行の防止という信頼境界そのもの）
- 表示セッションの寿命（`20260729-session-lifetime-timeout` で整理済み）
- 常駐の**永続化**（プロセス再起動をまたぐ復元）。設定から起動し直す仕組みは別の話
- 外部への通知（メール・OS 通知）

## 機能要件

- 常駐するのは**出力設定を持つサーバー設定由来のプリンターだけ**。それ以外は今までどおり
- **WS が切れても切断しない**。タブを閉じても、利用者がログアウトしても続く
- **アイドル掃除で消えない**
- ブラウザを開き直したら、**常駐中のプリンターが分かり**、**閉じている間に届いた帳票**が読める
- **出力の失敗が、ブラウザが居なくても届く場所に残る**
- **明示停止**の手段がある（止められないサービスを作らない）
- 常駐が上限を食い尽くして**表示セッションが開けなくなる**ことがない

## 非機能要件 / 制約

- **信頼境界を緩めない**。出力設定を受理してよいのは
  「サーバー設定 × canEditProfiles」のルートだけ（AGENTS.md）
- 既存の対話型プリンター（出力設定なし）の挙動を変えない
- `WatchRegistry` の設計原則「**寿命の異なるものを同じ箱に入れない**」と整合させる
- 実機で通しの確認ができること

## 完了条件 (受け入れ基準)

- [ ] 出力設定付きのプリンターが **WS 切断後も生き続ける**（テストで固定）
- [ ] **アイドル掃除で消えない**
- [ ] 出力設定の無いプリンターは**従来どおり WS 切断で切れる**
- [ ] ブラウザを開き直すと**常駐中のプリンターが一覧でき**、**閉じている間の帳票が読める**
- [ ] **出力の失敗がブラウザ不在でも届く場所に残る**（通知の置き場の決定と実装）
- [ ] **明示停止**ができる
- [ ] 常駐が表示セッションの枠を食い潰さない
- [ ] `npm run build` / `npm run lint` / `npm test` が通る
- [ ] 実機で通しの確認（帳票受信 → PDF 保存 → ブラウザを閉じても継続）
- [ ] backlog が更新されている

## 未確定事項 / 確認したいこと

- **常駐をどこに置くか**。`WatchRegistry` に `kind: "printer"` として移すか、
  `SessionManager` に常駐の印を付けるか。**アーキ判断なので design 工程で決める**
- **通知の置き場**（前提条件）。ログ・一覧 API・再接続時の配り直しのどれを、どう組むか
- **上限の扱い**。常駐ぶんを別枠にするか、上限に含めたまま断り方を変えるか
