# 調査: 純 DBCS の DBCLOB（実機）

**実機（IBM i 7.3）**。再現は `scripts/research-pure-dbcs-lob.mjs`。

## F1. ジョブの CCSID から純 DBCS への**直接変換が無い**

```
CAST('日本語' AS VARGRAPHIC(10) CCSID 300)    → SQLCODE=-332 SQLSTATE=57017
CAST('日本語' AS VARGRAPHIC(10) CCSID 16684)  → SQLCODE=-332 SQLSTATE=57017
```

`-332/57017` は「その CCSID 間の変換は無効」。ジョブは 5035（混在）で、
**5035 → 300 / 16684 の変換表が入っていない**。

## F2. **1200（UTF-16）を経由すれば通る**

```
CAST(CAST('日本語' AS VARGRAPHIC(10) CCSID 1200) AS VARGRAPHIC(10) CCSID 300)
  → "日本語"
```

INSERT も同じ二段キャストで通った。**純 DBCS の列を作るときの定石**として記録する
（次に同じことをする人が `-332` で止まらないように）。

なお **16684 は 1200 経由でも通らなかった**ので、検証は **300** で行った。

## F3. 申告長は文字数——UTF-16 と同じ

ロケーター経由の生バイト:

| 値 | 申告長 | 本体 | hex |
|---|---|---|---|
| `日本語`（3 文字） | **3** | 6 バイト | `45 62 45 66 48 e7` |
| `全角混在`（4 文字） | **4** | 8 バイト | `46 b1 47 7d 4b 46 47 cd` |

`isTwoByteCcsid` が純 DBCS を 2 バイト/文字として扱うのは**正しかった**。

## F4. 両経路とも正しい

| 経路 | 結果 |

| ロケーター経由（しきい値 0 ＋ 取得指定） | `"日本語"` / byteLength=6、`"全角混在"` / byteLength=8 |
| インライン（しきい値 65536） | 同上 |

**コード変更は不要。** PR #248 の実装が純 DBCS でも正しいことが確かめられた。
