# 要件: 純 DBCS の DBCLOB を実機で確かめる

## 背景 / 課題

`20260801-dbclob-locator-decode`（PR #248）で、LOB の申告長の単位を CCSID で分けた
（`isTwoByteCcsid` — UTF-16 ∪ 純 DBCS は文字数、それ以外はバイト数）。

だが**実機で測ったのは UTF-16（1200）だけ**。純 DBCS（16684 / 300）も
2 バイト/文字として扱っているが、**その CCSID の DBCLOB 列を作って測ってはいない**
（同 work の「未検証の穴」）。

判定関数の単体テストはあるが、それは**自分の理解を固定しているだけ**で、
ホストが本当にその単位で返す証拠にならない。

## 目的 / ゴール

**純 DBCS の DBCLOB が、ロケーター経由・インラインの両方で正しく返ることを実機で確かめる。**

## スコープ

### 対象

- 純 DBCS の CCSID で DBCLOB 列を作り、全角の値を入れる
- **ロケーター経由**（既定・しきい値 0）と**インライン**（しきい値以下）の両方で検証
- 申告長の単位を生バイトで確認
- 再現スクリプト

### 対象外

- 純 DBCS の GRAPHIC / VARGRAPHIC 列（LOB ではない。既存の経路）
- 16684 と 300 の**両方**を通すこと（片方で単位が確かめられれば足りる）
- コード変更（正しければ不要）

## 完了条件 (受け入れ基準)

- [ ] 純 DBCS の DBCLOB が**ロケーター経由**で正しい文字列と実バイト長で返る
- [ ] **インライン**（しきい値以下）でも同じく正しい
- [ ] 申告長が**文字数**であることを生バイトで確認
- [ ] 再現スクリプトがあり `scripts/README.md` に載っている
- [ ] `npm run build` / `npm run lint` / `npm test` が通る
- [ ] backlog が更新されている
