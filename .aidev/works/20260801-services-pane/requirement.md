# 要件: サービス一覧の画面

## 背景 / 課題

サービスの設定と操作は #258 で画面から出来るようになった。**ただし「そのサービスのタブを
開いている間」だけ**である。

サーバー側サービスは**ブラウザが居なくても動いている**のが要点なのに、いまは

- 何が動いているか**一覧で見られない**（タブを開くしかない）
- **プリンターのタブを開くと WS セッションが増える**——見たいだけなのに繋ぐことになる
- `サービス ✅ ＋ 自動で待ち受け開始 ☐` の定義は**起動直後に何も動いていない**ので、
  タブを開かないと開始ボタンに辿り着けない

一覧の API は #256 で出来ている（`GET /api/printers` / `GET /api/watches`）。**画面が無い。**

## 目的 / ゴール

**サーバー側サービスの現状が 1 画面で分かり、そこから開始・停止できる。**

## スコープ

### 対象

1. **サービス一覧のペイン**（`svc:services`）— プリンターと待ち行列を 1 画面に並べる
2. **一覧を一般ユーザーにも見せる**（利用者の判断: 見るだけは許す・操作は admin）
3. **定義から直接プリンターサービスを開始する口**（`printer-service-start`）——
   いまの `printer-start` は「登録済みのものを開始する」ので、**一度も開いていない定義には効かない**

### 対象外

- 待ち行列のサービス実行内容（コマンド実行等）— 独自の信頼設計が要る
- 定義の追加・編集（設定カードが持っている。一覧からは開かない）
- 定義変更の検知（起動時 1 回だけ。#257 の制約のまま）

## 機能要件

- サーバー設定のサービス定義が**動いていなくても**行として出る（`stopped`）
- 状態（待ち受け中 / 再接続中 / 停止中 / エラー）と受信数が出る
- **admin は開始・停止できる**。一度も開いていない定義も開始できる
- **一般ユーザーは見えるが操作できない**（ボタンを出さない）
- 個人設定のサービスは**所有者にだけ**見える

## 非機能要件 / 制約

- **信頼設定の中身を出さない**。パス（`autoPdfDir`）・プリンター名（`autoPrint`）は
  「持っているか」に畳む。**出力の警告文にはパスが載りうる**ので、警告は編集できる相手にだけ。
- 押しても 403 になるボタンを出さない。
- **タブを開いても WS セッションを増やさない**（一覧は REST、操作だけ WS）。

## 完了条件 (受け入れ基準)

- [ ] 一覧に定義が出る（動いていないものも）
- [ ] admin が一覧から開始・停止できる（**一度も開いていない定義も**）
- [ ] 一般ユーザーには状態が見え、操作ボタンが出ない
- [ ] 警告・エラー理由が一般ユーザーに出ない
- [ ] ビルド（`vue-tsc` 込み）・lint・全テストが通る

## 未確定事項 / 確認したいこと

- **サーバー設定は admin だけが読める**（`assertProfileAccess`）という既存規則を、
  この一覧のためにどこまで緩めるか。利用者の判断は「見るだけは許す」なので、
  **名札と状態だけを返す狭い口**を別に作る（`listSessions` は緩めない）。
