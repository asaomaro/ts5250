# 要件: 帳票の SO/SI を ACS と同じ桁で描く

## 背景 / 課題
- 帳票（SCS）の SO/SI を当 PJ は 0 桁（桁を占めない）で描いている（`20260728-scs-dbcs-column-align` D1。PUB400 の帳票で
  DBCS の行の説明欄が他の行と同じ桁から始まって見えることを根拠にした）。
- ACS は既定で **SO・SI とも 1 桁の空白**として描き、ホストの SPCC（`2B FD .. 03`）で「描かない」「SI だけ 2 桁」に切り替える
  （`PrintSCS5250DB.shiftOut` / `shiftIn` / `setPresentationControlCharacter`）。台帳「【まとめ】SCS の解釈の差」の「SO/SI の桁（要実測）」。

## 目的 / ゴール
- 帳票の DBCS の行が ACS と同じ桁で描かれ、ホストの SPCC の指定にも従う状態。

## ユーザーストーリー
- US1: 日本語の帳票を読む利用者として、ACS で見るのと同じ桁で帳票を見たい。なぜなら、ACS と桁がずれると帳票を突き合わせにくいから。（受け入れ: AC1, AC2）

## スコープ
### 対象
- SO/SI の桁（既定 1 桁ずつ）と SPCC の切り替え。スプールの HTML の印の位置。
### 対象外
- 画面（5250 表示）の SO/SI——こちらは従来から 1 桁ずつ占めている。

## 完了条件 (受け入れ基準)
- [ ] AC1: 既定で SO・SI が 1 桁ずつ空白を占める。SPCC の値 0 / 1 / 2（範囲外は 1）で切り替わり、長さ 2・4 以外は受けない。
- [ ] AC2: スプールの HTML の SO/SI の印が SO/SI の桁に重なり、印の有無で桁が動かない。
- [ ] AC3: 各判定を外すとテストが落ちる（`verify-by-mutation`）。
