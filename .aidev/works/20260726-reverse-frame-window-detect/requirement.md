# 要件: 反転表示で閉じた矩形を窓として判定する

## 背景 / 課題

利用者からの提案:

> Attn のコマンド入力欄もウィンドウ画面判定にできますか？
> 反転表示が途切れなく四角形の枠を構築していればウィンドウ、の条件では？

`detectWindowRect` は現在 2 経路しか持たない。

1. `gui.windows`（拡張5250 の宣言）
2. **罫線文字**の検出（`BORDER_H` = `. - ─ _ …` / `BORDER_V` = `: | │ …`）

Attn の窓は枠が**反転表示の空白セル**で、罫線文字を 1 つも使わないため**判定されない**。
合成スナップショットで確認済み（F1 ヘルプは検出される / Attn の窓は検出されない）。

### 実機で確かめた枠の形（PDM ＋ Attn）

反転セルの分布は**完全に閉じた矩形**だった。

```
行18: 24-78            ← 上端（途切れなし）
行19: 24-24 , 78-78    ← 左右端
行20: 24-24 , 78-78
行21: 24-24 , 78-78
行22: 24-24 , 78-78
行23: 24-78            ← 下端（途切れなし）
```

## 判定できないことで起きている実害

見た目の装飾（ウィンドウ設定の影・浮き出し・枠強調／背景のスモーク等）が効かないだけではない。
`detectWindowRect` は **F キー凡例ボタンの絞り込み**にも使われている（`detectFkeyLegends`）。
コード上のコメントのとおり:

> 窓の外＝下の画面の凡例は、ラベルが切れていたり（`F13= この画`）、押すと**前面の窓の文脈で
> 解釈されてラベルと食い違う**（`F3= 終了` → 実際はヘルプ終了）

Attn の窓が判定されないため、窓が出ている間も**背面（PDM）の F キー凡例がボタンとして並び**、
押すと窓側の文脈で解釈されてラベルと違う動作になる。実機のスクリーンショットでも背面の
`F3= 終了` `F9= コマンドの複写` が切れた状態で残っていた。

## 目的 / ゴール

反転表示が**途切れなく閉じた矩形**を作っていればそれを窓と判定し、装飾と凡例の絞り込みを効かせる。

## スコープ

### 対象

- `detectWindowRect` に**第 3 の経路**（反転表示の閉じた矩形）を足す。
- 既存 2 経路（`gui.windows` / 罫線文字）の判定は**変えない**。第 3 経路は既存が空振りしたときだけ動く。

### 対象外

- 反転以外の属性（下線・カラム分離・色）を枠とみなすこと。
- 窓の中の入力欄・カーソル・送信の扱い。**判定と、それに連動する装飾・凡例の絞り込みだけ**。
- core（`packages/core`）の変更。

## 機能要件

- 次のすべてを満たす矩形を窓と判定する。
  1. ある行に、**途切れない**反転の連なり `[c1..c2]` がある（長さは最小幅以上）
  2. 2 行以上下に、**同じ `c1..c2`** の途切れない反転の連なりがある
  3. その間の**すべての行**で、`c1` と `c2` の両方が反転している
- 複数見つかったら**面積が最大のもの**を採る（既存経路と同じ考え方）。
- **矩形は削らずそのまま返す**。上下端の行は枠ではなく**中身**（タイトル・F キー凡例が載る）で、
  削ると凡例が落ちる。拡張5250 の窓で削らないのと同じ理由。
- 既存 2 経路が矩形を返す場合は従来どおりそちらを優先する。

## 非機能要件 / 制約

- 変更は `packages/web-ui/src/composables/fkeyLegend.ts` に閉じる。
- 走査は 1 画面あたり数千セル程度。既存の罫線検出と同等のコストに収める。
- **誤検出を出さないこと**が最重要。反転は見出し行・メッセージ行・選択行の強調にも使われる。

- [ ] 左右端が 1 行でも途切れていれば**判定されない**ことを確認できる。
- [ ] 罫線文字の窓（F1 ヘルプ）は従来どおり検出され、結果が変わらない。

## 未確定事項 / 確認したいこと

- **上下端の連なりを「完全一致」にするか「大きく重なる」にするか**。罫線文字の経路は端の記号の
  有無で 1〜2 桁ずれるため重なり率 80% で判定している。反転枠は実機で完全一致だったが、
  他の ATNPGM や別の窓で 1 桁ずれる例があるかは未確認。spec で決める。
- **最小幅**をいくらにするか（罫線は 8 桁）。反転の見出しバーを拾わないための下限。
