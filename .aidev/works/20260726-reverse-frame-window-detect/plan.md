# 計画: 反転表示で閉じた矩形を窓として判定する

## 分割判定

**分割しない。** `fkeyLegend.ts` に純関数 2 つ＋分岐 1 つ、テスト 1 本。

## 実装方針

**先に失敗するテストを書く**（実機の反転分布をそのまま合成する）。判定条件は誤検出が怖いので、
**弾ける形のテストを判定できる形と同数以上**用意する。

## 作業順序

1. **T1** 回帰テストを書き、現状で「Attn 窓が判定されない」ことを確認
2. **T2** `reverseRuns` / `detectReverseFrame` を実装し、`detectWindowRect` の第 3 経路に繋ぐ（依存: T1）
3. **T3** 弾く形（上下バーだけ／側面が途切れる／幅不足／上下端の不一致）のテストを足す（依存: T2）
4. **T4** 既存経路（罫線・`gui.windows`）が変わらないことをテストで固定（依存: T2）
5. **T5** 全テスト・ビルド（依存: T2〜T4）
6. **T6** 実機で Attn の窓が判定され凡例が窓側になることを確認（依存: T5）
7. **T7** 実機で反転を多用する画面（SEU・UPDDTA・サブファイル）を回り誤検出が無いことを確認（依存: T5）

## リスク / 留意点

- **誤検出が最大のリスク。** 反転で閉じた矩形が偶然できる画面があれば、その画面の凡例が
  窓の中だけに絞られて**背面のボタンが消える**。T7 の実機巡回を省略しない。
- 上下端の完全一致は厳しめの判断（D2）。他の ATNPGM でずれる例があれば判定されないだけで、
  壊れはしない（従来と同じ「窓なし」に倒れる）。
- 走査コストは最悪 O(行×桁 + 上端候補×行)。反転が無い画面は即 return する。

## テスト方針

- **判定される形**: 実機の Attn 窓（行18-23 / 桁24-78）。
- **弾く形**: 上下バーだけ／側面 1 行欠け／幅 7 桁／上下端の桁不一致。
- **既存の維持**: 罫線窓（F1 ヘルプ相当）が従来の内側矩形を返す／`gui.windows` が優先される。
- **実機**: Attn 窓で凡例が窓側になる／反転を多用する画面で誤検出しない。
