# 調査: ACS の ROLL

## 判明した事実
- F1（原典）: `PS5250.processRoll` は行を写すだけで、空いた行を消さない。不正（上端 0・下端が画面の外・下端 ≦ 上端・行数 ＞ 下端−上端）なら false を返し、
  `DS5250.processCommand` はセンス・コードを立ててレコードの処理を打ち切る。行数 0 は何もしない。
- F2（実機・社内機・DSM）: 行 1〜24 に "ROW nn" を書いた画面を `QsnRollUp(3,2,20)` / `QsnRollDown(3,2,20)` で送らせた（`dscmd.c` の ROLLTEST）。
  ACS のコア: 上で 2〜17 行に ROW 05〜20、18〜20 行は ROW 18〜20 のまま。下で 5〜20 行に ROW 02〜17、2〜4 行は ROW 02〜04 のまま。
  当 PJ（修正前）: 空いた行が空白。方向と送り先は ACS と一致。
- F3（当 PJ）: `buffer.ts` の `roll` は空いた行に空白を入れ、範囲を超える送りは範囲を消していた。
