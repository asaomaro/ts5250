# レビュー: 開いたタブは閉じるまで生かす

## ラウンド 1

### 見た観点

要件適合 / 正確性 / 規約適合 / 保守性。差分は 14 ファイル（うち新規 2）。

### 確認したこと

- **利用者の指示 3 件がすべて入っている**: タブ切替・メニュー／システム切替・IFS の再読み込み。
- **裏で働き続けるペインを作っていない**——ここが今回いちばん壊しやすい所だった:
  - `WatchPane` は「マウント中ずっと既読」だった。隠れたまま生かすと**未読バッジが
    二度と出ない**。`active` で見えている間だけに絞り、テストで固定。
  - `ServicesPane` は `setInterval` で一覧を取り直している。同じく `active` で開閉。
  - 他 7 つは `onMounted` に定期処理を持たない（`setInterval` / `addEventListener` を全走査して確認）。
- **後片付けが走るか**: `SqlPane` の `onUnmounted` は結果セット（＝ホストの接続を掴む）を返す。
  `group.tabs` 由来で描いているので、タブを閉じれば必ずアンマウントされる。
  **`<KeepAlive>` を採らなかった理由がこれ**（閉じてもキャッシュに残る）。spec に明記。
- **種類の追加漏れ**: 接頭辞→ペインの対応表を
  `Record<(typeof PANE_PREFIXES)[number], Component>` にしたので、`paneLabels.ts` に
  足してここを忘れると**型エラー**になる。以前 `list:` の追加漏れで事故った経緯がある。
- **隠れた要素を掴まないか**: `App.vue` のペイン移動は `.admin` を探すが、これは
  `AdminPane` と `SqlPane` の両方が名乗る。包み紙の `data-hidden` で弾くようにした。
  算出スタイルでは判定できない（`display: none` は包み紙側に付く）。
- **画面が壊れていないか**: 実ブラウザで 5250 の寸法を前後で計測（26px / 1044x782 のまま）。
- **秘密の混入**: ステージ済み差分をパスワード・内部 IP で機械走査（陽性対照つき）。0 件。

### 指摘

**must**: なし
**should**: なし

**nit（対応済み）**:
- `<main>` を 2 つ並べて片方を隠す形にしていた → 1 つにまとめた（decisions.md D1）。
- `fit()` に不要なガードを入れていた → 実測で不要と分かり取り消し（decisions.md D3）。

### 残した制限（利用者へ報告する）

- **ペインの最大化をまたぐと状態が消える**（decisions.md D4）。同じ性質の欠陥だが、
  利用者が挙げた 3 つに含まれない。直すには `displayRoot()` の廃止と分割段の描き替えが要る。
  **黙って広げず、報告して判断を仰ぐ。**

## 判定

指摘なし（nit のみ・対応済み）→ deliver へ。
差分は複数コンポーネントに跨るが、変更の中身は「描き方 1 か所＋受け口 9 個」で
処理フローは単純なため walkthrough は挟まない（要点は PR 本文と decisions.md に集約）。
