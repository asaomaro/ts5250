# 計画: 開いたタブは閉じるまで生かす

## 実装方針

先に `active` の受け口（props）を全ペインへ用意し、次に `WorkspaceNode` の描画方式を替える。
逆順にすると、渡した `active` が未知の属性としてルート要素に漏れた状態で一度動かすことになる。

## 作業順序と依存関係

1. アプリ系ペイン 9 種に `active?: boolean` を宣言（依存: なし）
2. `WatchPane` — 既読は**見えている間だけ**（依存: 1）
3. `ServicesPane` — 定期取得は**見えている間だけ**（依存: 1）
4. `WorkspaceNode` — 接頭辞→ペインの表・遅延マウント・`v-show`（依存: 1）
5. `App.vue` — ペイン移動のフォーカス先から隠れた要素を除く（依存: 4）
6. 回帰テスト（依存: 1-5）
7. build / lint / web-ui スイート（依存: 6）

## リスク / 留意点

- **`v-show` はコンポーネントのルート要素に効く**。ルートが複数ある（フラグメント）ペインが
  あると効かない。`.pane-slot` の包み紙を挟んで、ペインの作りに依存しないようにする。
- **隠れているペインの要素が拾われる**恐れ: `App.vue` のペイン移動は
  `querySelector(".pane, .printer-pane, .admin")` で最初の 1 つを掴む。`.admin` は
  `AdminPane` と `SqlPane` の両方が名乗るので、隠れている方を掴みうる。
  `display: none` の要素を除いてから選ぶ。
- **裏で働き続けるペイン**を作らないこと（`WatchPane` / `ServicesPane`）。ここを外すと
  「未読が出ない」「見ていないのに通信し続ける」という別の不便を生む。
- 各ペインの `onMounted` は**初回だけ**走るようになる。再訪での自動再取得は無くなるが、
  それが今回の目的（自動で取り直すなら状態を保つ意味がない）。

## テスト方針

- `WorkspaceNode` をマウントして**タブを切り替え、入力値が残ること**を見る（本題）。
- **未訪問タブがマウントされていないこと**・**閉じたタブが消えること**を要素の有無で見る。
- `WatchPane` / `ServicesPane` は `active` を切り替えて、既読・定期取得の開閉を見る。
- jsdom は scoped CSS を計算しないので、`v-show` の判定は
  **インライン `style.display`** で見る（`v-show` は要素の style を直接触る）。
