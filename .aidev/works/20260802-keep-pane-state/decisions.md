# 決定記録

## D1: メニュー・システム切替でもワークスペースを外さない（追加指示）

- 背景: 作業中に利用者から「メニュー画面に遷移したり、別のシステムを選択した場合でも、
  残すようにしてください」と追加の指示。`App.vue` はワークスペースを
  `v-if="!showLauncher"` で切っており、**メニューへ寄っただけでペインが丸ごと消えていた**。
  `showLauncher` は「明示的にメニューを開いた」ときだけでなく
  **「選択中システムに見えるタブが無い」ときにも真**になるので、システム切替でも同じことが起きる。
- 決定: `<main>` を **1 つにまとめ**、メニューとワークスペースを `v-show` で出し入れする。
- 理由 / 代替案: `<main>` を 2 つ並べて片方を `v-show` にすると、`display: none` でも
  「文書に main は 1 つ」を崩す。1 つの `<main>` の中で入れ替えれば体裁を保てる。
  見た目の違い（メニューは縦スクロール・ワークスペースは固定）は `main.workspace` の
  クラス付け外しで従来どおり。
- 影響: `.ws-root { height: 100% }` を足して高さの連鎖を保つ。実ブラウザで
  5250 の画面寸法が前後で変わらないことを確認済み（`verify-pane-state.mjs`）。

## D2: IFS に再読み込みボタンを足す（追加指示）

- 背景: 利用者から「IFS には再読み込みのボタンを追加してください」。
- 決定: ヘッダーの先頭に `再読み込み` を置き、`tree.refresh(currentPath)` を呼ぶ。
- 理由 / 代替案: 状態を保つようにしたので、**戻ってきても自動では取り直さない**
  （取り直すなら状態を保つ意味がない）。ホスト側で増えた・消えたものを見る入口が要る。
  `tree.load` ではなく `refresh` なのは、`load` が読み込み済みなら何もしないため
  ——テストでわざと `load` に替えると落ちることを確認した。
  他のペイン（管理・一覧・スプール）は既に同等のボタンを持っており、体裁を合わせた。
- 影響: 居場所も選択も変えない（`openPath` とは別物）。

## D3: `ScreenGrid.fit()` の「大きさ 0 なら測らない」ガードは入れない

- 背景: 隠れている間に `fit()` が走ると `clientWidth === 0` で最小フォント（6px）まで縮み、
  表示に戻った瞬間に一度小さく描くのではないか、と考えて早期 return を入れた。
- 決定: **入れない**（実装したうえで取り消した）。
- 理由 / 代替案: 実ブラウザで測ると、ガードの有無にかかわらず画面寸法は
  26px / 1044x782 のまま変わらなかった（`verify-pane-state.mjs` を両方で実行）。
  ブラウザは描画されていない要素に ResizeObserver を配らないため、そもそも踏まない。
  一方でこのガードは **jsdom の既定フォントを 6px から 14px へ動かす**——1,200 件の
  テストが計算する座標が全部変わる。**要らないと分かっているものにその risk は取らない。**
- 影響: なし（現状維持）。必要になったら実測を添えて入れる。

## D4: ペインの最大化は今回の対象外

- 背景: `workspaceStore.displayRoot()` は最大化中に**そのグループだけ**を返すので、
  `WorkspaceNode` の描く木が丸ごと入れ替わり、**最大化した側も含めて全ペインが作り直される**。
  今回直した 3 つ（タブ切替・メニュー・システム切替）と同じ性質の状態消失が残る。
- 決定: 今回は**直さない**。報告して利用者の判断を仰ぐ。
- 理由 / 代替案: 直すには `App` が常に `root` を描き、`WorkspaceNode` の分割段が
  「最大化したグループを含まない側」を隠す形へ変える必要がある（`displayRoot` の廃止、
  `pane-maximize.test.ts` の書き換え、flex-basis の切替）。利用者が挙げたのは
  タブ切替・メニュー・システム切替の 3 つで、最大化はそこに含まれない。
  黙って広げず、**残した理由を明示して**次の指示を待つ。
- 影響: 最大化を使うと状態が初期化される、という制限が残る（PR 本文と報告に明記）。
