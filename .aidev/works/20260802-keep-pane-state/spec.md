# 仕様: 開いたタブは閉じるまで生かす（表示だけ切り替える）

## 概要

`WorkspaceNode.vue` の `.group-body` を、**アクティブなタブだけを描く**形から
**一度開いたアプリ系タブを全部マウントしたまま、見せる 1 枚だけ表示する**形に変える。

- 描くのは `group.tabs` のうち **一度でもアクティブになったアプリ系タブ**（遅延マウント）。
- 表示の切り替えは **`v-show`**（`display: none`）。DOM もコンポーネントも生き続ける。
- タブが `group.tabs` から消えれば（閉じた・別グループへ移した）**自動でアンマウント**され、
  `onUnmounted` の後片付けが走る。

## 設計方針

### なぜ `<KeepAlive>` にしないか

`<KeepAlive>` はキャッシュの追い出しを**コンポーネント名**でしか制御できない。
タブを閉じても、そのタブのインスタンスはキャッシュに残ったままになる
——`SqlPane` の `onUnmounted`（結果セットの解放）が走らず、**ホストの接続を掴んだまま**になる。
`:max` で数を絞っても「閉じたのに生きている」は解消しない。

`v-show` 方式なら**生存期間がタブの開閉と一致**する。利用者の頭の中（開いている＝生きている、
閉じた＝消えた）とも一致し、説明が要らない。

### なぜ 5250／プリンターを含めないか

- 状態は既に `sessionsStore` にあり、再マウントしても復元される（利用者も「エミュレータは無事」と言っている）。
- `ScreenGrid` は 1 画面で数千のセルを描く。開いているセッションぶん常時マウントすると、
  **見えていない画面まで snapshot 更新のたびに再描画**する。得るものが無いのに重くなる。

### 「見えているか」をペインへ伝える

マウントされたまま隠れる、という状態が新しく生まれるので、**`active` プロパティ**を渡す。
`tabId` を受けているアプリ系ペイン 9 種すべてに宣言する（宣言しないと未知の属性として
ルート要素に漏れる）。使うのは今のところ 2 つ:

| ペイン | `active` の使い道 |
|---|---|
| `WatchPane` | **見えている間だけ既読にする**。今は「マウント中ずっと既読」なので、隠れたまま生かすと未読バッジが二度と出なくなる |
| `ServicesPane` | **見えている間だけ定期取得する**（`servicesStore` は `setInterval` で回している）。隠れたまま回すのは裏で通信し続けるだけ |

残る 7 つは受け取るだけで使わない——**「隠れていることがあり得る」という契約**を
型として残すために宣言する。

### タブ ID → ペインの対応表

`v-if` / `v-else-if` の 9 連鎖と `activeIsXxx` の 9 computed を、
**接頭辞 → コンポーネントの表**へ畳む。`paneLabels.ts` の `PANE_PREFIXES` と同じ並びを使い、
**表に載っていない接頭辞が増えたら型で気づく**ようにする。

## 対象範囲

- `components/WorkspaceNode.vue` — 描画方式（本体）
- `components/WatchPane.vue` / `components/ServicesPane.vue` — `active` を使う
- `components/{Admin,HostList,Sql,Ifs,Dtaq,Transfer,Spool}Pane.vue` — `active` を宣言するだけ
- `App.vue` — ペイン移動のフォーカス先が**隠れている要素**を掴まないようにする

## インターフェース / データ構造

```ts
// WorkspaceNode.vue
/** 接頭辞 → ペイン。`PANE_PREFIXES` の全項目を必ず埋める（漏れは型エラー） */
const APP_PANES: Record<PanePrefix, Component>;
function appPaneOf(tab: string): Component | undefined;

/** このグループで一度でもアクティブになったタブ（遅延マウントの記録） */
const opened = reactive(new Set<string>());
/** いまマウントしておくアプリ系タブ（閉じたものは group.tabs から消えるので自然に落ちる） */
const liveTabs = computed<string[]>(...);
```

各アプリ系ペインの props に `active?: boolean` を足す（既定は未指定＝`undefined`。
`WatchPane` / `ServicesPane` は `=== true` で判定するのではなく `!== false` にはしない
——**明示的に渡す側が 1 か所しかない**ので、素直に真偽で見る）。

## 振る舞いの詳細

- 起動直後: `activeTab` のペインだけがマウントされる。他は `opened` に入っていない。
- タブ切替: 新しいタブが `opened` に入りマウント、前のタブは `v-show` で隠れるだけ。
- 再訪: 何も起きない（マウント済み・状態そのまま）。**自動の再取得はしない**
  ——「戻ったら勝手に問い合わせが飛ぶ」は状態保持と相反する。各ペインの再読み込みボタンで足りる。
- タブを閉じる: `group.tabs` から消える → アンマウント → `onUnmounted`。
- 別グループへ移す: 移動元でアンマウント・移動先で新規マウント（現状どおり）。
- システムを切り替える: マウントしたままにする。各ペインは既に
  `systemsStore.selected` を watch して自分の中身を捨てる／暖め直す実装を持っている。

## エラー処理 / 異常系

- 表に無い接頭辞のタブ（将来の追加漏れ）: `appPaneOf` が `undefined` を返し、
  従来どおり 5250／プリンターの分岐へ落ちる。**黙って空白にはしない**（型で先に気づく）。

## 受け入れ基準との対応

| 完了条件 | 満たし方 |
|---|---|
| SQL の入力が残る | `v-show` 方式（テスト: 入力 → 切替 → 戻ると値が残る） |
| IFS の居場所が残る | 同上（テスト: マウント数と `v-show` の状態で確認） |
| 未訪問タブはマウントしない | `opened` による遅延マウント（テスト: 未訪問タブのルート要素が無い） |
| 閉じたら後片付け | `group.tabs` 由来なので自然にアンマウント（テスト: 閉じるとルート要素が消える） |
| 隠れている間は未読のまま | `WatchPane` が `active` で判定（テスト） |
| 隠れている間は定期取得しない | `ServicesPane` が `active` で開閉（テスト） |
