# 計画: メッセージ待ち行列

## 実装方針

**危ういところから。** CL へ渡す値の検査を先に書き、そこに載せる形で 4 操作を実装する。

## 作業順序と依存関係

1. 名前・本文の検査（CL 差し込みを塞ぐ）（依存: なし）
2. REST 4 本（依存: 1）
3. MCP 4 つ（依存: 1）
4. web-ui のペイン（依存: 2）
5. 実機で往復（依存: 2,3,4）

## リスク / 留意点

- **CL への差し込み**が最大のリスク → 1 で塞ぎ、検査で固定する
- **実機を荒らさない**——`QSYSOPR` を使わず、専用の待ち行列を作って消す
- 既存 3,995 件を壊さない

## テスト方針

- `host-message` の検査（新規）— **名前と本文の拒否**（差し込みを試す）
- SQL の組み立て（列の明示・CAST・`onlyInquiry`）
- 実機 — 作成 → 送信 → 一覧 → 応答 → 削除 → 後片付け
