# 決定記録

## D1: `.gitattributes` は `eol=lf` で**全体**に掛ける（個別指定にしない）

- 背景: Windows チェックアウト（`core.autocrlf=true`）で `.rs` / `Cargo.toml` が CRLF になり、
  同梱 DLL の鮮度検査（sha256 の突き合わせ）が「中身は同じなのに古い」と誤判定していた。
- 決定: `* text=auto eol=lf`。指紋の対象（`crates/hllapi/**`）だけに掛ける案は採らない。
- 理由 / 代替案: 指紋を取る場所は**これから増える**（バイト単位の検査はこのリポジトリの
  作法として何度も出てくる）。掛ける場所を都度足す運用は「足し忘れたときに黙って壊れる」。
  もう 1 つの案（指紋の計算で改行を正規化する）は、`prebuilt-manifest.py` と
  `prebuilt-fresh.test.ts` の**両方を同時に**変えないと検査が意味を失うので、より危うい。
- 影響: Windows の作業ツリーが LF になる（Linux は変化なし）。
  `git status` は clean のまま——**登録内容は変えていない**。
  `.bat` も LF だが cmd.exe はそのまま実行できる（既存の `start.bat` が LF で通っている）。

## D2: 原典の `.ucm` は `-text` で変換の対象外にする

- 背景: `tools/gen-tables/ucm/*.ucm` は Unicode.org 由来の ICU マッピング表で、
  **3 ファイルが CRLF で登録済み**（残り 2 ファイルは LF）。
- 決定: `-text` で一切変換しない。登録されているバイトをそのまま保つ。
- 理由 / 代替案: 全部 LF に揃える案もあったが、**原典と同じバイトである**ことが
  生成物の裏取りの根拠になっている。`-text` を入れずに `--renormalize` を掛けたら
  実際に 2 ファイルが差分として上がったので、除外の書き方はそこで直した。
- 影響: `.ucm` は OS によらず登録どおり（混在も登録どおり）。

## D3: `ebcdic` のガードは **skip にせず直す**

- 背景: 相対パスの区切りが Windows では `\` になり、`startsWith("tables/")` が
  常に false ——**表に到達していてもガードが通ってしまう**（fail-open）。
- 決定: パスを `/` に正規化して**直す**。`skipIf(win32)` にはしない。
- 理由 / 代替案: 飛ばすと Windows では永久にガードが働かない。しかもこのガードが守るのは
  「web-ui の本番バンドルに 600 KB の DBCS 表が混ざらないこと」で、
  **壊れても型検査もテストもビルドも通る**種類の退行（テスト自身のコメントがそう書いている）。
- 影響: Windows でもガードが効くようになった。**対照のテスト（「検査が実際に効いている」）が
  落ちて気づけた**——対照を書いておいた設計の勝ちなので、コメントにその経緯を残した。

## D4: `print-dest` は suite ごと飛ばす（1 件ずつ飛ばさない）

- 背景: 偽コマンドが `#!/bin/sh`（拡張子なし）で Windows は実行できず、
  6 件のうち **4 件が別の理由でたまたま通り、2 件が落ちていた**。
- 決定: `describe.skipIf(win32)`。
- 理由 / 代替案: 落ちる 2 件だけ飛ばすと、**通っている 4 件が「検証済み」に見えてしまう**
  （実際には偽コマンドが動いていないので何も確かめていない）。
  Windows 用に `.cmd` の偽コマンドを置く案は、`spawn` が Windows で `.cmd` を
  直接起動できない（Node 20 以降の仕様）ため製品コードに手を入れることになり、
  この作業の目的から外れる。
- 影響: Windows では CUPS 経路の 6 件が飛ぶ。Windows の印刷経路は
  `printer-output-windows.test.ts` が見ている（コメントで相互に指した）。

## D5: `python3` だけは「実際に走らせて」判定する

- 背景: `isInstalled` は **ENOENT だけを見る**方針で書かれている（`-h` の扱いが
  コマンドごとに違うため、終了コードで見ると誤判定するという既存の教訓）。
  ところが Windows には `WindowsApps\python3.exe`（アプリ実行エイリアス）が既定で置かれ、
  **起動できるので ENOENT にならない**のに走らせると失敗する。
- 決定: `python3 -c pass` の終了コードで判定する関数を別に置く。`isInstalled` は残す。
- 理由 / 代替案: `isInstalled` を「走らせて 0 か」に変える案は、既存の教訓
  （`-h` が 0 を返さないコマンドがある）を踏み直すことになる。
  **python では `-c pass` が 0 を返すと当てにできる**ので、そこだけ特別扱いする方が安全。
- 影響: Windows では zip の外部検証 5 件が skip になる（`unzip` の 4 件は通る）。

## D6: 製品コードは変えない

- 背景: 11 件（＋ 新たに 5 件）が落ちていたが、**すべてテスト側の前提**だった。
- 決定: `packages/*/src` には触らない。変更はテストと `.gitattributes` のみ。
- 理由: 「Windows で赤い」ことを製品の不具合と読み替えると、
  直す必要のない場所を触って退行を持ち込む。落ち方は 1 件ずつ原因まで見て分類した。
- 影響: 差分はテスト 8 ファイル ＋ `.gitattributes` ＋ 記録に収まった。
