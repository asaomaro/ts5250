# 要件: 長さの足りないコマンドに ACS と同じ否定応答（0x10050121）を返す

## 背景 / 課題
`.aidev/backlog/acs-parity.md` の「その場で戻る否定応答の残り」（`20260927-early-return-cc2` から割った）と「【まとめ】DS5250 のうち否定応答の残り」の一部。
ACS は WTD・READ の CC、ROLL の 3 バイト、WRITE ERROR CODE の本体が足りないレコードで 0x10050121 を返してその場で戻る。
当 PJ は読み過ぎの例外になり、`handleRecord` がレコードの結果ごと黙って捨て、応答もしない。

## 目的 / ゴール
長さの足りないコマンドを含むレコードで、否定応答・画面・CC2 が ACS と同じになっている状態（実機で確かめてある）。

## ユーザーストーリー
- US1: 5250 端末の利用者として、ホストが壊れたレコードを送っても ACS と同じくホストに否定応答が返り、先に書かれた画面が残ってほしい。なぜなら応答が無いとホストの次の処理が ACS と変わるから。（受け入れ: AC1, AC2）

## スコープ
### 対象
- WTD（CC 2 バイト）・READ（0x42/0x52/0x82 の CC 2 バイト）・ROLL（3 バイト）・WRITE ERROR CODE（0x21/0x22 の 1 バイト）の長さの検査
### 対象外
- CLEAR UNIT ALTERNATE の引数が無いとき（ACS は長さの検査を通らず読み進める——`n5 > n2` の条件。backlog）
- WTD の中のオーダーの誤り（0x10050122 ほか）・SAVE PARTIAL の持ち越し・READ の CC2（backlog のまま）

## 機能要件
- 上の 4 つで長さが足りなければ 0x10050121 を返し、レコードの残りを読まず、同じレコードの CC2 の警報・メッセージ待ちを効かせない（`20260927-early-return-cc2` の `abortRecord`）。

## 非機能要件 / 制約
- 実機で作った試験プログラムは消す。

## 完了条件 (受け入れ基準)
- [ ] AC1: 実機（DSM）で WTD（CC2）＋長さの足りないコマンドの 1 レコードを 4 通り出させ、ACS のコアと当 PJ の画面・メッセージ待ち・否定応答が同じ
- [ ] AC2: 4 つのコマンドの長さの検査を単体テストで固定する（足りていれば否定応答にしない対照も）
- [ ] AC3: 実機の試験プログラムを消す
