# テスト結果: クライアント側とホスト側のメッセージを同じ形にする

| 検証 | 結果 |
|---|---|
| `npm run build`（`vue-tsc` 込み）／ `npm run lint` | 通過 / エラー 0 |
| web-ui 全体 | 1,264 / 1,265（**残り 1 件は既知のフレーキー**・単独では通る） |
| 実機で撮影 | `{カーソルが保護された区域にあるため入力できません}` |

## 実機で確かめたこと

SO/SI 表示を ON（Ctrl+F3）にして保護域に打鍵し、**印が付き、開始桁が 1 桁目から揃う**ことを
確認した。ACS の `{画面の保護域にカーソルがある。}` と同じ形。

## 新規テスト（4 件）

| 内容 |
|---|
| `{ }` 表示のとき、全角の前後に印が付く（`{あ}A`） |
| **印を出さないときも SO/SI の 1 桁は残る**（` あ A`） |
| 半角だけには入れない（`ABC`） |
| 全角で終わるときは末尾にも SI（`A{あ}`） |

**`wrapper.text()` では書けない。** 前後の空白を落とすので、肝心の「1 桁を占める」が
見えない——`textContent` で読む（実際に 1 度踏んだ）。

## 直したテスト（画面表示設定の通知・6 か所）

同じ行に出るので同じ整形が掛かる。**意図した変化**なので新しい見え方に合わせた:

```
画面の質感: CRT   →   画面の質感 : CRT
SO/SI 表示: 表示  →   SO/SI {表示}: {表示}   ← この操作自体が印を ON にするため
```

## 未検証（穴）

- **ホスト側のメッセージ（`systemMessage`）を実機で出していない**（WRITE ERROR CODE を
  意図的に起こしていない）。画面データとして行 24 に入る経路は元から `ScreenGrid` が描くので、
  今回の整形は掛からない（掛ける必要も無い）。
