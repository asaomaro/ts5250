# 仕様: クライアント側とホスト側のメッセージを同じ形にする

## 何が違っていたか

ホスト側のメッセージは**画面データ**（行 24 のセル）なので、SO/SI のセルを持ち、
`ScreenGrid` のセル描画がそれを `{ }`（`showShiftMarks` ON）や空白（OFF）として描く。

クライアント側は JS の文字列をそのまま `.opmsg` に流していたので、**SO/SI が存在せず**、
印も付かず、**先頭の 1 桁ぶんも詰まっていた**。

## 直し方

出す直前に**ホストの行と同じ形へ整える**:

```ts
function withShiftCodes(text: string): string {
  const so = props.showShiftMarks ? "{" : " ";
  const si = props.showShiftMarks ? "}" : " ";
  // 全角の連なりの前後に SO / SI を差し込む
}
```

**SO/SI は印を出さないときも 1 桁を占める**（実機がそうだから）。だから `showShiftMarks` が
OFF でも空白 1 桁を入れる——ここを省くと、ホストの行だけ 1 桁右にずれる。

## 副作用（意図した変化）

画面表示設定の通知（`画面の質感: CRT` など）も同じ行に出るので、同じ整形が掛かる:

```
画面の質感: CRT   →   画面の質感 : CRT
入力項目設定: 下線 →   入力項目設定 :  下線
```

**これは正しい**——実機・ACS でも SO/SI は桁を占める。`SO/SI 表示` を ON にする操作では、
その通知自体に印が付く（`SO/SI {表示}: {表示}`）。

## 受け入れ基準との対応

| 完了条件 | 満たし方 |
|---|---|
| 印が付く | `withShiftCodes`（`showShiftMarks` を見る） |
| 印なしでも 1 桁残る | 同上（空白を入れる） |
| 半角だけには入れない | 全角の連なりを検出したときだけ差し込む |
