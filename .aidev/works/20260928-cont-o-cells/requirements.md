# 要件: 継続欄の O（DBCS open）の編集を ACS と同じセルの並びで行う

## 背景 / 課題
台帳 `acs-parity.md`「継続欄（O）への挿入の余地の数え方が ACS と違う」。O 欄（継続でない）は `20260928-o-field-cells`（#443）で
ACS と同じセルの並び（SO/SI を印で持つ）に揃えたが、**継続した O 欄（FCW 0x86nn の鎖）は従来の論理値のまま**で、
区間ごとに SO/SI を付け直す。ACS は鎖全体を 1 つの欄として扱い、挿入でカーソルから鎖の終わりまでを組み直して区間へ詰め直す
（`PS5250.processCharWithDBCSOpenContField`）。結果、当 PJ は ACS と違う画面・違うバイト列をホストへ送る。

前回の測定（`scripts/acs-probe/cont-o-insert.txt`）は画面の文字だけを見ており、原典の読みと 2 件食い違っていた（B・D）。
2026-09-28 に DSM の CONTOX で**ホストが受け取ったバイト列**を 12 通り測り直し、12 通りとも原典の読みどおりだった（research）。

## 目的 / ゴール
継続した O 欄で打鍵（上書き・挿入）・Delete・Backspace・Erase EOF・Field Exit をしたとき、画面・カーソル・ホストへ送るバイト列が
実機の ACS のコアと同じになっている状態。

## ユーザーストーリー
- US1: 継続した O 欄（DDS の CNTFLD の DBCS 欄など）に日本語を打つ利用者として、ACS と同じ位置に字が入り同じ値がホストへ届いてほしい。
  なぜなら、ACS と違う値が届くとホストのプログラムの結果が変わり、代替として使えないから。（受け入れ: AC1〜AC6）

## スコープ
### 対象
- 継続した O 欄（`dbcsType === "open"` かつ `continued` あり）の、上書き・挿入・Delete・Backspace・Erase EOF・Field Exit・Field+ の打鍵
- core の送信（READ MDT 系）で、区間の境目の SI|SO を詰める（ACS `FFT5250.getFieldContents`）
- ACS が残す「死んだ桁」（DBCSPlane 8）の保持（再配置のときに捨てる桁）

### 対象外
- 語送り（FCW 0x8680 の word wrap）の欄の語送りの段（`processWordWrap`）——DSM の画面が語送りでなく、未測定
- 継続した O 欄への貼り付け・IME の複数字確定の特別扱い（1 字ずつ打鍵と同じ経路へ流すだけ。ACS の原典の貼り付けの節は未分析）
- 空白（0x40）と NUL（0x00）の区別（当 PJ の O 欄の値は両方を半角空白で持つ。ACS は末尾の 0x40 を中身として押し出す——差として台帳に残す）
- J・E 欄（別の作業）

## 機能要件
- 挿入: カーソルから鎖の終わりまでのバイト列を作り直し（死んだ桁は捨てる・隣り合う SI SO を取り除く）、末尾の空きだけを余地として数え、
  区間ごとに詰め直す（並びは区間の終わりで SI で閉じ次の区間で SO から開き直す・SO が区間の最後の 3 桁以内なら並びごと次の区間へ送り、残りを死んだ桁にする）。
  収まらなければ 0012 で値を変えない
- 上書き: 区間の終わりで足りなければ、カーソルの次から区間の終わりを死んだ桁にして次の区間の頭で打ち直す（最終区間は従来のエラー）
- Delete・Backspace: 鎖全体を左へ詰めてから挿入と同じ詰め直しをする。区間の頭の Backspace は前の区間の最後の桁を消す
- Erase EOF・Field Exit・Field+: カーソルから鎖の終わりまで消す（並びの中なら SI で閉じる）
- 送信: 前の区間の最後の桁が SI で次の区間の頭が SO なら両方を落とす

## 非機能要件 / 制約
- ACS の原典（`PS5250` の上記メソッド・`FFT5250.getFieldContents`）は事実だけを持ち帰り、自分の言葉で書く
- O 欄（継続でない）の既存の挙動（#443）を変えない

- [ ] AC2: 上書き（C05）・Delete（C06）・Backspace（C07）・Erase EOF（C08）で同じく一致する（単体）
