# 判断の記録

## D1: 全角は `isCertainWideGlyph` で分岐せず、**すべて 2ch の箱**に入れる

web-ui（`ScreenGrid.vue`）は East Asian Width が Ambiguous な文字（U+2212 `−`・罫線・
ギリシャ等）だけを `width:2ch` の箱に入れ、確実に全角の字はフォントに任せている。
**配布 HTML では同じ手が使えない**——Web フォントを持てないので、開いた環境のフォントが
全角をどう描くかを制御できない。

全部箱に入れれば、必要な前提は「ASCII が等幅」だけになる（`ui-monospace, monospace` で満たせる）。
DOM は全角セル数ぶんしか増えない。**requirement が唯一の技術リスクに挙げていたフォント問題は、
これで構造的に消えた**（外部フォントの埋め込みも不要）。

## D2: `.grid` に padding を置かない

`ScreenGrid.vue` の `.grid` は `padding: 8px 10px` を持ち、絶対配置で重ねる要素すべてに
`margin: 8px 0 0 10px` の補正が要る。**PR #191 でこの補正漏れを 4 か所直した**ばかりで、
「補正を書き忘れたものだけずれる」構造そのものが欠陥の温床になっている。

HTML 側は padding を持たせない。**ずれる余地を最初から作らない**方が、補正を正しく書くより強い。

## D3: 記録は「頼まれたときだけ」（常時記録にしない）

全セッションを常時記録すると、(a) 使いもしない画面のためにメモリを食い続け、
(b) 画面には利用者が打った値がそのまま写るので**秘密が黙って溜まる**。
`start_screen_recording` を明示的に呼ぶまで購読しない。

`Session5250` は既に `screen` イベントを出しており（`ws-handler` も購読済み）、
**新しい通知の仕組みは要らなかった**（`research.md` §2）。流儀は `AuditBuffer` に合わせた。

記録するのは `ScreenSnapshot` と送信 AID キーだけ。**フィールドの入力値は持たない**
（監査ログがフィールド値を記録しない方針と揃える）。

## D4: 画面の中身に `id` を使わない（操作ボタンだけ例外）

requirement の受け入れ基準に「2 枚以上を同じディレクトリに置いても干渉しない」がある。
**画面の描画（セル・罫線・窓・OIA）は `id` を一切使わず**、クラスと `data-*` だけで組む。

**例外はページ全体の操作ボタン**——テーマ切替（`t`）と履歴ナビ（`p` / `n` / `pos`）は
`id` を持ち、JS が `getElementById` で掴む。単票で 1 個、履歴で 4 個。

**この例外が効く範囲**: 生成物は 1 ファイル = 1 ページなので、同じディレクトリに何枚置いても
DOM を共有せず衝突しない（受け入れ基準はこれを指している）。
**ただし 1 つのページに複数の figure を流し込む使い方では衝突する。**
そういう束ね方をするなら、操作ボタンもクラス＋相対探索に変える必要がある
（現状は「ページ単位で分かれる」前提）。

## D5: 履歴版は JS 無効だと全コマが縦に並ぶ

初期状態で `hidden` を付けず、JS の `show(0)` が付ける。つまり **JS を切ると全コマが
そのまま縦に並ぶ**——「1 コマ目しか見えない」より、この方が使える。
読み込み直後に一瞬すべてが見えてから畳まれるが、エビデンスの可読性を優先した。

## D6: 反転に `currentColor` を使わない（review で見つけた欠陥）

`.a-r{background:currentColor;color:var(--crt)}` と書くと、`currentColor` が**同じルールで
上書きした `color`（＝地色）に解決**され、背景と文字が同色になって**反転部分が消える**。

web-ui が `--cell` 変数を経由しているのはこのためだった（`.a-reverse{--cell-bg:var(--cell);…}`）。
同じ形に直し、7 色すべてが `--cell` を持つことをテストで固定した。

**HTML の文字列としては正しく出ているので、目視しないと気付けない類の欠陥**。
だから CSS の形そのものをテストで縛った。
