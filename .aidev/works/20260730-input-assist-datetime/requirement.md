# 要件: 入力支援 UI（datepicker / timepicker / F4=Prompt の導線）

## 背景 / 課題

`.aidev/backlog/input-assist.md` の未着手 5 件。発端は **datepicker / timepicker を出したい**
という要望（2026-07-28）。同ファイルの 2 件（オプション欄のドロップダウン・`inputmode`）は
既に着地しており、残りは:

1. 署名から「日付らしい欄 / 時刻らしい欄」を導く
2. 桁順・区切りをシステム値で解釈する（`QDATFMT` / `QDATSEP` / `QTIMSEP`）
3. `F4=Prompt` の導線
4. `ViewSettings` に項目を足す（`VIEW_ITEMS` は単一の出どころ）
5. 既定は無効（`none` / OFF）にする

**5250 には「この欄は日付です」という宣言が無い。** 判定材料は `EDTMSK` が付いた欄が
**分解されて届く**という痕跡——同一行に連続する数値欄と、その間の保護された 1 桁の区切り文字で、
`2/2/2`（日付らしい）/ `2:2:2`（時刻らしい）/ `3-2-4`（SSN。日付ではない）という署名になる。

**ただしこの署名は合成データストリームで測った値**（backlog 26 行目）で、
**実機で確かめていない**。EDTCDE / EDTWRD については直近の作業（PR #212）で
「用途 B でも書けるが**分解されず**、編集文字が欄の中に入って来る」と実測済みなので、
**`EDTMSK` が本当に分解を起こすのかは未検証の前提**である。

## 目的 / ゴール

**日付・時刻の入力欄にブラウザらしい入力支援（カレンダー・時刻選択）を出す。**
ただし推測に基づく機能なので、**既定は無効**で、**入力補助に留める**
（バリデーション・自動変換はしない）。あわせて `F4=Prompt` の導線を出し、
これらを画面設定から選べるようにする。

## スコープ

### 対象

- 分解された欄の並びから**日付らしい / 時刻らしい**署名を導く純関数
- **システム値（`QDATFMT` / `QDATSEP` / `QTIMSEP`）の取得**と、それによる桁順の解釈
  （`2/2/2` を見ても YMD / MDY / DMY は決まらない。**システムの申告**で解く）
- カレンダー / 時刻の選択 UI（既存のポップオーバー作法に揃える）
- 選択結果を**分解された複数の欄へ**書き込む
- `F4=Prompt` の導線（凡例に `F4=` がある画面で、フォーカス中の欄から F4 を送れる）
- `ViewSettings` / `VIEW_ITEMS` への追加と既定値
- **実機で `EDTMSK` の分解とシステム値の取得を確かめる**

### 対象外

- **`EDTMSK` が付いていない日付欄**（単一 6 桁）。ただの数値欄と区別が付かない。
  取りこぼしは仕様として受け入れる（backlog の「限界」）
- **バリデーション・自動変換**。誤判定と取りこぼしがそのまま実害になるため
  （backlog の「用途で線を引くこと」）
- 数値スピナー（backlog で見送り済み。用途を区別する材料が FFW に無い）
- 拡張 5250 の選択部品・機能キー凡例のボタン化・スクロールバー（実装済み）

### 前提が崩れたときの扱い

**`EDTMSK` が実機で分解を起こさないと分かった場合、datepicker / timepicker は作らない。**
署名が取れないなら判定材料が無く、「6 桁の数値欄をカレンダーにする」は推測でしかない。
その場合は**実測の記録**と `F4=Prompt` / 設定の項目だけを着地させ、backlog に事実を残す。

## 機能要件

1. 同一行の連続する数値欄＋間の 1 桁保護文字から署名を作り、日付 / 時刻 / それ以外を分ける
2. 桁順と区切りはシステム値で解釈する。**取れなければ支援を出さない**（推測で決めない）
3. 支援 UI は**フォーカス中の欄**に対して出る。選ぶと分解された各欄へ値が入る
4. **矩形選択・コピー＆ペースト・キー操作を妨げない**（オプション欄の先例と同じ作法）
5. `F4=Prompt` の導線は、凡例に `F4=` がある画面でだけ出る
6. すべて画面設定から有効/無効を選べる。**既定は無効**
7. 入力値を書き換えるのは利用者が選んだときだけ。ホストが送った値を勝手に整形しない

## 非機能要件 / 制約

- **ホストが送る情報を UI 側で上書きしない／同じ事実の導出元を 2 つ持たない**（リポジトリの原則）
- システム値の取得は**接続ごとに 1 回**に留める（画面ごとに問い合わせない）
- システム値はホストサーバー（SQL）経由。**資格情報はサーバー内に留める**
- 設定の追加は `VIEW_ITEMS` の 1 か所（メニューとキー設定に自動で出る）
- 判定は純関数として切り出し、単体テストで固定する（実機なしで回帰できる形）
