# 決定記録

## D1: datepicker / timepicker は作らない（実機で前提が崩れた）

- 背景: backlog は「`EDTMSK` が付いた欄は**分解されて届く**」を前提に署名
  （`2/2/2` / `2:2:2`）で日付欄を見分ける設計を置いていた。その数値は
  **合成データストリームで測ったもの**（backlog 26 行目に明記）で実機では未検証だった。
- 決定: **作らない。** requirement に「前提が崩れたときの扱い」として先に書いた条件どおり。
- 理由:
  - 実機に 8 通りの DDS を作って実測した結果、**`EDTMSK` はどの綴りでも欄を分解しない**。
    編集文字は**欄の中の値**に入る（`" 0/00/00"`）。PR #212 の `EDTCDE`/`EDTWRD` と同じ形
  - 代替も成立しない（research F4）。とくに「現在値に `/` があるか」は
    **値があるときだけ**効き、`EDTWRD` の 0 は全桁空白で来る＝**新規入力の空欄では材料ゼロ**。
    出たり出なかったりは無いより悪い
  - 作れば「推測を真実として扱う」ことになり、リポジトリの原則
    （ホストが送る情報を UI 側で上書きしない／同じ事実の導出元を 2 つ持たない）に反する
- 影響: 要望（datepicker を出したい）には応えられていない。**やるなら欄ごとのオプトイン**
  ——数値スピナーで backlog 自身が出した結論と同じ形になる。backlog に実測と再現手段を残した。

## D2: システム値の引き方は確かめるが実装しない

- 背景: backlog は「`QSYS2.SYSTEM_VALUE_INFO` から引けるはず（**ビュー名は実機で要確認**）」。
- 決定: **実機で確認だけして、実装はしない。**
- 理由: ビュー名は実在し `QDATFMT=YMD` / `QDATSEP=/` / `QTIMSEP=:` が引けた（research F3）。
  だが D1 で日付欄を見分けられないので**消費する側が無い**。
  使わない配線（サーバー API・キャッシュ）を先に作ると、使われないまま腐る。
- 影響: 事実は backlog と research に残した。将来使うときはここから始められる。

## D3: `F4` は語ではなくキーで判定し、表示はホストのラベルを使う

- 背景: backlog は「凡例に **`F4=Prompt`** がある画面では」と書いている。
- 決定: `key === "F4"` で判定し、ボタンの `title` / `aria-label` には**凡例のラベルをそのまま**入れる。
- 理由 / 代替案:
  - ラベルは地域語で来る（実機は `F4=ﾌﾟﾛﾝﾌﾟﾄ`）。`"Prompt"` を探すと言語ごとに壊れる
  - 「プロンプト」と訳して出す案は、**F4 が別の意味の画面で嘘になる**。
    ホストが書いた語をそのまま見せれば、こちらが意味を決めずに済む
  - `MSG_PROMPT_HINT`（"F4 を送る"）はラベルが空のときだけのフォールバック
- 影響: backlog の項目名（`F4=Prompt`）より広い条件になった（F4 がある画面すべて）。
  意味を名乗らないので広くても嘘にならない。

## D4: 既定は OFF（検出は推測を含まないが、画面に部品を重ねる）

- 背景: backlog の既定の方針は「**推測を含む**機能は既定 OFF。`inputmode` は推測を含まないので
  既定 ON でも筋は通る」。`F4` の検出はホストの凡例＝推測を含まない。
- 決定: それでも **OFF**。
- 理由: backlog の上位の要求は「ここに積んだ機能はすべて画面設定から選べること。
  **勝手に有効化しない**」。`inputmode` が既定 ON でよかったのは**画面に何も足さない**からで、
  こちらは欄の隣にボタンを重ねる。見た目が変わる変更は利用者が選んでから出す。
- 影響: 使うには画面設定で ON にする必要がある（メニューとキー設定の両方に自動で出る）。
