# 判断の記録

## D1: 設定を 3 値（`auto`/`kana`/`latin`）にした——2 値では既定の見た目を保てない

切り替えを対称にすると、`kana: boolean` の 2 値では**どちらの既定も破綻する**。

- 既定を「英」に据え置くと: 930 セッションの既定表示が 1027 再解釈＝**今カナで見えている画面が
  いきなり英字になる**。既存利用者にとっては不具合にしか見えない。
- 既定を「カナ」にすると: 939 セッションの既定表示がカナになる。同じ問題が裏返るだけ。

原因は、2 値が**絶対値（カナ/英）でありながら既定が CCSID をまたいで 1 つしか無い**こと。
そこで「ホストの表のまま」を表す第 3 の値 `auto` を足し、これを既定にした。

```
resolveSbcsView(kana, hostIsKatakana):
  auto  → host                              # どの CCSID でも今までどおり
  kana  → hostIsKatakana ? host : "kana"    # 既にその向きなら再解釈しない
  latin → hostIsKatakana ? "latin" : host
```

**ホストの表と同じ向きを選んだら `host` に倒す**のが要点。再解釈経路を通さないので、
`rawByte` を持たないセル（DBCS・属性桁・オーダーが書いた文字）が巻き込まれない。

ユーザー判断で「既定を CCSID に追従させる」を選択済み（本作業の起票時）。

## D2: `uppercaseInput` は触らない

`EmulatorPane` の `uppercaseInput = isKatakanaCcsid(ccsid)` は、カタカナ系コードページで
**入力**した半角英小文字を大文字化する ACS 準拠の処理。今回の対称化とは軸が違う（表示 vs 入力）
ため、対象外とした。

ただし**組み合わせに未確認の食い違いが残る**: 930 セッションで表示コードを「英」にすると
画面は英小文字で読めるが、そこへ小文字を打つと `uppercaseInput` が大文字化する。
表示と入力で向きが揃わない。

これを直すべきか（表示コードに追従させるか、CCSID 固定のままにするか）は、
**実機 ACS で 930 接続時に表示コードを英へ切り替えたときの入力挙動**を確かめないと決められない。
推測で変えると ACS 準拠が崩れるので、本作業では触らず `review.md` の残課題に送る。

## D3: 設定ラベルを「半角カナ表示」→「表示コード」に変えた

3 値になったことで旧ラベルが成り立たなくなった——「半角カナ表示: 自動」「半角カナ表示: 英」は
日本語として意味を成さない。項目が指しているのは ACS でいう**表示コード**（カナ ⇔ 英小文字の
どちらの SBCS 表で読むか）なので、そのまま呼ぶことにした。

利用者に見える文字列の変更なので、⚙ 画面メニューと OIA の操作員メッセージ
（`ctrl+F1` の通知）に波及する。`view-cycle-ui.test.ts` の期待値を追随させた。

## D4: `latinChar` を `katakana.ts` に同居させた（サブパスを分けない）

`@as400web/ebcdic/katakana` は「バンドルに DBCS 表を持ち込まないための狭い入口」であり、
その役割は**表示コード切替に必要な SBCS 表だけを届けること**。930 の表も 939 の表も同じ役割に
属するので、入口を分けずに 1 つのモジュールへ置いた。

- 分けると到達可能性ガード（`katakana-no-dbcs.test.ts`）を 2 本に増やすことになり、
  **片方だけ壊れて気づかない**経路を作る。
- サイズ実測: 入口＋型＋SBCS 2 表で約 12.7 KB。**既存の 16 KB 上限に収まる**ので、
  ガードの閾値を緩める必要が無かった（緩めていたら検査の意味が薄れていた）。

モジュール名は `katakana.ts` のままだが、冒頭の doc に「2 表の往復」であることを明記した。

## D5: 陳腐化したコメントを一括で直した（review ラウンド 1 の指摘）

`katakanaViewActive` → `recodeViewActive` などの改名で、周辺コメントの「カナ表示」「英字」という
言い回しが**片方向を前提としたまま**残っていた。とくに `ScreenGrid.vue:1817` は
**既に存在しない `usesKatakanaCells` を名指し**しており、grep しても何も出ない状態だった。

AGENTS.md の「コメントは意図を書く」「実在するシンボルを参照する」に反するので、
方向に依らない表現（「再解釈表示」「表示コード再解釈」「素の値」）へ揃えた。
ローカル変数 `const kana = recodeViewActive(f)` も `recoded` に改めた。

**本当にカタカナ固有の記述は変えていない**（`uppercaseInput` の説明、
`displayText` の「930 カナ表と 1027 表で未定義バイトの集合が違う」注記、`fieldValidate.ts` の
半角カナ範囲など）。
