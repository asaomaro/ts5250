# 要件: 英カナ表示切り替えを CCSID 対称にする（930 で効かない不具合）

## 背景 / 課題

利用者報告: **CCSID 930 で表示した際、英カナ表示切り替えが機能しない。**

原因は確定済み（実データで検証）。表示切替 `katakanaChar()` は **常に CCSID 930 の SBCS 表
（コードページ 290＝カタカナ）** で生バイトを再解釈する。930 セッションはセッションのコーデック
自体が同じ表なので、**再解釈しても結果が変わらない**。

| byte | 930 SBCS（CP290） | 939 SBCS（CP1027） |
|---|---|---|
| `0x81` | `ｱ` | `a` |
| `0x62` | `a` | `ｲ` |
| `0x91` | `ﾀ` | `j` |

2 つの表は**互いの鏡像**で、切り替えとは「もう一方の表で読み直すこと」に他ならない。

| セッション | 通常表示 | カナ ON | 結果 |
|---|---|---|---|
| **939**（SBCS=1027） | `0x81`→`a` | `katakanaChar` → `ｱ` | ✅ 切り替わる |
| **930**（SBCS=290） | `0x81`→`ｱ` | `katakanaChar` → `ｱ` | ❌ **同じ＝無反応** |

`ibm939-sbcs`（1027 の表）はリポジトリに存在するのに、**表示側で一度も使われていない**。
片方向しか実装されていないのが不具合の本体。

**本作業の直前 PR（#191）とは無関係**の既存不具合。`katakana.ts` の履歴は
`f93917e perf(web-ui): CCSID テーブルを SBCS/DBCS に割り…` のみで、それ以前は `codec.ts` に
同居していた。分割の前後で片方向のままである。

## 目的 / ゴール

英カナ切り替えを **CCSID に対して対称**にする。どのホストコードページでも
「カナで読む」「英で読む」の**両方向**が選べ、かつ **既定の見た目は現状から一切変えない**。

## スコープ

### 対象

- **`latinChar()` の追加**（`@as400web/ebcdic`）: `ibm939Sbcs`（CP1027）で生バイトを再解釈する、
  `katakanaChar()` の対になる関数。
- **表示設定 `kana` の 3 値化**: `boolean` → `"auto" | "kana" | "latin"`（既定 `"auto"`）。
  - `auto`: ホストの表そのまま（＝再解釈しない）。**現状の見た目と完全に一致**。
  - `kana`: SBCS をカタカナで読む。ホストが既にカタカナ系なら `auto` と同じ。
  - `latin`: SBCS を英小文字で読む。ホストが既に英小文字系なら `auto` と同じ。
- **再解釈の対称化**（`ScreenGrid.vue`）。次の 3 経路すべて:
  1. `displayChar()` — 画面セルの描画
  2. `copyCharOf()` — クリップボードへのコピー
  3. `katakanaViewActive()` 系 — 入力欄の表示（`usesKatakanaCells` / `shiftCellsView` /
     フォーカス時の `el.value`）
- **保存済み設定の移行**（`viewSettings.ts` の `migrate()`）: 旧 `kana: true` → `"kana"`、
  `kana: false` → `"auto"`。**移行後も利用者から見た挙動は変わらない**（下記「移行の等価性」）。
- **UI**: 画面設定メニューとキー割り当て（`ctrl+F1` の `view:kana` 順送り）が 3 値を扱えること。
  トグルのラベル幅（`App.vue` の `.tv.kana`）が 3 ラベルでレイアウトシフトしないこと。

### 対象外

- **`uppercaseInput` の挙動**（カタカナ系コードページで英小文字入力を大文字化する）。
  これは**入力側**の ACS 準拠処理で CCSID から決まるものであり、表示の向きとは別軸。
  今回の対称化とは独立した論点なので触らない（`decisions.md` に検討記録を残す）。
- ホストへ**送るバイト**の変更。再解釈はあくまで表示であり、送信値は常に元バイトのまま
  （既存の `katakanaViewActive` が「編集したら再解釈をやめる」で担保している設計を維持する）。
- 930/939 以外の SBCS 表の追加（37・273 等は再解釈の対象コードページを持たない）。
- CCSID の自動判定・折衝の変更。

## 機能要件

1. **930 セッションで切り替えが効く**: `latin` を選ぶと SBCS が英小文字で表示される。
2. **939 セッションで切り替えが効く**（退行させない）: `kana` を選ぶとカタカナで表示される。
3. **`auto` は現状どおり**: どの CCSID でもホストの表のまま表示する。
4. **既定の見た目が変わらない**: 新規利用者も、既に設定を保存している利用者も、
   本変更の前後で画面の見え方が変わらない。
5. **画面・コピー・入力欄で一貫する**: 3 経路が同じ向きで再解釈される
   （画面はカナなのに入力欄は英字、のような食い違いを作らない）。
6. **バンドルを太らせない**: `latinChar` は `ibm939Sbcs` の 256 要素だけに依存し、
   DBCS 表・`codec.ts` へ到達しない（`katakanaChar` と同じ規律）。

## 非機能要件 / 制約

- **`@as400web/ebcdic/katakana` の到達可能性ガードを維持・拡張する**。
  `test/katakana-no-dbcs.test.ts` は「到達するのは 3 ファイルだけ」「合計 16 KB 未満」を
  固定しており、`latinChar` を足すとこの期待値が変わる。**ガードを緩めずに更新する**
  （DBCS 表・合成モジュール・`codec.ts` へ到達しないことは引き続き固定）。
- **`latinChar` の全 256 バイトを焼き付ける**。`katakana.test.ts` が `katakanaChar` に対して
  やっているのと同じ理由——化ける位置が 1 バイトずれても型もビルドもテストも通ってしまう。
- **トグルのレイアウトシフト禁止**（UI-DESIGN.md）。`.tv.kana` の固定幅は
  最長ラベルに合わせる。
- 保存済み設定の移行は `migrate()` に集約する（読み込み経路を増やさない）。
- `packages/web-ui/**` は eslint 対象外のため、web-ui 側の静的検査は `vue-tsc` で担保する。
- web-ui の vitest・vue-tsc は**パッケージ dir から**実行する（AGENTS.md）。

- [ ] `auto` ではどの CCSID でも再解釈されない（`c.char` のまま）。

## 未確定事項 / 確認したいこと

- **実機（ACS）が 930 接続時にどちらの表示コードで始まるか**は未確認。今回は
  「`auto`＝ホストの表のまま」を既定に置くことで**現状の見た目を保証**する方針を採ったので、
  この未確認事項は既定の決定に影響しない（ユーザー判断で確定済み）。
- 930 セッションで `latin` 表示中に小文字を打つと `uppercaseInput` が大文字化する。
  表示と入力で向きが食い違うが、`uppercaseInput` は対象外としたため本作業では変更しない。
  実機挙動を確かめたうえで別途判断する（`decisions.md` に記録）。
