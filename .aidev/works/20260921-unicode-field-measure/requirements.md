# 要件: Unicode の欄がホストから届くかを実機で確かめる

## 背景 / 課題
- 台帳「DS5250 のその他の差」に、「D9/72 で Unicode を申告するようになったので、ホストが Unicode の欄（FCW 0x90xx〜0x93xx。当 PJ は読み飛ばす）を送ってくる余地がある——扱いを確かめる」とある。
  R11 の調査（原典の読み）は、Unicode の欄は WDSF 0x54 の CCSID 版で届くと読んだが、ホストが**申告の無いクライアントにも**送るかは実機でしか決まらない（未確認）。

## 目的 / ゴール
- 当 PJ（Unicode を申告しない）と ACS のコア（既定）に、ホストが Unicode の欄を FCW 0x90xx・WDSF 0x54 で送ってくるかが、実機の生バイトで確定している状態。

## ユーザーストーリー
- US1: 保守者として、Unicode の欄を実装する要否を、推測でなく実機の事実で決めたい。なぜなら、要らない実装は複雑さだけを持ち込むから。（受け入れ: AC1〜AC3）

## スコープ
### 対象
- 社内機に DDS の Unicode の欄（G 型・`CCSID(13488)` / `CCSID(1200)`）を持つ試験画面を作り、当 PJ と ACS のコアで受ける。測ったら片付ける。
### 対象外
- Unicode を申告する実装（申告しない限り要らない）。0x80xx・0x84xx（実例なし）。

## 完了条件 (受け入れ基準)
- [ ] AC1: 試験画面の作り方（DDS・C のレコード入出力）と、当 PJ・ACS のコアで受ける手順が、再実行できる道具として残る。
- [ ] AC2: ホストが送った WTD の生バイトで、FCW と WDSF の有無が確定し、当 PJ と ACS のコアの見え方が並べて記録される。
- [ ] AC3: 台帳の記述が事実に直り、試験オブジェクトが片付いている（CHKOBJ で確認）。
