# 計画: コマンドサーバーの交換属性で「警告」の戻りコードを致命扱いしない

## split 判定
分割しない（受領差分の取り込み。core 2 ファイル＋テスト）。

## 実装方針
**取り込む前に原典を直読して裏を取る**（AGENTS.md「原典を先に確認する」）。
受領差分は他環境での修正であり、こちらで再現できない以上、根拠は原典に求めるほかない。

## 作業順序
1. T1 原典（JTOpen）を取得して該当箇所を直読し、6 件の一致を確認
2. T2 落ちるテストを書く
3. T3 差分を取り込む（datastream / connection）
4. T4 通し確認＋実機で回帰が無いこと

## リスク
| # | リスク | 対応 |
|---|---|---|
| R1 | 受領差分が推測に基づく可能性 | T1 で原典を直読。**一致を確認してから**取り込む |
| R2 | 許容しすぎて本当のエラーを見逃す | 原典が無視する 6 件のみ。未知は従来どおり例外（spec D2） |
| R3 | 英語 NLV がある環境で挙動が変わる | rc=0 の経路は不変。実機で回帰が無いことを実機確認 |

## テスト方針
- 0x0106 / 0x0100 が警告として許容され、後続フィールドが読める
- rc=0 で warning が undefined
- 未知の戻りコード（0x1234）は従来どおり例外
- 実機でコマンドサーバー接続が従来どおり成功する
