# 仕様: コマンドサーバーの交換属性で「警告」の戻りコードを致命扱いしない

## 設計方針

### D1. 警告扱いの戻りコードを表で持ち、原典への参照をコードに残す

```ts
export const EXCHANGE_ATTRIBUTES_WARNING_RC: ReadonlyMap<number, string> = new Map([
  [0x0100, "制限付きユーザー（LMTCPB(*YES)）"],
  [0x0104, "無効な CCSID"],
  [0x0105, "無効な NLV。既定（プライマリ）NLV を使用"],
  [0x0106, "指定した NLV が未インストール。既定（プライマリ）NLV を使用"],
  [0x0107, "製品情報の取得に失敗。NLV を検証できない"],
  [0x0108, "NLV ライブラリをシステムライブラリーリストへ追加できない（CHGSYSLIBL の権限不足の可能性）"]
]);
```

AGENTS.md「各モジュール冒頭に対応する原典のクラス／メソッド名を参照コメントで残す」に従い、
`archived/jtopenlite/com/ibm/jtopenlite/command/CommandConnection.java` を明記する。
**値と意味は事実**（バイト配置・定数）であり創作的表現ではない——日本語の説明文は自前で書く。

### D2. 「表に無い値は従来どおりエラー」＝安全側は変えない

許容するのは**原典が無視している 6 件だけ**。未知の戻りコードは引き続き例外にする。
「とりあえず全部通す」にしないのは、本当のプロトコルエラーを見逃さないため。

### D3. 警告は握りつぶさず `log.warn` に出す

既定 NLV へのフォールバックは**後から挙動の違いとして効きうる**（メッセージの言語等）。
接続は続けるが、運用者が気づける形にする。`CommandServerInfo.warning` で呼び出し側へ渡し、
`CommandConnection.connect` が `log.warn` に出す。

### D4. 送信する NLV の既定（"2924"）は変えない

**原典も既定を送って警告を受ける前提**。ここを変えると、英語 NLV が入っている環境で
挙動が変わってしまう。直すべきは「警告を致命扱いしていたこと」であって、要求内容ではない。

## 受け入れ基準との対応

| 完了条件 | 満たし方 |
|---|---|
| 0x0106 で例外にならず後続フィールドが読める | D1 の表＋判定を `rc !== RC_OK && warning === undefined` に |
| 0x0100 も許容 | D1 の表 |
| rc=0 のとき warning は undefined | `rc === RC_OK ? undefined : …` |
| 未知の戻りコードは例外 | D2 |
| 警告時に log.warn | D3 |
