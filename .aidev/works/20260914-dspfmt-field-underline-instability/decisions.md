# 判断記録

## D1: 実機トレースで確定的な再現に至らなかったため、スコープを「WEA 未実装の
プロトコル欠陥修正」に絞り、AC1/AC2/AC3 の一部を撤去する

- 背景: `research.md` の通り、実機トレース（WRKOBJPDM + F1ヘルプ窓開閉 + PageDown）では
  下線消失・罫線のみ表示を再現できなかった（F5）。また、黄・青緑以外の色での桁区切りの
  実際の送信経路（WEA 経由か否か）も、実機に RPG コンパイル用のソースファイル
  （`QRPGLESRC`）が現在存在せず確認できなかった（F6）。
  一方、コードの読解と2つの独立した参照実装（tn5250j, GNU tn5250）との突き合わせにより、
  **WEA（Write Extended Attribute, `ORDER.WEA = 0x12`）が未実装のため、これが WTD 内に
  現れると同じ WTD 内の以降の全オーダー（フィールド定義・属性設定を含む）が
  丸ごと読み飛ばされる**という、確実に存在するプロトコル上の欠陥を発見した（F7）。
- 判断: この work のスコープを「WEA オーダーを正しく2バイト読み飛ばして処理を継続する」
  修正に絞る。`requirements.md` の AC1（下線の一貫表示）・AC2（色の符号化網羅確認）は
  実機で再現・確証が得られなかったため撤去し、目標を `.aidev/backlog/acs-parity.md` へ
  引き継ぐ。AC3（再現条件の記録）は「再現に至らなかった記録」として research.md に
  既に満たされているため文言を調整のうえ維持する。AC6（WEA 使用有無の確認）は
  「使用しているかは未確認だが、使用された場合の確実な欠陥を修正した」という形に
  文言を調整して維持する。
- 理由 / 代替案:
  - 代替案として「実機に新しく `QRPGLESRC` を作成し、コンパイルして実際の送信バイトを
    確認する」も検討したが、利用者の実機ライブラリ（TESTLIB、実際に日々使われている
    開発ライブラリ）に新しい規約のソースファイルを追加することは、この work の裁量を
    超える判断だと考え見送った。ソースファイルの追加要否は利用者に確認すべき事項であり、
    `.aidev/backlog/acs-parity.md` に次の調査ステップとして残す。
  - 代替案として「再現できなかったので何もしない」も検討したが、F7 で見つけた WEA の
    欠陥はコードの読解だけで確実に存在すると分かる問題であり、直さずに終えるのは
    もったいない。実機で確認できなかった不確実な仮説（色の符号化衝突、窓開閉時の
    境界消失）ではなく、**確実に存在する欠陥**を直すことに軸足を移す方が、
    「推測のみでの修正をしない」という制約にも合致する
    （F7 は「推測」ではなく2つの参照実装との突き合わせによる確認済みの事実）。
- 影響:
  - `requirements.md` の AC1・AC2 を取り消し、目標を `.aidev/backlog/acs-parity.md` へ
    引き継ぐ（実機での再現・確証が取れてから再挑戦する）。
  - AC3・AC4・AC6 の文言を実際に得られた結果に合わせて調整する。AC4 は特に、
    「実機トレースに基づく」という当初の要求を、実際の根拠（コード読解＋参照実装との
    突き合わせ。実機トレースは「WEA が出現しなかった」という別の事実の確認に留まる）に
    合わせて明記する（60 review の要件適合点検で指摘、対応済み）。
  - `packages/tn5250/src/protocol/wtd-applier.ts` に `ORDER.WEA` の `case` を追加する
    （2バイト読み飛ばし、意味的な効果は実装しない）。
  - 実機診断スクリプト（`scripts/diag-dspfmt-underline.mjs`, `scripts/build-colsep-matrix.mjs`）は
    今後の調査（`QRPGLESRC` 整備後の再挑戦）のために保持する。
