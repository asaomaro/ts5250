# 決定記録

## D1: EA を ACS の `eraseToAddress` どおりに処理する（書き始めは行き先の次）

- 背景: research F1・F2（実機で ACS の X は行き先の次、当 PJ は行き先）。
- 決定: 属性タイプごとに後戻り → タイプの順で検査し、0x00・0xFF は消す、DBCS のセッションの 0x05 は受ける（消すものは無い）、その他は 0x1005012D。成功すれば行き先の次へ。
- 破棄した決定: `wtd-applier.ts` の旧コメント「再開アドレスは tn5250 に合わせ target」——原則 1（ACS が正典）により破棄（実機で 1 桁ずれていた）。

## D2: 画面の終わりを越える文字の並びは、並びを書かずにその場で戻る（0x10050121・CC2 を落とす）

- 背景: T1 の点検（書き始めを行き先の次にしたので、EA 24,80 の後ろの文字が画面の外になる）。実機で ACS を測った（research F4）。
- 決定: ESC とオーダー以外の並びの頭で長さを数え、画面の終わりを越えるなら書かずに `abort`（`abortRecord`）。EA だけでなく文字の並び全般（ACS の `writeString` と同じ単位）。
- 既知の差（未確認）: 原典では、越える並びの手前の桁の HostPlane（READ SCREEN・SAVE の応答に出る）と並びの中の属性は書かれている見込み（`addChar` の 1 つ目のループ）——当 PJ は 1 桁も書かない。実測したのは見える文字だけ。
- 未確認: TD（長さは画面の中）が画面の終わりを越える形は測っていない。

## D3: 最後の桁でちょうど終わった書き込みの次は 1 行 1 桁から（EA の後だけは画面の外のまま）

- 背景: review ラウンド 1 の指摘。ACS の `writeString` は書いた後の位置を画面の大きさで割った余りにする。EA（`eraseToAddress`）だけは割らない。
- 実測: 24,78 から XYZ → IC → W の W は 1,1 に書かれ、否定応答なし（EATESTWRAP）。
- 決定: ループの頭で、位置が画面の大きさで EA の直後でなければ 0 に戻す（`eaAtEnd`。SBA で外れる）。D2 の「越える」は、戻した後の位置で数える。
