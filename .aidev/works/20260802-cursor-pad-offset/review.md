# レビュー: カーソルと文字の位置ずれ

## ラウンド 1

### 見た観点

- 要件適合 / 正確性 / 規約適合 / 保守性
- 差分は `ScreenGrid.vue`（scoped CSS 12 か所＋注記）・`fitFont.ts`（注記）・
  `scripts/README.md`（1 行）・新規 2 ファイル（テスト・検証スクリプト）。

### 確認したこと

- **取り残しが無いか**: `margin: 8px 0 0 10px` の残存 0 件。`grid-pad` を直に持つ場所は
  `ScreenGrid.vue` と `fitFont.ts` だけで、他コンポーネントに同種の補正は無い
  （`EmulatorPane.vue` に `margin:` 宣言そのものが無い）。
- **var が届くか**: 12 か所すべて `.grid` の子孫。カスタムプロパティは継承するので届く。
  `Teleport` は使っていない（テストで固定）。
- **`.opmsg` との整合**: あちらは `left/right/bottom` で直接 var を読む形。基準（padding box）は
  同じで、表現が違うだけ。実測でもカーソルとメッセージ行の左端が揃っている。
- **秘密の混入**: ステージ済み差分をパスワード・内部 IP で機械走査（陽性対照つき）。0 件。
  新スクリプトは `process.env.AS400_HOST` を既定値なしで読む。
- **共有機への配慮**: 検証スクリプトは装置名を指定せず（ホストが `QPADEV0001` を割当）、
  画面を読むだけでオブジェクトを作らない。

### 指摘

**must**: なし
**should**: なし

**nit（対応済み）**:
- 注記が「同じ数字が 3 か所」と実態より少なく書いてあり、集約が終わったように読めた
  → 4 系統あることと、今回の取り残しを `fitFont.ts` に書いた。
- 各 CSS 規則に散っていた「padding 分の補正」の重複コメントを 1 か所（`.cursor` の上）へ集約。

### 残す判断

- **フォールバック値を書かない**（`var(--grid-pad-x, 2px)` にしない）。書けば「唯一の定義」が
  もう 1 か所に増え、今回と同じ食い違いの種になる。届かない配置になった場合はテストが落ちる。
- **実機で測ったのはカーソルだけ**。罫線・窓枠・GUI 部品は同一の 1 行を共有しており、
  カーソルが合えば同じ基準で合う。専用 DSPF を用意してまで測る価値は無いと判断した
  （test-result.md の「未検証の穴」に記載）。
