# 計画: 重ねる要素の余白補正を定数に従わせる

## 実装方針

CSS の置換 → 回帰テスト → 実ブラウザ計測、の順。置換が先なのは、テストが「直った状態」を
固定するものだから（先にテストを書いても、落ちる理由が今回の bug と一致しているかは
置換して初めて確かめられる）。

## 作業順序と依存関係

1. `ScreenGrid.vue` の 12 か所を `var(--grid-pad-y) 0 0 var(--grid-pad-x)` に置換（依存: なし）
2. `fitFont.ts` の注記を実態に合わせる（「3 か所」→ 実際の広がりと、margin 補正のこと）（依存: 1）
3. 回帰テスト `grid-overlay-offset.test.ts`（依存: 1）
4. 既存の web-ui スイート・build・lint（依存: 1〜3）
5. 実機で実ブラウザ計測（依存: 4）

## リスク / 留意点

- **カスタムプロパティは `.grid` の子孫でしか読めない。** `.opt-hints` などが将来
  teleport で `.grid` の外へ出ると無音で 0 になる。テストで親子関係を固定する。
- 実機は共有機。装置は作らず、既存の設定で接続して読むだけ（画面を出すだけで
  オブジェクトを作らない）。

## テスト方針

- **jsdom は scoped CSS を計算しない**ので、単体テストでは「ソースに px 直書きが無い」ことと
  「オーバーレイが `.grid` の子である」ことを見る。
- 実際の位置一致は**実ブラウザで測る**（`scripts/verify-cursor-align.mjs`）。
  `.cursor` の `getBoundingClientRect()` と、`.grid` の content box ＋ 実測字幅・行高から
  求めた桁・行のセル矩形を突き合わせる。
