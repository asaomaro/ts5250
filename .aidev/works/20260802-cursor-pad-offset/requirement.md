# 要件: カーソルと文字の位置が合わない（余白を詰めた影響）

## 背景 / 課題

利用者から「エミュレータ画面の余白を変えた影響だと思うが、**カーソル位置と文字の位置が合わなくなった**」
と画像つきで報告があった。

`fix(web-ui): エミュレータ画面の余白を ACS 相当に詰める (#274)` で `.grid` の内側余白を
`8px 10px` → `GRID_PAD_Y/X`（1px / 2px）に変えた。そのとき **`.grid` に絶対配置で重ねている
オーバーレイの補正 `margin: 8px 0 0 10px` を 12 か所そのまま残していた**。

絶対配置の要素は祖先の **padding box** を基準に置かれるため、桁 1・行 1 に合わせるには
padding と同じ量を margin で足す必要がある。padding だけ縮めたので、重ねるものが全部
**右へ 8px・下へ 7px** ずれた。

`fitFont.ts` の注記は「同じ数字が 3 か所」と書いているが、**実際は 15 か所**あった。
数字を 1 か所に集める作業が途中で止まっていた。

## 目的 / ゴール

重ねて描くもの（カーソル・矩形選択・罫線・窓枠・GUI 部品）が、**文字と同じ桁・同じ行に載る**。
かつ、**次に余白を変えても同じずれが起きない**形にする。

## スコープ

### 対象
- `.grid` に絶対配置で重ねる要素の余白補正を、余白の唯一の定義（`GRID_PAD_X` / `GRID_PAD_Y`）に従わせる。
- 同じ食い違いが再発したら落ちる回帰テスト。

### 対象外
- 余白の値そのもの（ACS 相当のまま変えない）。
- 文字の描画（`.grid-row` 等、通常フローの要素）——ずれていない。

## 機能要件

- ブロックカーソルが、指している桁・行のセルにぴったり重なる。
- 矩形選択・ホストの罫線・窓枠・窓見出し・GUI の選択欄／スクロールバー・オプションのボタンと
  リストも、同じ基準で位置が合う。
- 余白の値を変えても、上記が自動的に追従する。

## 非機能要件 / 制約

- 数字を CSS に直書きしない（`fitFont.ts` の定数が唯一の定義）。

## 完了条件 (受け入れ基準)

- [ ] `.grid` 内の絶対配置オーバーレイに、px 直書きの余白補正が 1 つも残っていない。
- [ ] 実ブラウザで、カーソルの矩形が指している桁・行のセル矩形と一致する（誤差 1px 未満）。
- [ ] 直書きが復活したら落ちるテストがある。
