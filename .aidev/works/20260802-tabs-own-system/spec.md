# 仕様: タブがシステムを持つ

## 概要

`systemsStore.selected` が担っていた **2 つの役割を分ける**。

| 役割 | いま | これから |
|---|---|---|
| 要求の宛先 | 全体で 1 つの選択値 | **タブごとのシステム**（`tabSystem`） |
| 表示の絞り込み | 選択中システムのタブだけ出す | **やめる**（全部出す。見分けは色と名前で） |
| メニューの対象 / 新規タブの既定 | 同じ値が兼ねる | ここだけ残す（**追従＋開いた時点で固定**） |

## 調査で判明した前提（設計を軽くする）

**ワークスペースの配置は保存していない。** `workspaceStore` に `localStorage` は無く、
`init()` は毎回まっさらなグループを作る（`viewSettings` / `keybindings` / スキンは保存するが、
タブの配置は保存しない）。利用者の「リロードは維持されなくて構いません」とも一致する。

したがって **タブ ID の形を変えても読み替え（マイグレーション）は要らない**。
requirement の未確定事項 1 はこれで解消。

## 設計方針

### 1. タブ ID にシステムを含める

```
<機能 ID>@<システム ref>      例: sql:query@own:a
```

- 区切りは `@`。機能 ID には既に `:` が入っており（`sql:query`）、
  システム ref にも入る（`own:a`）ため、`:` は使えない。
- `isPaneTab` / `PANE_PREFIXES` の接頭辞判定は**そのまま効く**（先頭は機能 ID のまま）。
- ラベル引き（`PANE_LABELS[id]`）は `@` の手前で引く。
- **セッション系タブ（5250・プリンター）の ID は変えない**。あちらは自分の接続情報を持つ。

`tabSystem` は残す（`@` から読めるが、**セッション系タブの所属**を持つ場所として要る）。
アプリ系は ID から、セッション系は `tabSystem` から引く一本の関数にまとめる。

### 2. 絞り込みをやめる

- `visibleTabs(g, systemRef)` の絞り込みを廃止し、全タブを出す。
- 連動して不要になるもの: `activeTabFor` のシステム引数、`lastActiveBySystem`
  （**システムを切り替えても表示が変わらない**ので、切替後に戻す先を覚える必要が無い）。
- `App` の `hasVisibleTabs` / `visibleTabCount` は「開いている全タブ」の意味になる。

### 3. ペインを自分のタブのシステムに束ねる

アプリ系ペイン 6 種（SQL / IFS / 一覧 / スプール / データ待ち行列 / データ転送）から
`systemsStore.selected` の参照を**全部外し**、`tabId` から引いたシステムを使う。

- `PanePool` は既に `tabId` を渡している。**同じ経路でシステム ref も渡す**
  ——ペイン側が自分で引くと、引き方が 6 か所に散る。
- 各ペインが持つ「システムが変わったら中身を捨てる」`watch` は**不要になる**
  （タブのシステムは生涯変わらない）。**捨てるのではなく、そもそも変わらない**。

**開き直しでシステムを付け替えない。** `LauncherPane.openFeature` の `assignSystem` 呼び出しを
やめ、`<機能>@<対象システム>` のタブが既にあれば前面に出す／無ければ作る、にする。
`開く` / `表示` の判定も (機能, システム) の組で行う。

### 4. メニューの対象

- **フォーカス中タブのシステムに追従**する。システムを持たないタブ（サービス一覧・管理）の
  ときは直前の対象を維持。タブが無い／未選択なら従来どおりシステム選択画面。
- **メニューを開いた時点で対象を固定する**（利用者の判断）。開いている間にフォーカスが
  変わっても対象は動かない——押した先が意図と違うシステムになるのを防ぐ。
- パンくず第 1 段から明示切替。**切り替えても既存タブは消えない**。
- メニュー内の作成系ボタンに対象システム名を入れる（`＋ A にセッションを追加`）。

`systemsStore.selected` は意味が変わるので **`menuSystem` に改名**する。
「選択中システム」という名前のまま意味だけ変えると、絞り込みの記憶が残って読み違える。

### 5. システムカラー

- 保存する値は**パレットの番号**（`color?: number`。1〜8。未設定＝自動）。
- 色の実体は**テーマ側の CSS 変数**（`--sys-1` … `--sys-8`）。通常／ダーク・各スキンで
  それぞれ定義する。**設定ファイルに生の色を入れない**（テーマを変えるたびに直す羽目になる）。
- **未設定は自動**——システム ref のハッシュから番号を決める。登録しただけで区別が付く。
- パレットに**赤と黄は入れない**。このアプリでは赤＝エラー・黄＝注意なので、
  印としての意味が濁る。
- 出す場所は 3 か所だけ:

| 場所 | 出し方 |
|---|---|
| タブ | 左端の細い**色帯** |
| ヘッダーのシステム名（パンくず第 1 段） | 名前の前に小さな**点** |
| メニュー（システムカード・`<名前> のセッション` の見出し） | 同じく**点** |

- **文字は着色しない**。パレット色は全テーマで文字色としてのコントラストを保証できず、
  タブの文字色は既にアクティブ／非アクティブを表しているため。
- **エミュレータ画面（`.grid`）の中には一切入れない。**

### 6. タブのシステム名

- 設定「タブにシステム名を出す」（既定 ON）。
- ON でも、**ワークスペース全体で 2 システム以上のタブが開いているときだけ**出す。
  1 システムなら今と同じ見た目。
- 範囲をワークスペース全体にするのは、ペイン単位だと**タブを移しただけでラベルが
  伸び縮みする**ため。
- **色だけに頼らない**（色覚特性）。名前が本体・色は補助。
- 設定の置き場所は**別作業 B（`外観` メニュー）**。本作業では既定 ON の挙動だけ入れ、
  トグルは B で足す。

### 7. 取り違えの防止

破壊的な操作の確認文言に**対象システム名を文字で**入れる
（ジョブの保留／解放／終了・IFS の削除・スプールの削除ほか）。

## 対象範囲

| 層 | ファイル |
|---|---|
| サーバー | システムのスキーマに `color`／`PublicSystem`／`publicSystem()` の白名簿 |
| 設定 UI | `ConfigCard`（kind=system）に色の選択、`SystemForm` |
| ストア | `stores/workspace.ts`（絞り込み撤去・ID）、`stores/systems.ts`（`menuSystem`・色） |
| ペイン | アプリ系 6 種（`systemsStore.selected` 撤去）、`PanePool`（システム ref を渡す） |
| 画面 | `PaneTabs`（色帯・システム名）、`App`（パンくずの点）、`LauncherPane`（対象の固定・点・作成ボタンの文言） |
| テーマ | `styles.css` に `--sys-*` をテーマごとに定義 |

## インターフェース / データ構造（要点）

```ts
// server: システム設定
color?: number;                    // 1..8。未設定＝自動
// PublicSystem にも同じ形で出す（白名簿に 1 項目だけ足す）

// web-ui
systemsStore.menuSystem: string | undefined;   // 旧 selected
function systemOfTab(tab: string): string | undefined;  // アプリ系は ID から、セッション系は tabSystem から
function systemColorIndex(ref: string): number;         // 設定値 ?? ref から自動
```

## 振る舞いの詳細

- `A のメニュー → SQL を開く` と `B のメニュー → SQL を開く` は**別のタブ**。
- システムを切り替えても**タブは 1 枚も消えない／増えない**。
- 1 システムしか開いていない間は、タブにシステム名が出ない（今と同じ見た目）。
- ペインの要求は**自分のタブのシステム**にしか飛ばない。

## エラー処理 / 異常系

- タブのシステムが**設定から消えた**（システムを削除した）場合:
  そのタブは操作できない状態で残し、**理由を出す**（黙って別システムへ飛ばさない）。
  既存の `closeSession` 相当の掃除に載せるかは design で決める。
- パレット番号が範囲外／未知: 自動（ref から導出）に倒す。

## 受け入れ基準との対応

| 完了条件 | 満たし方 |
|---|---|
| A と B の SQL を同時に開ける | 方針 1（ID にシステム）＋ 3（開き直しで付け替えない） |
| 要求がそのタブのシステムへ飛ぶ | 方針 3（`selected` 参照の撤去） |
| 切り替えてもタブが消えない | 方針 2（絞り込み撤去） |
| 未設定でも色が付く | 方針 5（ref から自動） |
| 2 システム以上のときだけ名前 | 方針 6 |
| メニューの対象が追従＋明示切替 | 方針 4 |
| 開き直しで付け替わらない | 方針 3 |
| 確認文言にシステム名 | 方針 7 |
| 画面の中に色が入らない | 方針 5（出す場所を 3 か所に限定） |
