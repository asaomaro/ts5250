# 要件: 異なるシステムのタブを並べて同時に見る（タブがシステムを持つ）

## 背景 / 課題

> 異なるシステムのタブを並べて同時に見たいケースに対応する

いまは `systemsStore.selected` が**アプリ全体で 1 つ**あり、2 つの役割を兼ねている。

1. **表示の絞り込み**——選択中システムのタブだけをタブ帯に出す（`visibleTabs`）
2. **要求の宛先**——アプリ系ペインが**要求を出す瞬間に**この値を読む

このため、並べて見ることが**できない**だけでなく、仮に並べても**危険**になる。

| ペイン | `systemsStore.selected` の使い方 |
|---|---|
| SQL / IFS / 一覧（ジョブ・オブジェクト・ユーザー）/ スプール / データ待ち行列 / データ転送 | 送信先のシステムとして読む |

一覧にはジョブの**終了**、IFS には**削除**があり、コード中にも
「誤って別システムのジョブを終了しかねない」という注記が既にある。
**画面に出ているシステムと、要求が飛ぶシステムが一致していない**状態を作ってはいけない。

さらに、アプリ系タブの ID は固定文字列（`sql:query` 等）なので、
**ワークスペースに SQL タブは 1 枚しか存在できない**。A と B の SQL を並べられない。

5250 セッションとプリンターは自分の接続情報を持つので、この問題は無い。

## 目的 / ゴール

**タブは 1 つのシステムへの窓**にする。どのタブを並べても、そのタブが出す要求は
**そのタブのシステム**にしか飛ばない。並んでいるタブがどのシステムのものかは、
見れば分かる。

## スコープ

### 対象
- アプリ系ペインを、**自分のタブのシステム**に束ねる（`systemsStore.selected` 参照の撤去）。
- アプリ系タブ ID を**システム込み**にし、(機能, システム) の組ごとに 1 タブにする。
- `systemsStore.selected` の役割を**「メニューの対象＝新規タブの既定」**に狭める
  （絞り込みをやめる）。メニューの対象は**フォーカス中タブのシステムに追従**し、
  パンくずから明示切替もできる。
- **システムカラー**（システム設定の項目・パレット番号）と、その表示。
- タブへの**システム名表示**（複数システムが開いているときだけ）。
- **破壊的な操作の確認文言に対象システム名を入れる**（ジョブ終了・IFS 削除・スプール削除ほか）。

### 対象外
- **メニューの再編（`外観` / `表示`）と表示設定のカスケード**。別作業（B）で行う。
- 5250 / プリンターの描き方。既に自分の接続情報で動いている。
- リロードをまたぐ永続化の新規追加（既存の保存範囲は変えない）。
- エミュレータ画面（`.grid`）の中の配色。**システムカラーを一切入れない**
  ——画面内の色はホストが意味に使っている（赤＝エラー・黄＝注意）ため。

## 機能要件

### 束ね直し
- アプリ系ペインは**自分のタブに紐づいたシステム**へ要求を出す。
- 既存タブを開き直しても**システムを付け替えない**（今は `assignSystem` が付け替える）。
  付け替えは「実行済みの結果が別システムのものに化ける」ことなので行わない。
- `A のメニュー → SQL を開く` と `B のメニュー → SQL を開く` は**別のタブ**になる。
  同じ組が既にあれば前面に出す。

### 見分け
- **システムカラー**をシステム設定に持つ。値は**パレット番号**（生の色ではない）。
  - 未設定でも**システム ref から決定的に色を割り当てる**（登録しただけで区別が付く）。
  - 色を出すのは **タブ / ヘッダーのシステム名 / メニュー（ランチャー）** の 3 か所のみ。
  - **文字を着色せず、色の帯（タブ）・点（ヘッダー・メニュー）で示す**
    ——パレット色は全テーマで文字色としてのコントラストを保証できず、
    タブの文字色は既にアクティブ／非アクティブを表しているため。
- タブに**システム名**を出す。既定は ON で、**ワークスペース全体で 2 システム以上の
  タブが開いているときだけ**出す（1 システムなら今と同じ見た目）。
  - 範囲をワークスペース全体にするのは、ペイン単位だと**タブを移しただけで
    ラベルが伸び縮みする**ため。
- **色だけに頼らない**（色覚特性）。名前が本体・色は補助。

### メニュー（ランチャー）
- 対象システムは**フォーカス中タブのシステムに追従**する。
  - システムを持たないタブ（サービス一覧・管理）のときは**直前の対象を維持**。
  - タブが無い／未選択なら従来どおりシステム選択画面。
- パンくず第 1 段から明示的に切り替えられる（従来どおり）。
  **切り替えても既存タブは消えない**（ここが今との違い）。
- メニュー内の作成系ボタンに対象システム名を入れる（`＋ A にセッションを追加`）。

### 取り違えの防止
- 破壊的な操作の確認文言に**対象システム名を文字で**入れる。

## 非機能要件 / 制約

- システムカラーは**そのシステムの設定として保存**する。認可の規則は**増やさない**
  ——サーバー設定のシステムは `assertProfileAccess` により admin にしか見えないので
  （認証 OFF なら全員が admin 扱い）、**見える人＝編集できる人**であり、
  「見えるが変えられない」は起きない。
- 資格情報の露出面（`publicSystem`）は**白名簿のまま**。色以外の項目を増やさない。
- 追加の依存を入れない。

## 完了条件 (受け入れ基準)

- [ ] A の SQL と B の SQL を**同時に開いて並べられる**。
- [ ] 並べた状態で、各ペインの要求が**そのタブのシステム**へ飛ぶ（別システムに飛ばない）。
- [ ] システムを切り替えても**開いているタブは消えない**。
- [ ] タブがシステムカラーで見分けられる。**未設定のシステムでも**色が付く。
- [ ] 2 システム以上開いているときだけタブにシステム名が出る。1 システムなら出ない。
- [ ] メニューの対象がフォーカス中タブのシステムに追従し、明示切替もできる。
- [ ] 機能タブを開き直しても**システムが付け替わらない**。
- [ ] 破壊的な操作の確認文言に対象システム名が出る。
- [ ] エミュレータ画面の中にシステムカラーが**一切入っていない**。

## 未確定事項 / 確認したいこと

- **既存の配置の読み替え**（保存済みのタブ ID → システム込みの ID）をどう扱うか。
  既存 ID を「今の選択中システムのもの」とみなして移す案を spec で詰める。
- パレットの色数と実際の色。テーマ（通常／ダーク）と各スキンで読めることが条件。
- **メニューの対象がフォーカス中タブに追従する**規則の詰め。とくに
  「メニューを開いている最中にフォーカスが変わったら対象も変わるのか」を spec で決める
  （変わると、押した先が意図と違うシステムになりうる）。
