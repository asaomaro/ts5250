# レビュー: タブがシステムを持つ

## ラウンド 1

### 見た観点

要件適合 / 正確性 / 規約適合 / 保守性。差分は 25 ファイル（うち新規 4）。
サーバー（スキーマ・露出面）・ストア・ペイン 6 種・画面・テーマにまたがる。

### 確認したこと

- **宛先の取り違えが起きないか**——この作業で唯一「間違うと実害が出る」ところ。
  - アプリ系 6 ペインから `systemsStore.selected` を全撤去。**残っていないことをテストで固定**。
  - 引き方は `workspaceStore.systemOf` の 1 か所に閉じ、配るのは `PanePool` だけ。
    ペイン側は受け取るだけ（`props.system`）。
  - 囮つきのテスト（全体の選択を別の値にする）で 6 種すべての送信内容を検査。
  - 実機で**本物の HTTP の body**まで確認（`srv:SYSA` / `srv:SYSB`）。
- **消えたシステムの扱い**: 銘板を出し、`system` を渡さない。**閉じない**——書きかけの
  内容ごと消えるより、止まって理由が出るほうが安全。文言は `MSG_SYSTEM_GONE` の 1 か所。
- **「システムを選んでください」の誤り**: タブは 1 つのシステムへの窓になったので、
  選び直す手立ては無い。促す文言を残すと利用者を無い操作へ誘う。共通定数へ寄せた。
- **旧防御を消したことの妥当性**: 各ペインの「切り替えたら捨てる」は、宛先が全体の値
  だったから必要だった。宛先が動かなくなった以上、捨てるのは**利用者の作業を捨てる**だけ。
  テストも同じ観点で書き換えた（弱くしたのではなく、**強い性質に置き換えた**）。
- **認可**: `color` は資格情報ではない。`publicSystem` は白名簿のままで、色以外を増やしていない。
  サーバー設定のシステムは `assertProfileAccess` により admin にしか見えないので、
  「見えるが変えられない」は起きない（利用者の確認どおり）。
  **色を足しても資格情報が漏れない**ことをサーバー側テストで固定した。
- **エミュレータ画面への非混入**: 色を出すのはタブ・ヘッダー・メニューの 3 か所だけ。
  `.grid` の中には一切入れていない（画面の色はホストが意味に使っているため）。
- **秘密の混入**: ステージ済み差分をパスワード・内部 IP で機械走査（陽性対照つき）。0 件。

### 指摘

**must**: なし
**should**: なし

**nit（対応済み）**:
- `PanePool` の `<style scoped>` が 2 つに割れていた → 1 つにまとめた。
- 検証スクリプトで `.first()` が隠れているペインを掴んでいた → `:not([data-hidden])` で絞った。

### 残した制限（PR 本文にも書く）

- **メニューの再編（`外観` / `表示`）と表示設定のカスケードは別作業（B）。** 本作業では
  タブのシステム名は既定 ON の挙動だけを入れており、トグルは B で足す。
- 実機で確かめた宛先は SQL の経路。他 5 ペインは囮つきの単体テストで担保。
- 色の見え方（テーマ・スキンをまたいだコントラスト）は目視していない。

## 判定

指摘なし（nit のみ・対応済み）→ deliver へ。
判断は design.md に 7 件残してあり、処理フローも図示済みなので walkthrough は挟まない。
