# 要件: WDSF のマイナー構造体の長さ・型・位置の否定応答を ACS と同じにする

## 背景 / 課題
台帳「WDSF の中の否定応答」。構造体の頭の検査・主構造の長さ/区画/矩形の否定応答は `20260927-wdsf-sense`・`20260928-wdsf-negative` で揃えたが、
その内側——選択欄（0x50）・窓（0x51）のマイナー構造体の長さ、罫線（0x60）のマイナー構造体の長さ・型・位置・反復/間隔——はまだ ACS と揃っていない。

## 目的 / ゴール
崩れたマイナー構造体（選択肢文字列・選択肢の属性・メニューバーの区切り・窓の枠・窓の表題/脚注・罫線のマイナー）を持つ WDSF が、
ACS と同じセンス・コードで否定応答になる状態。

## ユーザーストーリー
- US1: DSM・UIM で画面を組むホストのプログラムの作者として、選択欄・窓・罫線のマイナー構造体が崩れていたら ACS と同じセンスで知らされたい。
  なぜなら、当 PJ だけ違うセンス（またはセンス無し）で黙って読み飛ばすと、プログラムの誤りに気づけないから。（受け入れ: AC1）

## スコープ
### 対象
- 0x50 選択肢文字列（0x10・4 バイト未満）・選択肢の属性（0x01・4〜19 バイトの外）・メニューバーの区切り（0x09・selectionType=1 だけ・5〜8 バイトの外）→ 0x10050113
- 0x51 窓の枠（0x01・4〜13 バイトの外）・窓の表題/脚注（0x10・6 バイト以下）→ 0x10050113
- 0x60 罫線のマイナー: 自身の長さが 7〜11 バイトの外 → 0x10050113、型が 0〜7 の外 → 0x10050150、行・桁・横罫・縦罫が画面の外 → 0x10050151、
  反復・間隔（該当する長さ・型のときだけ）が 0 → 0x10050152

### 対象外
- 選択肢の属性の値そのもの（属性番号が扱えるか）・0x54 の CCSID 形（Unicode DS 専用）・0x50/0x51/0x53 の構造体そのものが画面の外（0x10050112。窓の枠の計算が要る）・
  罫線の反復/間隔つきの矩形が画面の外へ出る総延長（型ごとに式が違う）——いずれも台帳に残す

## 完了条件 (受け入れ基準)
- [ ] AC1: 上の対象の崩れたマイナー構造体が、単体テストで ACS のデコンパイル済みコア（原典）どおりのセンスになる。正しいマイナー構造体は通る
