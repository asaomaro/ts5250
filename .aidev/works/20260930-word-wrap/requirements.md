# 要件: 語送りの欄（FCW 0x8680・DDS の WRDWRAP）を ACS と同じに打てる・送れる

紐づく charter ゴール: charter.md なし（`.aidev/backlog/acs-parity.md`「継続した O 欄の残りの差」(b)。利用者の指示で対応不要から再開）

## 背景 / 課題
語送りの欄（複数行にまたがる欄で、行末にかかった語を次の行へ送る。DDS の `WRDWRAP`）は、ACS では打鍵・削除のたびに `PS5250.processWordWrap` が欄を組み直す。
当 PJ は FCW 0x8680 を読み飛ばしており、(1) 打っても語が送られない、(2) 欄の値が「空きの桁（NUL）」と「実空白」を区別できないので、
ホストへ送る欄（`aaa bbbb ` + NUL 2 つ ｜ `cccc dddd`。READ MDT では途中の NUL が 0x40、ALT では 00）が ACS と違う。

## 目的 / ゴール
語送りの欄に打ったとき、画面もホストへ届く欄のバイト列も、実機の ACS と同じになる状態。

## ユーザーストーリー
- US1: 自由記述欄（DDS の WRDWRAP）を使う画面の利用者として、行末で語が切れず次の行へ送られてほしい。なぜなら ACS で使っていた操作感が変わるため。（受け入れ: AC1, AC2, AC3）
- US2: 語送りの欄を読むホストのアプリの開発者として、ACS と同じ欄のバイト列（行の残りの NUL）を受け取りたい。なぜなら行の残りを NUL で判断するアプリがあるため。（受け入れ: AC3, AC4）

## スコープ
### 対象
- core: FCW 0x8680 の印（1 行に収まる欄では立てない）、欄の値が途中の NUL をセンチネルで運ぶ、NUL のセンチネルを空きのセルにする
- web-ui: 打鍵（上書き・挿入）・Backspace・Delete・Delete Word のあとの語送り、空きの桁を NUL で持つ編集モデル

### 対象外
- 貼り付け・IME 確定への語送り（ACS の貼り付けの語送りは未測定。台帳に残す）
- DBCS の欄・非表示の欄・継続欄（ACS は DBCS の欄を対象外にする。ほかは未測定）

## 完了条件 (受け入れ基準)
- [ ] AC1: 語送りの手順（語の頭・詰め物の整理・行ごとの押し出し・収まるときだけ書き換え・カーソル）が、実機の ACS のコアで測った W1〜W8 のバイト列とカーソルに一致する（単体）
- [ ] AC2: 打鍵・Backspace・Delete が語送りの欄で語送りを掛け、掛けない欄（語送りでない・1 行に収まる）では従来どおり（コンポーネント）
- [ ] AC3: 語送りの欄の値は途中の NUL を運び、READ MDT は途中の NUL を 0x40、ALT は 00 で送り、末尾の NUL は送らない（単体）
- [ ] AC4: 当 PJ のブラウザから実機に W1〜W8 を打ち、ホストが受け取った欄が ACS と 8 巡とも一致する（実機）

## 未確定事項 / 確認したいこと
- 貼り付け・IME・非表示の語送りの欄の ACS の挙動は未測定（台帳へ）
