# 要件: READ の無い WRITE ERROR CODE でも施錠を解き、先に押した AID を次の READ で送る

## 背景 / 課題
`.aidev/backlog/acs-parity.md` の「ホストのエラーの保留の残り」のうち「保留の無い WEC だけのレコードでも ACS は施錠を解く（当 PJ は READ まで施錠のまま）」と「ACS で AID がいつ応答扱いになるか」。

## 目的 / ゴール
0x21／0x22 だけのレコード（READ 無し）を受けた後の施錠・打鍵・AID の送り方が ACS と同じになっている状態。

## ユーザーストーリー
- US1: 5250 端末の利用者として、ホストがエラーだけを出して READ を後で出すとき、ACS と同じく Reset で打ち直して Enter を押しておけるようにしたい。なぜなら当 PJ は施錠のまま AID を拒み、ホストの READ が来るまで何もできないから。（受け入れ: AC1, AC2）

## スコープ
### 対象
- core のセッション（施錠を解く・READ が出ていない間の AID を溜めて次の READ で送る）
### 対象外
- 解錠中に届いた WTD がカーソルを動かす差（台帳のキー編集の細部の (f)。この work の実機でも AID のカーソルが 5,10〔ACS は 5,12〕になる）
- 溜めた AID の間も ACS は施錠しない（打鍵を続けられる）。当 PJ は AID の待ち（`sendAid` の約束）を保つため施錠する（台帳に残す）

## 完了条件 (受け入れ基準)
- [ ] AC1: 実機の ACS のコアで、0x21 だけの後の施錠・Reset 後の打鍵・Enter が次の READ に届くことを測り、当 PJ の単体テストで固定する
- [ ] AC2: 実機で当 PJ を当てて、施錠が解け、Enter と欄が次の READ に届く（`scripts/verify-wec-only-unlock.mjs`）
- [ ] AC3: 片付け
