### 直す前（原因）

```
record #2  opcode 03（PUT/GET）: 04 03 00 00 00 00 00
WARN unknown command 0x3 — discarding rest of record
```

**ホストは応答を待っていた**（opcode が PUT/GET）。返さないので次が来ず、
画面はメニューのまま・キーボードは開かない＝「待機中・ホストから応答がない」。

### 直した後

- ホストが即座に `CLEAR_UNIT → WTD … → READ_MDT_FIELDS` を送ってきて
  **「QSH コマンド入力」画面が出る**
- `ls -l /` → 13 行の一覧が読める／`echo A; echo B; echo C` → 出力が流れる
- **`unknown command` の警告が 0 件**になった

### ブラウザ E2E（6/6・スクリーンショットは `/tmp/as400-verify-qsh/shots`）

接続 → メインメニュー → **QSH が起動する** → `ls -l /` の出力が読める →
続けて実行して出力が流れる → **F3 で抜けられる**。

## 空振り検証（mutation）: 11/11

`0x03` を default に戻す／パラメータを消費しない／応答を要求しない／`0x13` を default に戻す／
ROLL を default に戻す／ROLL の方向を反転／行数マスクを外す／応答の先頭を `0x12` にする／
パラメータを写さない／**session が応答を送らない**／roll がフィールドも動かす。

初回は「session が応答を送らない」が空振りした（組み立てのテストしか無かった）。
**実機が送ってきたレコードをセッションに食わせて送信を見るテスト**を足して塞いだ。

## 実機検証で踏んだこと（スクリプト側の学び）

- **装置名が使用中**だと接続できない。前の検証が掴んだままになるので、
  空いている名前を順に試す形にした（`DEV1` を先頭に）。
  掴みっぱなしのジョブはコマンドサーバー経由の `ENDJOB` で片付けた
- **`getByText("F3")` は画面の凡例「F3= 終了」に当たる**（鍵盤のボタンではない）。
  ボタンを指定する形に直した
- 接続の成否を本文の文字で見ると、ランチャーの機能カード（「ユーザー」等）に当たって
  **繋がっていないのに成功と誤判定する**。入力欄の有無と失敗の帯で見るようにした

## 未検証の穴

- **`RESTORE PARTIAL SCREEN`（0x13）と `ROLL`（0x23）は実機で届いていない**（decisions D3）。
  形式は原典の定義に従っているが、動作は確かめていない。backlog に確認方法つきで残した
- **SAVE PARTIAL SCREEN のパラメータの意味は未解明**（実機は全て `00`）
- `0x02` と `0x03` を交ぜて使う画面があると退避スタックの順序が狂いうる（decisions D5）
- `packages/server/test/zip-writer.test.ts` の 4 件は `unzip` が無いため失敗（`main` でも同じ）
