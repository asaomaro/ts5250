# 要件: QSH が「待機中・ホストから応答がない」で固まるのを直す

## 背景 / 課題

エミュレーターで **`QSH`（Qshell）を実行すると待機中のまま**「ホストから応答がない」になる。
利用者の見立ては「必要なバイトを捨てて待機に陥っている」。

実機で確かめたところ、**そのとおりだった**:

```
record #1  opcode 02（OUTPUT ONLY） : 04 11 00 00                 ＝ WTD（副作用なし）
record #2  opcode 03（PUT/GET）     : 04 03 00 00 00 00 00        ＝ **ESC 0x03 ＋ 5 バイト**
WARN unknown command 0x3 — discarding rest of record
```

`ESC 0x03` は **SAVE PARTIAL SCREEN**。`wtd-applier.ts` の `default` 節が
「未知のコマンド → レコードの残りを捨てる」で握りつぶしており、
**ホストが待っている応答を返していない**。opcode が `PUT/GET(0x03)`＝
「送ったから返せ」なので、返さない限りホストは次を送ってこない。

同じ轍は既に 2 回踏んでいる（`SAVE SCREEN` を返さず SEU の F1 ヘルプが出なかった／
`WRITE ERROR CODE TO WINDOW` を未処理で後続の READ ごと捨てた）。

## 目的 / ゴール

- **QSH が起動して使える**（画面が出て、コマンドを打てて、出力が読める）
- 同じ形の取りこぼしを**この機会にまとめて塞ぐ**（QSH が使う他のコマンド）
- 未知のコマンドを捨てたときに**利用者と開発者が気づける**ようにする

## スコープ

### 対象

- `SAVE PARTIAL SCREEN`（`ESC 0x03`）の受理と**応答の送信**
- `RESTORE PARTIAL SCREEN`（`ESC 0x13`）の受理（ホストが保管物を返してくる側）
- `ROLL`（`ESC 0x23`）——**画面のスクロール**。QSH のような行送りの画面で使われる
  （COMMAND 表に値だけあって実装が無い）
- 実機で QSH を起動し、**画面を見て**確かめる

### 対象外

- Qshell の機能そのもの（コマンド補完・履歴など。端末側の仕事ではない）
- 5250 の未実装コマンド全部の網羅（**QSH で実際に来たもの**と、
  同じ族で形式が確定できるものに絞る）

## 機能要件

- `ESC 0x03` を受けたら**パラメータを正しく消費**し、ホストへ応答を返す
- 応答を返したあと、**同じレコードの後続コマンドを捨てない**
- `ESC 0x13` で退避した内容へ戻す（局所の退避スタックを使う。SAVE/RESTORE SCREEN と同じ考え方）
- `ESC 0x23`（ROLL）で指定範囲を指定行数だけ送る
- 未知のコマンドを捨てたことが**ログで分かる**（現状の警告を残す）

## 非機能要件 / 制約

- **推測で実装しない。** 応答の形式は実機の反応で確かめる
  （ホストが先へ進むか＝QSH の画面が出るか、を判定に使う）
- 既存の画面（メニュー・SEU・窓・サブファイル）を壊さない
- 秘密を成果物に書かない

## 完了条件 (受け入れ基準)

- [ ] `ESC 0x03` を受けて応答を返し、**実機で QSH が起動する**（画面を撮る）
- [ ] QSH でコマンドを打って**出力が読める**（行送りが起きる場面を通す）
- [ ] `ESC 0x13` / `ESC 0x23` が来ても捨てずに処理する
- [ ] 既存テストが通る（メニュー・窓・サブファイル・SEU の回帰）
- [ ] 実機で確かめた形式と、確かめられなかったことを記録に残す
- [ ] backlog に結論（または残件）を書く

## 未確定事項 / 確認したいこと

- `ESC 0x03` の**応答の形式**（SAVE SCREEN と同じでよいか／パラメータを含めるか）→ research
- パラメータ 5 バイトの意味（実機は全て `00` だった）→ research
- QSH が `ROLL` を使うか（起動後の出力で確かめる）→ research
