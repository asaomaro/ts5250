# 決定記録

## D1: 応答の形式は**実機の反応**で決めた（推測を積み上げない）

- 背景: `ESC 0x03` の応答形式は手元の資料に無い。原典（SC30-3533）にも当たれない。
- 決定: 既存の `SAVE SCREEN` 応答と同じ直列化に、先頭を `ESC 0x13` にして
  **受け取った 5 バイトを写す**形で送り、**ホストが先へ進むか**で判定した。
  1 回目の試行で QSH の画面が返ってきたので、それを採用した。
- 理由 / 代替案: 形式を何通りか用意して総当たりする準備をしていたが、要らなかった。
  ホストにとってこの中身は**不透明な保管物**（あとで `0x13` としてそのまま返る）なので、
  「受理されるか」以上のことは実機からは分からない——**分かったのはそこまで**、と記録する。
- 影響: `buildSavePartialScreenResponse`。テストは「実機が受理した形」を固定するもので、
  「この形式が唯一正しい」ことは主張していない。

## D2: パラメータ 5 バイトは**解釈しない**

- 背景: 実機は 5 バイトすべて `00`。範囲（上端・左端・深さ・幅）と見られるが確証が無い。
- 決定: 意味を解釈せず、応答へそのまま写す。退避は画面全体で行う。
- 理由 / 代替案: 「部分」の解釈を推測で入れると、外れたときに**画面の一部だけ壊れる**
  （気づきにくい壊れ方になる）。写して返す限り、ホストから見た振る舞いは変わらない。
- 影響: backlog に「パラメータの意味は未解明」を残した。

## D3: `0x13` / `0x23` は**未実測のまま実装する**

- 背景: どちらも QSH の経路では届かなかった（research F4）。
  実装しなければ `default` 節で「レコードの残りごと捨てる」に落ち、同じ種類の固まりを生む。
- 決定: 実装する。ただし **docstring とテストの冒頭に「実機では未確認」と書く**。
  backlog に確認方法つきで項目を起こす。
- 理由 / 代替案: 「届いていないから実装しない」も筋は通るが、
  **落ちる先が「レコードごと捨てる」＝最悪の壊れ方**なので、
  形式が原典で確定しているものは受け止める方が安全側。
  ただし**確かめていないことを確かめたように書かない**のがこの PJ の規律なので、
  実装と検証状況を明確に分けて書いた。
- 影響: `wtd-applier.ts` / `buffer.ts` / `screen-roll.test.ts` の docstring。

## D4: ROLL は**フィールド定義を動かさない**

- 背景: ROLL は表示イメージの行送り。フィールドまで動かすかは選択の余地がある。
- 決定: セルだけ動かす。
- 理由 / 代替案: 動かすと入力欄の位置がホストの認識とずれ、
  次の READ で報告するカーソル位置や MDT の対応が壊れる。
  ホストは ROLL の後に必要なら書き直してくるので、こちらで補う必要が無い。
- 影響: `buffer.roll`。空振り検証のミュータント「roll がフィールドも動かす」で固定した。

## D5: 退避スタックは `0x02`/`0x12` と**共用する**

- 背景: `0x03` は `saveScreen()`、`0x13` は `restoreScreen()` を呼ぶ（同じスタック）。
- 決定: 共用する。
- 理由 / 代替案: 別スタックにする案もあるが、**どちらの順序で来るかを実機で見ていない**。
  見ていないものに構造を足すより、既存の 1 本で素直に積む方が壊れ方が読みやすい。
- 影響: `0x02` と `0x03` を交ぜて使う画面があれば順序が狂いうる（そういう画面は未確認）。
  spec に明記し、backlog の未実測項目と併せて残した。
