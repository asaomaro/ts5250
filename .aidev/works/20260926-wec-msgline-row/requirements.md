# 要件: WRITE ERROR CODE（0x21）のメッセージを SOH が申告したメッセージ行に出す

## 背景 / 課題
ACS は WRITE ERROR CODE（0x21）の本文を、SOH が申告したメッセージ行に書く（原典 `DS5250.processWriteErrorCode`——`20260926-window-error-code` research F1）。
当 PJ は 0x21 の本文を常に**最下行**に重ねる（`packages/web-ui/src/components/ScreenGrid.vue` の `.opmsg`）。メッセージ行を最下行以外に申告する画面では、ACS と違う行に出る。
実機では未測定（0x21 を SOH の行で出す画面の実例が無い）。

## 目的 / ゴール
0x21 が届いたとき、当 PJ がメッセージを ACS と同じ行・桁範囲に出している状態（メッセージ行が最下行でも、申告された別の行でも）。
紐づく charter ゴール: ACS の代替として、同じ操作で同じ結果になること（AGENTS.md「判断の原則」1）。

## ユーザーストーリー
- US1: メッセージ行を最下行以外に置く画面を使う利用者として、エラーメッセージが ACS と同じ行に出てほしい。なぜなら ACS と同じ見た目で、画面の他の行を隠さずに読めるため。（受け入れ: AC1, AC2）
- US2: 開発者として、0x21 の行を実機の ACS で測った記録と、再実行できる手順が欲しい。なぜなら原典の読みだけで合わせず、事実で確かめるため。（受け入れ: AC3, AC4）

## スコープ
### 対象
- 0x21 の本文を出す行と桁範囲（ACS に合わせる）。
- 測定の手段（DSM の試験プログラムの 0x21 のモード・acs-probe の手順・当 PJ の検証スクリプト）。

### 対象外
- エラー状態のままメッセージ行へ WTD・RESTORE SCREEN が来たときの見え方（`20260926-window-error-code` decisions D4 の未確認）——測定で差が見つかれば別項目に割る。
- 0x22（済んでいる）。

## 機能要件
- 0x21 の本文を、SOH が申告したメッセージ行（申告が無ければ既定の行。24×80 では最下行＝24 行と research F2 で確かめた。27×132 の既定は最下行（27）——decisions D5 で原典により確定）の、ACS と同じ桁範囲に出す。
- 本文が 1 行より長いときは、メッセージ行の 1 行ぶんまで出す。**ACS は続きを次の行へ上書きして戻さないが、情報を捨てるので合わせない**（decisions D2。research F3）。
- エラー状態の入り方・抜け方は変えない（0x21 の既存の経路）。

## 非機能要件 / 制約
- ACS の原典は事実の確認に使い、表現は写さない（AGENTS.md「判断の原則」1 の ⚠）。
- 実機で作った試験プログラム・IFS のファイルは測定後に片付ける。
