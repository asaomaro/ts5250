# 計画: 既存セッションへの attach

## 実装方針

**購読の作り替えが本丸。** そこを先に直してから attach の口を開ける。
順序を逆にすると、2 タブになった瞬間に通知が壊れた状態を作ってしまう。

## 作業順序と依存関係

1. 購読リスト（`SessionManager`）と ws-handler の付け替え（依存: なし）
2. `WsOpen.sessionId` と attach 経路（依存: 1）
3. `GET /api/sessions`（依存: なし）
4. web-ui の一覧と「開く」（依存: 2,3）
5. 実機で 2 タブを確かめる（依存: 4）

## リスク / 留意点

- **購読の取りこぼし**（リーク）→ `dispose` で外れることを検査で固定
- **attach で新しい接続を作ってしまう** → `open()` を呼ばない経路にする
- 既存 3,955 件を壊さない

## テスト方針

- `session-manager.test.ts` — 購読の複数登録・個別解除
- `ws-handler.test.ts` — attach、他人のは開けない、2 接続で通知が両方に届く、
  片方の解除でもう片方が生きている
- 実機 — 2 つのタブで同じ画面を開き、**予約の覆いが両方に出る**
