# 要件: 既存のセッションをブラウザから開く

## 背景 / 課題

**MCP や HLLAPI が開いたセッションを、あとからブラウザで見る手段が無い。**

`WsOpen` に `sessionId` の口が無く、`onOpen` は必ず `sessions.open()` で**新規に開く**。
admin API も一覧と切断だけ（`/api/admin/sessions`）。

そのため:

- MCP のエージェントが操作している画面を、人が**横で見られない**
- 支援や障害対応で「その人の画面を見せてもらう」ができない
- タブを閉じると**もう戻れない**（セッションは生きているのに）

## 目的 / ゴール

**開いているセッションを一覧から選んで、ブラウザで開ける。**
すでに見ている人が居ても、**両方が同じ画面を見られる**。

## スコープ

### 対象

- `WsOpen` に既存セッションへ繋ぐ口（**所有者検査つき**）
- **通知フックを複数購読に**する（いまは 1 枠で上書き。2 つ目のタブが 1 つ目の通知を消す）
- 在席の数え方が attach 後も正しいこと（`20260803-mcp-session-exclusion` の予約判定が乗る）
- 画面から選ぶ導線（開いているセッションの一覧 → 開く）

### 対象外

- **プリンターセッションの attach**（既に `ref` で繋ぎ直せる。`20260801-printer-attach-by-ref`）
- 他人のセッションを一覧に出すこと（admin でも**既定では出さない**。別途判断）
- 画面の同時編集の調停（予約の仕掛けが既にある）

## 機能要件

- **自分のセッションだけ**繋げる（`get(id, user)` の所有者検査を通す）
- **状態を変えない**——繋ぎ直しただけで勝手に何かを再開しない
- **判定はサーバーに置く**（プリンターの前例。画面側だけで見るとリロード直後にすり抜ける）
- 2 つのタブが同じセッションを見ているとき、**片方が閉じてももう片方の通知が消えない**
- 在席が正しく数えられる（2 タブなら 2、1 つ閉じれば 1）

## 非機能要件 / 制約

- 既存の 3,928 件を壊さない
- `20260803-mcp-session-exclusion` の上に載る（予約の判定が在席に依存している）

## 完了条件 (受け入れ基準)

- [ ] 開いているセッションを一覧から選んでブラウザで開ける
- [ ] **2 つのタブが同じ画面を見られる**（両方に画面更新が届く）
- [ ] **片方を閉じても、もう片方の通知が生きている**
- [ ] 他人のセッションは開けない
- [ ] 在席が正しい（2 タブ = 2、閉じれば 1、全部閉じれば 0）
- [ ] **MCP の予約が attach 後も正しく働く**（見ている人が居る＝予約する）
