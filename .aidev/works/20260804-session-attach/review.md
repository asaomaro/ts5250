# レビュー記録: 既存セッションへの attach

## ラウンド 1（2026-08-04）

差分: `session-manager.ts`（購読）、`ws-handler.ts`（attach ＋購読）、
`ws-messages.ts`（1 属性）、`session-routes.ts`（新規）、`AdminPane.vue`。

### 要件との突き合わせ

| 完了条件 | 満たし方 |
|---|---|
| 一覧から選んで開ける | `GET /api/sessions` ＋「セッション管理」の「開く」 |
| 2 つのタブが同じ画面 | 購読リスト。**実機で覆いが両方に出ることを確認** |
| 片方を閉じても生きている | 解除は自分の分だけ。実機で在席 2 → 1 |
| 他人のは開けない | `get(id, user)` |
| 在席が正しい | 既存の増減方式（**変更なし**） |
| MCP の予約が働く | `hasViewer` がそのまま正しい |

### 設計判断の妥当性

- **購読リストにしたのが本丸。** 単数枠のままだと 2 タブで
  「画面は同期するのに覆いは片方にしか出ない」という**気づきにくい壊れ方**をしていた
- **解除の関数を返す形**にしたので、`delete entry.onX` で他人の購読まで消す事故が構造的に起きない
- **在席を触らずに済んだ。** `20260803-mcp-session-exclusion` で「疎通の有無で判断する」を
  選んでいたおかげ——出どころで判断していたら、ここで作り直しになっていた

### 実装中に見つけた欠陥（どちらも設計の穴）

1. **attach したタブが閉じると相手のセッションを殺していた。**
   `dispose` が表示セッションを閉じる設計だったため。
   「開いたのか繋いだだけか」を持たせて塞いだ。併せて**他に見ている人が居れば閉じない**ようにした
2. **「セッション管理」が admin API に依存**していて、監査の設定が無い環境では一覧が空だった。
   主たる出所を `/api/sessions` に変えた（調査での判断とも一致）

### 手際について

E2E のセレクタを 3 回外した（`.card` ではなく `.fn.app`／システム選択が不要／
admin API の 404）。**画面を撮って確かめれば 1 回で済んだ**——推測で直そうとして往復した。

### 残る弱点

- **認証を有効にした状態での attach を通していない**（他人のものが開けないことは単体で確認済み）
- 3 つ以上のタブを試していない

### 判定

**通過。** 完了条件を満たし、自動 3,967 件緑・実機 E2E 35/35・HLLAPI 33/33。
