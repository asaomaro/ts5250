# 要件: 負値入力（Field− / Field+）と符号付き数値の送信表現、Dup キー

## 背景 / 課題

`.aidev/backlog/field-input.md` に残る 3 件。**backlog が「切り離さずに考えること」と
明記している 2 件**（Field− / Field+ と符号付き数値の送信表現）を軸に、
同じローカル編集キーの仲間である Dup を足して 1 つの塊にする。

### 1. 実機の負値入力の主経路が無い

実機の数値欄で負の値を入れるのは **Field−**（数値キーパッドの `-` キー）。
本実装には Field− / Field+ が無く、`-` を直接打つと
`packages/core/src/screen/field-validate.ts:19` の許容集合 `/^[0-9.,+-]*$/` を通るので
**入力自体はできてしまう**が、実機の作法とは別物。

### 2. 符号がワイヤ上どう乗るのかを確かめていない

5250 の符号付き数値欄（`SHIFT_SIGNED_NUMERIC 0x0700`）は、**最終桁のゾーンに符号を埋める**
のが規約のはず。しかし `packages/core/src/protocol/read-response.ts` は
**フィールド値をそのまま EBCDIC へ変換して送るだけ**で、符号に相当する処理が無い。

前作 #205 の実測は**正の値（`12`）しか送っていない**。負値でどうなるかは未確認で、
「ホストが吸収しているのか、こちらの取りこぼしなのか」が分かっていない。
**Field− を実装する前にここを決めないと、送信表現ごと作り直しになる。**

### 3. Dup キーが無く、`DUP_ENABLE` が読まれていない

`DUP_ENABLE 0x1000` は前作（#210）で唯一残した FFW ビット。
「Dup キー自体が未実装なので、キーを足すかどうかとセットで判断する」と据え置いていた。

## 目的 / ゴール

実機と同じ打鍵で同じ値がホストに届く。とくに**負値が正しく届く**ことを実測で裏づける。

## スコープ

### 対象

| backlog 項目 | やること |
|---|---|
| **Field− / Field+** | ローカル編集キーとして実装する（`LOCAL_EDIT_ACTIONS` / `BindingTarget` / 既定バインド） |
| **符号付き数値の送信表現** `0x0700` | **実機で切り分けてから**決める。端末側でゾーン符号を埋める必要があるならそれも実装する |
| **DUP_ENABLE** `0x1000` | Dup キーを実装し、このビットが立つ欄でだけ効かせる |

### 対象外

- **EDTMSK 分解欄の境界をまたぐ操作**（backlog の「要確認」）— 欄をまたぐカーソル移動の話で、
  本件（欄の中の符号とキー）とは別問題
- **数値専用欄に編集文字が入る構成**（同上）— 許容集合の話で、実在するかの確認が先
- ホスト側の挙動は変えない。端末側の作法だけを揃える

## 機能要件

1. **Field−**: 数値欄（`numeric` / `signedNumeric`）でカーソル以降を消し、ADJUST を適用し、
   **符号を負に確定して**次の入力欄へ移る。数値欄でなければ Field Exit と同じ振る舞い。
2. **Field+**: 同様に**符号を正に確定して**次の欄へ移る。
3. **Dup**: `DUP_ENABLE` の立つ欄で、カーソルから欄末尾までを Dup 文字で埋めて次の欄へ。
   立っていない欄では**何もせず操作員メッセージ**（実機は操作員エラー 0019）。
4. 3 つとも **`LOCAL_EDIT_ACTIONS` に足し、キー設定から割り当てられる**ようにする。
   既定バインドは「版ごとに増分だけ混ぜる」既存方式で足す（消した既定を復活させない）。
5. **符号付き数値の送信表現**は実測で決めた形にする。端末側でゾーン符号が要るなら
   `read-response.ts` に実装し、要らないなら**要らないと分かった根拠を残す**。
6. `AUTO_ENTER` 欄では Field± / Dup のあとも Enter を自動送信する（原典どおり）。

## 非機能要件 / 制約

- **矩形選択・コピー＆ペーストを妨げない**（桁割りに触らない）。
- 既定バインドはブラウザ既定と衝突しないものを選ぶ。衝突するなら `preventDefault` する。
- **秘密を成果物に書かない**（実機検証は環境変数のみ）。

## 未確定事項 / 確認したいこと

- **U1（最重要・実機）**: いま `-12` を符号付き数値欄へ送るとホストは何を受け取るか。
  - 負値として解釈されるなら、**端末側のゾーン符号は不要**（ホストが吸収している）
  - `-12` が拒否される／正値になるなら、**端末側で最終桁のゾーンに符号を埋める必要がある**
- **U2（実機）**: ゾーン符号を埋めた形（例 `01K` = 0xF0 0xF1 0xD2）をホストは受け取るか。
  U1 で必要と分かった場合の裏取り。
- **U3（原典）**: Field− は「符号を負にする」以外に何をするか（右寄せ・消去・欄移動の順序）。
  Field+ は数値専用欄（NUM_ONLY）で何もしないという記述が原典にあった（#210 の調査で確認済み）。
- **U4**: Dup 文字は何を送るか（`0x1C`）。画面にはどう見せるか。
- **U5**: 既定バインドに何を割り当てるか。実機は数値キーパッドの `-` / `+` / Dup キーだが、
  PC キーボードには対応するキーが無い。
