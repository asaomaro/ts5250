# 要件: ホストのエラー（WRITE ERROR CODE）でも、ACS と同じくエラー状態に入る

## 背景 / 課題
DDS の妥当性検査（RANGE 等）で範囲外を入れると、ホストは WRITE ERROR CODE でエラーを返す。ACS はエラー状態に入り
（文字を拒否・挿入モードを解く）、矢印・Tab で抜けると最下行のメッセージを消す（メッセージ行を元に戻す）。
当 PJ は最下行にメッセージを出すだけで、エラー状態に入らず、抜けてもメッセージが残っていた。
台帳の「窓の中のエラーメッセージ…エラー状態が明けてもメッセージ行を元に戻さない」の、実機で差が確かめられた部分。

## 目的 / ゴール
- ホストのエラーでも、**ACS と同じくエラーに気づかず打ち続けても欄が壊れず、抜けたら最下行が元に戻る状態**。

## ユーザーストーリー
- US1: 端末の利用者として、ホストに弾かれたとき ACS と同じ操作で抜けたい。なぜなら当 PJ だけ打ち続けられ、
  抜けてもメッセージが残るから。（受け入れ: AC1, AC2）

## スコープ
### 対象
- WRITE ERROR CODE（0x21）でエラー状態に入る・挿入モードを解く・抜けたらメッセージを隠す。同じ文言の 2 回目も入り直す。
### 対象外
- 窓の中のエラー: 実機では WRITE ERROR CODE TO WINDOW（0x22）ではなく WTD で窓の中に書かれ、当 PJ も窓の中に出しているので差は無い。
  0x22 そのものは実機で観測できていない（来たら従来どおり最下行に出す）。

## 完了条件 (受け入れ基準)
- [ ] AC1: WEC が届くとエラー状態に入り（文字を拒否）、挿入モードが解ける。同じ文言がもう一度来ても入り直す。
- [ ] AC2: 矢印・Tab で抜けると最下行のメッセージを隠す（同じ番号のまま画面が更新されても出さない）。
- [ ] AC3: 各判定を外すとテストが落ちる（`verify-by-mutation`）。
- [ ] AC4: エラー状態はセッションに属する——タブを切り替えて戻る・裏のタブに届いてから切り替える・ペインを作り直す、の
  どれでも「メッセージが出ているのにエラーでない／隠したのに戻る」にならない。CLEAR UNIT でエラー状態を抜ける（操作員エラーも）。
- [ ] AC5: エラー中はローカル編集キー（Field Exit・Erase EOF・Erase Input・Field±・Dup）も拒否する。本文が空白だけの WEC でも入る。
