## 直す前に落ちることを確かめた

**これが今回いちばん大事な手順。** 実機で症状は確定していたが、**実機なしで再現できる形**に
落とさないと回帰を止められない——この不具合は LOB の長さで踏んだ 3 度目の同じ罠で、
いずれも「SBCS で通ったから良し」としてすり抜けている。

`packages/hostserver/test/lob-multi-segment.test.ts` を**先に**書き、
未修正の `retrieveLob` に当てた結果:

```
× **先頭から連続して取れる**（中抜けしない）
× オフセットを**文字**で進める（バイトを入れると 2 倍飛ぶ）
    AssertionError: expected 131070 to be 65535
× **上限（バイト）を超えて保持しない**
    AssertionError: expected 262140 to be less than or equal to 200000
× 小さなセグメントで何周しても連続する（境界を複数回跨ぐ）
× **奇数バイトの上限でも符号単位を割らない**（UTF-16）
× **孤立サロゲートを末尾に残さない**
  6 failed | 8 passed
```

**`131070` と `262140` は実機で採った値とビット単位で一致する**
（`research.md` F4 / F5）。偽ホストが実機を正しく模していることの裏取りになっている。

修正後は **14 passed / 0 failed**。

### 追加したテスト（14 件）

| 群 | 何を固定したか |
|---|---|
| 2 バイト CCSID | 先頭から連続（**中抜けしない**）/ オフセットを文字で進める / 上限を超えて保持しない / 総長はバイト / 全部収まれば `truncated` は立たない / **端数のある刻み（7 文字）で 143 周しても連続** |
| 切り詰め | 奇数バイトの上限で符号単位を割らない / **孤立サロゲートを残さない** / SBCS では切り詰めが起きない |
| SBCS・混在 | 位置がずれない（**元から正しい経路を壊していない**）/ 総長はバイトのまま |
| 異常系 | 応答が申告より短くても届いた分だけ進む / 進まなくなったら止まる / 上限 0 なら 1 度も要求しない |

**偽ホストは「文字で数えるホスト」**（`charCountingHost`）。`retrieveLob` が使う接続の口は
`conn.request` 1 つだけなので、そこだけ作れば足りる。`ccsid` を切り替えると
1 バイト/2 バイトの両方を同じ形で試せる。

## 実機検証（実機 / IBM i 7.3）

### 事実の採取

`scripts/research-lob-multi-segment.mjs`（`research.md` に全文の記録）。
`0x1816` の往復を生で覗き、**単位がすべて文字**であることと、
**2 周目で 65,535 文字が丸ごと抜ける**ことを確認した。

### 直ったことの確認

`scripts/verify-lob-multi-segment.mjs` — **14 passed / 0 failed**。

```
フィクスチャ: TESTLIB.LOBSEGV
  C (CLOB 混在)        : 262144 バイト / 262144 文字
  G (DBCLOB CCSID 1200): 524288 バイト / 262144 文字（バイト = 文字 × 2）

### 1. DBCLOB(1200) を上限 200000 バイトで取る（分割 2 周）
  取れた: 100000 文字 = 200000 バイト / unavailable=too-large
  PASS **先頭から連続している（中抜けが無い）**
  PASS 上限を超えて保持しない（200000 ≦ 200000）
  PASS 上限ちょうどまで取れる（200000）
  PASS 全体長はバイトで申告（524288 / 実際 524288）
  PASS 打ち切りの印が立つ

### 2. DBCLOB(1200) を上限 40,000 バイトで取る（1 周・従来は 80,000 バイト来ていた）
  PASS 上限ちょうど（40000）——**2 倍に膨らまない**
  PASS 先頭から連続している / 打ち切りの印が立つ

### 3. CLOB(混在) を上限 200000 バイトで取る（回帰）
  PASS 上限ちょうど（200000）/ 先頭から連続 / 全体長が一致（262144）

### 4. 小さい LOB は完全に取れる（truncated が立たない）
  PASS CLOB / DBCLOB とも完全一致・打ち切りの印が立たない

OK — 14 passed, 0 failed
```

**検査は件数ではなく「先頭からの連続性」で行う**（`contiguous()`）。
件数だけ見ると、直す前の 262,140 バイトも「たくさん取れた」ように見えてしまう。

後片付け: `finally` で `DROP TABLE`。表は自分のライブラリー（`AS400_LIB`、既定 `TESTLIB`）に作り、
他人のオブジェクトに触っていない。内部 IP はスクリプトに書いていない
（`process.env.AS400_HOST`、既定値なし）。

## 未検証の穴

- **純 DBCS（CCSID 300）の 64KB 超は作れなかった。** `20260801-pure-dbcs-dbclob` の
  二段キャスト（1200 経由）は小さな値では通るが、倍々に伸ばす経路では試していない。
  `isTwoByteCcsid` は 1200 と**同じ枝**なので同じ道を通る——型の分岐は
  `lob-ccsid-units.test.ts`（既存）と今回の単体テストで固定している。
- **BLOB（CCSID 0）の 64KB 超は測っていない。** `perChar=1` なので混在 CLOB と同じ経路。
- **`lobMaxBytes` の上限（`MAX_LOB_BYTES`）いっぱいでの実測はしていない。**
  往復数が増えるだけで、単位の扱いは 200,000 バイトで通した経路と同じ。
