# 仕様: web-ui のテストの不安定さを減らす

## 何が起きていたか（測定）

落ちるのは**ほぼすべて `document.activeElement` を見るテスト**。単独では通る。

数えたところ、**`mount()` 893 回に対し `unmount()` は 469 回**——**424 個が付けっぱなし**。
30 ファイルが `attachTo: document.body` を使っているので、終わったテストのコンポーネントが
`document` に残り、**フォーカスとキーイベントの購読を保持し続ける**。

次のテストが `focus()` を呼んでも、残骸のハンドラが割り込んでフォーカスを奪い返す。
残骸が増えるほど取り合いに関わる要素が増え、結果は実行の速さ（＝並列の混み具合）で変わる。

## 直し方

**1 つのテストが終わったら、そのテストが作ったものを全部畳む。**

```ts
// test/setup.ts（`setupFiles` で全ファイルに効かせる）
enableAutoUnmount(afterEach);           // マウントを毎テスト後に畳む
afterEach(() => {
  if (document.activeElement instanceof HTMLElement) document.activeElement.blur();
  document.body.innerHTML = "";
});
```

個々のテストに `unmount()` を書き足して回るのではなく、**書かなくても片付く形**にする
——書き忘れは必ず再発する。

## 並列度を落とさない理由

**逐次実行でも落ちる**ので、並列度は**悪化要因であって単独原因ではない**。代償も大きい:

| 条件 | 所要時間 | 失敗件数 |
|---|---|---|
| 既定（12 並列） | **67 秒** | 0, 0, 1, 4, 1, 1 |
| `maxWorkers=4` | 96 秒 | 0, 1, 0, 0 |
| 逐次 | 216 秒 | 1, 0, 0 |

並列時は**環境構築だけで 370 秒ぶん競合**している（逐次は 93 秒）。混み具合が結果を
変えているのは確かだが、**効き切らないものに 3 倍の時間は払わない**。原因はテスト側にある。
