# テスト結果: web-ui のテストの不安定さを減らす

## 測定（これがこの作業のテスト）

| 条件 | 失敗件数（1 回ごと） | 最悪 | 全部通った回 |
|---|---|---|---|
| **修正前**（7 回） | 2, 14, 0, 0, 2, 11, 12 | **14** | 2/7 |
| **修正後**（6 回） | 0, 0, 1, 4, 1, 1 | **4** | 2/6 |
| 修正後・逐次（3 回） | 1, 0, 0 | 1 | 2/3 |
| 修正後・`maxWorkers=4`（4 回） | 0, 1, 0, 0 | 1 | 3/4 |

**最悪値が 14 → 4、常態が 10 件超 → 0〜1 件。** ただし**ゼロにはなっていない**。

`npm run build`（`vue-tsc` 込み）と `npm run lint` は通過。

## 何が残っているか

残るのも focus 依存が中心だが、**残骸が原因ではない**（畳んでも出る）:

| テスト | 中身 |
|---|---|
| `opt-hints-ui` 開いたら選択中の項目にフォーカス | `nextTick` を 2 回待って `activeElement` を見る |
| `pane-nav` Tab で次の入力欄へ | `nextTick` 1 回でマウント時の自動フォーカスを待つ |
| `pane-protected-input` 文字キーでメッセージ | — |
| `sql-pane` 実行ログ | `.sqllog .row`（**先頭行**）を見る。`connect` の行が先に入ると外れうる |

共通するのは「**固定回数の `nextTick` で、いつ終わるか保証の無い処理を待っている**」形。
直すには 1 件ずつ「何を待つのか」を書き直す必要があり、**推測で触ると別の形で壊れる**ので分けた。

## 並列度の切り分け

**逐次実行でも落ちる**（1, 0, 0）ので、並列度は悪化要因であって単独原因ではない。
所要時間は 67 秒 → 96 秒（`maxWorkers=4`）→ 216 秒（逐次）。
**効き切らないものに 3 倍の時間は払わない**——並列度は既定のままにした。

## 未検証（穴）

- **残りをゼロにしていない。** 半分の回で 1 件前後落ちる。
- **retry で隠していない**（隠すとこの作業の目的の逆になる）。
- 測定はこの 1 台（12 コア）でのもの。**別の機械では比率が変わる**。
