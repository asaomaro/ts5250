# 計画: web-ui のテストの不安定さを減らす

## 作業順序と依存関係

1. **基準線を取る**（修正前に複数回まわして失敗件数を記録）
2. 落ちたものの assertion を実際に読む（推測しない）
3. 共通の後片付けを入れる（依存: 2）
4. **同じ回数で測り直す**（依存: 3）
5. 並列度の影響を切り分ける（逐次・ワーカー数を絞る）（依存: 3）

## リスク / 留意点

- **1 回通ったで「直った」と言わない。** 元が確率的なので、必ず複数回で比べる。
- **再試行で隠さない。** 落ちたことを見えなくするのは、この作業の目的の逆。
- 並列度を落とすのは最後の手段（時間の代償が大きい）。

## テスト方針

スイート自体が対象なので、**回数で測る**のがテスト。
