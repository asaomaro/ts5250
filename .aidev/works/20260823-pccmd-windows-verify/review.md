## 規約との突き合わせ（AGENTS.md）

- **コメントは why 中心**: 新テストの冒頭に「なぜ別ファイルか／何を見ているか／落とし穴」を置いた。
  「アプリに寿命を持たせない」理由（並行実行でタイマーがずれて偽陽性になった実測）を明記
- **実機検証を単体テストの代替にしない**: 逆向きの適用になった——**実機でしか測れないものを
  単体テストに落とした**。測定そのものは research.md に生の値で残した
- **記録の同期**: 閉じた項目に works slug ＋ 実測値（40 ケース・1,243 → 1,246 件・11 件の残り）を併記。
  誤りが確定した記述（「`CALL` 以外の入れ子は未確認」）は**取り消し線で残した**
- **一部だけ済んだ項目は割る**: 根本原因の項目を「測り直した（済）」と
  「あの 1 台の事情（未）」の**兄弟**に分けた（インデントした子にすると `aidev status` の
  件数から消える）
- **ログは stderr のみ / `console.*` 禁止**: テストは `expect` だけで、標準出力に何も書かない

## 自分で気になった点（と処置）

1. **回避策を残す判断は「効いていないかもしれないもの」を抱えることになる。**
   → docstring に「この機械では再現しない」「何が効いていたかは未確認」と明記した。
   回避策の無害さ（`CALL START` の `CALL` は意味を持たない）も同じ場所に書いてある
2. **新テストは 4.6 秒かかる**（suite 全体では並行して吸収されるが、単体では体感する）。
   → 3 形に絞り、`sleep` は 800ms 1 回だけにした。形を増やすなら probe（作業記録側）で振る
3. **`NET USE` を引数無しで実行している。** 原資料は `NET USE \\SRV` だが共有名がこの機械に無い。
   → 見たいのは `&` で繋いだ入れ子なので落とした。テスト内にその理由をコメントで残した
4. **`pc-command.test.ts` の `CALL START true` は cmd.exe では `true` が見つからず終了コードが
   非 0 になる**（テストは `status: "ran"` しか見ないので通る）。
   → 触らなかった。この 2 件が見ているのは**許可判定と置換の順序**で、
   コマンドの成否ではない。書き換えると見ているものがぼやける
5. **`.gitattributes` を足せば `prebuilt-fresh` の 1 件も緑にできる**が、
   **全ファイルのチェックアウトに影響する**変更なのでこの PR には混ぜない
   （backlog に推奨として書いた。decisions D5）
