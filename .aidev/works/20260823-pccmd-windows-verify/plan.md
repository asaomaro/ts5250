# 計画

## 手順

1. **環境を整える**（測る前に土台を確かめる）
   - `npm install`（workspace の張り直し）→ `npx tsc -b`
   - `packages/server` の suite を回して **Windows の baseline** を取る
2. **測る**（research.md の 4 段。段ごとに「次に何を振るか」を決める）
   - 段 1: コマンドの形 × spawn の指定（本番の指定を起点に 1 つずつ振る）
   - 段 2: `CMD /C "…"` の入れ子 × コンソール / GUI
   - 段 3: 親プロセス（bash / cmd.exe / **Electron main**）＋ ジョブオブジェクトの在否
   - 段 4: `CALL` の構文解析差（起動された側の argv）
3. **回帰テストを書く**（S1）→ Windows で緑を確認
4. **空振り検証**: アプリが 1 拍で終わるミュータントで落ちることを確認
5. **POSIX 前提を外す**（S2）→ コマンド文字列を `cmd.exe` と `sh` の両方で実行して確認
6. **記録**（S3）: docstring / backlog 2 ファイル / この作業記録
7. `tsc -b` ・ lint ・ `packages/server` の suite で締める

## 順序の理由

- **測るのが先。** 原因が分かれば回避策の見直し（`stripCallBeforeStart` を外す）まで
  射程に入るが、分からなければ「生存を固定する」しかできない。
  **仕様は測定の結果で変わる**ので、テストの形を先に決めない
- **親プロセスの段は最後に置かない。** 原資料の唯一の異常（「単体では効くのに
  サーバーからは効かない」）がここに関わるので、段 3 で Electron を親にした測定を必ず通す
- **POSIX 前提の除去は測定のあと**。先に触ると「落ちているのは元からか、直したせいか」が混ざる

## 分からなかった場合の落とし所（先に決めておく）

再現しなかったときに「異常なし」で閉じない。**何を否定したかを件数つきで残し、
残った未知（あの 1 台の事情）を項目として割る**（AGENTS.md「一部だけ済んだ項目は割る」）。
回避策は残す——無害で、1 台の観測がある。

## リスク

- **再現しない可能性が高い**（別環境・別 OS 版）。→ 上の落ち所で対応
- 測定が「アプリの起動失敗」と「起動後の消滅」を混同する。→ 追記ファイルで**拍**を測り、
  0 拍（起動せず）と数拍で止まる（消えた）を**区別できる形**にする
- Windows の suite が元から赤い。→ 先に baseline を取り、**この作業の変更と切り分ける**
