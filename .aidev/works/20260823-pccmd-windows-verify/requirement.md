# 要件: PC コマンドの Windows 実機の穴を 2 件とも閉じる

## 背景

`.aidev/backlog/pc-command.md` に **Windows 実機でしか進められない項目が 2 件**残っていた。
どちらも `20260730-pccmd-call-start-and-winbat`（decisions D5「この環境に Windows が無い」）
が残した穴で、**今回はじめて Windows 実機で作業できる**。

- [ ] **`CALL START` が消える根本原因の特定** — 回避策（`stripCallBeforeStart`）で実害は
  消えているが、なぜ消えるのかは分かっていない。「プロセスツリー・ジョブオブジェクトの観察が要る」
- [ ] **Windows 実機での回帰確認の自動化** — `stripCallBeforeStart` は単体テストで固定したが、
  **「アプリが生き残る」ことは Windows でしか確かめられない**

原資料（別環境の実測。リポジトリには入っていない）が主張していること:

- `CMD /C "NET USE \\SERVER & CALL START "title" /B "app.exe" args…"` は
  **起動した app.exe が直後に消える**。ログは `status: "started"` のままで、エラーは見えない
- `CALL` を外した `START …` は毎回生き残る。**`CALL` の有無だけが唯一の分岐点**
- 手でコマンドプロンプトから同じ文字列を実行すると成功する
- `detached: true` 単独は「単体の再現スクリプトでは効くが、実際のサーバープロセスからは効かない」

## 目的

1. **測る。** `CALL START` で消えるのかを、この Windows 実機で自分の目で確かめる。
   消えるなら原因（ジョブオブジェクト・コンソール・cmd の構文解析のどれか）まで詰める
2. **回帰資産にする。** 「アプリが生き残る」ことを**自動テストで固定**し、
   次に Windows で回した人が黙って壊さないようにする

## 完了条件

- [ ] `CALL START` の生存が**実機の測定値**として記録されている（振った軸と件数つき）
- [ ] 原因が分かるか、**分からないことが分かる**（何を測って何が否定されたか）
- [ ] 「アプリが生き残る」ことを見るテストが `npm test` で回り、**Windows で緑**
- [ ] そのテストが**空振りしない**（アプリが消えるミュータントで落ちる）
- [ ] backlog の 2 件が根拠つきで閉じる／割れる（AGENTS.md「記録の同期」）

## 非目標

- **原資料の機械の再訪**（あの環境には届かない）
- `packages/server` の suite 全体を Windows で緑にすること
  ——見えた分は台帳（`.aidev/backlog/windows-test-run.md`）に置くに留める
