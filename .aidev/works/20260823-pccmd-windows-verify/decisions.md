# 決定記録

## D1: 再現しなかったが **回避策（`stripCallBeforeStart`）は残す**

- 背景: この機械では 40 ケースすべてでアプリが生き残り、`CALL` の有無で差が無かった
  （argv も同一・ジョブにも入っていない）。「`CALL` が原因」という筋は成り立たない。
- 決定: **外さない。** docstring に「別の機械では再現しない」ことを測定値つきで足すだけにする。
- 理由 / 代替案: 外す案もあったが、(a) `CALL START` の `CALL` は意味を持たないので
  落としても**無害**、(b) 実機 1 台に「落とせば直った」という観測がある、
  (c) こちらは**あの環境に届かない**——「再現しないから不要」は、
  再現しない理由が分かっていない段では言えない。
- 影響: 製品の振る舞いは変わらない。**docstring が「効いている理由は未確認」と
  正直に言う形**になる（万能薬と誤解させない）。

## D2: 生存の判定は **「シェルが終わったあとに増えたか」**（プロセス一覧を見ない）

- 背景: 「起動したか」と「生き残ったか」は別で、原資料の症状は
  `status: "started"` のままアプリだけが消えるものだった。
- 決定: アプリに追記させ、`600ms` と `1,400ms` の**行数の差**で判定する
  （`late > early + 2`）。`Get-CimInstance` でのプロセス照会は測定用の probe に留め、
  テストには持ち込まない。
- 理由 / 代替案: プロセス照会は PowerShell の起動（数百 ms）と権限に依存し、
  GUI アプリだと窓が出る。追記なら **0 拍（起動せず）と数拍で止まる（消えた）を
  同じ物差しで区別できる**。
- 影響: テストは 1 件あたり約 1.5 秒（3 件で 4.6 秒）。`it` の上限を 15 秒に明示した。

## D3: Electron の Windows ビルドでは回さない

- 背景: backlog の項目は「Electron 版の Windows ビルドで回す道を検討する」だった。
- 決定: **採らない。** 生存に効くのは `spawn` の経路だけで、そこは `runPcCommand` を
  呼べば通る。親を Electron の main プロセスにした測定（測定 3）でも結果は同じだった。
- 理由 / 代替案: ビルドを回す道は「毎回パッケージングが要る・失敗しても原因が遠い・
  CI に載せにくい」の三重苦で、**得られる保証は同じ**。
  配布形が Electron main の中でサーバーを動かす（`electron/main.cjs` の `startServer()`）
  ことは測定で押さえた。
- 影響: `npm test` に載る（Windows で回せば毎回走る）。Electron 固有の退行は
  引き続き手で確かめる範囲。

## D4: `pc-command.test.ts` の POSIX 前提は **実測で落ちた／揺らいだ 3 か所だけ**外す

- 背景: この suite は「POSIX 前提」と明記して書かれていた（`test -d .` / `sleep`）。
  Windows で回すと `test -d .` が落ち、`sleep 5` は **Git 同梱の `sleep.exe` が
  PATH に居るかどうか**で結果が変わる（居ないと即終了して「上限で打ち切る」テストが壊れる）。
- 決定: この 3 か所を両シェルで通る形に置き換える。`echo … > file` を使っている箇所や
  `exit 3` は**そのまま**（cmd.exe でも同義）。
- 理由 / 代替案: suite ごと `skipIf(!isWin)` で割る案は、**Windows の回帰確認が
  半分になる**（許可判定・置換の順序は OS に依らない資産）。
  逆に全部を書き直すのは、この作業の目的（生存の回帰）から離れる。
- 影響: 置き換えた `cwd` のテストは**前より強い**——`test -d .` は成功しても
  「cwd を見た」ことにならないが、書かれた場所を見れば cwd が効いた証拠になる
  （空振り検証: `cwd` を落とすミュータントで死亡）。

## D5: Windows で見えた他の 11 件は **別の項目に割る**

- 背景: Windows の baseline は 1,243 件中 12 件 failed。1 件は pc-command で直したが、
  残り 11 件（`lp` / `unzip` / `python3` の不在、`chmod` が効かない、
  CRLF チェックアウトで指紋が変わる）は**この作業の対象外**。
- 決定: 直さない。`.aidev/backlog/windows-test-run.md` に**原因つきで**起票する。
- 理由 / 代替案: ついでに直す案もあったが、依頼された範囲（backlog 2 件）から外れ、
  `.gitattributes` の追加は**全ファイルのチェックアウトに影響する**変更で、
  この PR に混ぜるべきではない。**製品の不具合ではない**ことは測って確かめた
  （`prebuilt-fresh` は DLL が古いのではなく、CRLF で指紋が変わっているだけ）。
- 影響: Windows の suite は当面 11 件赤いまま。**その 11 件が何で赤いかは記録にある**。
