# 決定記録

## D1: 貼り付けは新しい規則を作らず、打鍵と同じ鎖の操作を回す
- 背景: ACS の貼り付け（`ECLPS.pasteLineWrap`）は 1 字ずつの打鍵と同じ操作（P1〜P4 と P5〜P8 の値が同じ）。当 PJ の貼り付けは区間の中だけの別の経路だった
- 決定: 継続した O 欄の単一行の貼り付けは `chainInsert`／`chainOverwrite` を字ごとに回し、カーソルが最初の区間を出た字を置いたところで止める（`chainPaste`）。P1・P2・P4 の実機の一致は変えない
- 影響: 複数行の貼り付けは従来の経路（対象外）

## D2: 単独の SO/SI の Delete は「エラーを出す」と「詰め直す」を両方返す
- 背景: ACS は 0065 のあとも詰め直しを回す（D1〜D8）。当 PJ の `ChainResult` は「結果」か「エラー」のどちらかだった
- 決定: `warn?: 0x65` を足し、値を反映したうえで理由を操作員メッセージにする（`oChainApply` が `oRejection` を立てて true を返す）

## D3: 過去の決定の破棄
- 破棄: `20260930-cont-o-nul` D3「貼り付けの P3 は実装しない（稀）」と、台帳の「(d) 単独の SO/SI の Delete は値を変えない（未測定）」
- 証拠: 利用者の指示で再開し、実機の ACS のコアで測った（D1〜D8・P3）。実機のブラウザは D1〜D8 が 16/16・P1〜P8 が 15/15（P3 を含む）一致

## D4: 0065 の操作員メッセージの文言は変えない
- ACS の日本語のメッセージは「画面の保護域にカーソルがある」（D1〜D8 の画面の 24 行目）。0005 と同じ文言で、当 PJ の 0005（`MSG_PROTECTED`）と 0065（`MSG_SHIFT_POSITION`）は別の文言。バイト列・カーソルには出ない差なので台帳に残す
