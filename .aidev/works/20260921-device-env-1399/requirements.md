# 要件: 1399 の KBDTYPE / CODEPAGE / CHARSET を ACS と同じにする

## 背景 / 課題
- 台帳「【まとめ】telnet・自動サインオン・装置名の差」の 1399 の申告（中・要実測）。ACS は KBDTYPE=JPE・CHARSET=32000、当 PJ は JEB・1172（`packages/base/src/device-env.ts`）。

## 目的 / ゴール
- 1399 のセッションで、ホストに名乗るデバイスの属性が ACS と同じになっている状態。

## ユーザーストーリー
- US1: 1399（日本語 英小文字・拡張）の利用者として、ACS と同じ属性で装置を作ってほしい。なぜなら、ホストが作る装置の文字 ID が ACS と違うと、
  表示装置ファイルの CHRID の扱いが ACS の利用者と食い違いうるから。（受け入れ: AC1, AC2）

## スコープ
### 対象
- `deviceEnvFor(1399)`（5250・3270・VT が共有）。
### 対象外
- 5035・931・5026（ACS のコードページの一覧に無い。当 PJ だけの対応のまま）。930 の「Katakana（290 として扱う）」の選択（ACS の既定の選択は未確認）。

## 完了条件 (受け入れ基準)
- [ ] AC1: 1399 の申告が KBDTYPE=JPE・CODEPAGE=1027・CHARSET=32000（ACS のワイヤと同じ）。930・939・37 は ACS と同じままであることを実測で確かめる。
- [ ] AC2: 1399 で両方の実機にサインオンでき、日本語が往復する。3270・VT でも繋がる。
