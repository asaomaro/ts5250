# 要件: SCS の重ね打ち・罫線（DGL）・半分の幅を ACS の JPS と同じに描く

紐づく charter ゴール: charter.md なし（`.aidev/backlog/acs-parity.md`「【まとめ】SCS の解釈の差」。利用者の指示で対応不要から再開）

## 背景 / 課題
ACS は SCS を Java 印刷（JPS）で 1 字ずつ `drawString` し、罫線を `draw` する。当 PJ の帳票は桁の格子（後の字が先の字を置き換える）で、
次の 3 つが紙・画面から落ちていた: (1) CR で戻った重ね打ち（下線・二度打ちの太字・合成文字）は先の字が消える、(2) DGL（罫線の定義）は読み飛ばす、
(3) SFSS の半分の幅（0x08）は 1 倍として扱う（1 桁に 2 字入る）。

## 目的 / ゴール
帳票の画面・配布 HTML・PDF が、重ね打ちの両方の字・DGL の罫線・半分の幅の字を、ACS の JPS と同じ位置に描く状態。

## ユーザーストーリー
- US1: 下線や太字を重ね打ちで出す古い帳票の利用者として、ACS で紙に出ていた下線・太字が画面・PDF にも出てほしい。なぜなら重ね打ちの字が消えると帳票の意味が変わるため。（受け入れ: AC1, AC4）
- US2: 罫線（DGL）で表を組む帳票の利用者として、罫線が表示・PDF に出てほしい。（受け入れ: AC2, AC4）
- US3: 半分の幅（1 桁に 2 字）の帳票の利用者として、字が 1 桁に 2 字入った形で見たい。（受け入れ: AC3, AC4）

## スコープ
### 対象
- `@ts5250/scs` の復号（`LogicalPage.decor`）と、描く 3 か所（配布 HTML・web-ui の画面・PDF）

### 対象外（合わせないもの。decisions D1）
- 最後の FF が無いジョブ（ACS は最後の FF より後を印刷しない＝情報を捨てる）
- SIT の無い DBCS の詰め方（ACS の既定値が字の進みを変える）
- 罫線の位置に効く SPPS（用紙の大きさ）の字幅、印刷の物理量（用紙の向き・縮尺）

## 完了条件 (受け入れ基準)
- [ ] AC1: 重ね打ちで下になった字を層に残す（半角・全角・同じ字・空白は残さない）。重ねない帳票の形は変えない
- [ ] AC2: DGL を ACS の順で解釈する（種類・選択・位置・縦線は行が変わってから横線か「消す」で引く・SCD の字幅で桁へ直す・ページで捨てる）
- [ ] AC3: 半分の幅の字は格子を空白のまま 0.5 桁刻みで層へ置く。通常の幅に戻った字も半桁の位置なら層へ
- [ ] AC4: 配布 HTML・画面・PDF が層と罫線を行の箱に重ねて描く（選択・コピーに入らない・決定的）

## 未確認 / 確かめたいこと
- 実機のホストがこれらの形の SCS を出すか（実採取の 2 件〔DSPLIBL の SBCS・DBCS〕には無い）。ACS の描き方は原典（JPS）の読みで決めた
