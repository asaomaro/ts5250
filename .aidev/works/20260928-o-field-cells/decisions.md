# 決定記録

## D1: `20260926-dbcs-insert-sosi-room` decisions D2（O 欄は「入るか・0012 か」だけ合わせ、値は正規化した並びのまま）を破棄する

- 背景: 利用者の指示で O 欄の作り替えを優先した（2026-09-28「O欄から」）。D2 は規模の判断で B（値に SO/SI の位置を持たせる）を割った
- 決定: B を採る。編集の値に SO/SI の印を持たせ、ACS の表どおりにセルの上で編集する（`oFieldCells.ts`）
- 証拠: 原典の表（research F2〜F7）を実機の ACS のコアで 24 通り測り、すべて予測どおり（F10）。ブラウザの当 PJ も同じバイト列を送った
- 影響: 以前の近似の関数（`acsInsertShortOfRoom`）は外した。既存テストのうち古い振る舞いを固定していた 44 件は、ACS の規則に照らして期待値を直した

## D2: 印は生バイトのセンチネル（0x0E・0x0F）にし、「印を含む値は明示の並び」と決める

- 理由 / 代替案: センチネルはコアの送信（`writeValue`）と `setFieldValue` が既に生バイトとして扱い、未編集の DBCS 欄の原本も同じ形で運んでいる。
  別の私用文字を足す案は、コアとサーバーの検証の全部に新しい種類を教える必要がある
- 影響: web-ui の桁数・列ビュー、コアの送信は「印があれば暗黙の SO/SI を足さない」。E・J・G 欄と、全角の無い O 欄は印を持たないので従来どおり

## D3: 選択の置き換えは「最終のセルの判定だけ外す」を O 欄でも保つ

- 背景: 選択の置き換えは当 PJ 独自（ACS の GUI は未測定）。SBCS・DBCS 欄は「消した跡を埋めるだけ」として最終桁の判定を掛けない決めがある（`dbcs-insert-room.test.ts`）
- 決定: O 欄も同じく最終のセルの判定だけ外し、空きの数え方は ACS の表どおり（`insert` の `allowLastCell`）。1 字目で止まったら選択の削除も戻す（打鍵・IME とも）

## D4: 当 PJ 独自の操作の後は並びを組み直す（`normalizeO`）

- 背景: 選択の削除・語の削除・複数行の貼り付けは ACS に無く、印を考えずに字を出し入れする
- 決定: `syncDbcs` で並びが崩れていたら（印が交互でない・全角が SO と SI の間に無い・半角が間にある）、印を外した論理値から SO/SI を付け直す。空の SO/SI は失う（差として記録）

## D5: 継続した O 欄は対象外

- 理由: ACS は別の手順（`processCharWithDBCSOpenContField`。並びの併合と語単位の詰め直し）で、台帳の別項目（`20260927-cont-o-insert` で測定済み）。今回の作りに乗せると区間をまたぐ印の扱いが要る
