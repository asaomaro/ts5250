# 決定記録

## D1: 止まったときは rc=5 を返し、後ろのキーを処理しない

- 背景: ACS はエラー 20 / 21 で入力禁止になり、後ろの字を受けない（実機: Tab の後ろの CD は入らない）。HLLAPI（当 PJ）は入力禁止の状態を持たない。ACS の HLLAPI（Windows のネイティブ層）がこのとき返す rc は測れない
- 決定: 入力禁止の欄へ打ったときと同じ `rc=5`（FUNCTION_INHIBITED）で返し、残りのキーを処理しない
- 理由 / 代替案: 状態を持つ（Reset まで字を拒否する）案は、HLLAPI の他の入力禁止（キーボードロック・保護欄）が rc で返す作りと食い違う。画面に残る結果（値・カーソル）は ACS と同じ
- 影響: docs/HLLAPI.md の戻り値の表に足した

## D2: 空白を空とみなす（ペインと同じ近似）。非表示欄は判定しない

- 背景: ACS はヌルだけを空とみなす。HLLAPI の書き込み（`writeIntoField`）は欄全体を空白で埋めるので、ヌルでは判定できない。非表示欄はスナップショットに値が無い
- 決定: ペインの `mandatoryFillViolated` と同じく末尾の空白を空きとみなす。DBCS は字のセルだけを中身にし、字の直後の SI だけを使った桁に数える（独立レビューの指摘）。非表示欄は判定せず、既知の差として docs と台帳に残す
- 理由 / 代替案: core に値を問い合わせる口を作る案は、パスワードの値をサーバーの判定へ持ち出す経路を増やすので採らない（この work の範囲外。台帳に残した）
