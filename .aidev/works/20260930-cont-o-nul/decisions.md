# 決定記録

## D1: 空きと空白の区別は継続した O 欄の鎖だけに持たせる
- 背景: 台帳は「O 欄の値の表し方と core の置き場」を重いと見て閉じていた。全欄（O・E・J）に広げると、編集モデル（`padDbcs`・`trimPad` ほか）と値の意味が全部変わる
- 決定: 鎖だけ。値の文字 U+0000 が空き、U+0020 は中身の空白。継続でない O 欄・J・E は従来どおり（末尾の全角空白の差は台帳に残す）
- 影響: `toCells` の `padNul`、`eraseToEnd` の `fill`、`trimPad`・`padDbcs`・`logicalFromCells`（鎖の分岐）

## D2: 空きかどうかの見分けは snapshot のセルの生バイトで
- ホストが書いた空白は生バイト 0x40 を持ち、書かなかった桁は持たない。core が打った空白にも 0x40 を持たせる（鎖の空白だけ。表示の再解釈は空白に効かない）ので、編集した後に読み直しても見分けがつく

## D3: 貼り付けの P3（全角が区間の残りに入らない）は実装しない
- 測ったこと（`scripts/acs-probe/cont-o-paste.txt` の P3）: ACS は入らない全角を次の区間へ置いて止まる。P1・P2・P4 は当 PJ が既に同じ。P3 は貼り付けが区間をまたぐ経路を要し、実際に貼る文字列では稀（区間の残りが 2〜3 桁のとき）。台帳に残す（未着手）

## D4: 過去の決定の破棄
- 破棄: 台帳の「(a) 空白（0x40）と NUL の区別は…当 PJ の O 欄の値は両方を半角空白で持つので、末尾の 0x40 を送らず、ALT で途中の NUL を `40` で送る」（`20260928-cont-o-cells` decisions D・2026-09-30 の「対応不要」）
- 証拠: `scripts/verify-browser-cont-o.mjs` の C09・C10 は末尾の `40` まで、`verify-browser-cont-o-paste.mjs` の P4・P7・P8 は ALT の `00` まで、ACS と一致した（修正前は不一致）
