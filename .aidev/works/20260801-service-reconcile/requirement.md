# 要件: 定義の変更をサービスに反映する

## 背景 / 課題

`20260801-boot-autostart`（#257）は**起動時に 1 回だけ**定義を読む。その結果:

| したこと | 起きること |
|---|---|
| サービス定義を足した | **再起動まで上がらない** |
| 定義を消した | **動き続ける**（定義が無いのに） |
| 設定を直した | **古い設定のまま動く**（止めて開始し直しても直らない——材料が古いまま） |
| 「サービスとして使う」の ✅ を外した | **常駐したまま** |

一覧（#259）は**定義ベース**なので画面には出る。つまり「自動」と書いてあるのに上がっていない、
という**画面と実体の食い違い**が見える形で残っている。

## 目的 / ゴール

**設定を保存したら、その通りに動く。** 再起動を挟まずに。

## スコープ

### 対象

- アプリ経由の設定変更（`POST` / `PUT` / `DELETE /api/sessions-config`）を動いているサービスに反映
- 反映しきれないもの（動作中の接続設定）を**画面で知らせる**

### 対象外

- **`profiles.json` を外から直接書き換えたときの検知**（ファイル監視）。
  アプリの画面から編集する経路を先に成立させる。
- 個人設定（`own:`）— 起動時の自動開始と同じ線引き（所有者が居ないところで繋がない）

## 機能要件

- 定義を足す（サービス ✅ ＋ 自動 ✅）と**その場で立ち上がる**
- 定義を消すと**止まって実体も消える**
- 「サービスとして使う」を外すと**止まる**
- 動いているサービスの設定を直しても**待ち受けは切れない**。代わりに
  **「要再起動」が画面に出る**（開始し直せば新しい設定で繋がる）
- 反映に失敗しても**設定の保存は成功のまま**（500 を返さない）

## 非機能要件 / 制約

- **設定の保存の応答を遅らせない**（ホストへの接続を待たせない）
- CRUD の経路に実体（`SessionManager` / `WatchRegistry`）を持ち込まない

## 完了条件 (受け入れ基準)

- [ ] 上記 4 つの変更が再起動なしで効く
- [ ] 動いているサービスが設定の保存で切れない
- [ ] 「要再起動」が出て、開始し直すと消える
- [ ] 反映の失敗が保存を巻き添えにしない
- [ ] ビルド（`vue-tsc` 込み）・lint・全テストが通る
