## 実機で測ったこと（新しい節）

```
### 5. 定義の変更を反映する
  PASS サービス ✅ に変更できる
  PASS **サーバーを再起動せずに立ち上がる**
  PASS 動いているサービスの設定を保存できる
  PASS **「要再起動」が出る**（直したのに効いていない、を黙らせない）
  PASS **保存で待ち受けが切れない**（帳票の受け取りを止めない）
  PASS 開始し直せる
  PASS **開始し直すと「要再起動」が消える**
  PASS **サービス ☐ に戻すと止まって実体が消える**
  PASS 定義を消すと動いていた実体も消える
  PASS 一覧からも消える

OK — 24 passed, 0 failed
```

**「保存で待ち受けが切れない」を実機で押さえた**のが要点。設定変更で動いているサービスを
落とす作りにすると、この検査が通らない——**落とさない**という判断が実物で守られている。

## 新規の単体テスト（15 件）

偽のマネージャを使い、**呼び出し列そのもの**を突き合わせている。

```ts
expect(await reconcileService(d, "srv:p1", "saved")).toEqual({ stale: true });
expect(calls).toEqual(["updatePrinterOptions e1"]);   // 止めていない
```

「止めていない」は**結果の値では表せない**（何も起きなかったのと区別が付かない）ので、
呼ばれた順に並べて確かめる。

| 群 | 内容 |
|---|---|
| 足された | サービス ✅ ＋ 自動 ✅ で上がる／自動 ☐ は登録だけ／サービス ☐ は上げない／`dtaqwatch` は `service` を見ない／個人設定は扱わない |
| 直された | **動いているものは落とさず差し替え**／止まっていれば `stale` にしない／サービス ☐ で止める／監視も同じ |
| 消された | 止めて捨てる／監視は**先に stop**／動いていなければ何もしない／**解決しに行かない** |
| 失敗 | **投げない**（保存を巻き添えにしない）／レジストリが無ければ飛ばす |

## 未検証（穴）

- **`profiles.json` を外から直接書き換えたときは検知しない**（対象外にした）。
  アプリの画面から編集する経路だけが反映される。
- **認証を有効にした状態での通し確認をしていない**（実機 E2E は認証オフ）。
  反映は保存が成功したときだけ走るので、**認可は既存の CRUD の層がそのまま効く**。
- **同時に多数の定義を保存したときの挙動**を測っていない（1 件ずつ独立に走る）。
