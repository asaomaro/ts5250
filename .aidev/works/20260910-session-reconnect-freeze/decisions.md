## D7 口の同一性が reactive プロキシで壊れていた。差し替えを markRaw にする（2026-09-10T07:10:17Z）

- **背景**: T1 の独立点検が、design D-a のとおりガードを `acceptsFrame` に差し替えても
  **4 件とも赤のまま**であることを実測で示した。原因は Vue のリアクティビティ——
  `sessionsStore` は `reactive({...})`（`stores/sessions.ts:340`）で、口を `markRaw` しているのは
  `add()` の 1 か所だけ（`:355`「client は Vue のリアクティブ化から除外（外部オブジェクト）」）。
  繋ぎ直し成功時の差し替え `cur.client = client`（`session-controller.ts:443`）は**素のまま入る**ので、
  読み戻すとリアクティブプロキシになり、口の同一性比較が**必ず偽**になる。一次資料で確認済み。
- **決定**: 繋ぎ直し成功時の差し替えを `markRaw(client)` にする。タスク **T9** を追加し、T3 / T4 より前に置く。
  AC5（成功 → 再切断 → はしごが回る）の characterization も T9 で書く。
- **理由・代替案**: 代替案は比較側に `toRaw` を置く形。却下する——`session-link.ts` は
  **Vue を知らない純粋モジュール**（import は `type { WsClient }` の 1 行のみ）なので、`toRaw` を使うなら
  判定の一部が `session-controller.ts` に残り、requirements AC7 に反する。`markRaw` は
  **store が `add()` で既に宣言している不変条件を、差し替え経路にも適用するだけ**で、
  そもそも `WsClient` がプロキシに包まれること自体が意図されていない。
- **影響（design の訂正）**: design「D-c」の「`onClose` の判定は式を関数へ移すだけで**真偽が変わらない**」は
  **誤り**だった。現行の `onClose`（`session-controller.ts:493`）の `sessionsStore.get(sessionId)?.client === client` は
  繋ぎ直し成功後に必ず偽になるので、**成功 → 再切断ではしごが二度と回らない**（本件と同じ根から出た
  2 つ目の不具合）。AC5 は「退行が無いことの確認」ではなく「いま壊れているものを直す」になる。
  実装の変更は `session-controller.ts` に閉じたまま（`stores/sessions.ts` は注記だけ）で、
  design「対象範囲」の表は変わらない。**この逸脱は review が見る対象**。

## D12 第 2 項に `connected` の門を付ける——D5 / D10 / D11 の判断そのものを覆す（2026-09-10T08:45:23Z）

- **背景**: review ラウンド1 の must（組み込みレビュー由来）。**`SessionState.client` は繋ぎ直しが
  成功するまで差し替わらない**ので、はしごが回っている間ずっと第 2 項が真になる。そこへ

## D14 `openSession` の `onClose` にも同じ述語を当てる（2026-09-10T10:40:29Z）

- **背景**: T11 の独立点検が、対の片側だけが述語化されていると指摘した。`tryResume` の `onClose` は
  `isSessionClient` で門番するのに、`openSession` の `onClose` は無条件に `startReconnect` へ入る。
  `sessionsStore.add` は同じ id で `byId.set` し直すので、**既に開いているセッションを開き直す**と
  口が差し替わり、そのあとに古い口の `close` が届くと**健全な口を抱えたままはしごが始まる**。
- **決定**: `openSession` の `onClose` も `isSessionClient(sessionsStore.get(sessionId)?.client, client)`
  で門番する。テストで両方向を固定した（変異で赤化を実測）。
- **理由・代替案**: **本 work の門がこの経路を悪化させる**ため、据え置けない。門が無かった頃は
  健全な口からのフレームが `updateScreen` を通って `connected` へ戻し、はしごが黙って隠れていた
  （自己回復）。門を付けた今は同じフレームが落ちるので、**画面が固まる**側へ倒れる
  ——本 work が直しに来た症状そのもの。代替案（backlog へ回す）は、自分で作った退行を残すことになる。
- **影響**: 「この口がまだセッションのものか」で `startReconnect` を門番する形が両方の `onClose` で

  従来も `startReconnect("")` が先頭で早期 return していたので**振る舞いは変わらない**。
