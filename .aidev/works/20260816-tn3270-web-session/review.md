## 作ったもの

**`terminal: "3270"` を指定すると 3270 ホストに繋がり、既存の web-ui がそのまま描く。**

| 層 | 追加/変更 |

| `web-ui` | `ConfigCard.vue`（端末の種類・モデルの選択）・`openConfigured.ts`（開く指示に載せる）・`stores/systems.ts`（型） |

**`web-ui` の描画は 1 行も触っていない**（spec D2 のとおり）。

## 効いた判断

### 1. `SessionEntry` を触らなかった（spec D5）

`SessionEntry.session: Session5250` は `server`（1,357 行）と `ws-handler`（778 行）の前提。
ここを差し替える案もあったが、**プリンターセッションと同じ形**——別マネージャを立てて
`ws-handler` の入口で振り分ける——に倣った。

結果、**5250 の経路は 1 行も変わっていない**（`onOpen` の先頭に 1 行足しただけ）。
server の既存テスト **1,183 件が緑のまま**なのがその証拠。

### 2. 画面の変換を 1 か所に閉じた

2 つの `ScreenSnapshot` は近いが同一ではない。**変換は `server` に置く**——
`tn5250` と `tn3270` は**兄弟パッケージで相互参照禁止**（`dependency-direction.test.ts`）で、
両方を知ってよいのは上位の `server` だけ。

写像で気をつけた点:

- **`modified` → `mdt`**。名前が違うだけで意味は同じ（変更データタグ）
- **色**——3270 の `default` / `black` は 5250 に無い。どちらも「地の色」なので `green` に寄せた
- **`columnSeparator`** は 5250 側にしか無いので `false` 固定

### 3. 使えないキーを読み替えなかった（spec D4）

`PageUp` を `F7` に写すような気の利かせ方はしない。ホストのアプリが F7 に別の意味を
持たせていたら**取り返しがつかない**。`PA1`〜`PA3` は 3270 で新たに通す。

### 4. モデル 3 / 4 を入口で断った（spec D3）

32 行・43 行は web-ui の `rows: 24 | 27` に収まらない。**型を曲げるより入口で断る**。
対応するときは web-ui ごと広げる話になる。

## 直したもの（自分の変更が壊した 2 件）

- **`log-independence`**——`childLog` をライブラリ側（`@ts5250/base`）から取っていた。
  server は**自前の pino を直接使う**規約（監査ログが静かに消えるのを防ぐため）。`./log.js` に直した
- **`electron-stage-packages`**——配布物の一覧に `tn3270` が増えた。
  一覧は依存から自動で辿る作りなので、**テストの期待値だけ**を追随させた（これがこのテストの役目）

## 残っていること（今回の対象外・spec 6）

マクロ・HLLAPI・PC コマンド・watch・プリンター・自動サインオン・予約・永続化。
**3270 セッションでは `PROTOCOL_ERROR` で断る**——「3270 では使えない」と言い分ける
（「セッションが無い」と返すと、開いているのに使えないのか分からない）。

### 実機で通した（配線の確認）

`mini3270` だけで終わらせず、**server の WS 経路そのものを実ホスト（TK4-）へ通した**。

```
opened: 24x80   欄 147・非保護 1
 1|Terminal   CUU0C0                                    Date  16.08.26
21|                              MVS 3.8j Level 8505
23|Logon ===>
```

続けて `Logon` 欄に文字を書いて Enter を送ると、**ホストが応答を返した**:

```
key-done: true
 1| IKJ56420I USERID HELP N ***
```

TSO が「そのユーザーIDは使えない」と答えている——つまり**打った文字がホストに届いている**。
欄の書き込み・AID・応答画面・監査ログまで、経路が実機で一通り動く。

> 残るのは**ブラウザからの操作**（画面描画とキーボード）。型を合わせたので描けるはずだが、
> **人の目で見たわけではない**。

## 追加レビュー: **ブラウザで実際に触った**（Playwright）

`scripts/verify-browser-3270.mjs` を足し、**build 済み web-ui を server で配信して
実ブラウザから TK4- に繋いだ**。既存の `verify-browser-*.mjs` と同じ作り。

### 実バグが 1 件出た——**欄の添字が 1 つずれていた**

`Field.index` は**1 始まり**（5250 の口と同じ規約）。それを**配列の添字**として使っていたため、
UI が入力欄を添字で指すと**隣の保護欄に当たり `FIELD_PROTECTED`** になった。

**server 側のテストでは出なかった**——あちらは座標（`{row, col}`）で指していたため。
**ブラウザは添字で指す**ので、実際に触るまで見つからない類の食い違いだった。
回帰テストを `ws-tn3270.test.ts` に追加（添字で指して打ち、保護欄に当たらないこと）。

### 私の判定が誤っていた 1 件——`innerText` では真っ白に見える

**3270 は画面全体が欄になる**ので、UI は文字を `<input>` の value に入れて描く
（5250 は定数部分が欄でないのでテキストとして出る）。
最初 `innerText` だけを見て「画面が描かれていない」と判定したが、
**スクリーンショットを見たら完璧に描けていた**。判定を value 込みに直した。

> 実装ではなく**確かめ方の誤り**。「テストが赤い＝実装が悪い」と決めてかからず、
> 目で見て切り分けたのが効いた。

### ブラウザで通ったこと

| 確認 | 結果 |
|---|---|
| 3270 ホストの画面が描かれる | **PASS**（TK4- の起動画面・AA 込みで正しく描画） |
| 状態表示に画面サイズが出る | **PASS**（`画面 24x80`） |
| 入力欄が描かれる | **PASS** |
| 打った文字がホストへ届き応答が返る | **PASS**（`IKJ56420I USERID HELP N ***`） |
| PF キーで例外が出ない | **PASS** |
| WS にエラーが流れていない | **PASS** |

**これで「ブラウザからの操作は人の目で見ていない」は解消**した。

## 追加レビュー 2: **pub400（実 IBM i）で試したら、ブラウザのタブが落ちた**

TK4-（メインフレーム）だけで確かめて終わりにしていたが、**このライブラリの主な接続先は IBM i**。
`scripts/verify-browser-3270.mjs` を相手先で切り替えられるようにして pub400 に繋いだところ、
**画面が出ず、ブラウザのタブごとクラッシュ**した。

### 原因: **長さ 0 の欄**

3270 は**属性桁が隣接すると中身の無い欄**ができる。
pub400 のサインオン画面は **52 欄中 13 欄が長さ 0**（行末 80 桁目に属性桁が並ぶ形）。

web-ui の描画は欄を `c += スライス幅` で辿るので、**幅 0 だと同じ桁を回り続ける**
——`segs` が無限に伸びてメモリを食い潰し、タブが落ちる。
**5250 では長さ 0 の欄が出ない**ので、この形は今回初めて踏んだ。

### 直した 2 層

1. **server（`tn3270-adapt.ts`）**——長さ 0 の欄は**渡さない**。
   5250 側の消費者は「欄は 1 桁以上ある」前提で書かれており、描画も入力も置き場が無い。
   **添字（`index`）は振り直さない**——入力欄の指定に使うため番号を保つ
2. **web-ui（`ScreenGrid.vue`）**——幅 0 のスライスは**桁を占めない**として飛ばす。
   データ次第でタブが落ちる作りを残さない（他の生産者が同じ形を出しても耐える）

回帰テストを両方に入れた（`ws-tn3270.test.ts` / `screen-grid-zero-length-field.test.ts`）。

### 切り分けで効いたこと

「画面が出ない」の原因を、**届いていないのか描けていないのか**で切り分けた:

1. WS フレームを覗く → `opened` だけで `screen` が無い
2. server 側にログを入れる → **push は 52 欄で発火し送信も成功**している
3. 生の WS クライアント（ブラウザ抜き）で繋ぐ → **`opened` と `screen` の両方が届く**
4. → ブラウザ側の問題と確定。`page.evaluate` が `Target crashed` を返して**クラッシュが判明**

**サーバーとクライアントのどちらかを外して試す**のが決め手だった。

### 判定側の誤りも 2 つ直した

- **`innerText` では真っ白に見える**——3270 は画面全体が欄になるので、文字は `<input>` の value に入る
- **空画面のうちに判定していた**——桁数だけ見ると空の 24x80 でも条件を満たす。
  中身（既知の文字列）が出るまで待つように変えた

### ブラウザで確認できたこと（2 ホスト）

| | TK4-（MVS 3.8j） | **pub400（IBM i 7.5）** |
|---|---|---|
| 画面が描かれる | PASS | **PASS** |
| 画面サイズ表示 | PASS | PASS |
| 入力欄が描かれる | PASS（2） | **PASS（3）** |
| 打った文字が入る | PASS | PASS |
| Enter でホストが応答 | PASS | PASS |
| PF キーで例外なし | PASS | PASS |

**メインフレームと IBM i の両方**で、ブラウザから 3270 が使えることを確かめた。

## 追加レビュー 3: **ファンクションキーとページ送りが効かない**（利用者からの指摘）

### 分かったこと

| キー | 状況 |
|---|---|
| **F1〜F24** | **効いていた**（pub400・実機の実機で画面が変わることを確認） |
| **PageUp / PageDown** | **効かない**——`PROTOCOL_ERROR` で弾いていた |
| **Attn / SysReq** | 同上（3270 に AID が無い） |

UI の状態バーは 5250 の語彙のまま **Attn / SysReq / PageUp / PageDown のボタンを出していた**。
押せるのに効かないので、利用者には「機能していない」としか見えない。

### ページ送りは**実機で測って決めた**

社内機のサブファイル画面（`EMPSFR`）を 3270 で開き、キーを順に送って画面が動くかを見た:

| 送ったキー | 結果 |
|---|---|
| **`PF8`** | **次ページへ動く**（00011 吉田純一） |
| **`PF7`** | **前ページへ戻る**（00001 田中太郎） |
| `PA2` / `PA1` | 動かない |

x3270 も**同じ割り当てのキーマップを同梱している**（`Prior→PF(7)` / `Next→PF(8)`）。
ただし別のキーマップでは `Prior→PA(1)` としており、**正解が 1 つに決まる話ではない**
——だから**実機で測った方**を採った。

### 直したところ

**読み替えは送信の一本道（`sendKey`）に置いた。** キーボードも状態バーのボタンもマクロも
ここを通るので、片方だけ直すと「キーボードでは動くのにボタンでは動かない」になる。

- `PageUp` → **`F7`** ／ `PageDown` → **`F8`**（3270 セッションのときだけ）
- `Attn` / `SysReq` / `Help` / `Print` → **送らず案内を出す**（黙って捨てない）
- 状態バーは 3270 のとき **Attn / SysReq を無効化**し、PageUp/PageDown の説明に
  「3270 では F7 / F8」と出す

**サーバー側は厳しいまま**にした——`toAid3270` は今も `PageUp` を拒否する。
これは**キーの割り当て**の話であって、プロトコルの話ではない。線上には `F7` が流れ、
監査ログにも `F7` が残る。

### 確認

ブラウザ（pub400）で **PageDown が `F8` として送られる**ことを確かめた。
`F8` が実機でページを送ることは、社内機のサブファイル画面で確認済み。
`sendKey` の読み替えは単体テストで固定した（`aid-3270-mapping.test.ts`）。

### 検証の途中で踏んだこと（記録）

**ブラウザからのサインオンを自動化しようとして、欄をまたいで入力した。**
Playwright の `click()` は**要素の中央**を押すので、10 桁の欄の 5 桁目にカーソルが載り、
そこから打った文字が欄からあふれて隣の欄へ流れた（`"     USER"` のような並びになる）。
**製品の不具合ではない**——カーソル位置から打つのは正しい挙動で、
実機の 5250 端末でも同じことが起きる。自動化の側で欄の先頭へカーソルを置く必要があった。

> このとき**デバッグ出力に、あふれた 3 文字（パスワードの一部と思われる）が出た**。
> 出力していたスクリプトは削除済み。**資格情報の扱いは要対処**。
