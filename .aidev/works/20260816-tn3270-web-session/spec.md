# 仕様: 3270 を Web エミュレータとして使う

## 1. 端末タイプは `kind` ではなく `terminal` で指定する

WebSocket の `open` に **`terminal?: "5250" | "3270"`（既定 `"5250"`）** を足す。

**`kind`（display / printer）と混ぜない。** あちらは**セッションの種別**で、こちらは**端末の種類**。
直交する軸を 1 つの列挙に畳むと、`kind: "printer"` × `terminal: "3270"`（TN3270E プリンター）を
足したくなったときに破綻する。

3270 では併せて次を受ける:

| 項目 | 既定 | 備考 |
|---|---|---|
| `model` | 2 | 2/3/4/5。**代替画面サイズ**を決める（`EWA` で効く） |
| `ccsid` | 37 | 日本語機は 5035 / 930 / 939 |
| `host` / `port` / `tls` | port 23 | 5250 と同じ |

`screenSize`（`24x80` / `27x132`）は **5250 の語彙なので 3270 では使わない**——3270 の代替サイズは
モデル番号が決める（32x80 / 43x80 / 27x132）。

## 2. 画面は**変換して既存の型に載せる**

`server` と `web-ui` が話す画面型は `@ts5250/tn5250` の `ScreenSnapshot`。
3270 の型はこれに**極めて近い**ので、**server 側で 1 か所変換**し、**web-ui は無改修**にする。

| 項目 | 変換 |
|---|---|
| `sessionId` | 3270 側に無い → 付与する |
| `rows` / `cols` | `number` → `24 \| 27` / `80 \| 132`（3270 のモデル 3/4 は 32/43 行） |
| `Cell.columnSeparator` | 3270 に無い → `false` |
| `Cell.background` / `intensified` | 5250 に無い → **落とす**（描画に使われていない） |
| `alternate` / `unformatted` | 5250 に無い → 落とす |

> **行数が合わない問題**: モデル 3（32 行）・4（43 行）は 5250 の `rows: 24 | 27` に収まらない。
> **今回はモデル 2（24x80）と 5（27x132）だけを受ける**——型を曲げるより入口で断る。
> 3/4 は「web-ui の型を広げる」別作業（要求があってから）。

## 3. キーは名前で受け、3270 の AID へ写す

| WS のキー名 | 3270 | 備考 |
|---|---|---|
| `Enter` | `enter` | |
| `F1`〜`F24` | `pf1`〜`pf24` | |
| `Clear` | `clear` | |
| **`PA1`〜`PA3`** | `pa1`〜`pa3` | **3270 で追加**（5250 には無い） |
| `PageUp` / `PageDown` / `Help` / `Print` / `SysReq` / `Attn` | — | **拒否する** |

**拒否するものを勝手に読み替えない。** `PageUp` を `F7` に写すような気の利かせ方は、
ホストのアプリが F7 に別の意味を持たせていたときに**取り返しがつかない**。

## 4. 入力欄への書き込み

`WsKey.fields`（`{field, value}` の配列）を 3270 でも受ける。
`field` は**添字**または**行桁**で、どちらも `snapshot().fields` から解決する。

書き込みは **`setCursor(欄の先頭) → type(値)`**。3270 の `type()` は欄の種類（素・混在入力・DBCS 欄）を
見て日本語を撥ねたり `SO`/`SI` で包んだりするので、**そのまま呼べばよい**。

`secretRef`（マクロの秘密）は**今回受けない**——マクロ自体を対象外にしているため。

## 5. セッションの持ち方——**5250 の `SessionEntry` には混ぜない**

`SessionEntry.session: Session5250` は `server`（1,357 行）と `ws-handler`（778 行）の前提。
ここに 3270 を差し込むと影響が全体に及ぶ。

**プリンターセッションと同じ形にする**——`SessionManager` とは別の
**`Tn3270Manager`** が 3270 のセッションを持ち、`ws-handler` が `terminal` で振り分ける。
既に `kind: "printer"` が `openPrinter` へ振り分けられているので、**同じ筋**に乗る。

## 6. 対象外（今回入れない）

マクロ・HLLAPI・PC コマンド・watch・プリンター・自動サインオン・予約・永続化。
**5250 の周辺機能は 3270 の入口を通らない**（`ws-handler` で `terminal === "3270"` のとき拒否）。

## 決定

- **D1**: 端末タイプは `terminal` で受ける（`kind` に混ぜない。軸が直交するため）
- **D2**: 画面は **server で変換**して既存の `ScreenSnapshot` に載せる（web-ui 無改修）
- **D3**: **モデル 2 と 5 だけ**を受ける。3/4（32/43 行）は既存の型に収まらないので入口で断る
- **D4**: 使えないキーは**拒否する**（読み替えない）
- **D5**: 3270 は**別マネージャ**が持つ（`SessionEntry` を汚さない）
