# 3270 を Web エミュレータとして使えるようにする

## 背景

`@ts5250/tn3270` は**ライブラリとしては一通り仕上がっている**——接続・交渉（基本 TN3270E 含む）、
コマンド 8 種、オーダー全種、DBCS の入出力、編集キー・移動キー・挿入モード、応答モードまで
s3270 との突き合わせ済み（`20260815-tn3270-emulator` / `20260815-tn3270e-basic`）。

**しかし Web からは使えない。** 現物で確かめた:

| パッケージ | `tn3270` への参照 |
|---|---|
| `server` | **0 件**（`@ts5250/tn5250` のみ依存） |
| `web-ui` | **0 件**（同上） |
| `electron` | **0 件** |

端末タイプという設定項目自体がどこにも無く、**UI から 3270 を選ぶ口が無い**。
これは最初のスコープ決め（「ライブラリ層まで」）どおりで、取りこぼしではない。

## やりたいこと

**ブラウザで 3270 ホストに繋いで画面を見て、キーを打てるようにする。**

## 満たすこと

1. WebSocket の `open` で**端末タイプ 3270 を指定**でき、3270 ホストへ繋がる
2. 画面が**既存の web-ui の描画でそのまま出る**（日本語 DBCS 込み）
3. **AID キーが打てる**（Enter / PF1-24 / PA1-3 / Clear）
4. **入力欄に文字が打てる**（欄指定・カーソル指定の両方）
5. 5250 の既存機能を**壊さない**

## 今回やらないこと（意図的）

**5250 固有の周辺機能は 3270 に持ち込まない。** どれもプロトコルか IBM i に依存していて、
3270 では意味を持たないか、別途の設計が要る。

- マクロ・HLLAPI・PC コマンド（STRPCCMD）・画面監視（watch）
- プリンターセッション・自動サインオン（RFC 4777）・予約（Reserve）
- セッションの永続化・再接続（ブラウザを閉じたら切れてよい）

これらは**別作業**とし、要るとなったら都度足す。

## 制約

- **既存の型・経路を壊さない**。`SessionEntry.session: Session5250` は `server` 全体（1,357 行）と
  `ws-handler`（778 行）が前提にしている。ここを差し替える改修は影響が大きすぎる
- 画面の型は近い（後述）が**同一ではない**——`server`/`web-ui` が話すのは
  `@ts5250/tn5250` の `ScreenSnapshot`
- ブラウザから TCP は張れないので、**必ず server 経由**

## 手掛かり（先に現物で確かめた）

**2 つの画面型は驚くほど近い。**

| | 5250 | 3270 |
|---|---|---|
| `Cell` | `columnSeparator` あり | `background` / `intensified` あり |
| `CellKind` | `+ "unmappable"` | 同じ 6 種 |
| `ScreenSnapshot` | `sessionId` / `gui` / `lastWrite` | `alternate` / `unformatted` |

**差は数フィールド**なので、server 側で**変換して既存の型に載せれば web-ui は無改修で描ける**見込み。

## 受け入れ基準

- `open` に端末タイプ 3270 を指定して**画面が出る**（`mini3270` を相手にした自動テストで確認）
- **AID キーと文字入力**が 3270 セッションに届く
- 既存の 5250 のテストが**全部緑のまま**
