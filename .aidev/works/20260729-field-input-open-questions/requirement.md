# 要件: field-input の「要確認」2 件を決着させる

## 背景 / 課題

`.aidev/backlog/field-input.md` に残る 2 件はどちらも
**「実機がどう振る舞うか確認してから直すか決める」**と据え置かれたまま。
判断材料が無いので誰も触れず、**backlog に残り続けている**。

1. **EDTMSK 分解欄の境界をまたぐ操作** — EDTMSK（編集マスク）はワイヤ上に存在せず、
   ホストは「複数の入力欄＋間の保護された編集文字」へ**分解して**送る（前作 #205 で確認済み）。
   分解された欄は独立した欄なので、**2 つ目の欄の先頭で Backspace を押しても前の欄へ戻らない**。
   `ArrowLeft` は左端でペインのセル移動へ委譲されるのに、`Backspace` は `cursor <= 0` で何もしない。
2. **数値専用欄に編集文字が入る構成** — `field-validate.ts` の許容集合は `/^[0-9.,+-]*$/`。
   `$1,234.56` / `1,234.56 CR` / `***1,234` は `FIELD_TYPE` で拒否される。
   EDTWRD / EDTCDE は IBM の仕様上 **output-capable フィールド向け**なので通常は表示のみだが、
   「編集文字を含む値を入力欄へ送り返す構成が実在するか」を確かめていない。

## 目的 / ゴール

**2 件とも判断を確定させ、backlog から消す。** 直す必要があるものは直し、
必要が無いものは**必要が無いと分かった根拠を残して**閉じる（再調査させない）。

## スコープ

### 対象

- 上記 2 件の**調査と、その結論に基づく対応**（実装 or 「不要」の記録）
- 実装する場合の単体テストと回帰テスト

### 対象外

- EDTMSK そのものの実装（前作 #205 で「追加実装は要らない」と結論済み）
- 数値欄の許容集合を**根拠なく広げること**。誤入力を通すだけになる

## 機能要件

1. **境界をまたぐ Backspace**: 調査で「戻るべき」と決まったら、
   欄の先頭で Backspace を押したときに**前の入力欄の末尾へ移って 1 文字消す**。
   戻るべきでないなら現状維持とし、理由を残す。
2. **数値欄の許容集合**: 調査で「編集文字入りの値が入力欄へ来る構成が実在する」と分かったら
   受け入れる。実在しないなら現状維持とし、理由を残す。
3. どちらの結論でも **backlog の該当項目を閉じる**（結論と根拠を書いて `[x]` にする）。

## 非機能要件 / 制約

- **矩形選択・コピー＆ペーストを妨げない**（桁割りに触らない）。
- 既存のキー操作（`Backspace` の欄内挙動・`ArrowLeft` の委譲）を壊さない。
- **秘密を成果物に書かない**（実機検証は環境変数のみ）。

- [ ] 直すと決めたものは実装され、単体テストがある（**空振り検証**まで確認）
- [ ] 直さないと決めたものは、`decisions.md` と backlog に**理由が残っている**

## 未確定事項 / 確認したいこと

- **U1**: 実機（5250 端末）は**欄の先頭で Backspace を押したとき前の欄へ戻るか**。
  参照実装（GNU tn5250 / tn5250j）の `kf_backspace` が何をしているかで決める。
  戻る場合、**どの欄へ**戻るか（画面順の 1 つ前か、同じ行の左隣か）。
- **U2**: そもそも本実装の `Backspace` は欄内でどう動くか（破壊的か非破壊的か）。
  原典には `destructive_backspace` という設定がある。
- **U3**: 編集文字（`$` `,` `*` `CR`）を含む値が**入力欄へ**来る構成が実在するか。
  DDS で `EDTWRD` / `EDTCDE` を**入力可能欄**に書けるのかを実機のコンパイルで確かめる。
- **U4**: U3 が「書ける」場合、ワイヤ上その欄はどんな FFW / 長さで来るか。
  分解されるのか、編集文字ごと 1 つの欄で来るのか。
