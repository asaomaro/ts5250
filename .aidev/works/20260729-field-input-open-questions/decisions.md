# 決定記録

## D1: 欄の中の Backspace は**破壊的なまま**にする（原典と意図的に違える）

- 背景: GNU tn5250 の Backspace は**既定で非破壊**（カーソルを左へ動かすだけ。
  `destructive_backspace` は既定 0）。本実装は破壊的（1 文字消して左詰め）。
- 決定: 欄の中は**破壊的のまま**。**欄の先頭のときだけ**原典に合わせて前の欄へ移す。
- 理由: 破壊的 Backspace は PC の利用者が期待する挙動で、非破壊に変えると既存の操作が
  全部変わる。**欄の先頭では原典も削除していない**ので、そこだけ合わせても食い違いは生じない。
- 影響: backlog の指摘（分解欄をまたげない）は解消し、既存の欄内編集は無変更。

## D2: 許容集合は広げず、「その欄の現在値にある文字」を通す

- 背景: `EDTCDE` / `EDTWRD` は用途 B でも書け、編集文字が**入力欄の中に**来る（実測）。
  `EDTCDE(A)` 系は `CR`、`EDTWRD` の定数文字は任意（`$` `*` `/`）。
  いまの許容集合 `/^[0-9.,+-]*$/` で弾くと**画面ごと送信できなくなる**。
- 決定: `validateFieldContent` に「その欄の現在値」を渡し、**そこに含まれる文字は違反にしない**。
- 理由 / 代替案:
  - 許容集合に `$` `*` `/` `C` `R` を足す案 → **編集語の定数文字は任意**なので網羅できず、
    かつ**ただの誤入力まで通る**
  - 送信時検証を丸ごと外す案 → MCP・マクロ・ペーストという実機に無い入口が無防備になる
  - 「ホストが書いた文字だけ通す」なら、**不合理（自分が受け取った値を送り返せない）だけが消えて
    他は締まったまま**
- 影響: DBCS 種別・コードページの検証は**緩めない**（別の理由の検証）。テストで固定した。

## D3: 送信時検証は「実機に無い層」だと明記した

- 背景: 実機の端末はシフト種別を**打鍵のときだけ**見て、バッファの中身はそのまま送る
  （原典の `tn5250_field_valid_char` の呼び出し元は打鍵処理の 1 か所だけ）。
- 決定: `validateFieldContent` の JSDoc に「これは実機に無い層で、MCP・マクロ・ペーストという
  実機に無い入口を守るために要る」と書いた。
- 理由: この前提が無いと、次に同じ不具合を踏んだとき**「実機がそうだから」で
  誤った方向（検証を強める）へ倒れる**。層の目的を書いておく。
