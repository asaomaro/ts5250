# 計画: グリッド線の実機検証と色の修正

## split 判定
分割しない。

## 作業順序
1. T1 DDS リファレンスを取得して `GRDBOX` 構文と色表を確定
2. T2 色の解釈を修正（GRID_COLOR）
3. T3 実機で DSPF をコンパイルして表示 → バイト列を捕捉
4. T4 マイナー構造を length 基準に直し、項目ごとの線種を読む
5. T5 実機のバイト列で回帰テストを固定し、再検証

## リスク
| # | リスク | 対応 |
|---|---|---|
| R1 | DDS 構文を推測で当ててコンパイルを繰り返す | **原典（IBM DDS リファレンス）を直読**してから書く |
| R2 | 実機と原典（ディセクタ）が食い違う | 実機のバイト列を正とし、テストに焼き付ける |
| R3 | 既存のグリッド描画テストを壊す | 色コードでの期待値へ更新し、全通過を確認 |

## テスト方針
- 実機のバイト列そのものを使ったテスト（2 種の箱）
- 既定へのフォールバック（項目 0xFF → 主構造）
- 実機: DSPF を表示し、警告ゼロで DDS の指定と一致すること
