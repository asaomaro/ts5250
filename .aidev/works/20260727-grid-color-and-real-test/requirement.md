# 要件: グリッド線を実機で検証し、色の解釈を正す

## 背景 / 課題

PR #178 でグリッド線（WDSF 0x60/0x61）を実装したが、**実機表示は未検証**のまま残していた。
DDS の `GRDBOX` 構文が確定できなかったためで、PR にも未検証の穴として明記していた。

IBM の DDS リファレンス（`rzakcmst.pdf`）を取得して直読し、構文を確定して実機に当てる。

## 原典で判明した事実

### 1. `GRDBOX` の構文（DDS リファレンス「GRDBOX (Grid Box) keyword」）

```
GRDBOX((*POS ([*DS3] [*DS4] start-row start-column depth width))
       (*TYPE type-of-box [horizontal-rule] [vertical-rule])
       [(*COLOR color)] [(*LINTYP line-type)] [(*CONTROL)])
```

- **`*POS` は 4 値**（開始行・開始桁・深さ・幅）を括弧で包む
- **`*TYPE` は必須**（`PLAIN` / `HRZ` / `VRT` / `HRZVRT`）
- レコードには **`GRDRCD`** が要る
- 機能欄は 45–80 桁の **36 文字**しかないので `+` 継続が要る

### 2. **グリッド線の色は 5250 の属性バイトではない**（GRDATR の Table 14）

`BLU=X'01' GRN=X'02' CYAN=X'03' RED=X'04' VLT=X'05' YLW=X'06' WHT=X'07' …
NONE=X'FF'`（表示装置の既定）。

PR #178 の実装は `decodeAttribute` に渡しており**誤り**（全部緑になる）。

### 3. 線種は実装と完全一致（Table 15）

`SLD=00 THK=01 DBL=02 DOT=03 DSH=08 THKDSH=09 DBLDSH=0A NONE=FF`。

## 実機で判明した事実

DSPF をコンパイルして表示し、バイト列を捕捉した。

**マイナー構造は `length=0x0b`＝11 バイト**で、Wireshark のディセクタが模す 10 フィールドより
1 つ多い。増えているのは**項目ごとの線種**で、`(*LINTYP DSH)` を指定した箱の実データが
`… 01 08 02 08`（色=BLU / 線種=DSH / 横罫 2 / 縦罫 8）と並ぶことから確定した。

## スコープ

### 対象
- `GRID_COLOR` 表の追加と、描画側の色解釈の修正
- マイナー構造を**先頭の length に従って読む**（長さを決め打たない）
- 項目ごとの線種（`lineStyle`）の追加と、既定（0xFF）へのフォールバック
- 実機のバイト列をそのまま使った回帰テスト

### 対象外
- グリッド線の印刷・DBCS 端末以外での挙動
- `*CONTROL`（p-field による実行時の表示/消去切り替え）

## 完了条件

- [ ] グリッド線の色が DDS の色コードで解釈される（属性バイトではない）
- [ ] 0xFF（表示装置の既定）は主構造の値へ、なお既定なら白・実線へ倒す
- [ ] 項目ごとの線種を読み、主構造の既定より優先する
- [ ] マイナー構造を length に従って読む（11 バイトでも位置がずれない）
- [ ] 実機のバイト列を使った回帰テストがある
- [ ] **実機で GRDBOX を使った DSPF を表示し、警告ゼロで DDS の指定と一致する**
- [ ] build / test / lint / vue-tsc ビルドが通る
