# 要件: WDSF 0x60 の罫線の寿命を ACS と同じにする（窓・0x5F・0x61）

## 背景 / 課題
台帳「DS5250 の残り（罫線の寿命・WDSF 0x54/0x55）」の罫線。原典（CLEAR UNIT は `GridPlane` だけを捨てる）と実機の記録（S9R167D で CLEAR UNIT の後も罫線が残る）が食い違って見えていた。
ACS のコアの罫線の面（`ECLPS.GridPlane`＝描画の元）を probe から読めるので、DSM で寿命を測った。

## 目的 / ゴール
窓・REMOVE ALL GUI CONSTRUCTS（0x5F）・CLEAR GRID LINES（0x61）・CLEAR UNIT の後に残る罫線が ACS と同じ状態。

## ユーザーストーリー
- US1: 罫線のある画面に窓を出すアプリの利用者として、ACS と同じく窓の中に罫線が通らないでほしい。なぜなら、窓の中身の上に罫線が引かれると読めないから。（受け入れ: AC1, AC4）

## スコープ
### 対象
- 窓を作ると、その範囲の罫線を消す／0x5F は罫線を残す／0x61 は矩形だけを消す
### 対象外
- WDSF の否定応答（台帳の別項目）・0x54・0x55・画面の大きさが変わるときの罫線（このセッションは 27x132 にならず測れない）

## 完了条件 (受け入れ基準)
- [ ] AC1: 窓を作る前の罫線は窓の範囲（位置から幅＋6 桁・深さ＋2 行）が描かれない。後の罫線は削られない（単体）
- [ ] AC2: 0x5F の後も罫線は残る（単体）
- [ ] AC3: 0x61 は指定の矩形だけを削る（単体）
- [ ] AC4: 実機のブラウザで GRIDLIFE の 7 巡の罫線が ACS の罫線の面と一致
