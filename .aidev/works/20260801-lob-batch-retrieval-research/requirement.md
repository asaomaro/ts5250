# 要件: LOB をまとめて取る要求形式が原典にあるか確かめる

## 背景 / 課題

`fillLobs` は **LOB セルの数だけ往復する**（`packages/hostserver/src/db/query.ts:443-478` が
セルごとに `retrieveLob` を呼び、`lob.ts:54` が locator を 1 つだけ受け取る）。
100 行 × 1 列なら 100 往復。実機は 1 往復 4〜7 秒（PUB400）なので現実的でない。

既定では取りに行かないため既定利用では 0 往復だが、backlog（`hostserver.md:336`）は
**「無いと決めつけて自前で最適化するのは避けた。まず原典を確かめること」**として保留していた。
AGENTS.md の「参照実装の該当クラスを**ソースで読む**。要約や記憶で代替しない」に沿った保留。

## 目的 / ゴール

**原典（JTOpen / jtopenlite）を直読して、まとめ取りの要求形式があるか白黒つける。**

結論が「無い」でも価値がある——推測で自前の最適化を組む道が閉じ、
代わりに原典が実際に使っている手段が分かる。backlog の項目を根拠つきで閉じられる。

## スコープ

### 対象

- `0x1816`（Retrieve LOB Data）の要求形式が複数ロケーターを取れるか
- DB ホストサーバーの **要求 ID を全列挙**し、複数 LOB 用の要求が他に無いことを確かめる
- 原典が往復を減らすために実際に使っている手段があれば、その仕組みと既定値
- 結論を `research.md` と backlog に残し、後から辿れる形にする

### 対象外

- **実装**。しきい値・要求形式はプロトコルの挙動であり、
  AGENTS.md「実機検証を単体テストの代替にしない」に従えば**実機でしか確かめられない**。
  このセッションは `.env` に `AS400_SECRET_KEY` しか無く実機に接続できないため、
  実装は**別 work** に送る（本 work は判断材料を揃えるところまで）
- 原典ソースのリポジトリへの取り込み（AGENTS.md: 同梱頒布になる）

## 機能要件

- 結論が**一次ソースの引用**に基づく（クラス名・メソッド名・行の内容）。
  要約サイトや記憶に基づく記述をしない
- 「無い」と結論するなら、**探した範囲を明示する**（要求 ID の全列挙など、
  網羅の根拠を示す）。「見つからなかった」と「存在しない」を区別する
- 原典の既定値・上限は**数値で**書く（次に読む人が基準線を持てる）

## 非機能要件 / 制約

- **原典照合は主エージェントが直読する**（protocol「2.6」）。サブエージェントに委譲しない
  ——委譲先のネットワーク権限が落ちると照合不能になり、知識ベースの幻覚を量産する
- 実機（IBM i）は使えない（資格情報なし）
- 原典のソースをリポジトリに取り込まない
