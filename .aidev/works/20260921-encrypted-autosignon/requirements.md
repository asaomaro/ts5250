# 要件: 自動サインオンのパスワードを ACS と同じく代替パスワードで送る

## 背景 / 課題
- 台帳「【まとめ】telnet・自動サインオン・装置名の差」の「自動サインオンでパスワードを平文で送る（中・要実測）」。
- 当 PJ は RFC 4777 の自動サインオンで `IBMSUBSPW` に平文のパスワードを入れていた。平文 telnet（23）ではパスワードがそのまま流れる。

## 目的 / ゴール
- 自動サインオンでパスワードが平文で流れない状態（ACS と同じ送り方）。

## ユーザーストーリー
- US1: 保存した資格情報で自動サインオンする利用者として、パスワードを平文で流したくない。なぜなら、TLS でない接続では盗み見られるから。（受け入れ: AC1, AC2, AC3）

## スコープ
### 対象
- 代替パスワードの計算（QPWDLVL 0〜4）、パスワード・レベルの問い合わせ、telnet で暗号化して送る、表示・プリンター。
### 対象外
- 多要素認証（ACS の `ssoBypassSignonAdditionalFactor`）。Kerberos。
- ホストサーバー側のサインオン（`signon()`）の QPWDLVL 4 と数字で始まるパスワード（別の経路。台帳に残す）。

## 完了条件 (受け入れ基準)
- [ ] AC1: 代替パスワードは ACS の `PasswordSubstitute` と同じバイト列（QPWDLVL 0〜4）。
- [ ] AC2: 利用者名・パスワードがあれば、ホストの SEND のシードで代替パスワードを作り、IBMRSEED に自分のシード・IBMSUBSPW に代替パスワードを入れる。平文は送らない。作れないときはパスワードの変数を送らない。
- [ ] AC3: QPWDLVL はサインオン・サーバーに聞き（認証しない）、聞けなければ 0（ACS と同じ）。PUB400 で暗号化した自動サインオンが通る。
- [ ] AC4: 各判定を外すとテストが落ちる（`verify-by-mutation`）。
