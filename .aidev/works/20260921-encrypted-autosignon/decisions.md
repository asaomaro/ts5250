# 決定記録

## D1: 自動サインオンは暗号化する（平文をやめる）

- ACS の製品には平文の自動サインオンの設定が無く、常に代替パスワード（F1）。当 PJ も資格情報があれば暗号化する。コアの `TelnetLayer` は関数を渡されなければ従来の平文の形を残す（テスト・比較用）。

## D2: QPWDLVL が聞けなければ 0

- ACS も 0 にして DES で計算する（F1）。サインオン・サーバーに届かない環境で QPWDLVL 2 以上のホストだと自動サインオンが通らない（サインオン画面になる）が、ACS と同じ結果。
  平文へ落とすことはしない（パスワードを流さないのが目的）。

## D3: 計算は hostserver、配線は server

- tn5250 はホストサーバーに依存しない規約。代替パスワードとパスワード・レベルはホストの認証の仕組みなので hostserver に置き、server が関数にして tn5250 へ渡す。

## D4: IS を送るまで後続の受信を溜める（実測で見つけた）

- 最初の版は代替パスワードの計算（とレベルの問い合わせ）を待つ間に端末タイプ・BINARY・EOR へ答え、IS が交渉の後に届いた。ホストは IS を待たずにサインオン画面を出した（PUB400）。
  平文と同じ順序になるよう、IS を送るまで受信の処理を止める。あわせてレベルは作成時（接続の前）に聞き始める。

## D5: レベル 4 は実機で確かめていない

- 手元の実機は 0 と 3。レベル 4 は ACS の `PasswordSubstitute` を Java から呼んだ出力とバイト単位で一致させたところまで（未確認）。
