# レビュー: 最大化・タブ移動でも状態を維持する

## ラウンド 1

### 見た観点

要件適合 / 正確性 / 規約適合 / 保守性。差分は 8 ファイル（うち新規 2）。

### 確認したこと

- **利用者の指示 2 件が入っている**: 最大化・タブ移動。リロードは対象外（明示）。
- **アンマウントされる条件が「閉じたとき」だけになっているか**:
  プールの母集合は「一度でも開いた」∩「どこかのグループが持っている」。
  木を組み替えても、最大化しても、どちらの条件も変わらない。
  閉じたときだけ後者から外れる → `onUnmounted`（SQL の結果セット解放）が走る。
  単体テストで実体（`TransferPane`）が 0 件になることまで見ている。
- **Teleport の行き先**: 実要素にした理由と、`null` を無視する理由を decisions.md D1 に。
  ここは**セレクタ文字列だと静かに壊れる**（外れた要素にぶら下がる）ので、
  落ちるテストを必ず持たせた。
- **`registerPaneSlot` が古い要素を残す**件: 閉じたタブはプールの母集合から落ちるので
  参照されない。**残っても害が無い**ことを確認した（消す方が順序依存で危ない）。
- **最大化で木も比率も書き換えない**: `pane-maximize.test.ts` で不変条件として固定。
  実ブラウザで 695 → 1400 → 695px を実測（解除で戻る）。
- **`displayRoot()` の削除**: 参照は `App.vue` とテスト 3 か所だけだった。残すと
  「これを描けばよい」と読めて同じ事故を招くので消した。
- **フォーカス探索**（`App.vue` の `focusPane`）: 受け皿は空の `div` のままで、
  中身は Teleport で**本当にその中へ入る**ので、`.group[data-group-id] .admin` の
  子孫セレクタは従来どおり効く。`data-hidden` による除外もそのまま。
- **秘密の混入**: ステージ済み差分をパスワード・内部 IP で機械走査（陽性対照つき）。0 件。
