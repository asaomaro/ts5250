# 決定記録

## D1: 差し込み先はセレクタ文字列ではなく**実要素**にする

- 背景: `<Teleport :to="...">` は **`to` が変わったときだけ**行き先を引き直す。
  最初は `[data-pane-slot="<グループ id>/<タブ id>"]` というセレクタにしていた。
  グループ id を含めれば「別グループへ移した＝文字列が変わる」は拾えると考えたため。
- 決定: 受け皿の**実要素**を `ref` で登録し（`paneSlotEls`）、それを `to` に渡す。
- 理由 / 代替案: **同じグループ id のまま受け皿の DOM が作り直される**経路がある。
  `split()` は分割される側のグループ**オブジェクトを再利用**しつつ `root` を差し替えるので、
  木ごと描き直されて受け皿の要素だけが新しくなる。文字列は同じままなので Teleport は
  引き直さず、**外れた古い要素にぶら下がったまま**になる。
  単体テスト「最大化・解除で両側の入力が残る」が、まさにこの経路（分割で再利用された側に
  居る `dtaq:entries`）で落ちて判明した。要素そのものを渡せば作り直し＝別オブジェクト＝
  `to` の変化になる。
- 影響: `registerPaneSlot` は **`null`（取り外し）を無視する**。受け皿が別グループへ移るとき、
  新しい方の登録と古い方の取り外しの順序は保証されないため。閉じたタブは
  プールの母集合（どこかのグループが持っている）から落ちるので、古い登録が残っても使われない。

## D2: 差し込み先がまだ無い一瞬は `disabled` でプールに残す

- 背景: 受け皿の要素は `ref` 経由で届くので、木を組み替えた直後の 1 tick は未登録になりうる。
- 決定: `:disabled="!e.el"` にして、その間は `PanePool` の中（`display: none`）に置く。
- 理由 / 代替案: その場合にエントリごと描かない手もあるが、**アンマウント＝状態の消失**で、
  この作業の目的そのものを壊す。`disabled` なら実体は保たれ、要素が届いた次の tick で移る。
- 影響: プールの箱は常に `display: none`。中身は通常そこに無い（受け皿へ出ている）。

## D3: 最大化は「木を差し替える」のをやめ、片側を隠して表す

- 背景: `App` が `workspaceStore.displayRoot()`（最大化中はそのグループだけ）を描いていた。
  描く木が入れ替わるので**最大化した側も含めて全ペインが作り直され**、状態が消えていた。
- 決定: 常に `root` を描く。`WorkspaceNode` の分割段が「最大化したグループを含まない側」と
  仕切りを `v-show` で隠し、含む側を `flex-basis: 100%` にする。`displayRoot()` は削除。
- 理由 / 代替案: 比率（`split.ratio`）は書き換えないので、解除すれば元の形に戻る。
  `displayRoot()` を残すと「これを描けばよい」と読めてしまい、同じ事故を招くので消した。
- 影響: `pane-maximize.test.ts` の検査を「木も比率も書き換えない」へ書き換えた。
  実ブラウザで幅 695→1400px（全面）→ 695px（復帰）を実測。

## D4: タブの D&D は `dragAndDrop` ではなく手でマウスを動かす

- 背景: 検証スクリプトで Playwright の `dragAndDrop` を使うと、落とし場所
  （端 4 ゾーン／タブ帯）の判定が走らなかった。
- 決定: `mouse.down` → `mouse.move`（複数ステップ）→ `mouse.up` で行う。
- 理由: HTML5 の DnD は**マウスを動かさないと `dragover` が出ない**。
  こちらの判定（`zoneFrom`）は `dragover` の座標で決まるので、動かさないと決まらない。
- 影響: `scripts/README.md` に注意書きを残した。
